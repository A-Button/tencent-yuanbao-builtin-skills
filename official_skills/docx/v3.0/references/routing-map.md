# DOCX 路由与模板资产规则

> 这是创建成品 Word 时唯一的体裁路由、模板路径、资产选择与 L3 兜底规则来源。先按「快速决策」选路径，再读取所需部分；不要把同类但结构不匹配的模板硬套到文档上。

---

## 一、快速决策

| 条件 | 路径 | 下一步 |
| --- | --- | --- |
| 用户提供模板、范文或明确格式 | L1 用户模板 | 按 `SKILL.md` 的用户模板流程处理，不再选系统模板 |
| 命中下表中的精确子类 | L2 系统模板 | 下载同一行的全部 `template_files`，再按「模板资产契约」选择执行方式 |
| 未命中精确子类，或命中的模板与目标结构明显不兼容 | L3 自由生成 | 按「L3 最小硬规则」与 `yuanbao-default-style.md` 用 `docx-js` 新建 |

只有在用户明确接受“使用相近模板”时，才能用同大类的相近子类替代；否则没有精确子类就走 L3。`priority` 是模板建设顺序，不是运行时路由条件，不能据此选择或拒绝模板。

## 二、模板资产契约

每个子类目录使用 `<大类>/<子类>/` 两级路径，运行时只读取 `design-sources/` 下的设计来源：

| 资产 | 必需性 | 运行时用途 |
| --- | --- | --- |
| `design-sources/*.docx` | 必需 | 只读设计来源；选择与目标体裁匹配的具体文件，复制到任务目录后填充，不得复制案例事实 |
| `design-sources/*.layout.md` | 可选 | 只读版式说明；用于提取结构、版式约束与占位符说明，不得复制案例事实 |

下载方法：对命中行中的每个文件执行一次。

```bash
yuanbao-cli download --skill docx "<template_file>" --output-dir "<task_template_dir>"
```

下载后按实际资产选择：

| 下载结果 | 执行方式 |
| --- | --- |
| `design-sources` 中的具体 `.docx` 含具体的样式参考 | 复制 → `unpack` → 保留格式替换内容 → `pack` 注意只是提取版式或参考结构，不复制案例事实|
| 没有可用的 `.docx` | 按 L3 生成 |

设计来源应使用 Word 内置段落样式承载标题与正文；关键正文不放在文本框或艺术字中。表格使用 Word 原生表格。具体 `.docx` 与对应 `.layout.md` 不一致时，以 `.layout.md` 的版式说明为准。

## 四、L3 最小硬规则

L3 不匹配模板时，仍按路由判断体裁；按本节与 `yuanbao-default-style.md` 用 `docx-js` 生成。只写用户提供或可验证的信息，不为凑结构补写事实。

| 大类 / 子类 | 必备结构 |
| --- | --- |
| 公文·上行文 | 标题「关于…的请示/报告」、发文字号、主送、缘由与事项、结束语、附件说明、落款 |
| 公文·下行文 / 平行文 / 会议公文 | 标题、主送或对象、正文分条、落款；会议公文另含时间地点、参会人员、议题与决议 |
| 论文·学位 / 期刊 / 会议 / 课程 | 题目、摘要与关键词、层级标题、参考文献、图表题注；综述另含研究空白，实验报告另含方法、数据、分析与结论 |
| 研报 | 标题与摘要、章节或目录、核心观点、数据来源、结论与风险提示；可行性研究另含方案、投资与效益 |
| 商务报告 | 工作总结含期间、量化成果、不足与计划；周报含执行摘要、完成项、指标、风险与计划；会议纪要含参会人、决议、负责人和 Deadline |
| 合同法律 / 信函 | 使用用户提供的条款、主体和事实；不得补写法律结论、承诺或条款 |
| 简历 | 一页优先；个人信息、意向、教育、工作/项目、技能；不得编造 |
| 教案 / 试卷 | 教案含目标、重难点、教学过程与作业；试卷含题型、题号、分值及所需答案解析 |
| 文学创作 | 章节标题与正文分段；不强行套入公文或报告结构 |
| 财务 / 旅行 / 日程 / 技术报告 | 财务含清晰表头、单位与不可篡改数值；旅行含日期、地点、交通住宿与行程；日程含时间轴或表格、任务、负责人和状态；技术报告含背景、环境/方法、结果、结论与建议 |

## 五、易混淆边界（重点消歧）

- **党政「纪要」 vs 企业「会议纪要」**：正式党政机关行文 → `公文类/会议公文`；公司内部会议记录/简报 → `商务报告类/会议纪要简报`。
- **「工作总结/述职」**：默认走 `商务报告类/工作总结述职`；仅当明确是机关正式行文口径时才归 `公文类`。
- **「报告」**：向上级请示性报告 → `公文类/上行文`；研究/分析类报告 → `研报类`；项目/工作汇报 → `商务报告类/项目汇报`。
- **「方案」**：项目进展、立项汇报、复盘类 → `商务报告类/项目汇报`；项目论证或可行性分析 → `研报类/可行性研究`；活动/营销/工作方案暂无云端 `template_files`，走 L3 自由生成。
- **虚构叙事 vs 个人写作**：明确网文、连载小说、起点/番茄风 → `文学创作类/网络小说`；普通小说、随笔散文、日记、读书笔记、演讲稿、个人陈述等暂无云端 `template_files`，走 L3 自由生成。

---

## 六、维护说明

- **新增子类**：在云端模板库新增 `<大类>/<子类>/design-sources/`，至少放入一个对应体裁的 `.docx`。
- **新增大类**：在云端模板库新增大类与子类，本表补一个二级小节。
- **改风格**：替换云端子类 `design-sources/` 下对应的 `.docx` 或 `.layout.md`，路由规则无需改动（运行时通过 `yuanbao-cli download` 读取最新设计来源）。
