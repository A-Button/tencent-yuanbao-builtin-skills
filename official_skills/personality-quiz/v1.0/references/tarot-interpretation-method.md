# 塔罗结构化解读方法

## 目标

把牌面视作一组用于自我观察的象征信号。解读要比“关键词串联”更具体，但不把牌面包装成事实证据或固定未来。

## 七层解读

### 1. 核心母题

先用 `archetype`、`meaning` 和 `keywords` 定义这张牌正在谈什么。牌桌交接中的 `displayMeaning` 是同一标准层的即时摘要，可以作为开场线索，但不能原样充当结合问题后的结论。不要一上来把牌名直接翻译成用户的人生结论。

### 2. 朝向

- 正位：主题较容易被看见、表达或推进。
- 逆位：从受阻、内化、过量、延迟、松动五种机制中选择一至两种，不机械反义。

### 3. 位次

位次是句法，牌是词义。同一张牌落在“障碍”和“建议”必须得出不同解释。先写清位次的问题，再把牌义放进去。

### 4. 问题与主题

围绕用户原问题选择最相关的观察角度：行动与选择、关系互动、资源与工作、情绪体验、学习与成长。不要平均展开全部生活领域。

### 5. 情境案例检索

有具体用户问题时，用脚本检索三条候选案例；没有具体问题时跳过，不要为了使用案例而替用户编造背景。

本地可执行环境中使用：

```text
python3 scripts/tarot_cases.py \
  --question "用户原问题" \
  --topic "事业" \
  --spread three-card-issue \
  --card "力量|逆位|障碍|受阻" \
  --top-k 3
```

多张已翻牌时重复传入 `--card`。常规命令只返回解释所需的精简字段；审计完整案例记录时才加 `--full`。检索结果只用于形成候选解释，必须遵守：

- 先保留案例的主张、适用条件、反向信号与校准问题之间的逻辑，不直接复制整段案例；
- 优先参考牌面、朝向、位次和主题都相近的案例；分数低或仅主题相似时，只作为语言启发；
- 至少保留一个替代表现或反向信号，不能把第一名写成事实；
- 检索结果出现高影响标记时，停止预测式解释，改为现实信息梳理与专业支持；
- 团队案例不是古典原文或真实用户个案，对外不得称作“经典原案例”。

### 6. 已抽牌组合

只组合已抽开的牌，至少检查：

- 大阿尔卡那比例：更偏长期母题，还是日常情境；
- 花色重复或缺席：行动、情感、思考、资源哪一层被放大或遗漏；
- 数字/宫廷阶段：开始、积累、冲突、转折、完成，或人物角色与应对方式；
- 正逆位分布：顺畅推进与卡点落在哪里；
- 牌阵叙事：从前一位到后一位是加强、转向、补偿还是冲突。

组合不是把两张基础牌义相加。优先写“关系”：一张牌如何改变另一张牌在该位次的表现。

### 7. 校准与行动

生成 2—4 个候选解释，保留一个替代表现或反向信号。选择最贴近问题、最能由现实经验验证的候选，并给：

- 一个区分候选的具体问题；
- 一至三个低风险、可逆的小行动。

校准问题随完整解读直接给出，供用户自愿回应；它不是流程前置条件，不调用 `ask-user-question`，也不延迟当前解读或产物交付。只有新牌局缺少原问题时，才按 [tarot.md](tarot.md) 使用一次问题采集。

## 输出表达

公共语气见 [chart-language.md](chart-language.md)，本链路的写法直接在此维护。

先用平实的话回答背景问题，再解释牌面、朝向和位次怎样关联这个问题。展开可以有温度，也可以借用牌面里的具体图像帮助理解；不要在首句用“命运给你的讯息”或大段神秘修辞定性。

单牌解释其主题与朝向，多牌说明牌之间的关系，不把关键词逐一换成同义句。保留已有方法要求的替代表现、可选校准问题与可逆小行动，用自然段衔接，不把内部七层方法标题全部列给用户。

不直接复写基础牌义或检索案例作为个人结论。团队中文牌义、案例与古典原文分开；原文引用按需读 [原文与出处](source-registry.md#原文与出处)。

## 牌桌消息交接规则

牌桌消息已经包含用户实际抽开的牌面信息。收到后直接在当前对话中回答，不重新抽牌、不调用写回操作，也不猜测尚未抽取的位次。牌阵尚未抽完时可以提供阶段性解读，但要明确结论只基于目前已经揭示的信息。
