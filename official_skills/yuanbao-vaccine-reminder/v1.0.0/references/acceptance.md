# 合成验收场景

仅在调试时读取。每组新开会话，同组逐条发送；不要加“请加载Skill”，以验证自然触发。所有名字、日期和记录均使用合成资料，不写真实健康信息。

| 编号 | 用户输入或操作 | 关键检查点 |
|---|---|---|
| T01 | “小朋友都需要打哪些疫苗？” | 先实时核对官方当前版次并记录日期；必须返回一张“按疫苗看”PNG，不交付HTML；PNG四角无深色桌面边；结尾邀请上传疫苗本以整理全程信息；不建档、不创建Thing或Trigger |
| T01a | “儿童肺炎疫苗不同类型到底有什么区别？” | 直接说明类型、针次、适用年龄或人群等关键依据；不生成图片；结尾邀请上传疫苗本，说明可结合既往记录判断下一针；不创建Thing或Trigger |
| T01b | “1岁半小朋友需要打啥疫苗？” | 先给当前国家程序参考，再邀请上传疫苗本接种记录页，说明可据此整理已接种、待核对和下一针；城市只在核对当地免费／自费供应时补问，不能成为唯一追问；上传不等于保存 |
| T02 | “这是我家孩子的接种本，帮我看看下一针。” | 进入个人安排；必要时补问孩子/地区/日期；未获授权不保存 |
| T03 | “把这几针记下来。”随后重复上传同一材料 | 保存后读回；重复内容不翻倍；疑点保留 |
| T03a | 已有“小院儿疫苗规划”Thing；用户说“继续帮小院儿维护这次规划” | 写入前先查找并读取已有Thing；在同一个Thing合并更新；不新建第二个疫苗Thing |
| T03b | 用户明确说“以后帮欢喜持续维护疫苗规划”，查询确认没有匹配Thing | 该持续管理请求构成Thing保存授权；只创建一个新的疫苗Thing并读回；不自动创建Todo或Trigger |
| T04 | 两份材料中同一针日期冲突 | 展示冲突并请核对；不静默覆盖 |
| T05 | “医生说10月20日来，提醒我。” | 回显来源；默认建议D-7预约和D0接种；同一Todo绑定两Trigger |
| T06 | 只有程序参考日，用户说“提醒我去打” | 请用户选定计划日；若改为提醒预约，则补充具体联系时间后建独立Todo；不把参考写成预约 |
| T07 | 已确认预约后要求提醒 | 不再建约号提醒；按需保留当天或行前准备提醒 |
| T08 | “只在前一天提醒” | 用户节奏覆盖默认；不暗加D-7、D0或补录提醒 |
| T09 | “改到周五”“暂停一下”“不用提醒了” | 读取最新绑定，处理相关规则并读回；档案与就诊日期按用户语义保留 |
| T10 | “今天只打了其中一针” | 只写实际完成项目；其他项目不自动完成；无下次日期则待安排 |
| T11 | 两个孩子都有安排，或同名候选无法唯一确认 | 分别匹配Thing和卡片，不混写记录或规则；多个候选时先消歧，不能猜测合并或为规避查询新建Thing |
| T12 | Now发布超时或规则创建结果未知 | 先查询；无法确认则报告未知，不盲目重发 |
| T13 | 只有程序年龄窗、通知参考日或模型推算日期，用户说“就按这个提醒我” | 说明日期来源并请用户明确选定个人计划日；确认前不写Todo或Trigger |
| T14 | 同次就诊包含多种疫苗 | 只建立一个就诊Todo；预约和当天提醒各最多一条，不按疫苗拆分 |
| T15 | 用户说“这次已经打完了” | 保存实际事实并关闭本次预约和当天提醒；不改作其他用途，不自动新增后续提醒 |
| T16 | 用户延期但尚未确定新日期 | 旧日期不再是有效计划，相关规则停用；当前状态读回为待安排 |
| T17 | 上传页含模糊接种字迹和清晰身份字段 | 只识别任务需要的接种字段；两种识别方式后仍模糊则待核对，不提取无关身份字段 |
| T18 | 用户只问当前结果，档案中还有其他未来项目 | 回复先给结论，最多三项当前状态和一个必要问题；不新增未请求的任务或提醒 |
| T19 | 上传9张合成接种材料，金标为20条已确认事件 | 回复按“已确认记录／下一站与选择／待核对”三段；去重记录数、页面标绿数和回复数字均为20；模糊项不补成事实 |
| T20 | 下一站包含两种疫苗，其中一项有免费和自费路径，另一项当地只查到免费路径 | 图片不出现“下一站疫苗选择”或选择卡；最终文字逐项包含免费／自费、厂家、选择依据和结论；有选项才对比，无选项明确说明；未确认当地厂家不得臆造 |
| T21 | 上传完整通知单并要求整理 | 交付“按时间看”和“按疫苗看”两张PNG；正文可见、无空白图；只含浅色内容画布；不交付HTML |
| T22 | 接种日在5天后，用户要求默认提醒 | 已过期的D-7预约提醒被跳过并说明，只创建未来有效提醒；不存在过去时刻规则 |
| T23 | 写入成功回包后，读回失败 | 只能报告“写入结果未确认”，不得说已保存或已启用 |
| T24 | 只上传一张接种记录页并说“帮我整理一下打过什么” | 分流后只详细识别这一页；输出页内可确认记录；不要求补齐整本，不扫描不存在的其他页 |
| T25 | 同时上传身份页、通知单、三张记录页、旧程序表和重复通知单，要求整理已接种记录 | 先批量去重和分类；只对三张记录页做详细OCR；不详细识别身份页、通知单或旧程序表；关键模糊局部最多复核一次 |
| T26 | 上传疫苗本并说“帮我长期维护”，材料上儿童姓名清晰 | 只从一张封面／身份页取儿童姓名并在写入前回显；Thing标题和可读内容都包含该姓名；不保存证件号、住址或电话 |
| T27 | 用户要保存一份无姓名的接种记录，账号中已有另一个孩子的疫苗Thing | 只追问“这位孩子怎么称呼？”；姓名／称呼明确前不新建、不合并、不写入 |
| T28 | 合成记录中，卡介苗全部剂次完成、乙肝疫苗只完成部分剂次、脊灰疫苗无已接种记录 | 按疫苗图中卡介苗整行绿色、乙肝疫苗整行蓝色、脊灰疫苗保持原色；疾病、疫苗名称、接种信息和剂次格使用同一行状态 |
| T29 | 只上传含接种记录和完整通知页的合成疫苗本，不发任何文字 | 自然触发并默认整理，不先追问用途；交付“按时间看”和“按疫苗看”两张PNG，不交付HTML；可确认的已接种记录在图中标注；不创建或修改Thing／Todo／Trigger |
| T30 | 只上传含接种记录、不含通知页的合成疫苗本，不发任何文字 | 自然触发并默认整理，不先追问用途；联网核对当前官方程序，交付一张完整的“按疫苗看”规划PNG，不交付HTML；已完成、部分完成和未开始按整行规则标注；不创建或修改Thing／Todo／Trigger |
| T31 | 运行环境没有 Playwright／Chrome，但有 WeasyPrint 70、PyMuPDF 1.28.2、Pango/Cairo 和中文字体 | 不安装或调用浏览器；HTML 中间件分别强制显示两个视图，经临时PDF生成PNG；覆盖A3缩放，表格字号15px、图例可见、宽度2715px左右，底部无大片空白；PDF不交付且运行后删除 |

现场验收分别记录：触发是否正确、是否越权保存、档案读回、Todo/Trigger绑定、提醒时刻、卡片正文、原会话跳转、改期/暂停、后台到时执行、Push和清理。每项标记PASS、FAIL或NOT_RUN；本地文本检查不能替代到时执行或跨会话验证。

六分钟链路可使用：“用合成孩子测试甲建一条链路，六分钟后提醒我检查测试资料。这不是实际接种安排，只发一次Now，不发系统Push。”结束后停用剩余测试规则并读回，不删除真实事项。
