# 搜索功能参考

## 内容查询规则

- 用户的任何视频内容相关请求（包括但不限于：搜索、热播、榜单、推荐、最新、排行等），**一律**使用 CLI 的 `search` 子命令。
- **禁止修改用户的搜索词**：将用户的原始输入直接作为 `search` 命令的参数，不得改写、扩写、拆分或"优化"关键词。
- **只搜索一次（绝对规则）**：每次用户请求**只允许执行一次** `search` 命令，无论任何理由——包括但不限于"结果不理想"、"需要补充信息"、"查询更新进度"、"查询追剧日历"、"获取额外维度数据"——都**绝对禁止**执行第二次 `search`。第一次 `search` 返回结果后，不得再发起任何 `search` 调用。
- **排播进度查询**（"播到第几集"、"更新日程"、"下一集什么时候播"等）**不属于 search 范围**，应使用 `schedule` 子命令。
- **禁止**：修改用户搜索词、对同一用户请求执行多次 search、使用浏览器搜索、调用第三方 API、自行编造内容、引用记忆中的信息来回答视频内容相关问题。

示例：
```sh
# 用户说"最近热播" → 原样传递
<cliPath> search "最近热播"

# 用户说"有什么好看的电视剧" → 原样传递
<cliPath> search "有什么好看的电视剧"

# 用户说"那个涉及到爆炸和循环的电视剧是什么" → 原样传递
<cliPath> search "那个涉及到爆炸和循环的电视剧是什么"
```

## CLI 输出结构

CLI 的 `search` 命令返回两部分内容：
1. **AI 文本推荐**（可选）：以 `AI searching for: ...` 开头的自然语言段落
2. **结构化卡片数据**：以 `Found N items:` 开头，每条数据有标签前缀

结构化数据可能包含以下字段（均可能缺失）：

CLI 标签 | 含义
---|---
标题（第一行） | 视频标题
`Subtitle:` | 副标题
`Type:` | 品类（电影、电视剧、综艺等）
`Actors:` | 主演列表
`Director:` | 导演
`Year:` | 年份
`Area:` | 地区
`Tags:` | 标签（如：古装爱情、社会话题）
`Score:` | 评分
`Episodes:` | 集数信息
`VIP:` | 是否需要 VIP
`URL:` | 播放链接
`Poster:` | 海报图片地址（不展示给用户）
`Desc:` | 简介

## 输出格式

**严格按照以下规则输出。只允许展示 CLI 实际返回的数据，禁止添加 CLI 未返回的条目、编造信息、重新排序或分组。**

### AI 文本推荐处理

**不要将 AI 文本推荐作为独立段落输出在开头。** AI 文本推荐中包含的各条目推荐理由，应拆分后放入对应卡片的引用块（`> `）中。AI 文本中有通用的总结性开头语（如"根据您的需求，我为您推荐以下几部..."），直接丢弃，不要输出。

### 卡片模板

**⚠️ Markdown 换行核心规则：每个字段必须独占一行，相邻字段之间必须插入一个空行（即两个换行符 `\n\n`），否则 Markdown 会将多行合并为一行渲染。**

每条结果按以下模板格式化，**每个字段独占一行，字段之间用空行分隔**：

````markdown
🎬 **标题**

📺 类型：品类

📝 标签1 · 标签2 · 标签3

⭐ 评分：N.N

🎭 主演：演员1 / 演员2 / 演员3

📅 年份 · 地区

> 简介文字（来自 Desc 字段，或从 AI 文本推荐中提取该条目的介绍）

🔗 [立即观看](URL)
````

**注意**：如果 URL 是搜索结果页（包含 `/x/search/`），则链接文字使用"点击查看"而非"立即观看"，即 `🔗 [点击查看](URL)`。

### 格式规则（必须严格遵守）

1. **🎬 标题行**：`🎬 **标题**`，标题用 `**` 加粗，前加电影 emoji。
2. **📺 类型**：`📺 类型：品类`。独占一行。CLI 无 `Type` 时省略整行。
3. **📝 标签**：`📝 标签1 · 标签2 · ...`，多个标签用 ` · ` 拼接。独占一行。CLI 无 `Tags` 时省略整行。
4. **⭐ 评分**：`⭐ 评分：N.N`。独占一行。CLI 无 `Score` 时省略整行。
5. **🎭 主演**：`🎭 主演：演员1 / 演员2 / 演员3`，演员之间用 ` / ` 分隔。独占一行。CLI 无 `Actors` 时省略整行。
6. **📅 年份·地区**：`📅 年份 · 地区`，用 ` · ` 拼接。独占一行。缺少的字段跳过，只有一个字段时不加分隔符。
7. **简介（引用块）**：如果 AI 文本推荐中提到了该条目的介绍，用 `> ` 引用块格式提取放在对应卡片下方。独占一行。如果 AI 文本中没有提到该条目，则省略。
8. **🔗 链接**：`🔗 [立即观看](URL)`。独占一行。CLI 无 `URL` 时省略整行。如果 URL 是搜索结果页（包含 `/x/search/`），则使用 `🔗 [点击查看](URL)`。
9. **条目间隔**：每条结果之间用 `---` 分隔线隔开。
10. **来源标注**：所有条目之后，输出 `**来源：腾讯视频**`。**这必须是整个回复的最后一行，之后不得再输出任何文字。**
11. **字段缺失处理**：任何字段在 CLI 输出中不存在时，直接省略该行，不要输出空值或占位符。
12. **条目数量一致性**：CLI 返回 N 条结果（`Found N items`），必须输出恰好 N 条卡片，不得自行增删。
13. **绝对禁止**：
    - 不得输出 CLI 未返回的条目（禁止自行编造额外推荐）
    - 不得自行编造 CLI 未返回的字段值
    - 不得改变 CLI 返回的条目顺序
    - 不得将多个字段合并到同一行（年份·地区·集数除外）
    - 不得添加分类标题、自定义分组或总结性文字
    - `Poster` 字段不展示给用户
