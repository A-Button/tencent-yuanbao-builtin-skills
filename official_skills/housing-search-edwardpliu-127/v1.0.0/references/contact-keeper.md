# 联系管家

`prepare_keeper_call` 是带隐私影响的联系准备工具，不是找房搜索的自动下一步。只有用户已经选定一套本轮或历史展示过的真实房源，并明确表示要联系管家时才使用。

用户对某一套房表达明确兴趣但尚未提出联系时，可以先建议：“需要我帮你获取这套房负责管家的可拨打号码吗？”这只是询问，不调用工具。只有用户肯定后才进入下面的预览流程。不要承诺提供管家的私人手机号；工具返回的是用于联系该管家的可拨打号码或虚拟号。

## 调用前

1. 将“第 2 套”“富力十号那套”等指代对齐到已展示房源的 `listing_ref`。无法唯一确定时先让用户选择，不猜房源。
2. 用户明确要联系或打电话时，首次调用使用 `phone_action=preview`。该调用只读取 OAuth 用户账号手机号并返回脱敏值，不绑定虚拟号。
3. 不接收用户或模型自行填写的 `inv_no`、`keeperId` 或电话号码替代 `listing_ref`。

## 手机号与结果

- `status=requires_phone_confirmation` 时，使用 `account_phone_masked` 询问：“为保护隐私，将使用账号手机号 138****8000 建立虚拟号，是否使用该号码？也可以修改。”不得展示或猜测完整账号手机号。
- 用户确认使用账号手机号时，再调用 `phone_action=use_account_phone`，不要传 `user_phone`。MCP 会根据当前 OAuth `sub` 重新查询账号手机号并绑定。
- 用户明确给出新号码时，调用 `phone_action=replace` 并传 `user_phone`。不要在回复中复述完整手机号；可用“尾号 1234”确认。
- `status=requires_phone_replacement` 表示账号没有可用手机号。说明用途后询问是否提供一个本次呼叫号码，不要把它说成授权失效。
- `status=ready`：展示管家姓名（有才展示）和可拨打的 `call_uri`/号码，并说明点击或拨号由当前客户端完成。不要声称已经拨通。
- `status=keeper_resting`：展示工具返回的休息提示，不展示或猜测号码；询问是否稍后再联系。
- 上游失败与没有管家是不同状态。失败时建议稍后重试，不把它说成该房源没有管家。

## 隐私边界

手机号只用于本次管家呼叫流程。不要把手机号写入找房条件、长期记忆、房源比较或其它工具参数；不要在调试信息中输出完整手机号、虚拟号、Access Token 或签名引用。
