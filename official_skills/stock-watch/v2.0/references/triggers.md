# 创建、回调与用户改动

Thing/Todo/Trigger 怎么建、两类 Trigger 形态、命中后回调怎么走、用户改主意时怎么改。

## 内部发布记录（不作为附件交付）

要发出的 Now 动态，其 setup 记录和回调事件记录均按真实 Thing ID 与本次事件区分，保留完整 `show_widget` 请求、调用状态以及实际返回的 `now_id` 或错误，供恢复与防重复发布使用。仅在宿主明确提供不会被收集为用户产物的内部持久化位置时落盘；不猜测目录，不因目录隐藏或位于 `/tmp` 就认定安全。不得将这些内部 JSON 写入 `/data/workspace` 等产物位置，不使用 `tee` 在产物目录保留副本，也不在最终回答中附上文件、下载链接或原始 JSON。

宿主未提供已确认的内部存储位置时，使用当前会话中的原始工具请求与回包记录继续正常调用，不额外创建 JSON 文件，不因缺少文件而阻断首次发布。恢复时先查已有记录及实际可用的查询能力；上下文或回执缺失、无法确认上次是否发布时，报告发布结果未确认，不自动重发。记录缺失不代表未发布。不得为隐藏附件删除仍用于恢复的发布凭据，也不得改动 `_run.py` 的 stdout / sentinel、卡片协议或 Thing/Todo/Trigger 的保存流程。

## 发 Now 动态的通则

回调动态，以及这一轮要发的那张股票 Now 卡，都按这一节，后文不再重复。本会话已经发过股票 Now 卡、这一轮只是创建盯盘的，不发，不走这一节。

- **平台既不幂等也不去重**，同参数再调一次就是另发一张卡。所以先按「内部发布记录」记下完整请求，再调用工具，再记下实际回执，不生成用户附件。
- 只有回包里拿到真实 `now_id` 才算发出。超时、回包缺失、Polaris 找不到调用方或结果未知时，必须报告发布结果未确认，不要自动重试，也不能改口说已通知；回调这一轮报告完就停下。
- 重试前必须先核对内部记录及真实回执，确认上一次到底发没发出去。
- `show_widget` 失败如实报告，不由对话或前端补一条假动态。

## 创建

1. **先读行情、定条件。** 用户给定观察意图后（异动、到价、资讯监控），先用 `westock quote` 读行情，确认市场、币种、最新交易时刻和可用价格。缺少明确条件时才询问。用户只要行情和观察事项、明确不通知时，出盯盘卡结束，不启用规则，也不出 K 线渲染卡。一次性验收按 references/acceptance.md，不把测试阈值当用户投资目标。
2. **默认开两项。** 新建一个盯盘任务默认开两项：异动监控 + 每晚 20:00 收盘日结（先一张 `stock`，再一张盘面总结）。资讯不在默认里：用户明确要资讯监控或每晚资讯汇总，才挂一条资讯 Todo（`schedule_info.kind=MONITOR`，不另建定时规则）。没挂这条 Todo，日结不搜资讯。到价/止损提醒仅在用户给出明确价位时再加。
3. **建之前先查已有的，别平行再来一套。** **`get_thing` 只查了 Thing，查不到规则。** 它要带上标的名当 keyword，别只传 `limit`。建任何规则前先 `trigger/list_triggers` 按 Thing / 标的核对一遍：这只票已经有同类规则就**复用或 `update_trigger` 改条件**，不要新建。只要这只票的规则挂在别的 Thing 下、或者已有 Thing 没排进 `get_thing` 返回的前 10 条（只传 `limit: 10` 时），就会平行长出第二套——两套都在跑，用户收到双份提醒，而且停掉一套还剩一套。
4. **按 make-things 的顺序建，这一步不能省。** 先 `load_skill` make-things，再按它的创建顺序创建空 Thing、预设 Todo ID、停用规则、一次写入 Todo.rule_ids、检查依赖后启用。观察意图与条件写入 Thing.goal（到价含目标价/止损价与方向，异动含量比/涨跌幅阈值，资讯含监控范围与推送时机）；一个观察事项一个 Todo，多条规则仍可绑定同一 Todo。使用原生 Trigger，禁止 create_timer、番茄钟 phase、App-Server Runner 和逐轮创建 DELAY。规则按「两类规则」建，judge.prompt 按「judge.prompt 怎么写」写。默认两项都要建完并启用：异动监控（`check_anomaly`，`FREQ=HOURLY`）和每晚 20:00 日结。
5. **没建成就不能说已创建。** 正文里的「已创建」「已纳入盯盘」「已开启异动监控」「每晚 20:00 会推」只能写在工具回包之后，而且回包里要有真实 `thing_id`，异动规则和日结规则都 `enabled: true`。没调用 make-things、回包没有真实 ID、或规则仍停用：写没建成和原因，不能改口说已创建。2026-09-28「帮我盯平潭发展、特斯拉、Burberry」只跑了 `show_quote` 和一段正文，Thing 没建。
6. **股票 Now 卡按下一节发**，不要用「创建默认不发」把第一次那张也省掉。

### 两类规则

**价格类（到价、异动）—— 原生 Trigger + Judge。**

- `schedule.rrule` 写 `FREQ=HOURLY`。交易时段和周末由 `check_anomaly` 滤掉，不要把午休再写进 rrule。
- `judge.tool_call` 写 `{"tool_name": "check_anomaly", "tool_arguments": {"symbol": "…", "mode": "anomaly"}}`（到价规则的写法见下），**按工具名调，不要写成 bash 跑 westock，也不要写成 `stock_market_data`**：Judge 那套精简环境是判定 Agent 自己的 skill 列表，不继承建规则那一轮加载过的东西，`westock` 这个二进制在不在无从确认，不在就是每小时一次取数失败。让判定模型自己读原始行情表，判错一次就是一次假唤醒。
- 阈值（`volume_ratio_min` / `change_pct_min`）由入参带进去，交易时段、量比、涨跌幅三条都在脚本里算完。
- `judge.condition` 只写一句：**回包 `triggered` 为 true 时命中；其余一切情况都不命中。** 别让判定模型去读原始行情表自己做算术和时间比较——那比读一个布尔脆得多，判错一次就是一次假唤醒。周末、非交易时段、没越线、取数失败、回包不是 `triggered: true`，都写在这一句里，由 judge 判不命中。
- **没命中就什么都不发生。** 跟旅行围栏同一条：judge 未命中不投递 prompt、不唤起执行，主对话里看不到这一轮。不要把这些情况写成「先投递，再由 prompt 向用户解释」。
- **不要建成不带 judge 的每小时 Timer。** 不带 judge 的 Timer 每次到点都把 prompt 投进主对话。有的创建挂了 judge，所以安静；没挂上的，每小时一条说明。启用前必须回读：`judge.tool_call.tool_name` 是 `check_anomaly`，并且 `judge.condition` 还在。缺一样就不要 `enabled: true`。
- **每小时规则未命中或取数失败：本场景明确静默，不发默认提醒卡。** make-things 允许上层技能写明本次不发卡。故障留到每天一次的日结体检里说，不在每小时打扰一次。
- **异动和到价各建一条规则，不合并。** 两者的节奏不一样：异动命中后当天停用、次日由日结恢复；到价是一次性的，命中发完就结束。合在一条规则里就共用一个开关和一份参数，怎么停都会误伤另一个——异动命中停用会把到价一起停到收盘后，到价收口会把异动也停掉，日结恢复又会把已完成的到价重新打开。
- **到价规则的写法**：`{"tool_name": "check_anomaly", "tool_arguments": {"symbol": "…", "mode": "alert", "alert_price": 280, "alert_direction": "below"}}`，condition 同样只读 `triggered`。`mode: alert` 只判价位，不看涨跌幅和量比。到价只在用户给了明确价位时才建，一条价位线一条规则，单独挂一个到价 Todo，跟异动监控的 Todo 分开。
- 回调那轮按回包里的 `hit_kind` 出卡：`anomaly` 出 `show_anomaly`，`alert` 出 `show_alert_hit`。
- 代价说清楚：有到价线的票每小时多取一次数。make-things 自己写着「每条都挂 judge 会让每次运行都跑一次取数调用，成本和失败面都上去」，所以默认盯盘只有异动这一条，到价按用户要求才加。换来的是两件事能各停各的：单独取消到价，停用那条到价规则就行，异动不受影响。
- **同一类判定别建两条。** 同一只票只建一条异动规则，同一条价位线只建一条到价规则。**错开五分钟不算分开**：那只会让人以为是两件互不相干的事，实际仍是同一个轮询打两遍。

**收盘日结 —— 每日 20:00 的原生 Trigger。**

**日结那条不合并**：它是 Timer、每天一次、不带 judge，跟小时级判定不是一回事。到点触发，callback **不比价，直接跑当日收盘取数**（走「命中之后」的日结路径）。一次先发股票卡、再发盘面总结。资讯 Todo 没挂上就不搜资讯；挂上了才搜，和进展行 `已推资讯：` 做差，有新的才发。禁止 create_timer。

- **日结这一轮第一件事：恢复今天被停用的异动规则**（`update_trigger {enabled: true}`）。异动命中后会把自己停掉以免一天报十几次，靠这里恢复（见「异动一天只报一次」）。这步无条件做，排在取数和发卡之前——后面任何一步失败，规则也已经恢复了。只恢复异动规则，到价规则不动：到价是一次性的，停了就是完成了。
- **日结这一轮顺带体检异动监控。** 对清单里每只票跑一次 `python3 /data/skills/stock-watch/scripts/check_anomaly.py '{"symbol":"…"}'`，看回包的 `phase`：全是 `ok` 就什么都不说；出现 `error` 才在日结正文里写一句「异动监控取数异常（N/M 只失败），今日可能漏报」，并如实带上 `message`。**不要报「今日检查 N 次、失败 M 次」这种计数**：judge 是无状态的，未命中不唤醒任何人，`trigger/list_triggers` 也只返回开关不返回执行历史，那个数字拿不到真值；按 rrule 推算出来的「应该跑了几次」不是「实际跑了几次」，写上去就是假指标。这里是收盘前当场实测一次，回答的是「这条监控现在还能不能用」，那才是用户真正关心的事。
- **一个 Trigger 管这一档日结，不要为股票卡、盘面总结、资讯总结各建定时规则**——同一批标的、同一个时点，拆开就会有的发了、有的没发。

盘中重大资讯的即时推送需 make-things 的资讯轮询/事件触发能力；若暂不支持，先只落地这个日结，即时推送作为后续增强，不用 create_timer 硬凑。

### judge.prompt 怎么写

`judge` 只放 `tool_call` 和 `condition`。执行指令放顶层 `prompt`，只在 judge 命中之后才会被投进会话。回到原会话的路由由服务决定。不硬编码 Skill 版本或回调地址。

prompt 照下面写，尖括号换成真实名称和代码。照抄，不要再加一句给用户看的说明。

```
加载 stock-watch，处理 Thing「<标题>」下 <名称>（<代码>）的异动。
再跑一次 check_anomaly，入参与本规则 judge 相同（mode 为 anomaly）。
回包 phase 为 error：正文只写取数失败和 message，不发卡，不停规则。
回包 triggered 不是 true：不发卡，直接结束。
回包 triggered 为 true：用 westock 做归因，主对话 show_anomaly，Now 用 now_stock.py 发一张只含这一只的 stock。卡上写「今日不再重复提醒，明天开盘恢复」。拿到 now_id 后把这条异动规则停用。
```

到价规则另写一段，不要套上面「今日不再重复提醒」那句：再跑一次 `check_anomaly`（`mode` 为 `alert`，带上原来的 `alert_price` / `alert_direction`）。`phase` 为 error 同样只写失败原因，不发卡，不停规则。`triggered` 不是 true 就不发卡，直接结束。是 true 才出 `show_alert_hit`，Now 一张只含这一只的 `stock`，拿到 `now_id` 后停用的是到价规则。日结那条不带 judge，prompt 按「收盘日结」写，不要套这两段。

- **prompt 里不要写「静默结束」，也不要写「零输出」。** 2026-09-23 模型把 prompt 里的「静默结束」原样念进了会话。后来换成在 prompt 末尾放一句同样意思的说明，2026-09-27 周末又被念了出来。这两句都是回复正文，不是闸门。闸门是上面的 judge：没命中根本不投递。

### 股票 Now 卡发不发

用正文确认记下了哪些票、开了哪几项（异动监控 + 每晚 20:00 日结；到价仅当用户给了价位），以及现在的价。完成态措辞遵守上一节「没建成就不能说已创建」。

- **本会话还没发过股票 Now 卡**，用户这一轮说的是盯盘、看看盘面、看看股票：发 **1 张** `stock`。入参由 `now_stock.py` 生成，带上真实 `thingId`（这一轮刚建好的就用刚返回的 ID；还没建 Thing 的纯看盘可以不带）。发布与防重按「发 Now 动态的通则」。不要改成 `image_text`，不要追一张盘面总结 `recommend_list`。
- **本会话已经发过股票 Now 卡，这一轮只是创建盯盘：** 不发 Now，不要再跑 `now_stock.py`。先看了盘面、卡已经推过，再说「帮我盯」或去走 make-things，不要连发两张。
- **已经在盯盘里、之后又问盘面：** 再发 1 张 `stock`。那是再看一次，不是创建确认。
- **主对话按场景只出一张 xcard。** 盘面只 `show_quote`，资讯只 `show_news`，不要两张一起出。不出 Now 不等于主对话也不出卡。
- **全清单总结仍是每晚 20:00 的收盘日结。** 当面不要追发。
- **规则没启用成功就不能写「已开启」。** 规则仍停用、授权未完成或启用失败时，正文写已记下观察、规则尚未运行。这种时候也不要为了补一张卡改口说已开启。

## 回调与动态

### 先判断：被叫醒不等于该说话

正常的未命中不会走到这里。judge 没过，prompt 不会被投递。

真被投进来了（judge 误判，或规则当初没挂 judge）：不发卡，直接结束。回复里一个可见字符都不要有，不要解释原因，不要交代下一步，也不要说「规则保持启用」。进展行该回写照样回写——那是写进 Todo 的，不进会话。

判据只有一条：**这一轮有没有用户会想看的新事实**（到价命中 / 异动命中 / 收盘日结）。没有 → 回复为空，直接结束。

**下面这些写法全部算违规**（出现过就说明没静默）：

| 违规写法 | 为什么违规 |
|---|---|
| 「本次检查未命中，不打扰用户」 | 那句话本身就是打扰 |
| 「已过收盘，静默跳过」 | 能说出「静默」就说明没静默 |
| 「按规则本轮静默结束：不取数、不发卡、不通知」 | 嘴上说不通知，会话里已经推了一条 |
| 「不在交易时段……美股开盘后继续轮询」 | 时段说明不是用户要看的新事实 |
| 「规则保持启用」「今晚 20:00 照常推」 | 这是状态确认，不是命中事件 |

规则本身也要配合：`judge` 的取数用 `check_anomaly` 这类**返回布尔的工具**，别让判定模型去读原始行情表现算——判错一次就是一次假唤醒，而假唤醒到了这一层只能靠上面那条兜。

### 命中之后

1. 从本轮可信 callback 取得 Thing/Todo/规则引用，重读 get_thing。已完成、已暂停、条件已改或规则不再绑定时不执行旧任务。
2. 再查实际行情，记录数据时刻；行情与 Judge 之间可能变化。查询失败如实记录错误，不能声称条件未命中。当前条件不再成立则不发布动态（不发卡，直接结束）。按类型取内容：
   - 到价：比对现价与目标价/止损价及方向。
   - 异动：用 westock `news`/`events`/`fund flow` 做归因。
   - 资讯：用 westock `news`/`report`/`notice`/`events` + web_search 兜底取内容，整理成 item 列表。

   拿不到明确内容就如实说明，不编造。
3. 主对话出盯盘卡：到价/异动调 `show_alert_hit` / `show_anomaly`；资讯汇总调 `show_news`。**不要调 `emit_kline.py`，不要 `load_app(stock-kline)`。** 任一张失败要如实记录，不虚构 App ID，也不用另一张冒充。
4. 把 `stock-watch` 的稳定 App ID 合并进当前 Thing 的 `mcp_app_ids`，保留其他绑定，不要互相覆盖，**也不要补绑 `stock-kline`**。实例刷新不等于新动态。
5. 形成事件：到价/异动事件含标的、规则、行情观测时刻、价格/涨跌幅/量比及触发方向；资讯事件含 item 列表（每条含利好利空与一句话解读、来源）。
6. 调用 make-things 绑定的正式 `show_widget` 工具把动态发到 Now，同时传真实 `thingId`，发布与防重按「发 Now 动态的通则」；确认要重发时复用原始请求，不要改写措辞或数据。普通图表刷新不调用它，同一事件不再 notify。卡型按「Now 动态发什么卡」，并且**必须跑对应脚本，不要手写 `show_widget`**：到价/异动、当面问盘面用 `now_stock.py` 的一张 `stock`。**资讯一律 `now_news.py` 的 `recommend_list`，禁止用 `stock` 卡**——股票卡只能画报价，标题写成「资讯」身子仍是行情块（2026-09-27 许继电气）。每晚 20:00 日结先 `now_stock.py`（今天值得盯的，最多 3 只），再 `now_board.py`。资讯 Todo 没挂上就不搜、不发。挂上了才搜，和 `已推资讯：` 做差，差集为空就不跑 `now_news.py`；取数失败不当成没有新资讯。拿到真实 `now_id` 之后才把这张卡上的 key 写入进展行。不要为盘中重大另建规则；资讯卡只能是 `now_news.py`。**A2UI 卡只在主对话出，Now 这边发不了它**，不要把 `stock-watch` 写进任何字段。
7. 一次性到价目标在真实发布成功后收口那个到价 Todo，并停用那条到价规则（异动规则不动）；持续观察（异动、资讯监控）则保留 Todo，但已发布的同一观测不能重复打扰。
8. **异动发出去之后，立刻 `trigger/update_trigger {enabled: false}` 停用这条异动规则**（到价规则不动），见「异动一天只报一次」。停用要在拿到真实 `now_id` 之后做——卡没发成就停规则，等于今天白盯一场。

## 异动一天只报一次

**命中即停用，次日由 20:00 日结恢复。**

为什么必须这样：判据 `change_pct` 是**当日累计涨跌幅**，分母是昨收、一整天不变。股票上午冲到 +6%，只要不跌回去，后面每个小时算出来还是 +6%，judge 每跳都判命中，它没有任何办法分辨「这是上午那一次」。拿状态量当事件量用，重复是必然的，不是去重没做。现实里异动本来也不会持续一整天——要么冲高回落，要么封板不动。

三步，用的都是 `update_trigger {enabled}` 这一个已验证的调用：

1. 异动卡发成功（拿到 `now_id`）→ 把这条异动规则 `enabled: false`
2. 当晚 20:00 日结 → 把它恢复成 `enabled: true`
3. 用户当天明确说「继续盯」→ 立刻恢复，不用等日结

- **卡上必须说一句「今日不再重复提醒，明天开盘恢复」**，否则用户会以为监控挂了。
- **恢复这一步在日结里是无条件的**：清单为空、股票卡和盘面总结都没发、资讯总结也没发，也要先把今天停掉的异动规则恢复了再结束这一轮。漏掉就是规则永远停在那儿，而界面上看不出来——这是这套设计唯一会静默失效的地方。
- 当天第二次异动（比如上午 +6%、下午反向 −6%）按本规则不再报。要区分方向得记住上次的方向并在规则参数里传递，`update_trigger` 能不能改 `tool_arguments` 尚未验证，所以先不做；真出现漏报反馈再说。

## 用户改动

改目标时重读状态并更新原规则，不删除重建；暂停时先停规则，保留事项。用户强行插队后的恢复仍重读状态和发布回执，不能重复发通知。不要按会话旧文本恢复已取消的观察。
