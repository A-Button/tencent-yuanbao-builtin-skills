# 长期记忆系统（Career Memory System）— 精简版

> 完整规则见本文件附录。以下是每次对话需要执行的**核心动作速查表**。

---

## ⚡ 快速执行清单（每次对话按此执行，不读全文）

### 1. 读取（条件触发，非无条件）

> **记忆文件固定路径**（**固定绝对路径**，不随当前工作目录漂移）：`~/.offer-e/offer-e-memory.md`（可通过环境变量 `OFFER_E_MEMORY_PATH` 覆盖）
> ⚠️ 记忆必须落在用户家目录下，**绝不能写进 skill 安装目录**（skill 更新时安装目录内的文件会被替换，用户档案会丢失）。`references/career-memory-template.md` 仅为空白结构模板，供参照字段结构，不作为读写目标。
> 使用 `Read` 工具读取该文件，不要用脚本 subprocess 调用。

```
IF ~/.offer-e/offer-e-memory.md 存在 AND 含已填充的有效信息（即存在非"待补充"/非"暂无"的实质字段）：
    用 Read 读取该文件 → 过滤出当前场景相关段落 → 开场带入（"上次我们聊到XX，最近怎么样？"）
ELSE（文件不存在，或存在但全为"待补充"/"暂无"的空模板）：
    视同首次用户，跳过带入，直接进入正常对话流程（不要拿空模板硬凑"上次我们聊到…"）
```

**关键提示**：不要每次都尝试读文件——先判断是否老用户；**"文件存在"≠"有内容"**，空模板所有字段均为"待补充"，此时应视同首次用户。读的时候用 `Read` 工具，路径为固定路径 `~/.offer-e/offer-e-memory.md`。

### 2. 写入（即时征求同意 + 阶段性写入）

> **写入目标**：`~/.offer-e/offer-e-memory.md`（与读取同文件，位于用户家目录；目录不存在时由 `Write` 首次写入自动创建）
> **写入方式**：使用 `Write`（整体覆写）或 `Edit`（局部替换）工具直接操作该文件，不要用 subprocess 调用脚本。
> 脚本 `scripts/memory/career_memory.py` 仅供用户在终端手动执行或调试时使用，Agent 不通过脚本写入。

```
用户首次提供有价值信息时（如专业、年级、目标方向等）：

IF 记忆文件不存在 OR 未含同意标记：
    → 在回答用户问题的同时，顺带征求同意（一句话，不单独发一条消息）：
      "你提到的方向/专业等信息对后续建议有帮助，我可以记下来方便下次接着聊吗？
       只记会影响建议的内容，不记身份证/手机号/薪资等隐私。"
    → 用户同意 → 立即写入已有信息 + 标记"已同意"，后续阶段性静默写入
    → 用户拒绝 → 不写，后续不再追问

IF 用户已同意过记忆：
    → 阶段性静默写入（见下方"阶段性写入触发点"），不再询问
```

**阶段性写入触发点（已同意用户，不打断对话）：**
- 用户确认/调整目标方向时 → 更新「目标方向」字段
- 用户补充技能栈/项目经历时 → 更新「能力与经历」字段
- 简历诊断完成时 → 写入「简历改进方向」
- 面试复盘完成时 → 写入「面试复盘」摘要
- 阶段切换时 → 更新「当前阶段」字段
- 对话结束时 → 追加一行会话摘要

**核心原则：第一次有价值信息出现时即时征求同意（一句话），同意后按阶段静默写入，不再逐条问。**
用户说「别记这个」「清空」「忘记我」时才中断。

### 3. 会话结束（轻量）

追加一行会话摘要：`日期 | 话题 | 关键产出 | 下次切入点`

### 4. 跨阶段衔接

```
explore输出(方向) → build输入  → 不再问"你想做什么"
build输出(能力)  → sprint输入 → 直接用于简历/面试
sprint输出(进展) → career-path输入 → 基于轨迹给路径建议
```

## 允许记录 ✅

年级/专业/毕业时间/目标方向/城市/技能栈/项目亮点(摘要)/简历改进方向/面试复盘/沟通风格偏好

## 禁止记录 ❌（硬约束）

身份证/手机号/邮箱/地址/银行卡/薪资/HC通过率/完整原文/主观评价/推断信息/第三方个人信息

## 用户控制权

- 「忘记我」「清空」→ 立即停止并删除
- 「别记这个」→ 跳过该条
- **记忆确认只做一次**：用户首次提供有价值信息时即时征求同意（一句话，附在回答中），同意后按阶段静默写入不再逐条问；拒绝后不追问

## 附录 B：详细规则（按需查阅）

### B.1 设计原则
1. **越用越懂你**：增量更新，不让用户重复自我介绍
2. **主动但不打扰**：待办追踪顺带提，不刷存在感
3. **隐私由用户掌控**：写入前告知用途；随时可删
4. **记忆服务决策**：只用于更好建议，不做评判预测

### B.2 写入时机
- 用户主动提供新信息后（不打断对话流）
- 里程碑事件：方向确认/简历迭代/面试完成/收到offer
- 阶段切换时同步更新"当前阶段"
- 对话结束时写会话摘要

### B.3 信息冲突
- 新旧不一致 → 以最新表述为准，旧值标记 `[已过时]`
- 与官网冲突 → 以官网为准，记忆中标注差异

### B.4 进展回顾（距上次 >2 周时触发）
> "好久不见！上次我们聊的是[topic]，最近有新进展吗？"

### B.5 里程碑庆祝（简短真诚）
- 确定方向 → "有了方向就可以针对性准备了"
- 简历完成 → "这是重要的第一步"
- 收到面试邀请 → "好好准备"
- 收到 offer → "对你能力的认可"

### B.6 卫生规则
| 数据类型 | 保留期限 | 过期处理 |
|---|---|---|
| 基础画像 | 长期 | 随更新覆盖 |
| 探索记录 | 长期 | 标注[已变更] |
| 能力建设 | 1年 | 标记[历史]归档 |
| 求职进展 | 周期结束后6个月 | 归档或清除 |
| 会话日志 | 最近20条 | 滚动删除最旧 |
| 待办事项 | 30天未更新 | 标记[需确认] |

### B.7 技术实现

> **Agent 运行时**：直接用 `Read` / `Write` / `Edit` 操作固定路径 `~/.offer-e/offer-e-memory.md`，不调用下方脚本。
> **下方脚本仅供用户在终端手动执行或调试时使用。**

| 命令 | 用途 |
|---|---|
| `python scripts/memory/career_memory.py init` | 初始化（终端手动执行） |
| `python scripts/memory/career_memory.py show` | 展示摘要（终端手动执行） |
| `python scripts/memory/career_memory.py append --text "..."` | 追加记录（终端手动执行） |
| `python scripts/memory/career_memory.py forget` | 清空（终端手动执行） |
