# 快递100 Connector验收用例

本文件记录平台接入时应验证的可观察行为。测试环境必须使用专用账号和测试数据；
涉及新增、修改、删除、设置默认地址和预下单时，必须由测试人员明确确认。

## 一、连接与鉴权

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 正常连接 | 完成`initialize`后调用`tools/list` | 返回本Skill声明的稳定Tool名称和输入Schema |
| 未认证 | 不带Bearer Token调用任一Tool | 返回HTTP 401，不返回用户数据 |
| Token过期 | 使用过期凭据调用Tool | 提示重新认证，不要求用户在对话中提供Token |

## 二、地址簿

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 按姓名查收件人 | `search_address_book(keyword, receiver)` | `structuredContent.items`只包含收件地址 |
| 查询寄件地址 | `search_address_book(addressType=sender)` | 结果只包含`tag=1`的地址 |
| 同名多条 | 姓名匹配多条地址 | Agent展示脱敏候选并等待选择，不自动使用第一条 |
| 新增寄件地址 | 用户确认分类和完整地址后新增 | 返回新增地址，`tag=1`且`isDefault=0` |
| 新增收件地址 | 用户确认分类和完整地址后新增 | 返回新增地址，`tag=2`且`isDefault=0` |
| 修改地址 | 只修改一个字段 | 未提供字段、地址分类和默认状态保持不变 |
| 设置默认寄件人 | 选择已有寄件地址并确认 | 写后查询返回同一`addressId`，旧缓存失效 |
| 删除普通地址 | 选择非默认地址并确认 | `structuredContent.deleted=true`，重新查询不再返回该地址 |
| 删除默认寄件地址 | 直接请求删除 | Tool失败，提示先设置另一条默认寄件地址 |
| 写操作超时 | 新增、修改、删除或设置默认时超时 | Agent不自动重试，改用查询确认状态 |

## 三、寄件与查价

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 自然语言指定收件人 | 用户说“寄给某人” | 先查收件地址簿；唯一匹配仍需用户确认 |
| 查询运费 | 提供寄件城市、收件城市和重量 | 返回可用快递、预估价格和时效，不自动替用户选择 |
| 未最终确认 | `confirmed=false`调用预下单 | Tool失败且不保存预订单 |
| 已最终确认 | 完整参数且`confirmed=true` | 返回 `structuredContent.url` 与 `structuredContent.qrCode`，同时展示跳转与二维码入口，说明仍需在小程序确认并支付 |
| 预下单结果未知 | 调用超时或断网 | 不自动重试，避免重复预订单 |

### 链接与二维码输出

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 新对象结果 | 成功返回顶层 `structuredContent.url`、`qrCode` | 使用两个原始地址；不再固定读取 `structuredContent.result` |
| 原始JSON-RPC | 响应外层为 `result` | 先解包，再读 `result.structuredContent.url` 与 `qrCode` |
| 仅文本结果 | 缺少结构化内容，文本块含两个字段的合法JSON | 解析JSON并展示两个入口，不把整段JSON当URL |
| 兼容旧服务 | 只返回 `structuredContent.result` Scheme字符串或纯文本Scheme | 用真实链接渲染“去小程序确认并支付”文字入口，禁止裸链接；说明旧服务未返回二维码，不自行生成图片地址 |
| 缺失字段 | 新对象只有 `url` 或只有 `qrCode` | 保留已有入口并说明缺失，不补造其他字段，不重复下单 |
| 业务失败 | `isError=true`，文本里恰好包含URL | 展示失败，不按成功预订单输出链接与二维码 |
| 自定义协议不能点击 | 宿主把 `weixin://` 渲染为普通文字 | 引导使用真实二维码入口，不输出裸Scheme或完整URL代码块，不把Scheme改为HTTPS |
| 支付链接观感 | 服务返回很长的支付跳转URL | 可见文字严格为“去小程序确认并支付”，地址只在链接目标中；正文、表格、行内代码和代码块均不出现裸链接 |
| 主对话展示二维码 | 成功返回 `url` 和 `qrCode` | 主对话显示固定支付文字链接和内嵌二维码；不附加“打开二维码”入口；零次浏览器或侧边预览打开操作 |
| 图片加载失败 | 二维码区域显示占位符 | 主对话保留支付文字链接并说明显示问题；不自动打开新页面、不声称码已过期、不创建新预订单 |
| 明确要求浏览器打开 | 用户另行明确要求在浏览器打开二维码 | 才可打开已有图片URL；不重复预下单，不把普通“展示二维码”请求视作此授权 |
| 重复展示 | 用户要求把刚才的链接和二维码摆出来 | 重用同一次成功结果；零次新增预下单调用 |
| 编码一致性 | 对实际 `qrCode` 的 `code` 参数按URL规则解码一次 | 结果与同一响应的 `url` 完全一致，内层 `orderNo%3D` 不丢失 |
| 图片内容验证 | 图片URL返回HTTP 200和PNG | 状态码不足以证明内容正确；用解码器核对二维码内容与 `url` 一致，微信拉起另行验证 |
| 报告失效 | 用户说扫码提示失效 | 不编造有效期；重绘同一链接不视为续期，不自动重复下单 |
| 明确重新创建 | 用户明确要求重新下单，寄件信息已确认 | 成功后展示同一新结果的链接与二维码；不混入旧地址；超时或结果未知不自动重试 |

## 四、订单与物流

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 最近订单 | 用户未指定数量或状态 | 默认传limit=200，先做状态统计，再展示前50条明细；包含已取消订单，不自动过滤 |
| 默认保留已取消 | 返回已取消，同时物流UNKNOWN | 计入已取消统计，若在展示范围内则正常展示明细且订单状态为已取消 |
| 用户指定状态 | 用户要求“只看已取消订单”或“排除已取消订单” | 按明确要求筛选；未要求时不筛选状态，不调用写操作 |
| 明细不超过50条 | 本次返回45条订单，其中37条已取消 | 一次展示全部45条明细，包含已取消记录，不要求用户再说继续 |
| 明细超过50条 | 本次返回65条订单，其中包含已取消订单 | 统计全部65条，按返回顺序展示前50条，说明剩余15条未展开；用户明确要求更多时按要求展示 |
| 未查询全部订单 | 接口total大于本次实际返回条数 | 区分接口总数与本次返回数，状态数量及时间跨度只描述本次结果 |
| 全部结果已取消 | 查询范围内订单全部已取消 | 正常汇总并按展示上限列出已取消明细，不声称无可展示订单 |
| 用户指定条数 | 用户要求展示5条/30条，或只查询最近200条 | 遵循查询范围和展示数量，默认保留所有状态；工具允许limit=200，拒绝0及201 |
| 按单号查物流 | 调用`aiserviceapiquery4agent_get` | 真实轨迹必须以Markdown表格展示，至少包含“时间”和“物流轨迹”两列 |
| 自然语言轨迹 | Tool返回段落、列表或Markdown格式的轨迹 | 提取真实记录整理成表格，不直接贴长文本，不补造时间地点 |
| 单条轨迹 | 仅返回一条有效轨迹 | 仍使用表格，不退化为列表或段落 |
| 需要手机号验证 | 物流Tool提示需要手机号 | Agent只追问手机号或后四位后再查询 |
| 查无结果 | 单号不存在或上游无数据 | 如实说明未查询到，不编造轨迹或预计送达时间 |

## 五、物品知识路由与未匹配处理

对同一组问题比较修改前后的首次工具选择、参数和回答依据；服务端部署后重新获取`tools/list`，确认工具description更新，再加载新版Skill。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 独立包装咨询 | “手机寄快递怎么包装？” | 优先调用`query_item_weight(itemName=手机)`，不先收集地址或重量；依据实际包装建议回答 |
| 运输条件咨询 | “香水能空运吗？” | 优先查询物品，按实际返回的空运规则和条件回答；没有空运依据时如实说明 |
| 保价建议 | “寄手机建议保价吗？” | 查询并使用返回的保价建议，不编造保价金额或赔付规则 |
| 寄件估重 | “羽绒服寄快递大概多重？” | 优先查询并说明是参考重量，后续查价前要求用户确认 |
| 名称缺失 | “这个怎么包装？”且上下文没有物品 | 只追问物品名称，不编造`itemName` |
| 未匹配 | Tool返回`matchSource=DEFAULT`，重量和限制为空 | 说明未匹配，不认定可寄或估出1公斤；继续查价时询问实际重量 |
| 兼容旧版兜底 | `DEFAULT`同时返回1公斤、可寄递 | 不把旧兜底当作有效知识，可补充网页信息 |
| 已匹配但重量为空 | Tool返回规则和包装信息，无重量 | 知识咨询仍依据已有信息回答；只有继续查价时追问重量 |
| 条件限制 | Tool返回空运`FORBIDDEN`、陆运`CONDITIONAL`及条件 | 分别说明运输方式和条件，不概括为全部禁寄或无限制可寄 |
| 规则未覆盖 | Tool规则和包装建议为空 | 不推断无限制，可补充搜索并区分信息来源 |
| 用户指定搜索 | “联网查手机快递包装要求” | 遵循明确联网要求，不强制拦截为仅工具查询 |
| 路由回归 | 查快递单号、提供城市重量查价、查询普通新闻 | 分别进入物流工具、查价工具或通用搜索，不误用物品查询 |
