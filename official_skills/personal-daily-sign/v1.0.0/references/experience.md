# 入口与需求澄清

本文件处理用户这轮想要什么、已知什么、何时追问以及何时接力专业 Skill。确定可执行的内容方向后，本文件的工作结束；出签创作由主 Skill 按需进入相应参考。

## 从内容兴趣到日签

单次咨询先满足用户所问的主题与时间范围。已有星座、方法、专业结果或指定来源直接沿用；相对日期按用户当地日期理解。需要专业测算时接力相应 Skill 的结果，再由日签 Skill 把本次问题说清楚。趣味运势以象征启发和轻建议承接，自然点明娱乐参考。

日签是这份内容可以继续陪伴用户的方式。初次运势咨询在回答后，用一句与当前兴趣有关的轻问邀请每日签；其他轻量启发按兴趣自然承接。邀请只是一个选择，接收安排由后续意愿决定。用户已限定单次、拒绝邀请或已有服务时，沿已有选择收束。

表达持续接收意愿后，把已确定的内容主线承接为每日签：一张图片围绕当天一个重点展开，点缀随内容选择。主题、依据、口味和已确认的安排从上下文继承。内容依据、频率和送达时刻决定服务本身，只补确实缺失的条件；信息齐全后按 [服务安排](service.md) 落地。明确要求的纯文字或其他形式继续保留。

用户用“每天出／给我＋主题＋日签”委托持续内容时，日签和每日频率已经确定，主题也已有方向。“心情指数”“今日能量”等可以是签上的趣味表达，不自动变成需要用户打卡的量表；先结合本轮与近期对话创作，再由实际内容决定是否用星级、短句或其他视觉表达。没有真实记录就不把数字写成对用户心情的客观测量。用户明确说每天会提供练习时长等记录时，这些数据是当日签的依据，不把日签转成普通打卡任务；“我会发数据”说明内容来源，不等于取消已经提出的每日接收。用户明确选择“我发来再出、无需定时”时则按其选择。数据尚未到来时保留委托，已到来的数据用于当日签。只有用户要求累计、连续天数或回顾时，才依据实际保存的记录计算。服务尚缺送达时刻时，直接问时刻，不用“纯文字／带图／运势／记录”混合菜单重新定义日签。

内容所指日期与发送日程分别理解：单次查询日期属于本次内容，周期服务默认围绕送达当天；明确要求提前看次日等安排时按该委托保存。

## 判断已知信息与缺口

从当前对话、原 Session、已保存偏好和可见 user insight 中复用与本轮委托有关的答案。只核对会改变交付的主体、主题、方法及其必要资料、形式、持续接收安排；阶段背景、当天线索和近期 Things 如何影响这一张，留到出签创作时决定。用户本轮明确表达优先于旧画像，信息已足够就继续。

## 一个人、几个人与一段关系

日签服务围绕用户的生活展开，内容主体不限定为用户本人。用户提到多个人时先保留这个范围，再判断内容焦点：可以分别呈现每个人当天的主题，也可以聚焦相处、配合与共同节奏，还可以将两者收在一张共同日签里。只有焦点会实质改变内容时才询问；上下文已经明确就直接沿用。

每个主体的依据分别记录，共同关系的内容另记共享主题。需要星座、生肖或其他个人资料时，只补当前方法确实需要且尚未知的部分；关系主题可以基于双方已确认的信息与当前诉求创作。多人内容仍归属于同一个用户委托，可以使用一个 Thing、一个接收安排和一张组合日签图；用户明确要求分开发送时再拆分。

## AUQ 只补影响下一步的缺口

提问前复用已有答案。主体范围、内容焦点、内容依据与接收安排是不同维度；只问当前会改变结果或阻塞交付的部分。已经说“每天”就沿用每日频率；已给主题且可按原创日签完成时，这个主题不再算内容缺口，只确认未知的送达时刻。明确专业方法后直接承接该方法。画风通常从已有口味推导。

有限选择用 ask_user_question，具体时间等自由值用一句正文追问。同一轮有多个独立的有限选择缺口时，可在一次调用里分题呈现；每题只承载一个选择。问题直接问用户想要的体验，不讲技能选择、工具能力或内部判断。选项用用户能感知的差异命名，说明保持一行；只有上下文支持明确建议时才标推荐，不因排序或预选替用户确认。

用户把天气、运势或随机灵感作为日签的可选线索时，按已知口味选择适合当天的内容，不把这理解成必须先定一种测算方法。用户明确要求每天以运势为主线、尚未指定方法且不同方法会改变结果时，问“想按哪种方式看每天的运势？”选项区分星座、生肖和随机灵感签：星座与生肖表示轻量趣味解读，随机灵感签表示原创寓意。能力边界只有在确实改变选项时才用一句自然说明；选项描述采用日签本身能够兑现的体验。已指定星座或生肖而具体信息仍未知时，只补该方法确实需要的资料；已有可靠资料时直接沿用。

送达时刻未明确时，直接问“每天几点收到比较合适？”；用户已说“早上”，只补具体几点，不擅自定 8 点。确有几个已知候选时间时可以用 AUQ，让用户选或自由填写；不把预选当确认。字段和单独调用要求遵循宿主工具。

| 当前缺口 | 如何推进 |
|---|---|
| 已知涉及多人，尚不清楚想分别看还是看彼此关系 | 问内容焦点；允许“分别看”“看关系”“合在一起”，随后沿选择收集对应依据 |
| 已有信息足以满足本次内容 | 直接交付，持续接收意愿尚未形成时先完成单次体验 |
| 内容方向会明显影响结果 | 补一个主题或兴趣方向；开放创作可由既有口味推导 |
| 用户指定的方法缺少依据 | 优先接收已有结论；确需推算时核实专业能力，再收集其必要资料 |
| 已委托持续或定时接收，日程有缺项 | 只补缺失的频率、时刻或实际需要的时区；已知安排直接沿用 |
| 内容依据与接收安排都缺失 | 分别问内容依据与送达时刻，后者需要自由填写时直接追问；回答前不生图、不创建服务 |

问题随当前缺口变化，AUQ 的目标是让下一步可执行。单次内容咨询先交付内容，明确持续委托后先确认服务条件；纯概念与术语问题直接解释。

“你推荐一种”授权选择当前可执行的方法：优先使用匹配的专业能力；确无可用能力且用户没有坚持精算/真实随机要求时，说明原创象征方式后继续。“别问，直接出”补默认创作信息，但不推定每日授权。只说“这次看看”按单次文字理解；已经明确要图片时则交付单张图片。

## 专业内容接力

专业 Skill 提供确需推算的排盘、牌面或解释，日签承接结果与交付。根据用户实际选择只接力所需方法，不为丰富日签同时加载多套体系。先复用各主体已经给出的明确结论，例如“我喜木火”已足够作为该主体指定的创作依据；只有用户要求核算或依据确实缺失时才进入推算。个人标签与完整命盘分开：仅知日主、星座等标签，可以给相应的轻量趣味解读；出生月份、时辰、宫位、大运等个人盘面信息要来自用户或可靠测算，当前月份不能代替出生月份。专业追问与本轮 AUQ 合并，个人资料按方法和主体分别补齐。结果回来后保存每个主体的方法、关键结果和来源作为 basis，共同关系另存 shared_focus，文字、图片或每日服务沿用户选择继续。

| 方法 | 内容依据 |
|---|---|
| 心情寓意、抽签意象 | 用户期待与原创象征；随缘已够用 |
| 太阳星座、生肖趣味 | 已知星座/生肖可直接用，未知才补必要信息；创作联想与精算结论分开 |
| 塔罗 | 真实专业牌面及正逆位；无抽牌能力时说明可做原创象征体验，由用户接受后继续 |
| 八字、星盘等精算 | 先核实实际能力或用户提供的明确盘面，再收集所需参数；具体字段沿专业 Skill |

专业结果缺失时保留待继续状态。用户坚持真实方法且拒绝替代，就说明缺口。涉及现实选择时，用象征启发用户核实信息、表达需要，决定仍依据现实条件。
