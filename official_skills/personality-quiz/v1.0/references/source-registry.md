# 解释资料路由

这是一张按需加载索引，不是“公认权威排行榜”。单体系任务只读取匹配的一张来源表；用户明确要求体系比较时，可为每个被比较的体系各读取一张，不扩展到无关体系：

| 体系 | 来源表 |
|---|---|
| 八字 / 子平法 | [sources-bazi.md](sources-bazi.md) |
| 西洋占星 | [sources-western.md](sources-western.md) |
| 用户导入的紫微斗数或印度占星 | [sources-imported.md](sources-imported.md) |
| 人格测试 | [sources-personality.md](sources-personality.md) |
| 塔罗 | [sources-tarot.md](sources-tarot.md) |

书目被列入只表示值得参考，不表示全书观点均被采纳。使用前确认 `source_id`、版本/译本、流派、适用问题和 `review_status`。本文件同时维护来源目录、复核状态、入库范围与下方的原文引用规则。

`review_status`：

- `seeded`：候选资料，尚待专家逐项复核；
- `reviewed-scope`：已确认适用范围，不代表逐条规则通过；
- `reviewed-rule`：某条结构化规则已核对到具体版本或章节；
- `reviewed-card-draft` / `reviewed-case-draft`：团队已初审的塔罗内容或案例草稿。

只入库书目元数据、流派与适用范围、团队短摘要、已核验规则及其版本/页章指针、专家复核状态和已知冲突；公版原典也只保留完成任务所需的短摘。不入库来源不明的整本扫描、现代版权书全文、大段 OCR、网络文章拼贴、无法确认版本的页码或仅凭模型记忆生成的“原文”。

## 知识回答的表达

首句回答概念、区别或来源问题，再解释原因和适用范围。复杂概念可用温和、具体的例子帮助理解；不把一般知识转成对用户的性格判断，也不收集出生资料。先区分原文、注解和现代转述，再解释差异；普通概念问答不为装饰文风强加古籍引文。

## 原文与出处

- **原文与转述分开。** 只有实际读到且核对过的文字才标为“原文”、加引号作为引文。自己的归纳标为解释或转述，不用“古书有云”“某某说”包装模型记忆。
- **出处跟随引文。** 写清作者或书名，以及已核验的篇章、版本或页码；没查到的项目不补造。链接到支持该段内容的具体来源，不用搜索结果页或一本书的介绍页冒充原文出处。
- **不改写引文来配合文风。** 原文保持准确；白话解释放在引文之外。删节需要明确标记且不改变原意。古籍原文、注家评语、译文与团队编辑稿分别说明。
- **只摘必要部分。** 遵守来源许可与宿主引用限制，不复制整章、整本、逐牌全文或大段文章。来源表收录书目不表示已核验原文；`seeded` 记录不能直接支持逐字引述。
- **来源不足时直接说明。** 可以回答已知概念并注明无法核验该句，不补造原文、书名、页码或权威归属。来源是解释框架，不能据此声称已证明个人性格或未来。
- **用户文字与示例对话分开。** 只有用户确实说过的话才称为用户原话；自编生活场景标为例子，不当作真实经历。复制的模板、牌面基础解释和星座预置文案均不成为个人行为证据。

输出格式服从当前产物契约。普通聊天可以附核验链接；现有深度报告 `paragraphs[].text` 只接受单段纯文本，不支持引用卡片、脚注或 Markdown 链接。需要可点击出处时在报告外单独给出；不得擅自扩展 Schema、把链接塞进正文或改写生成的 HTML。既有页面规定保留在内部的来源与许可信息，仍按其资产契约处理。
