# 火车票搜索路由

## 使用 `train_search`

当用户查询国内火车票，且出发地、目的地和日期要求明确或可无歧义解析时使用。往返需求只要去返程日期和路线明确，可分别调用 `train_search`。

- `toolQuery` 必须保留用户明确给出的地点、日期、时间段、车次类型、席别、直达或中转等全部条件。
- 用户明确日期或日期表达时传 `hasUserSpecificDate=true`。
- 用户完全未指定日期时传 `hasUserSpecificDate=false`，不要自行补日期。
- 不要自行增加返程、改写城市或删除用户的硬条件。
- 用户只提出车次类型、席别、时间段、直达或中转等客观条件时优先直连；条件多不等于需要 `ai_search`。

示例：

| 用户需求 | 路由 | 原因 |
|---|---|---|
| “明天北京到上海的高铁” | `train_search` | 国内单程，地点、日期和车型明确 |
| “9月20日杭州到南京，下午出发，只看二等座” | `train_search` | 单程且约束可在自然语言查询中保留 |
| “成都到重庆有哪些动车，不限日期” | `train_search` | 单程，明确传未指定日期状态 |
| “国庆北京到上海，5日返回，查往返高铁” | `train_search` | 去返程条件明确，分别查询两个方向 |

## 使用 `ai_search`

以下情况使用 `ai_search`：

- 使用模糊评价、主观体验或个性化长尾标准，例如“坐得舒服”“适合老人”“带孩子更省心”“沿途风景好”；
- 在同一次国内火车票搜索中，需要结合票价、耗时、换乘难度或乘坐体验等多个维度进行语义筛选，且需求无法由 `train_search` 的标准条件直接表达。

AI 搜示例：

| 用户需求 | 路由 | 原因 |
|---|---|---|
| “北京到青岛，带老人坐哪趟更舒服省心” | `ai_search` | 舒适、省心属于个性化体验，需要综合车次与出行条件判断 |
| “上海到厦门沿途风景好的火车” | `ai_search` | 沿途体验不是普通票务筛选字段 |
| “北京到上海，想兼顾票价、耗时和换乘轻松” | `ai_search` | 属于国内火车票垂类内的非标准需求筛选 |

## 与 `train_search` 配合

- 标准路线、日期、车次类型、席别或时间段条件直接使用 `train_search`；成功返回后不要再调用 `ai_search` 重复搜索。
- 长尾、非标准、主观体验等非标准需求直接使用 `ai_search`；如用户随后改为只按标准条件查询，再调用 `train_search`。
- `train_search` 报错、超时或为空时先如实说明；若用户需求本身属于 `ai_search` 适用范围（长尾、非标准、主观体验等），可再调用 `ai_search` 兜底，不强制、不默认。
- `ai_search` 只能辅助选择方案，不能产生火车票详情、占座或预订能力。

## 边界

- `train_search` 仅支持国内火车票搜索，不支持国际铁路。
- 往返可拆成去程和返程两次标准搜索，并在结果中明确区分两个方向；不要仅因往返使用 `ai_search`。
- 不要自行把“舒服”“适合老人”等描述等价为高铁、一等座或直达；应使用 `ai_search`，并对未验证的服务和体验信息保留说明。
- 当前没有火车票预订、占座、支付、出票、订单查询或退改签办理工具。
- 不得把查询结果表述为已锁定席位或保证可售。
- 工具未返回的席别、余票、票价、车站设施和退改规则不得猜测。
- 搜索无结果不表示现实中没有符合条件的车次；`ai_search` 也不能替代实时余票和可售价格。
- `ai_search` 不处理火车与航班、酒店之间的综合比较，也不规划多城市、多段行程。
- 国际铁路、铁路政策、目的地攻略等非国内火车票搜索问题不属于本技能范围。
