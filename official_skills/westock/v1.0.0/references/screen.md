# 筛选速查：先确认可实现性

仅在用户需要候选池或排行时使用；已有明确候选则直接查询。默认输出文字/候选表，用户明确要求文件才创建文件。详细低频语法见[筛选手册索引](screener/ai_usage_guide.md)。

## 1. 把条件和能力逐项对应

内部记录：市场、资产类型、目标时点、完整范围、字段、阈值、AND/OR、排序、缺失处理。不额外添加用户没要求的估值、行业或正值门槛；“低PE”是否排除负值如需消歧应明确说明，不静默改写精确不等式。

| 需求 | 入口 | 能力边界 |
|---|---|---|
| 数值条件组合 | `westock screen condition` | 沪深/港/美字段不同；无offset分页 |
| 技术信号 | `westock screen strategy` | 当前大小关系不等于交叉事件；仅使用已有信号名 |
| 标签池 | `westock screen label` | 多标签并查不是AND；必须明确交集及范围 |
| 事件池 | `westock screen event` | 窗口内嵌类型；不能统一追加date/start/end |
| 排行 | `westock screen ranking` | 不同指标族的字段/范围/排序不同；固定榜单不可套普通参数 |
| ETF主题/排行 | `westock screen label` / `westock screen ranking` | 显式asset=etf，与股票同名条件不等价 |

- 沪深条件字段如`PE_TTM`、`DividendRatioTTM`，港美如`PeTTM`等；逐字段查[字段表](screener/fields-guide.md)，不把quote返回名当表达式名。
- 用户问选项或名称确实未知时才查一次`--list`或`--list-presets`；已有合法名称不重复发现。
- 文档/帮助没有某字段，不枚举`MaxDrawdown1Y/MaxDD1Y/...`试拼写。一次确认后归入“需本地计算”或“能力不足”，不能盲猜。
- 关键条件无法核验时，不用相近概念替代：主力资金≠北向资金，季度持仓≠连续5日净流入，单期ROETTM≠连续多年年报ROE。

## 2. 最小合法示例

| 明确条件 | 完整命令示例 |
|---|---|
| 沪深0<PE<20且ROE>15 | `westock screen condition --market hs --expression 'intersect([PE_TTM > 0, PE_TTM < 20, ROETTM > 15])' --limit 20` |
| 沪深股息率>5，不另加条件 | `westock screen condition --market hs --expression 'DividendRatioTTM > 5' --limit 30` |
| 高ROE或高股息 | `westock screen condition --market hs --expression 'union([ROETTM > 15, DividendRatioTTM > 5])' --limit 20` |
| 港股0<PE<15 | `westock screen condition --market hk --expression 'intersect([PeTTM > 0, PeTTM < 15])' --limit 20` |
| MACD金叉信号 | `westock screen strategy --type macd_golden --limit 20` |
| 北向活跃固定榜单 | `westock screen ranking --type north_active_d` |
| ETF高股息主题 | `westock screen label --type high_dividend --asset etf --limit 20` |

示例不是默认投资条件；实际使用用户指定时点和阈值。布林字段示例存在历史文档别名差异时，先核验当前能力，不以示例中的别名替换权威字段。单位按该筛选字段定义检查，不能假设TotalMV与quote市值单位相同。

## 3. 不把列表、上限和范围混为一谈

- `condition`支持条数、排序及部分范围参数，但**不支持`--offset`**；不能照搬公告或策略分页。不要用不断切阈值制造伪分页来穷举全市场。
- 返回恰好达到limit时视为可能截断；少于limit也不单独证明完整，需要结合返回总量和服务覆盖。limit不是条件数值阈值。
- `--universe`与`--within-label/strategy/event`不是同一种范围标识。condition与ranking的接受值逐入口核对；不要凭搜索结果去掉`pt`就认定可用，不自行替换证券代码和标签名。
- 用户要求全量：一次确认范围、覆盖与可用分页。无法证明全量则明确交付“不完整样本/无法确认完整名单”，不能称筛选已全部完成。
- 正常无匹配直接回答无匹配及条件；不扩大市场、不放宽阈值、不用搜索凑名单。

## 4. 筛选后只做必要核验

1. 优先保留服务端已经返回且口径清楚的条件字段，不重复用quote/finance重新获取所有同名指标。
2. 首次请求就为后续程序处理保存完整JSON；按[解析说明](parsing.md)检查失败、部分返回和代码覆盖。请求计数不等于证券计数。
3. 核验用户必要条件的时间、单位和缺失处理；返回值不满足表达式时保存冲突、最多一次有依据的核查，不静默当完整正确筛选结果。
4. 只补必要缺列或用户要求的代表性公司信息。不为每只候选附加完整财务研究；行业字段未知时可标未分类，不能拖住整个候选池交付。
5. 排序规则明确时在已取得范围内本地稳定排序，例如股息率降序、代码升序。保留数据原值，不把展示文本中的格式或百分号当新字段。
6. 已获取足够条件数据则进入答案/文件阶段；核心条件仍缺失就说明无法验证，不继续探索相近端点。

## 5. 本地计算与不支持项

- 有限且已知的候选池，历史序列完整时可计算最大回撤等必要指标；记录公式、复权、窗口、缺失日和计算值身份。
- 用户明确要求全市场筛选时，不能从Top N候选本地算回撤后冒充全市场完整结果。只有已验证前置池完整且执行规模可控，才继续完整核验；否则说明边界。
- 分批查询部分失败：先核对实际代码；至多一次小批诊断，不从60改20改5再逐只遍历，不以更多并发突破限频。
- 北向逐日资金不存在或未提供时直接说明；不能用`MainNetFlow5D`、买卖活跃额、季度持仓差代替。用户已允许无法取得时说明的，应立即选择该分支。

## 6. ETF多门槛仅在需要时组合

单一主题/榜单直接调用，不启动多路交集。多门槛按[ETF字段表](screener/etf-pools.md)选择必要维度；独立请求同轮执行，交集时保留各池截断范围。50条只是开放探索初始样本，不是能力上限或满足全量要求的证明。

明确未验证门槛；主题估值不等于场内溢折率，场内价格不等于净值。对返回样本求交为空不代表全市场无匹配，不无依据地反复扩池。

## 7. 停止与输出

- 文本：列市场/时点/条件/范围、候选表、排序和未验证项即可，不固定生成长报告或附件。
- 文件：仅用户要求时使用表格/文档技能，提前建最小结构；通过必要检查立即交付，不在预算末尾继续可选美化或清理。
- 无法满足全量或必要数据要求：明确未完成部分；已有样本仅作为样本，不能包装成完整结果。
