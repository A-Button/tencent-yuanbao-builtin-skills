# 西洋星盘分析规范

本文件维护西占的事实范围、解释方法与输出表达。公共语气见 [chart-language.md](chart-language.md)，链路写法见下方“输出表达”。普通分析只用本方法；报告的候选与正文契约分别由流水线在对应阶段返回，不提前读取。

只提供星座标签、要轻聊性格或对照 MBTI 时，使用 [zodiac-personality.md](zodiac-personality.md)，不为轻量请求启动本报告链路。本文件用于已经通过生成或导入流程核对的盘面。

## 可用事实

只使用去身份化分析盘真实存在的路径。新盘普通分析读取 `analysis_charts.western`；报告由流水线返回自己的去身份化数据，均须在盘面展示后使用。

深度报告只使用流水线投影的五项已确定星座：`chart.planets.sun|moon|venus|mercury.sign`（各项展开为真实路径）及 `chart.ascendant.sign`；日期级使用 `chart.stable.planet_signs.sun|moon|venus|mercury`。`chart.unavailable` 只提示缺项，不能作为人格信号。候选范围、度数、相位、其他天体、宫位与预置文案不进入这条报告链路；字段缺失时减少判断，不能推导补齐。信号路径由校验器限制到上述具体星座叶子字段。

深报复用八字的“整体解读—表达与互动方式—关注主题—观察与建议”文章组织方式，但不借用四柱、十神或大运。太阳、上升、月亮、金星、水星是解释来源，而不是五个必须重复出现的章节。

用户另行明确请求普通技术分析时，才使用完整去身份化盘中实际存在的以下路径：

- `chart.zodiac`
- `chart.planets.<planet>.sign`
- `chart.planets.<planet>.degree_in_sign`
- `chart.planets.<planet>.longitude_deg`
- `chart.aspects.<index>`
- `chart.coverage`
- `chart.houses`、`chart.ascendant`，只有非空时才能使用

当前上升为非空对象时，可引用 `chart.ascendant.sign|longitude_deg|degree_in_sign`；`ascendant_status` 只说明计算可用性，不支持性格推断。页面中的预置文案不作为模型分析的行为证据；维护页面才读 [western-presentation.md](western-presentation.md)。

日期级初盘只解释 `chart.stable.planet_signs`；`chart.possible` 只能说明范围。精确度数、时间敏感相位、上升点和宫位没有出现在盘面时全部省略。

明确出生时段的范围盘同样只使用 `chart.stable.planet_signs.sun|moon|venus|mercury`，并可引用实际存在的 `chart.stable.ascendant.sign`。稳定上升不是缺项，无须强调出生分钟未知。只有真实跨界或资料／能力缺口的项目跳过；五项深报投影不包含候选值，不能分别解释候选或请用户按性格选一项。`time_range_stable_facts` 不允许回读原始探测时刻补造确定性。

## 解释方法

沿用盘内字段导读的象征主题；这些主题是解释框架，不是天体影响人格的证据：

| 可用信号 | 观察主题 | 可展开的生活问题 |
|---|---|---|
| 太阳 | 核心表达 | 哪类投入更有认同感，怎样表达自己的主张 |
| 上升（已计算时） | 初见印象 | 进入陌生环境时如何表达、开始互动 |
| 月亮 | 情绪反应 | 不舒服时如何回应，怎样表达希望被照顾的方式 |
| 水星 | 思考沟通 | 怎样整理信息、表达想法和澄清误会 |
| 金星 | 偏好与关系表达 | 欣赏怎样的互动、如何表达在意 |
| 火星 | 行动与边界 | 如何开始行动、面对分歧和提出拒绝 |

按用户问题选择实际存在的信号。深报整体性格可先看太阳与月亮的异同，再用上升或水星补充具体场景；关系问题优先看月亮、金星与水星；学习或协作问题优先看水星、太阳与上升。火星、相位等仅供另行明确请求的技术分析，不能进入五项深报。这个顺序只帮助选材，不是硬凑字段或按天体逐项写报告。

1. 先找与用户问题相关、且有可追溯信号的配置或张力。不要从太阳星座直接推出完整人格；个人行星信息较少时缩小解释范围，不用慢行星的代际共性补满个人画像。
2. 普通分析只展开 2—4 个相关发现。每点写清适用场景和可能的反应或取舍，必要时补充局限；不强制搭配优点、缺点和建议。校准点可留到末尾，不逐段提问，也不输出后台路径清单。
3. 行星说明观察主题，星座提供象征表达方式，相位提供已计算的角度关系。只有实际相位记录存在时才讨论该相位；两个天体落同一星座不等于合相，星座层面的对立也不等于已计算的对冲。
4. 相位只在关联用户主题时加入。容许度小可帮助排序，但不自动表示更重要或影响更大；不把刑冲称为灾难，把拱六合称为成功保证，也不从相位推出情感依恋类型或现实冲突史。
5. 支持与冲突配置综合成一个有条件的判断，不拆成后台式“支持 / 限制”清单。即使多条信号一致，也只是同一象征框架内的一致，不提高科学可信度或生成准确率。
6. 把术语立即翻译成具体体验，但保留用户否定的空间。例如“临时改计划时，更在意重新明确下一步，还是先确认彼此的感受？两种都不像就排除这一条”。用户反馈调整解释，不反向修改盘面或从未知候选中挑“更像”的星座。
7. 当前盘面没有行运时不生成未来阶段、具体日期或事件预测。不借本命配置生成配对分、正缘时间或近期运势。

日期级读盘只从上表中挑选稳定字段。月亮不稳定时仍可解释其他稳定行星；只把月亮候选说明为待定范围，不分别写两份月亮人格再让用户选。精确度数缺失不影响稳定星座的轻量观察，但相位、上升和宫位的缺口必须保留。

用户同时要求 MBTI 对照时，按 [zodiac-personality.md](zodiac-personality.md) 的对照方法使用已有结果；星盘候选和正式报告的 `signal_paths` 仍只引用该盘实际字段，不将 MBTI 类型、分数或用户经历伪装为盘面路径。

低风险解释可以直接进入内容，但应保留适用条件，不声称已经知道用户的表现。信号不足的内容直接省略。通用安全边界遵循 [safety.md](safety.md)，不在报告中重复展开检查过程。

## 输出表达

- 一句结论与普通分析：先回答当前问题，再展开二至四个相关发现。不用“宇宙能量、灵魂底色”等修辞开篇，也不按天体逐项背诵形容词。可以用温和的日常例子解释不同配置之间的关系。
- 深度报告：候选与总览概括清楚；正文围绕已选判断解释相处、沟通或做事场景。观察点与建议沿用报告契约，不逐段劝导。

只解释已确定项目，未知项用脚本原因保留待定。借助象征主题理解体验时，不把预置描述当作用户的实际表现；资料较少就缩小范围。引用原文时按需读取 [原文与出处](source-registry.md#原文与出处)。
