# 卡片配图

将图片用作 NOW 卡片的视觉主体。仅在以下三处放置图片：

| 位置 | 字段 | 端上显示 |
| --- | --- | --- |
| 图文卡主图 | `image_text` 的 `cover.url` | 通栏，**裁到固定高 140**（`object-fit: cover`） |
| 推荐列表缩略图 | `recommend_list.items[].image` | 每行左侧小方图 |
| 选择卡选项图 | `todo_choice.options[].image` | 选项左侧小方图，`done` 的那张会置灰 |

仅使用可访问的 HTTPS 地址。无法获取合适图片时省略对应字段，不要使用占位图或未经工具返回的网页图片。

## 选择图片来源

| 来源 | 适用内容 | 调用方式 |
| --- | --- | --- |
| **`picture_search`（默认）** | 真实存在的实体：餐厅、街区、夜市、地标、菜品 | 直接调用函数工具 |
| `get_place_media` | 同程收录的景区、公园、博物馆、酒店；图片匹配度较高 | 通过 bash 调用本包工具 |
| `image_generation`（兜底） | 不存在真实照片的内容：一周天气图、行程示意图 | 通过 bash 调用独立 skill |

优先搜索真实图片。不要为真实地点生成图片，以免图片与地点不符。

### 默认：`picture_search`

直接调用函数工具，不要通过 bash 调用。向 `query` 传入字符串数组以批量搜索：

```json
{"query": ["深圳石洲中路夜市", "深圳学府路小吃街", "成都武侯祠"]}
```

原样使用回包中 `[url]` 的值。不要重写、截断、拼接或补全协议；将非工具返回的 URL 视为不可用。

在 query 中提供城市和完整名称，例如使用 `深圳石洲中路夜市` 而非 `夜市`。核对图片与目标实体是否一致；无法确认时省略图片。

### 查询景区和酒店：`get_place_media`

```bash
app <pkg> get_place_media '{"city":"成都","names":["武侯祠","杜甫草堂"]}'
```

每次最多查询 8 个名称。将回包中的 `places[].thumbnail` 直接写入卡片；通过 `missing` 识别没有图片的名称。
如果已调用 `prepare_landing kind=scenery`，复用其返回的 `thumbnail` 或 `images`，不要重复查询。

仅对景区、公园、博物馆和酒店使用该工具。对 `missing` 中的名称改用 `picture_search`。

### 生成非实景图片：`image_generation`

仅为一周天气预报、行程概览、路线示意等不存在真实照片的内容调用 `image_generation`。

该工具属于独立 skill，先 `load_skill` 加载它，再按它正文给出的方式调用。不要猜测脚本路径——
各环境的目录结构不同，写死 `scripts/generate.py` 会得到 `No such file or directory`。
加载失败就放弃配图，省略字段即可，不要为了出图去试别的路径。

将返回的 `[url] https://...` 地址写入 `cover.url`。

始终使用 `--ratio 12:5`（约 340×140）。端上会将主图裁剪为固定高度 140；其他比例可能裁掉天气图或信息图中的内容。

仅将生成图用于主图 `cover`。不要为列表项逐条生成图片。

先判断目标是否真实存在。对餐厅、街区、景点、菜品和车站等实体搜索真实图片；仅对「深圳未来一周天气」或「今晚行程概览」等内容生成图片。

## 省略图片

- 在结论可以用一句话说明时省略图片。
- 在所有图源均无结果或图片与目标不符时省略图片。
- 在图片与卡片主题不一致时省略图片，例如不要用城市风光图搭配出门时间结论。

允许 `image_text` 省略 `cover`，仅展示标题和摘要。不要为了使用图文卡而添加无关图片。
