# 报告呈现维护

运行时正文格式与组织原则以 [report-content.md](report-content.md) 为准；本页只用于维护渲染，不额外加入生成前的阅读链。

5.0 正文使用模型组织的 `sections`。模型决定标题、章节顺序、合并与展开；脚本只负责转义、排版、阶段参考日、必要的不可用说明和末尾一次免责声明。不固定总论、性格、十神、关注主题或建议章节，不按段数、篇幅、重点位置设置返工门槛。

各节可引用多个原局判断，也可包含经过校验的阶段事实。章节顺序不改变条件分支的含义：匿名分支仍须分清，不选边或串成一条确定结论。技术字段与来源路径留在后台。

八字与西占仍复用 `report-shell.html` 单容器文章外壳。八字保持红棕主题，西占由已验证配置加载 `report-western-theme.css` 的绿白主题；主题不从模型标题猜测。基础视觉、素材与附件协议不因文章结构变化而改变。

`finalize` 校验结构化正文后直接装配 Markdown 并渲染 HTML，不重复进行模型规划或润色。历史 4.0 正文保留旧装配分支；`validate_report_markdown.py` 是历史固定版式的离线检查器，不用于自由章节报告。

普通排盘在同一条回复交付概要与排盘 HTML。深报则在同一条回复交付核心结论与报告 HTML，正文完整保存在报告中；宿主不能打开 HTML 时才回退同源 Markdown。
