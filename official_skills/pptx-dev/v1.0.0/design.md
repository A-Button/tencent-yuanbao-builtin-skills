# 排版与设计参考（按需阅读）

模板本身已有成套设计，下面只在你需要调整文案密度、配色倾向或挑选版式时参考，不必逐条照搬。

## 选版式（layout）
模板提供多种版式积木，按内容类型选用，避免整套都用同一种文字密集版式：
- 封面 / 目录 / 章节分隔：开篇与过渡
- 要点卡片 / 双列 / 三列：并列信息、对比
- 图文分栏 / 大图：需要插图的内容
- 数据大字 / 图表页：KPI、趋势、占比
- 流程 / 时间线 / 路线图：步骤与计划
- 收尾 / 联系方式：总结与 CTA

## 文案密度
- 标题短而有力；正文用短句或要点，不要整段大段文字。
- 多条目用多个段落（`<a:p>`），不要拼成一句。
- 替换文字尽量不超过示例文案的长度，过长会溢出——复核脚本会预警。

## 配色与字体
- 模板用主题色（Theme Color），优先沿用；如需贴合品牌，改主题色而非到处 hardcode RGB。
- 字体已在模板/环境内置（含政府类方正字库）。替换文字时保留原 run 的字体设置，不要随意换字体导致缺字。

### 字色↔背景对比度（`check_contrast`，advisory）
文字与其背景对比度过低（浅底白字、蓝底蓝字、黑底黑字）过去是头号可读性杀手，最常见诱因是**给背景/衬底图位重生成了明度不合适的图**，压住了模板原本浅色或深色的文字。现在 `check_images` 已**默认禁止替换**"给文字当背景/衬底"的视觉槎（见下文「图片」，`replaced_protected_backdrop` 会硬性阻断），保留模板原图从根上规避这个风险，正常流程不需要再手动调对比度。`check_contrast` 只是 advisory 提醒（不阻断交付），仅在极少数你确实需要突破默认规则改了背景图时才用得上，修法二选一：
- 给该页背景图重写 prompt：文字是浅色就配**深底**、文字是深色就配**浅底**，文字区留低对比/留白；用 `image_generation` 重生成后换上。
- 直接改字色：在 `layout_ops.json` 里加 `{"ref":"slideN:shapeM","fontColor":"FFFFFF"}`（深底用白字、浅底用深字，6 位十六进制），随 `apply_plan --layout` 一起跑。
- 经验阈值：正文需对比度 ≥ 4.5、大字（≥24pt 或加粗≥19pt）≥ 3.0。深底配 `FFFFFF`/浅灰、浅底配 `1A1A1A`/深主题色通常都能过。

### 垂直居中与字号
- 文字偏上/偏下不居中：`{"ref":"slideN:shapeM","anchor":"ctr"}`（`t`/`b` 为上/下对齐）。
- 同类文本框字号忽大忽小：尽量沿用模板同版式的字号；个别框装不下用 `{"autofit":"normal","fontScale":90}` 让其自适应，而不是手填超大/超小字号。

### 写入阶段自动缩字（防溢出的第一道确定性防线）
排版正确性是确定性约束，应在**生成阶段**就保证，而不是留给质检兜底。`replace_text` 写入每个框后会按框反解：拿框的实际内尺寸（扣 `bodyPr` 内边距）、框内最大字号、逐段文本宽度，估算所需空间 vs 可容空间；一旦明显放不下（典型：短数字/短标签槽保留了 200pt 大字号、却被换成更宽的 `****`/多字），就把该框内所有 run 的 `sz` 成比例缩小到刚好放下，并把 `spAutoFit` 改成固定框的 `normAutofit`（`spAutoFit` 会撑大框、挤占相邻槽，是压字根因）。
- 直接改 `sz` 而不是只挂 `normAutofit`：因为 `normAutofit` 的自动缩字**只有部分渲染器实现**（实测 LibreOffice 无头导出 PDF 完全无视它），直接改字号才能得到 PowerPoint/WPS/LibreOffice 一致的结果。
- **单位/短标签强制单行**：单位/数字/短标签（≤20 字、≤2 段）绝不换行，缩字目标是"每段单行放下"，允许缩到更小的字号（最低约 10pt）以保住单行；长正文才走"面积能塞下（可换行）"的适配。这样避免把单字符 `%` 槽换成 `万人次` 后被折成"万人/次"的错误单位格式。
- **横向折行也要缩，不只看面积**：短标签只要**所需行数 > 段数**（横向折了行）就缩字，哪怕框够高、面积溢出比 ≤1.15。否则数字卡如 `15万+公里` 在高框里折成两三行断字（`15万+公`/`里`）会被当成"放得下"漏过去。`fit_font_scale` 的"无需缩"早返回同样加了行数约束，保证单行诉求不被面积判定架空。
- **组合（`grpSp`）内形状同样缩字**：KPI 数字卡多为「圆角矩形+标签+数字」的组合，跳过它们正是数字换行断字的主因。溢出比与所需缩放比对"组的同比缩放"是不变的（框宽与字号一起被组缩放，`line_capacity = 框宽/字号` 相互抵消），因此用形状**自身** `ext`/字号反解即正确，无需组坐标换算。
- 有底线（长正文最小缩放 0.35 / 8pt，短标签最低约 10pt），不会缩成不可读。缩到下限仍放不下，说明该换更宽的版式或精简文案——这交给引导，不硬缩成蚂蚁字。
- 这是兜底而非借口：文案仍应「一次写合身」，尤其**单位槽要贴合模板的位数**（模板给单字符 `%` 的槽就别塞三字 `万人次`，宁可把单位并进大数字或另择版式），自动缩字只处理结构性溢出。

### 质检兜底：基线降级不再放过"加重的溢出"
`check_layout` 会把模板原生的几何问题降级为 warning，但**仅当成品该槽的溢出没有被替换文案加重**时才豁免。历史 bug：模板某数字槽原文 `3亿` 能放下、换成 200pt 的 `****` 后严重溢出，二者几何相同曾误命中基线降级而蒙混过关。现在按溢出比 gate：成品溢出比 > 基线×1.1 即视为内容导致、照常 blocking。生成阶段自动缩字 + 质检溢出比 gate，双层保证这类问题不再带病交付。

## 图片
- **先判断内容要不要配图，再去选/找带视觉槽的页面承载**，顺序不能反过来：不能选完页发现没槽，就倒推"这页不需要配图"——那多半是选页阶段漏配了适合的版式。
- 只在已有视觉槽替换，用 `image_generation/generate` 生成贴合主题的插图或背景图；优先使用 `deck.selected.json` 的 `visual_slots`。
- 强视觉型 PPT 要让视觉槽覆盖关键页面：演讲、作品集、摄影、发布会、文化讲座等，不应做成大段纯文字。
- 生图 prompt 描述清楚主体、风格、色调，与整体配色协调；不要生成装饰性噪点图。
- 同一版式复制多页时，每个视觉槽都要按本页主题生成不同图片，避免整副看起来像同一张图换文案。
- **只有占画布 2%～50%、且没有文字压在上面的独立视觉槽允许替换**。有文字压顶或面积 ≥50% 的槽标为 `protected_backdrop:true`；面积 <2% 的槽按 icon/装饰资源标为 `protected_small_visual:true`。两类均为 `replaceable:false`，禁止生图和替换；`replace_image.py` 写入前会直接拒绝，`check_images` 也会硬性阻断旧流程造成的误换。只有 `replaceable:true` 的中等面积照片位才换成主题图。
- **分批 `--scope` 用物理 slide 编号**：`prepare_deck.py` 输出末尾的 `scope速查` 可直接照抄；不要把 `order=` 当 scope。

## 语义交付
- 成品里不要留下“还需要用户再核实/再补充”的交付承诺；无法确认的内容应改成可展示的保守表达，或删除该数据点。
- 交付前用 `content_semantic.json` 记录模型自审：确认是否还有未解决占位、事实待补、免责声明式文案。空风险写 `{"issues":[]}`。

## 演讲备注（speaker notes）
- 一副交付级 PPT 应带演讲备注：站在演讲者视角，写"这页要点 + 怎么讲 + 上下页衔接"，2~4 句口语，**不是复述幻灯片文字**。每页都写（含目录/过渡/结尾）。
- 内容全部定稿后作为**收尾前一步**统一写进 `notes.json`，随 `apply_plan --finalize-only --notes` 注入。
- 备注是**增强项、不阻断交付**——`set_notes.py` 写进对应页 `notesSlide`（PowerPoint "视图→备注" 里可见），模板缺 notesSlide 的页（常见于目录/分节页）会克隆已有结构自动补建并补齐内容类型/关系；注入在打包前完成，失败只记录、绝不挡交付。这符合"少约束、给模型空间"的取向：它是一层锦上添花的确定性写入，而非又一道拦人的关卡。

## 常见返修点
- 文本溢出：缩短文案或拆分到多页。
- 元素重叠：删除多余元素（图+文整组删除，而非只清空文字）。
- 残留示例文字：markitdown 全文搜一遍占位词。
