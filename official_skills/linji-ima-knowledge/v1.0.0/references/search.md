# 搜索与条件

## 形成完整查询

先确认城市与租赁方式。预算使用元/月和明确上下界，居室使用工具支持的精确整数；金额和否定按用户语义理解。用户只说“贵了”时，以已展示真实价格为参照，询问可接受上限或明确提出替代预算；用户未给出的阈值不能当作已确认条件。“不限”在对应字段省略表达。

通过 `resolve_locations(purpose=area)` 查居住范围，同时提交用户明确的 `city_name` 与 `city_code`。候选中的地铁、商圈、小区不是同一范围；优先保留 `match_kind=exact` 的自如原生可搜索实体，名称相似或多候选时先选定，使用 `area_ref`。`searchable=false` 表示当前工具不支持该范围。SUG 可能返回兜底实体，不能把未命中原名解释成用户所指地点，也不能用 `related` 商圈替代公司/园区。

首次搜索 `page=1`。以后每次提交完整查询，字段省略即取消该筛选。多范围“任选”分别查询、按 `listing_id` 去重并保留来源；“同时满足”必须逐项验证，不能把并集当交集。

输入契约之外的偏好先保留。能由返回事实核对的可作为候选比较维度，并说明仅检查了当前候选；无法核验的直说未知。用户同意调整前，不用删条件的替代搜索冒充原需求。

## 翻页与引用

用户只要下一页时，保持全量条件并递增 page；条件改变重置 page。分页总数与 has_more 可能未知；可继续实际检索，但不能把某一页没结果解释成全城没有房源。实时库存可能跨页重复，按稳定 `listing_id` 去重，不按每次变化的签名引用去重。

把展示序号映射到房源 ID 和最新 `listing_ref`；“第二套”默认指最近实际展示的列表，指代不明就澄清。“第一个要南山，第二个要五层”这类条件列举不是选房源。

## 比较与刷新

比较已返回的真实列表字段即可。需要确认变化时调用 `refresh_listing`，它只会重新检索来源页：`not_in_current_page` 表示本次未找到，不等于已下架。需要完整详情时说明当前只有列表事实，并给出按 SKILL.md 规则拼接的详情页链接；不生成工具未返回的照片或详情内容。

引用过期或失效后重新解析/检索；保留人的需求，不把旧引用错误当作用户取消条件。
