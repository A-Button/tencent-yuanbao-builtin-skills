# Word 文档导出方案

> HTML 报告已由 `templates/report_template.html` 生成。本文件说明如何转为 .docx。

---

## 一、导出路径选择

| 场景 | 方案 | 说明 |
|---|---|---|
| **推荐** | 调用 `tencent-docx` 技能的 `html-to-docx` 能力 | 保真度最高，支持表格/样式/中文字体，直接把渲染好的 HTML 转 docx |
| 备选 | 调用 `docx` 技能从结构化内容生成 | 适合需要精细控制 Word 原生样式时 |
| 不推荐 | 自行用 python-docx 拼装 | 表格与配色还原度差，且会丢失 L1-L4 面板的视觉分级 |

---

## 二、标准流程

1. 先按 `report_template.html` 生成完整 HTML（占位符全部替换，无残留 `{{}}`）
2. 保存 HTML 到工作目录
3. 调用 `tencent-docx` 技能，传入 HTML 路径，请求转换为 .docx
4. 转换完成后**必须调用 present_files**，同时呈现 HTML 与 docx 两个文件

---

## 三、转换注意事项

| 项 | 要求 |
|---|---|
| 趋势图 | Chart.js 渲染的图表**不会**被转换进 docx。需先截图为 PNG 嵌入，或在 docx 版中用表格替代图表 |
| 配色 | L1 红 / L2 琥珀 / L3 蓝 / L4 绿的分级色必须保留，这是快速定位风险的核心视觉线索 |
| 表格 | 交叉模式表、定量评估表、趋势表须保留表格结构，不要降级为纯文本 |
| 免责声明 | 必须完整保留，不可因排版原因删减 |
| 字体 | 中文用等线/宋体，确保在 Windows 与 macOS 的 Word 中均正常显示 |
| 页边距 | 建议 2.5 cm，便于打印后带去门诊使用 |

---

## 四、文件命名规范

```
报告解读_<脱敏标识>_<报告日期>.docx

示例：报告解读_男55岁_20260820.docx
```

**禁止**在文件名中使用完整姓名、身份证号、手机号等可直接识别个人身份的信息。

---

## 五、交付要求

- 生成 docx 后，HTML 与 docx **两个文件都要交付**（HTML 看图表，docx 便于归档编辑）
- 交付时在文字回复中给出核心结论摘要，不要只丢文件
- 必须调用 present_files，否则用户看不到产物
