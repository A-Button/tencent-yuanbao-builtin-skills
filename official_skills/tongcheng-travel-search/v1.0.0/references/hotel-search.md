# 酒店搜索路由

## 使用 `hotel_search`

当用户查询单一目的地的一次酒店住宿，且 `city`、`region`、`preference` 至少有一个明确值时使用。

- 用户明确入住和离店日期：传 `hasUserSpecificDate=true`、`checkInDate` 和 `checkOutDate`。
- 用户未指定日期：传 `hasUserSpecificDate=false`，不要编造入住或离店日期。
- 地标、商圈、车站等位置要求传 `positionKeyword`。
- 明确酒店名称或品牌传 `hotelNameKeyword`。
- 星级、早餐、房型、明确设施、预算等可验证条件写入 `preference`。

示例：

| 用户需求 | 路由 | 关键参数 |
|---|---|---|
| “9月20日至22日杭州西湖附近五星酒店” | `hotel_search` | 城市、位置、星级和日期明确 |
| “上海虹桥机场附近有儿童乐园的酒店，不限日期” | `hotel_search` | `hasUserSpecificDate=false`，位置和设施条件明确 |
| “查北京王府井希尔顿” | `hotel_search` | 城市、位置和酒店品牌明确 |

## 使用 `ai_search`

以下情况使用 `ai_search`：

- 使用模糊评价、主观体验或个性化长尾条件，例如“服务好的酒店”“有宝宝辅食的酒店”“对过敏儿童友好”“适合带老人长期住”；
- 在同一次酒店搜索中，需要结合位置、预算、设施、服务或入住体验等多个维度进行语义筛选，且需求无法由 `hotel_search` 的标准字段直接表达。

AI 搜示例：

| 用户需求 | 路由 | 原因 |
|---|---|---|
| “杭州服务好的酒店” | `ai_search` | “服务好”是模糊评价标准，普通筛选条件无法直接验证 |
| “三亚有宝宝辅食、适合一岁孩子住的酒店” | `ai_search` | 宝宝辅食和低龄入住体验属于个性化长尾需求 |
| “西湖附近，预算一千以内，想住得安静且服务好” | `ai_search` | 属于酒店垂类内的非标准需求筛选 |

## 与 `hotel_search` 配合

- 标准位置、日期、星级、预算或明确设施条件直接使用 `hotel_search`；成功返回后不要再调用 `ai_search` 重复搜索。
- 长尾、非标准、主观体验等非标准需求直接使用 `ai_search`；如用户随后改为只按标准条件查询，再调用 `hotel_search`。
- `hotel_search` 报错、超时或为空时先如实说明；若用户需求本身属于 `ai_search` 适用范围（长尾、非标准、主观体验等），可再调用 `ai_search` 兜底，不强制、不默认。
- `ai_search` 只能辅助选择酒店，不能产生酒店详情、房型或预订能力。

## 边界

- `hotel_search` 只提供搜索结果，不提供真实预订、锁房、支付、取消或订单售后。
- 不要把主观或长尾需求降级成宽泛 `preference` 后声称已满足；这类需求交给 `ai_search`，结果中未被数据源明确验证的内容仍需说明待确认。
- 不得把未返回的房态、早餐、设施、房型或价格解释为存在或不存在。
- 用户说“帮我订酒店并支付”时，应明确无法完成交易；可以按已知条件搜索候选，但不能声称预订成功。
- 搜索无结果不表示现实中没有符合条件的酒店。
- `ai_search` 提供的建议不能冒充实时房态或可订价格。
- `ai_search` 不处理酒店与航班、火车之间的综合比较，也不制定住宿或行程规划。
- 目的地攻略、天气、接送等非酒店产品搜索问题不属于本技能范围。
