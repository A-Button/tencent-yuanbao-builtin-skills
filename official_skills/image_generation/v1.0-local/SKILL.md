`image_generation/generate` 是原子级视觉创作能力，分文生图（`Text2Image`，文字→图）与图生图（`Image2Image`，基于已有图→图）。它不是被动画图器：除响应用户「画一张…」的直接请求，也应在完成更大任务时主动判断「配张图能否让结果更好」，并与图搜、代码、链式再生成等协作。一次调用只产出 1 张图，需要多张就并行多次调用。

## 目录与路径约定

任务开始时先确定，占位符必须替换为真实绝对路径：

- `WORK_DIR="<当前工作目录的真实绝对路径>"`：用户工作区，只存放最终交付文件。
- `RUN="<系统临时目录的真实绝对路径>/image_generation_runs/<run_id>"`：需要下载、转换或暂存图片时使用的运行目录，只存放中间产物；纯 URL 传递任务无需创建。
- `<run_id>` 使用主题短名；每个新交付文件使用新的 `<run_id>`，修改同一组图片时复用原 `$RUN`。
- 禁止在 skill 目录下创建文件；不得把 `$RUN` 内的路径作为最终交付路径。

**环境依赖故障处理**：当某条脚本命令因依赖缺失失败（`ModuleNotFoundError`、`ImportError`、`command not found` 等）时，执行一次 `python $YB_SKILL_PATH/image_generation/scripts/ensure_deps.py`，然后**重试原命令一次**。全任务 `ensure_deps` 最多执行一次；补齐后仍失败，则停止并向用户报告，不要循环重试。

## 1. 触发时机

### 1.1 文生图（Text2Image）

纯文本表达图像生成需求，命中任一类即触发：

1. 明确绘画/生成/创作画面或视觉形象/艺术可视化：「画一张小猫」「生成美女写真」「生成 labubu」「创作龟兔赛跑连环画」「把这些信息生成手绘艺术风格展示图」。
2. 配图：为文章/诗歌/社交媒体/广告/黑板报/手抄报/邀请函配图：「帮我为这篇文章插图」「写了首诗能帮我配图吗」。
3. 设计/创意视觉应用：包括但不限于摄影、海报、品牌 logo、室内装修、贺卡、菜单、头像、产品设计、ip形象/玩具三视图、绘画线稿等：「设计一张夏季海滩旅游海报」「帮我做一个微信头像」。
4. 想象性场景的画面感描述（结合上文语义，避免与小说创作混淆）：「想象一个未来城市，天空中飞行汽车穿梭的样子」。
5. 描述式或词组逗点式提示词，含画面特征关键词：比例分辨率（16:9）、摄影词（景别/镜头/光圈/噪点/饱和度）、绘画词（艺术家风格/构图/像素风）、空间关系等：「跳舞女孩，50mm 大光圈，背景模糊花园」「夜空与星星，梵高风格」。

多轮：对上文的文生图结果整体重画/不满意/要求重新生成，仍走文生图（「太差了」「重新画」）。

### 1.2 图生图（Image2Image）

消息中已有**可通过 URL 定位**的图片（用户消息中的公网 URL、此前 `picture_search` 或 `generate` 返回的 URL），且要求基于该图处理：

- 局部编辑/替换/新增元素：「移除图中的凳子」「换成白衬衫」。
- 画风/质感转换：「改成水彩画」「改成莫奈油画风格」。
- 全局调整：「下雨天变晴天」「改成冬天，草地有积雪」。
- 特征再生成：「参考图中女人相貌，生成她爬雪山」。
- 修复/补缺/上色/翻新老照片/去马赛克。
- 比例/分辨率/大小调整：「改成 800×800」「改成 9:16」。

多轮：如果对上文中的文生图结果，明确提出局部修改点（「背景改夜景」「不要这么胖」），本轮由图生图处理，不走文生图重画。

**本地限制（重要）**：本地模式下，图生图**仅接受 URL 形式的输入图**。用户上传的本地图片文件、代码在本地产出的图片，均**无法**作为图生图输入。用户基于这类图片要求编辑/再创作时：
- **不要**调用图生图，**禁止**伪造 URL 或把本地路径当 URL 传入；

### 1.3 不触发

- 无图像生成意图的陈述、闲聊、信息分享。
- 图像专业参数处理（亮度/对比度/饱和度/色相/反色/灰度/指定文件格式或大小）走本地代码执行；但「P 亮一点」「颜色鲜艳些」这类口语仍属图生图。
- 视频生成（文生视频/图生视频/动图/vlog）。
- 简单数据可视化图表绘制（无艺术化渲染或其他画面元素）等，代码生成即可非图像产出。
- 小说创作或角色扮演，通常有场景描述但没有配图要求，也没有提到画面参数/绘画风格等。

判断不出是否有生图意图时不要猜测性调用，可自然回复或反问澄清。

## 2. 构造 prompt

画面质量取决于你写的 `prompt`，且**文生图与图生图写法不同**：

- **文生图**：把用户想要的画面用清晰、完整的语言描述出来，该有的细节（主体、交互/动作、属性、风格、画面比例、构图、光影、氛围等）写充分；用户没交代全的，可结合上下文合理补全，但不偏离其意图。
- **图生图**：与文生图相反，prompt 是对用户这句话的**改写、而非扩写**——只做指代消解（把「这张」「那只猫」解析清楚）和语言整理，prompt 里出现的对象、属性、改动都应能在用户原话里找到，不替他构想或补充。输入图已承载原画面，故只写**相对输入图要做的改动**，并据此**禁止**：复述整张图原貌、枚举用户没提的部位/细节、说明「保持……不变」（除非用户明确要求保留某物）。
  - 编辑/替换/调整类：用简洁的指令写清改什么即可（如「给猫加一副护目镜，毛发更精致」）。
  - 参考再生成类：描述要生成的新画面，并点明参考输入图的哪些特征（如「参考输入图人物的相貌，生成她在雪山攀登」）。
  - **多图输入**：用「第一张图」「第二张图」（编号与 `input_images` 顺序一致）来指代各张图、描述它们的相对关系（如「把第一张图的人物放进第二张图的场景里」），**不要**用「左图/右图/上面那张」等易混淆说法。

通用要求：

- **忠实用户意图**：保留用户显式给定的主体、属性、风格、要素，不偏离用户想要的方向。（补全尺度按上文区分：文生图信息不足时可结合上下文合理丰富，图生图只做清晰化、不额外发散。）
- **解析上下文引用**：下游看不到对话历史，把「那只猫」「这篇文章的主题」「上一版的场景」等指代解析成自包含文字（或改走图生图把参考图传进去）。
- **知识/时效类先检索**：涉及最新事物、真实人物、时事、专业事实等你不确定的内容，先用 `web_search` 等搜索工具查证，用结果把 prompt 写准写实，避免凭空臆造。
- **硬约束**：画面比例、必须出现的文字、用途带来的版式要求等务必写明。
- **组图一致性**：当任务需要产出风格/构图/主体一致的组图（连环画、绘本、同一角色多分镜、产品系列海报等）时，**每张图的 prompt 中关于风格、构图、主体的描述必须用一致的措辞**——比如同一套画风词（「水彩绘本风格，柔和暖色调」）、同一个主体描述（「圆脸短发女孩，红色连衣裙」）、同一类构图语（「居中半身，浅景深」），仅让场景/动作/道具/情绪等差异化部分随分镜变化。措辞不一致会让模型理解成不同主体或不同风格，配合 `seed` 也救不回来。
- 不塞与画面无关的闲聊或时间信息。
- **语言**：如用户无要求，默认使用中文，但用户要求画英文内容或主题时要遵循使用英文。

## 3. 参数

- `dst_intent`：`Text2Image` / `Image2Image`（按 §1 判定）。
- `prompt`：按 §2 构造。
- `input_images`：仅图生图必填，文生图传 `[]`。**这是单次调用传入的【输入】图，不是输出**——每次调用恒只产出 1 张图，要多张输出就并行多次调用（见 §4）。**单次调用可传 1-3 张输入图**（多图融合/风格迁移/元素合成等多图任务一次最多 3 张）。每项 `{type, value}`：
  - `url`：公网/短链 URL，来自用户消息或此前 `picture_search`/`video_search`/`generate` 的返回。
- `seed`：**仅文生图可选**，整数，取值范围 `1-10`。用途是**锁定一组图的风格/主体一致性**——当本次任务要并行产出同一系列的多张组图（连环画分镜、绘本插画、产品系列海报、品牌视觉物料等需要统一风格或同一主体复现的场景）时，该组**所有请求传同一个数字**；当多图目的是探索多样性、给用户挑选不同方向时，**不要传此参数**。单张生成默认不传。
- `image_ratio`：输出图的画面比例，可选，两种写法二选一，留空为 auto。
  - `"W:H"` 整数比（如 `16:9`／`3:4`／`1:1`）：**用户明确给了比例或分辨率时用它**——分辨率换算成最接近的整数比（如 `1080×1080`→`1:1`）。
  - `"ref:N"`：**跟随第 N 张输入图的比例**（1-based，`N` 与 `input_images` 顺序一致，也就是 prompt 里的「第 N 张图」）。仅图生图可用。
  - 留空（auto）：图生图默认跟随第一张输入图、文生图用后端默认。
  - **用户没明确比例/分辨率时，按「跟随哪张图」来决定取哪张作 `ref:N`**：
    - 用户语义明确指向被处理的那张图（「图1」「这张」）→ 跟随该图。
    - 仅作风格/妆容/姿势等参考用的图，其比例**不**作生成依据。
    - 多图融合/替换类：跟随「主体承载／被编辑」的那张（如「把第一张图的主体放进第二张图的风景照里」→ 主体落在第二张图，取 `ref:2`）；用户未指明主体承载图时，默认取第一张（`ref:1`）。
    - 其他情况一律默认第一张输入图（`ref:1`，即留空）。

用户用代词指代（「这张图」「那个示意图」）时，回顾上文**所有**图片来源（图搜、历史生成、消息 URL）择相关图传入；确实都没有才反问。禁止伪造路径或 URL。

## 4. 生成多张与工具组合

一次调用只产出 1 张图，要多张就并行多次调用。出几张、各张多样还是相近、要不要锁 `seed`（**`seed` 仅文生图可用**），看这批图是**给用户挑选**还是**为任务填槽**：

**给用户挑选**（用户直接的图像需求，或多轮里让你再画）：未指定张数时默认出 4 张，按方向定没定——

- **方向未定 → 多样**（笼统主体「画只猫」、开放创意「设计张海报」、首轮探索）：并行多次、每次写不同 prompt（不同角度/构图/风格），帮用户**选方向**；**不传 `seed`**，让多样性尽量展开。
- **方向已定 → 相近**（prompt 已钉死主体+风格+要素+比例、特定用途或统一风格、已选定方向要更多同款）：并行多次、每次用同一/相近 prompt，帮用户**选执行**；如需进一步锁主体/风格一致可传同一个 `seed`（仅文生图）。

**为任务填槽**（主动生图，消费方是文档/PPT/故事等产物）：张数由任务需要的图数决定，不套用默认 4——

- 单槽位（一篇文章一张题图、一页 PPT 一张示意）：1 张，prompt 贴合该槽位内容，不凑候选；通常**不传 `seed`**。
- 多槽位（多场景故事、连环画分镜、多页配图）：并行多次、每槽一个不同 prompt 各 1 张，一次产出一组各司其职的图。
  - **同系列要统一风格/主体**（连环画、绘本、同一角色多分镜、产品系列海报）：**每条 prompt 中风格、构图、主体的描述措辞必须保持一致**（详见 §2 通用要求·组图一致性），仅让场景/动作差异化；**若走文生图**，再对所有请求**传相同的 `seed`（1-10 任选一个）**进一步锁一致性。`seed` 仅文生图可用——图生图系列只能靠 prompt 措辞一致 + 相同参考图来保持统一。
  - **每槽位风格独立、不需要统一**（不同章节配图风格本就该差异化）：不传 `seed`。

与其他工具组合（链式）：返回的 `url` 可作下次图生图输入；与 `picture_search`（取公网底图/参考）联动，逐步逼近目标。注意：代码在本地画出的图表**无法**作为图生图输入（见 §1.2 本地限制），需要艺术化图表时直接用文生图在 prompt 里描述图表内容与风格。

约定：并行调用比逐张串行更省时；单次工具调用只产出 1 张图，但同一次用户请求（即本轮 agent loop，无论中间经过多少步推理、多少次工具调用）累计最多消费 10 张输入图、最多产出 10 张图——这是**请求级累计上限，不是单次调用上限**。

## 5. 结果消费与诚实

每次调用成功返回生成图片的 `url`（**照抄原值，禁止改写或拼接**）：会话内配 `<media_info>` 展示；作下次 `input_images`（`type=url`）；或 `curl -sSL -o "$WORK_DIR/cover.png" "<url>"` 下载到工作区$WORK_DIR（仅中间加工用途下载到 `$RUN`）。

返回 `[ok] false` 时不要谎称成功，可用更短/更安全的 prompt 重试 1 次；图生图确无可用图片时反问用户，禁止伪造或硬当文生图。不暴露内部 `gen_id`，失败如实告知原因。

当用户单次请求需要处理的图量超过 §4 的请求级上限时，先在上限内把能做的做满（累计产出/消费到 10 张为止），再在回复中简短解释，禁止谎称已全部完成。措辞口径统一，例如当用户要生成/输入的数量超限时，模型先完成累计 10 张的生成/消费，再解释"每次请求最多生成 10 张图 / 每次请求最多消费 10 张输入图"。
