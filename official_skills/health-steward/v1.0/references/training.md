# 训练 · 体重围度 · 身体档案

调用方式和平台规则见 SKILL.md，本篇只讲训练这件事怎么做对。

## 训练建议规则

`workout_readiness` 记当天疲劳（1–5）和酸痛，按固定规则算出建议，你只照抄回执：

- 疲劳 >= 4 → `rest`（今日休息）
- 疲劳 == 3，或有中度及以上酸痛 → `reduced`（减量训练）
- 其余 → `normal`（正常训练）

轻微酸痛只是记录，不降档。`normal` / `reduced` / `rest` 只能来自回执，不要自己判断，也不要在参数里传结论。一天一条，同一天再记会覆盖。

## 排训练与加练

`workout_plan` 给某天排训练。当天还没排过就新建一场，要给 `plan_name`、`cycle_index`、`cycle_size`（「第 2/3 次」里的 2 和 3）。当天已经排过，这次给的动作接在末尾，已勾掉的动作一个字段都不动，原来那场的名字也不改：用户说「今天再练一个」「晚点加个卷腹」就是这样加。一场最多 20 个动作。同一天的训练、身体状态、体重各是一个对象；两个沙箱同时改同一天，后写的那份整份生效。

`exercise_key` 必须是动作资料里有的，不认识的会一次全报出来并列出可选项。组数、次数、负重不给就用资料里的默认值。

## 勾完成、改组次、看要领

都按动作名或第几个定位，不用先查 id：

- `workout_done {"names":["臀桥","硬拉"]}` 或 `{"positions":[1,3]}`：一次勾多个，重复勾是安全的。全部勾完时整场自动标成已完成；之后再加练会重新打开。
- `workout_adjust {"position":2,"sets":4}`：只改传进来的字段，`load_text` 传空字符串表示改成徒手。
- `workout_detail {"position":1}`：position 是今天清单里第几个，从 1 数。也可以给 `name` 或 `exercise_key`。

找不到的名字、越界的序号会连同今天的清单一起报回来，照着改一次再调。今天的清单里没有对应序号时，如实说那个位置没有动作，不要拿相近的顶。

## 训练卡

动作行右侧的勾选只改卡面，不发消息。卡上按钮都是把一句话递进主对话，不是工具调用：

| 按钮 | 发进来的话 | 你该做什么 |
|---|---|---|
| 改计划 | `我想调整今天的训练计划` | 改组次数用 `workout_adjust`，加动作用 `workout_plan` |
| 练了这些，帮我记上 | `今天这些动作我练完了，帮我记上` | 这句话不带动作名：问他练了哪几个，再 `workout_done` |
| 查要领 | `看「第1个动作」的动作要领` | `workout_detail {"position":1}` |
| 还有 N 个动作 · 看完整清单 | `把今天完整的训练清单说一遍` | `workout_today` 后念全部动作 |

卡面最多露三条，按排期原顺序，已完成的行还在、右侧变成 ✓，其余写在「还有 N 个动作」里。这是卡面的显示口径，不是数据口径：说完整清单时以 `workout_today` 回执里的 `today.session.exercises` 为准，不要照着卡面那三条说「今天只有三个动作」。

用户说「练完了」但记录里查不到，引导他记一笔，不要直接当成练完。

## 体重围度与身体档案

- `body_log` 记体重或腰臀腿围，至少一项，一天一条。体重不进身体档案。
- `body_profile_set` 设性别、身高、年龄、日常活动量，用来算基础代谢；`body_profile` 回执的 `missing` 说明缺什么。缺档案或缺体重时基础代谢是 `null`，不要估一个数顶上。
- `body_expenditure` 算某天消耗（基础代谢 + 日常活动 + 训练），没练时训练项是 0，不是缺数。
