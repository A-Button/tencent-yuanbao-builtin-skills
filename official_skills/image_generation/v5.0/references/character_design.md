# character_design · 品牌 IP / 角色资产化生图技能（优化版）

```text
确认 Core 来源 → 输出生成前执行摘要 → 计算并建立资产清单 → 建立或确认 Core → Core 核查放行
→ 输出 Core 放行执行摘要 → 提取正式 Anchor → 输出衍生/家族执行摘要 → 基于 Core 图生图衍生 → 逐项资产核查 → 输出最终完成核对
```

## 0. 触发与任务路由

### 0.1 触发与边界

当用户需要品牌 IP、吉祥物、影视/游戏/漫剧角色、角色设定、三视图、转身图、设定卡、表情/姿态、服装道具、角色海报、周边、品牌应用、IP 家族或基于参考图的角色延展时触发。

不触发或降级处理：

- 角色仅是商品、包装或普通海报的装饰，且不需要角色资产体系时，按普通生图或商业视觉处理；
- 将完整故事拆成多格连续画面时，归 storyboarding；
- 纯 Logo、纯字体、无角色主体的商业海报，归商业视觉 Skill；
- 只有单次人物肖像、无一致性与资产化诉求时，可按普通生图处理。
- 用户只要求“几个 IP 方向”“多个吉祥物概念”“4 个候选方案”等早期方向探索时，不触发本 Skill 的 Core/Anchor/衍生流程；待选定一个方向或给出足以形成具体角色的需求后再触发。

### 0.2 五类输入路由与 Core 来源

| 输入状态 | 路由 | Core 处理 | 后续处理 |
|---|---|---|---|
| 用户已有清晰图或上一轮确认图 | 已有 Core | 直接作为 Core，不重复生成/交付 | 作为 Core 提取 Anchor，图生图衍生 |
| 无图，但有明确单一角色方向 | 从零创建 | 文生图生成并交付完整全身 Core | 提取 Anchor，图生图衍生 |
| 无图，但有明确 IP 家族构成 | 家族创建 | 先建立单体 Core，再以单体 Core 生成家族 Core | 双层 Anchor，分别衍生 |
| 草图、低清参考、粗糙旧图 | Core 重建 | 保留用户意图，重建并交付完整全身 Core | 提取 Anchor，图生图衍生 |

### 0.3 快速决策

1. 用户要的是角色资产还是一次性普通生图？不是角色资产则退出本 Skill。
2. 判断 Core 状态：用户提供/已确认的清晰视觉 Core，或模型从零创建、补齐或重建的完整全身 Core，或 IP 家族 Core。
3. 本轮资产属于表演状态、设定与规范、还是传播与应用？按第 3 节路由。
4. 判断关联路由：品牌 IP / 吉祥物使用品牌本体关联；游戏、漫剧、真人影视或其他叙事角色使用世界观与叙事关联；兼具两者时并行核查。
5. 将 Core 状态、用户资产诉求和明确排除条件传入 **3.4.1**，由该节计算唯一的 `asset_goal`，并建立内部资产清单。
6. 用户提供/已确认的清晰视觉 Core 经可见身份核对后可提取正式 Anchor 并进入覆盖范围内的衍生；模型创建、补齐或重建的 Core 必须通过 **2.5 Core 核查关卡**，才可提取正式 Anchor 或进入任何衍生。
7. Core 未指定数量时默认生成 **1 张**确定主形象；衍生资产的合页或独立单张形式由 **3.4.1** 判定，不机械套用单图规则。

### 0.4 可见执行摘要与阶段门禁

所有角色任务必须维护内部 `execution_record`，并在以下关键节点向用户输出简短、可核对的**执行摘要**：生成/确认 Core 前、Core 核查放行后、家族 Core 或任何衍生资产开始前。摘要只呈现已确认的执行结论与实际输入，不展示长篇内部推理、完整 Prompt 或隐私路径；普通单一衍生任务可将 Core 放行与衍生摘要合并。无对应摘要、摘要字段缺失或关卡为“未通过”时，禁止进入下一阶段；不得先生成、后以文字补述流程。

```text
【执行摘要｜阶段：生成前 / Core 放行 / 衍生或家族前】
任务路由：[已有 Core / 从零创建 / Core 补齐 / Core 重建 / 家族任务]
Core 来源与类型：[用户提供视觉 Core / 已确认视觉 Core / 模型完整全身 Core]
角色比例：[头身、躯干与四肢、手脚/关节；家族补充共同五官语言与比例基线]
主体与关联：[角色主体；品牌关联 Level 与本体关联依据，或叙事身份依据]
配色与材质：[颜色来源、主/辅/点色结论、主体具体材质；食品补充食材本体与可食质感]
Core / Anchor 状态：[未建立 / 待核查 / 已通过 / 已锁定]
asset_goal：[本轮资产、数量、合页或单张形式]
实际输入：[本次实际传入的 Core、参考图、主题参考图或拼版；无则写“无”]
关卡结果：[用户图可见身份核对 / 2.4 / 2.5 / 家族成员核对 / 主题变化清单：通过、未通过或不适用]
[家族任务：成员名、单体 Core/拼版来源、总人数与分组]
[主题版本：变化清单与锁定项；三视图：仅使用 Core、无主题参考图]
```

生成调用只能使用执行摘要中已列明且状态为通过/已锁定的 Core、Anchor、实际输入与 `asset_goal`。未实际建立、核对或传入的内容不得写为“已完成”或“已使用”；任一缺项必须明确指出并先补齐，不得以事后承认跳步、增加装饰或生成后修正替代。

## 1. 共享定义与全局执行锁

### 1.1 Core / Anchor / 资产类型定义

**Core** 是角色一致性母版，分为两种来源：**用户提供视觉 Core** 为用户上传的清晰图或上一轮确认图，直接作为 Core 输入，不重复生成；**模型完整全身 Core** 为从零创建、补齐或重建的角色图，必须完整、结构清晰，用于锁定主轮廓、比例、脸、服装（如有）、材质、主配色、道具和结构锚点。用户提供视觉 Core 只锁定图中可见或用户明确的身份信息；模型完整全身 Core 默认只交付 1 张确定主形象。

模型完整全身 Core 必须是干净完整的角色设计图：只使用正面或 3/4 角度，从头顶到脚底完整呈现，双脚/鞋完整可见；禁止半身、胸像、脸部特写、裁切下半身或以遮挡姿势隐藏肢体。背景为与角色主色保持足够明度对比的浅色纯净背景，不出现任何环境、建筑、道具、纹样、氛围特效或叙事元素。它不含标题、文字、信息排版、色卡、细节框、多格缩略图、品牌应用、Logo 或水印；角色结构、比例、服装（如有）、道具与轮廓必须清楚可辨。用户提供视觉 Core 可保留原图画幅与可见范围；只有任务要求展示未见区域、完整全身、三视图或完整设定时，才进入模型完整全身 Core 路径。

**预设 Anchor** 是生成 Core 前根据用户需求整理的方向锚点，用于约束第一次生成。它只描述合理的比例倾向和设计方向，不虚构未确认的精确结构。

**正式 `character_anchor`** 是从用户提供视觉 Core 的实际可见身份信息，或从已通过核查的模型完整全身 Core 中校准出的唯一身份标准，并记录用户明确设定及已确认的补全设计。用户提供视觉 Core 未出现的身体、服装、道具或结构不得虚构写入 Anchor。每个角色使用约 30–80 字，后续任何图生图衍生 Prompt 必须逐字复用；不再混用未校准的预设 Anchor。

**资产类型**：

- 表演状态类：改变情绪、姿态、动作、镜头与表演状态；
- 设定与规范类：改变观察角度、展示版本和信息组织，服务说明、制作与提案；
- 传播与应用类：改变场景、事件、构图、品牌载体与传播信息，服务曝光与落地。

### 1.2 不可变、可变、应用包装三层

所有任务先将信息分为三层；这是设计判断和 Prompt 组织的共同语言。

| 层级 | 内容 | 规则 |
|---|---|---|
| 不可变身份层 | 头身与躯干比例、头部/身体面积与高度关系、肩宽/胯宽、四肢相对躯干的长度、手脚与关节简化方式、脸型、五官、主辅点色、材质、服装结构、核心道具、耳朵/尾巴/发型/机械件等外轮廓锚点 | 所有衍生必须继承 |
| 可控变化层 | 表情、动作、镜头、场景、主题服装、局部光线、天气、氛围、道具使用状态 | 仅按当前资产目标变化 |
| 应用包装层 | 标题、色卡、标签、信息模块、背景、品牌载体、版式、装饰 | 不得覆盖、改写或削弱身份层 |

所有新建或重建设角色必须先形成五个通用执行字段，并按角色类型补充一项关联执行字段；字段用于得出具体画面结论，不原样重复写入 Prompt：

```text
readability_strategy：主体轮廓、皮肤/毛发、服装/外壳、道具、背景及应可见五官如何通过色相、明度、材质、轮廓或景深分离
color_palette_rule：先基于用户需求/参考图、角色身份、品牌、受众、场景、功能与画风确定颜色来源，再得出主色、辅助色、点色的色温、明度、纯度、面积职责与主体/服装/道具/背景分层；食品可来自食材、烘焙、糖霜、果实或合理包装，动物可来自毛色、皮肤、栖息环境或功能标记，机械可来自功能模块、材质、品牌识别或状态系统，叙事角色可来自阵营、职业、服装、装备、世界观或用户设定
proportion_rule：头身、躯干、肩胯、四肢、手脚与关节的相对尺寸、连接方式和简化边界
information_hierarchy：标题、主体、模块、装饰的阅读优先级
layout_strategy：栅格、对齐、模块位置、同级间距、跨级留白与信息安全区
brand_embodiment_rule：仅用于品牌 IP / 吉祥物；角色主体与品牌产品、服务、体验或价值主张的本体关联，以及关联等级和可见载体
world_narrative_embodiment_rule：仅用于游戏、漫剧、真人影视等叙事角色；角色与世界观、阵营、职业、物种、能力、剧情身份、标志性行为及关键装备的关联；叙事角色设定页还须记录轻量氛围 Brief：1 个环境色调、1 种光线/天气倾向、1–2 个低对比世界观母题或材质纹理；无已确认世界观依据则不补设氛围元素
```

角色类型路由：用户明确为品牌 IP / 吉祥物时使用 `brand_embodiment_rule`；明确为游戏、漫剧、真人影视或其他叙事角色时使用 `world_narrative_embodiment_rule`；同一项目同时具有品牌与叙事属性时可并行使用，但以用户明确的角色身份边界为最高优先级。

品牌 IP / 吉祥物的本体关联分三级：**Level 1** 为角色主体直接关联品牌产品、原料、工具、容器或核心服务对象；**Level 2** 为主轮廓、材质、结构或行为机制关联品牌核心业务或体验；**Level 3** 为仅依赖制服、道具、Logo 或文字提示。单体角色必须至少达到 Level 1 或 Level 2，Level 3 不可单独作为通过依据。游戏、漫剧、真人等叙事角色不适用这套拟物化要求；其服装、武器、职业装备、发型和演员外貌若属于已确认设定，可作为不可变身份锚点。

品牌关联按以下顺序建立：用户要求与已有品牌资产 → 产品/服务本体及机制 → 角色主轮廓、结构、材质或行为 → 小面积辅助道具、符号或标识。未获用户、品牌资产、产品机制或参考图支持时，整套服装、潮流配件、墨镜、运动装备和行业符号不得主导角色识别、主体面积或主色；移除这些辅助元素后，角色仍须可读出品牌关联。

非用户指定同色、全黑或低对比时，皮肤/毛发与服装/外壳不得融为同一色块，优先使用不同色相或明确明度区间；核心道具也须与相邻区域可辨。用户指定同色时，保留其配色意图，但以材质粗糙度、反射、拼接边界、局部明度或背景层次维持边界。Core 背景必须与角色外轮廓分离；浅色角色使用明度或色温不同的浅色背景，不以强光晕代替设计分层。

**角色配色**先以用户需求与参考图、角色身份及其合理视觉来源判断，再结合品牌、受众、场景、角色功能与画风收敛。颜色来源可来自食品的食材/烘焙/糖霜/果实/合理包装，动物的毛色/皮肤/栖息环境/功能标记，机械的功能模块/材质/品牌识别/状态系统，或叙事角色的阵营/职业/服装/装备/世界观/用户设定；用户明确的品牌色、阵营色或高饱和风格优先。主色承担角色身份识别，辅助色承担结构、服装或材质分层，点色承担功能、核心道具、品牌识别或信息强调；均须明确色温、明度、纯度与面积关系。食品角色的主体色优先来自食材、烘焙与可食用表层，默认采用低至中饱和的自然或柔和色域；品牌色和高饱和色仅作小面积识别点，除非品牌规范或参考图明确要求。除用户、品牌规范或参考图明确要求外，不使用荧光、大面积纯色服装、强互补对冲、无来源撞色、随机加色或多种高饱和配件抢占主体；高对比色仅作为小面积功能点色、核心识别点或品牌标识。无明确特殊要求时避免过于鲜艳、灰旧、泛黄、脏、无层级荧光和浑浊渐变。角色、服装/外壳、核心道具和背景之间优先通过色相、明度、材质、景深和构图分层，光效只作克制补救。

角色具有可识别五官，且当前资产为正面/3/4 主形象、设定页、表情页、定妆或近中景主体时，应出现的眼、眉、鼻、嘴需与主体材质、高光、阴影、反射及相邻色块清楚分离。用户设定口罩、面罩、头盔、刘海遮挡、无口鼻设计、非人形无五官，或当前为背面、远景、侧后镜头时，不强行露出或补全五官，只呈现实有可见结构。

#### 真人参考图身份保真与年龄阶段

当用户提供清晰真人参考图，并明确要求“同一个人”“同一张脸”“保持脸部身份”或基于该真人延展角色资产时，启用真人身份保真。用户原始真人照片是唯一的 `identity_source_image`，始终作为面部身份母版；真人照片、半身照和头像均为清晰局部参考图，不是正式 Core，须先补齐并核查完整全身 Core。后续建立的全身 Core 负责体型、服装、构图、材质和角色造型，任何全身 Core 或衍生图均不得替代 `identity_source_image` 的面部身份来源。

真人身份保真启用 `face_identity_lock`：严格保持原参考人物的脸型与骨相、五官比例、眼型与眼距、眉形、鼻部结构、唇形、下颌线、耳朵、肤色及可见辨识特征。发型、妆容、服装、表情、姿态、镜头、光线和场景不得导致脸部重新设计；“同一张脸”必须指向原始参考人物，不接受仅性别、年龄、脸型或气质相近的替代人物。

Core 必须锁定 `proportion_rule`：记录头部与身体的面积/高度关系、躯干宽高、肩宽与胯宽、四肢相对躯干的长度、腿长与身高关系，以及手脚、手指和关节的简化方式。后续衍生以 Core 正面标准姿态为准；透视、镜头、姿态造成的视觉缩短不算比例漂移。只有用户明确提出具体年龄/生命阶段，且确实跨越幼年、儿童、少年、青年/成人、中年或老年等阶段时，才启用跨年龄模式；年龄阶段不清楚时先确认，不擅自改变比例。

未启用跨年龄模式时，真人默认按同龄造型变化处理：只允许发型、妆容、服装、轻微表情、姿态和场景变化，不主动改变年龄、皮肤状态、头身比例或面部结构。用户同时要求“同一个人/同一张脸”与明确跨年龄时，两者可以同时成立，面部身份不得锁死在 Core 的单一年龄；年龄阶段带来的身高与头身比例、面部软组织、皮肤纹理、发色和妆容变化，只能来自用户明确的本次变化内容。所有阶段共享同一 `identity_source_image` 与正式 `character_anchor` 中的面部视觉锚点；`face_identity_lock` 作为真人专属的内部强化约束，不得改变骨相、五官关系、脸型基础、眼距、鼻部结构、唇形或其他辨识特征。

### 1.3 通用执行锁

#### 强一致性图生图

一旦存在 Core，设定卡、三视图、表情、姿态、服装、周边、海报、IP+Logo 和应用图均基于该 Core 图生图生成。衍生 Prompt 必须逐字复用正式 Anchor；主题变体只能改可控变化层，不能重新定义角色身份。三视图与主题/服装版本为独立资产：三视图只以 Core 核对固定结构，不使用主题参考图；主题/服装版本以 Core 和用户主题参考图共同输入，但主题参考图只定义其相对 Core 实际改变的服装、表情或姿态，不成为新的身份来源。

```text
base_image: <core 路径>
mode: image-to-image
character_anchor: <逐字复用正式 Anchor>
asset_goal: <当前资产>
asset_system_rule: <同轮多类资产时的共享视觉系统；未触发则省略>
series_rule: <同类独立多张时的子系列规则；未触发则省略>
change_request: <本次允许变化的内容>
```

真人身份保真启用时，使用以下补充输入；`identity_source_image` 与当前全身 Core 同时传入，原图负责脸部身份，Core 负责全身造型。未启用真人身份保真时，不添加这些字段：

```text
identity_source_image: <用户原始真人参考图>
face_identity_lock: <锁定脸型与骨相、五官比例、眼型与眼距、眉形、鼻部、唇形、下颌、耳朵、肤色及辨识特征；不得换脸>
age_mode: <同龄造型变化 / 跨年龄模式>
```

#### 局部编辑

仅改局部时使用局部编辑，不重做未指定区域：

```text
base_image: <路径>
mode: local-edit
edit_mask: <区域描述或坐标框>
edit_prompt: <该区域如何变化>
lock_outside_mask: true
```

Mask 外区域继承原角色身份、构图和材质；参考图只迁移用户声明的材质、色彩或风格，不能借机改变角色几何结构。真人身份保真任务中，仅改发型、妆容或局部服装时优先使用局部编辑；脸部不在编辑范围内时必须置于 Mask 外锁定，避免整图重新采样导致换脸。

主题/服装版本生成前，内部建立“变化清单”：逐项比对主题参考图与 Core，只登记服装、表情、姿态中实际发生的变化。服装变化可迁移款式、局部颜色、图案、层次与服装材质；表情变化只改眼、眉、嘴与必要脸部张力；姿态变化只改动作、手势、重心与镜头关系。未登记的内容一律锁定为 Core 与正式 `character_anchor` 的已确认结果，包括主体/物种、主轮廓、五官结构、比例、主辅点色、主体材质、核心道具、附属结构及未变化服装区域；食品角色还须锁定食材本体、可食材质、低至中饱和主体色与短肢体比例。若用户要求改动清单外的内容，须先更新或重新确认 Core 与 Anchor，不以主题参考图直接覆盖。

#### 信息层级与排版

信息层级适用于所有含文字、标签、信息模块、品牌内容或应用载体的资产；无文字 Core 仅执行角色主体、背景、皮肤/服装/道具的视觉层级。含文字资产默认 2K 高清输出，文字只保留标题、标签、短句和必要字段，优先 2–6 个字或简短中英双语；不塞长段世界观。

```text
一级：角色名、品牌主题或主标题
二级：角色主体，或角色与核心场景/载体组成的主视觉
三级：身份、功能、色彩、细节、CTA、说明或应用信息
四级：边框、图标、纹样、粒子和其他装饰
```

标题、主体、模块和装饰不可互相遮挡。文字、色块、细节框和装饰必须置于角色轮廓外的安全区，不遮挡脸、完整身体或核心道具。同级模块使用统一栅格、对齐、标签样式和均匀间距；跨级内容以更大留白分隔。空间不足时减少模块或装饰，不裁切角色、不压缩文字、不让角色侵占信息区。

资产按以下模式调用 `information_hierarchy + layout_strategy`：表情/姿态页为“标题 → 姿态主体 → 短标签”；设定卡/三视图为“标题 → 完整角色或结构图 → 信息模块 → 装饰”；海报为“主标题 → 角色与场景 → 副标题/行动信息 → 氛围”；应用页为“品牌/标题 → 角色与载体 → 功能说明 → 装饰”。

所有含文字的 Prompt 末尾追加：`文字完整清晰、不截断、不变形、不错位、逐字显示。`

#### 身体结构与持物

涉及姿态、动作、手势或持物时：手指数量遵循 Core（人类通常五指，Q 版/非人类遵循其简化规则）；手臂从肩部自然连接；肘膝方向合理；胸腔、腰、骨盆和双腿关系自然；无多指、融合指、穿透、反关节、不可能扭转；手在物体外侧，握持关系清楚，左右手不随意切换。

#### 家族一致性与差异

家族共享同一视觉语法：画风、色彩职责、背景规则、五官语言、身体比例基线与版式系统一致。家族须先锁定可共同识别的五官规则（如眼型/眼距、眉口的简化方式、五官尺度与面部留白）和身体比例规则（如头身关系、躯干与四肢的相对尺度、手脚与关节的简化程度）；成员可因物种、食材或角色功能保留差异，但不得脱离该基线而变成不同系列的脸型、五官体系或身体比例。食品家族默认以完整食材本体配合简化短肢体建立紧凑、可爱的共同比例；食材形态与真实可食质感主导，五官和肢体仅作拟人化表达，不默认叠加独立人形躯干、厚重服装或抢戏配饰。材质采用两层机制：家族统一 Anchor 只锁定材质域与共性材质语法——如媒介/真实度、渲染方式、光源、表面细节密度、粗糙度与高光控制、材质世界观；单体 Anchor 必须锁定与其物种、食材、角色功能或主体本体相符的具体材质——如毛发、金属、织物、表皮、纹理、切面、夹层、透明度或油润感。家族统一性不得把成员强制处理成相同的实体材质、表皮或纹理；统一光线和完成度下，成员具体材质仍须清楚、合理且可辨。每个成员仍有独立 Anchor。成员差异应优先体现在主体、轮廓、功能、具体材质与经确认的个体特征，不得仅换颜色或衣服，也不得破坏家族共同的五官与比例体系。品牌家族至少半数成员达到品牌关联 Level 1 或 Level 2，差异在同一品牌品类或体验体系内展开；叙事家族在共享世界观下保持各成员的阵营、职业、物种或角色职责差异，不因统一性抹除人物身份。

## 2. Core 建立引擎

> 先按 **2.1 / 2.2 / 2.3** 选择建立方式；任何从零创建、参考重建或全身 Core 补齐，均须先完成 **2.4 Core 生成前快速检查**，再生成或重建完整全身 Core，并通过 **2.5 Core 核查关卡**。只有用户已有清晰完整全身 Core 的任务可跳过 2.1–2.4，直接进入 2.5。

### 2.1 从零创建与参考重建

#### 2.1.1 从零创建

仅当用户没有可直接用于当前资产的清晰视觉 Core，且方向明确时执行。先提取：品牌/行业/受众/使用场景、角色身份与功能、核心气质、用户指定文字或参考、最终资产目标。用户只给抽象方向时主动补足不涉及事实承诺的角色设计判断；用户提供明确品牌资产、角色图或参考时优先继承其身份与边界。

形成以下内部设计结果：

```text
角色定位：为谁服务，承担什么功能
创意母题：物种/品类/道具/文化来源如何结合
专属记忆点：至少一个非品类必然、可长期复用的识别点
关联结论：品牌 IP / 吉祥物写明 brand_embodiment_rule 与达到的 Level 1/2；叙事角色写明 world_narrative_embodiment_rule，锁定所属世界、人物身份与可继承的叙事锚点
核心设计来源：角色主体/物种、主轮廓、主色、核心道具、服装与材质分别来自用户要求、品牌资产、产品/服务机制、参考图、世界观或明确的自主设计判断；行业、品牌品类、受众与场景仅说明其功能、气质、传播语气与约束
形态规则：morphology_rule，根据已确认的核心设计来源锁定主体、主轮廓、功能、风格与边界，再自主补全
预设 Anchor：头身比例、躯干、四肢、手脚/关节的相对比例，轮廓、应可见五官（如有）、核心设计来源、颜色来源与配色结论（主/辅/点色、面积和分层）、材质、服装、道具和结构方向
可读性与版式策略：readability_strategy + color_palette_rule + information_hierarchy + layout_strategy 的具体画面结论
```

Core 画面结论必须额外锁定：从头顶到脚底的完整全身站位、双脚/鞋的可见状态、正面或 3/4 角度，以及与角色主色形成明度对比的浅色纯净背景；不将半身、胸像、特写、叙事场景或排版页作为 Core。

整体视觉方向由四项彼此独立但相互支持的判断组成：

- `visual_direction`：比例、体型、轮廓、形状语言、五官强度、动作倾向与细节密度；
- `art_style`：单一主画风；用户有 Core 时优先继承，不默认软萌潮玩 3D；
- `visual_finish`：材质、光影、渲染边界和商业完成度，不替代比例或结构判断；
- `color_palette_rule`：先依据用户需求/参考图、角色身份与合理颜色来源，再结合品牌、受众、场景、功能与画风确定主色、辅助色、点色的色温、饱和度、明度、对比关系和面积职责；并明确主体、服装/外壳、道具和背景的具体分层关系。食品、动物、机械和叙事角色分别按其食材/生物特征/功能系统/世界观设定选择颜色来源，不使用无来源的大面积颜色。
- `morphology_rule`：用户输入、品牌资产、产品/服务机制、参考图与世界观优先；锁定角色主体、主轮廓、结构词、动作/功能词和用户边界，在不改写这些边界的前提下自主补全比例、五官、材质、附肢、道具和动作能力。行业、品牌品类、受众与场景不得单独锁定物种、性别、年龄、主轮廓、主色、默认服装、道具、符号、媒介或材质；仅当用户需求、角色功能或参考图支持时增加附肢、服装或身体模块；不得增加会削弱或改写主形态的独立躯干、服装或四肢。
- `proportion_rule`：按角色类型、功能、画风与用户需求确定头身、躯干、肩胯、四肢、手脚和关节的相对关系；Core 确认后锁定，衍生仅允许受透视和姿态影响的视觉变化。
- `brand_embodiment_rule`：品牌 IP / 吉祥物须将品牌产品、服务、体验或价值主张落实为主体、主轮廓、材质、结构或行为机制；不得只通过外加制服、道具、Logo 或文字贴标签。
- `world_narrative_embodiment_rule`：游戏、漫剧、真人影视等叙事角色须锁定世界观、阵营、职业、物种、能力、剧情身份、标志性行为及关键装备；这些已确认的设定可成为身份层，不强制改为品牌产品拟物化。叙事角色的设定页另从已确认世界观提取轻量氛围 Brief，仅包含 1 个环境色调、1 种光线/天气倾向与 1–2 个低对比世界观母题或材质纹理；它只服务设定页的背景语气，不改写角色身份或设定信息。
- 品牌 IP / 吉祥物简化规则：仅当用户明确要品牌 IP 或吉祥物时，以直接主轮廓、克制元素、一个清晰主记忆点和一眼可读的个性建立识别；该记忆点必须成为轮廓、脸部、核心道具或材质中的主特征，而非由大量小细节拼凑。移除非必要的服装层级、装饰、道具和复杂纹样。影视、游戏、漫剧、国风叙事角色或用户明确要求复杂设定时不套用本规则。

Core 生成时的**风格判断**按以下优先级确定：

```text
用户明确表达的主题、情绪和方向
> 品牌与商品气质
> 传播目的
> 素材条件
```

用户明确的画风、媒介、材质、参考图和排除条件优先于其他判断。品牌与商品气质用于判断角色的视觉温度、精致度、材质倾向与传播语气；传播目的用于判断信息密度、镜头、构图和商业完成度；素材条件用于判断可继承的轮廓、配色、材质、角色设定与可用参考范围。行业、品牌品类、受众与场景不能单独推翻用户明确方向，也不能自动套用固定物种、性别、年龄、主轮廓、主色、默认服装、道具、符号、媒介或实体材质。用户未提供品牌资产、角色方向或参考时，行业仅用于抽象判断；先检索相关案例并提炼规律，再基于产品/服务机制或明确的创意母题收敛原创方向。风格判断必须收敛为五项可见结论：媒介与表现方式、形状/线条语言、材质与渲染方式、光线与细节密度、构图倾向；它们只决定如何表现角色，不得默认或改写角色主体/物种、主轮廓、主色、服装、道具、比例或场景内容。最终 Prompt 只写已确定的二维/三维表现、具体材质、色彩和光线，不写推导过程。

用户从零设计且参考不足、方向模糊时，先检索与任务相关的视觉案例并提炼至少两条可执行规律；无法检索时只基于用户资料推断，不伪造检索结论。最终收敛为一个完整方向，不并列输出多个未选择的完整方案。

#### 2.1.2 草图 / 粗糙参考重建

草图、低清图和旧图不是直接 Core。先识别必须保留的物种、角色功能、主轮廓、关键服装/道具、颜色或用户明确点名的特征；再按 2.1.1 建立稳定的完整全身 Core。可以提升结构、比例、材质和商业完成度，但不擅自改写用户已明确的身份设计。

### 2.2 单体与家族 Core

#### 单体角色

Core 画面优先让角色完整清楚、主轮廓有识别、材质与身份相符：从头顶到脚底完整展现，双脚/鞋可见，仅采用正面或 3/4 角度，置于与角色主色有明度对比的浅色纯净背景中，不含任何背景元素或排版内容。角色必须有可记忆母题，不能只是行业模板角色；移除背景与渲染后，仍应能从主体形态、轮廓、脸、服装结构（如有）或核心道具辨认。品牌 IP / 吉祥物优先以一个直接主轮廓、一个主记忆点和清楚个性建立识别，不以非必要的层叠服装、装饰、道具或复杂纹样堆砌；叙事型角色或用户明确要求复杂设定时按其设定完成。物件/食材型角色的主体本身就是完整角色，不默认拆成头部与独立躯干；食品角色默认使用完整食材本体、可读五官与简化短肢体，保留烘焙、酥脆、孔洞、糖霜、颗粒、夹层、纤维或油润等对应的真实可食质感，不以人形躯干、厚重服装或抢戏配饰替代食材本体。仅在用户需求、角色功能或参考图支持时增加附肢、服装或身体模块。

#### 家族角色

先分别建立并各交付 1 张单体角色 Core；家族 Core 与 lineup 必须以全部已确认单体 Core 的视觉图像作为输入，`character_anchor` 只用于核对身份，禁止仅凭成员文字补生成缺失角色。家族 Core 不是把成员文字列在一起，而是以统一比例、色彩、站位和画面秩序展示成员关系。家族统一 Anchor 只定义材质域与渲染语法；家族图必须继承每位成员 Core 已确认的具体主体材质，不得为追求一致性而抹平成员本体差异。

单次调用最多输入 3 张图：1–3 位成员直接输入全部单体 Core；超过 3 位时，将单体 Core 均衡分配为 1–3 张拼版后输入。4 人为 2+2，5 人为 2+2+1，6 人为 2+2+2，7 人为 3+2+2，8 人为 3+3+2，9 人为 3+3+3；超过 9 人仍压缩为 3 张并尽量均衡分配成员数量。拼版只用于压缩输入数量，统一裁切、去背景、底色、边距与缩放；不得重绘、替换、删减、新增或改变任何成员的脸、轮廓、比例、颜色、服装、道具、结构与具体材质。

### 2.3 用户视觉 Core 的全身补齐

清晰半身角色图、头像、局部角色图和真人肖像可直接作为用户提供视觉 Core：先提取其中已确认的脸、主轮廓、配色、服装可见部分、材质和道具信息，并直接用于不超出原图可确认范围的主题服装、妆容、表情、姿态等图生图衍生。仅当用户明确要求完整全身、三视图、完整设定或其他需展示未见区域的资产时，才在不改写这些已确认身份信息的前提下补足身体比例、下装、鞋、完整服装结构及必要背面结构，生成并交付 **1 张**模型完整全身 Core。真人身份保真启用时，原始真人照片持续作为 `identity_source_image` 参与补齐与后续衍生。

未由参考图或用户设定确认的补全内容，必须在生成前作为设计判断明确，不得在正式 Anchor 中伪装为原图可见信息。补齐后的 Core 必须符合本 Skill 对正面或 3/4、头顶至脚底完整呈现、双脚/鞋可见、浅色纯净背景和无排版信息的全部要求。

### 2.4 Core 生成前快速检查

仅在从零创建、参考重建或清晰局部参考图补齐完整全身 Core 前执行。检查：角色是否有明确身份和服务对象；主体/物种、主轮廓、主色、核心道具、服装与材质是否均有可追溯来源，且未仅因行业、品牌品类、受众或场景套用默认模板；用户输入或参考图中的主体、主轮廓、结构词和功能边界是否被保留；补齐内容是否已明确区分“参考图可见 / 用户明确设定 / 本次设计判断”；创意母题是否转化为可见轮廓/道具/材质；是否至少有一个非品类必然的记忆点；风格是否已依据主流程收敛为媒介与表现方式、形状/线条语言、材质与渲染方式、光线与细节密度、构图倾向，且未改写角色身份或限制场景内容；颜色是否能追溯到角色身份或用户设定，主色、辅助色、点色的来源、职责、面积关系和具体结论是否明确，且无未被要求的无来源高饱和主体色、互补对冲、撞色或随机加色；家族任务是否已建立成员注册表，确认全部成员单体 Core 均作为视觉输入覆盖、单次输入未超过 3 张、拼版分配合理，且家族 Anchor 只核对身份而不补生成成员；是否已分别确定家族材质域/共性材质语法与每位成员的具体本体材质，且未以家族统一性覆盖成员身份；是否以正面或 3/4 角度从头顶到脚底完整呈现，双脚/鞋未被裁切或遮挡；头身、躯干、肩胯、四肢、手脚和关节的相对关系是否明确并支持三视图、表情和姿态；皮肤/毛发、服装/外壳、道具和背景是否各自可辨；背景是否为与角色主色有足够明度对比的浅色纯净背景，且没有环境、建筑、道具、纹样、氛围特效、叙事元素或排版内容；当前应展示脸部时，已设计五官是否被同色主体、高光、阴影或反射吞没；风格、材质、背景和光线是否属于同一世界。全部通过后，先输出“生成前”执行摘要，才可生成 Core；任何一项缺失时先补设计判断，不用“高级感、氛围感、精致 3D”替代。

食品/食品家族任务额外检查：去除服装、道具、Logo 与辅助符号后，食材本体、主轮廓和可食质感是否仍能成立；是否采用完整食材本体、可读五官与简化短肢体，而非食材头加独立人形躯干；家族成员是否共享紧凑可爱的五官与比例基线；主体色是否来自食材、烘焙或可食表层，并保持低至中饱和，未被荧光、大面积纯色服装、强互补撞色或多种高饱和配饰抢占。任一项不通过，回到 Core 重构。

关联路由检查：品牌 IP / 吉祥物移除外加制服、道具、Logo、文字与背景后，主体、主轮廓、材质、结构或行为机制是否仍可关联品牌产品、服务、体验或价值主张，并至少达到品牌关联 Level 1 或 Level 2；若只剩 Level 3 的外挂提示，回到创意母题重构主体。游戏、漫剧、真人影视等叙事角色移除 Logo、文字、无关背景与临时宣传道具后，是否仍能通过脸、体态、服装结构、职业装备、阵营符号、能力表现或行为方式识别所属世界与叙事身份；若不能，回到角色定位、阵营/职业/能力与关键设定重构。

媒介、画风和材质必须来自用户需求、参考图或完整自主判断，不得因行业名称直接套用默认角色、制服、材质或二维/三维表现。例如“国潮插画角色”默认按二维绘画、平面色块、笔触、纸本/版画/岩彩等具体画面语言完成；只有用户明确陶瓷公仔、玉雕摆件、3D 潮玩或实体周边时才使用对应立体材质与渲染。

### 2.5 Core 核查关卡

模型完整全身 Core 生成或确认后、提取正式 Anchor 或进入任何衍生前，必须逐项检查以下内容。用户提供视觉 Core 可经“可见身份核对”直接提取仅含可见信息的 Anchor，并进入不超出原图可确认范围的衍生；若资产需展示未见区域，则必须先补齐为模型完整全身 Core 并通过本关卡。任一项不通过，即停止后续流程，定向修正或重生 Core 后重新核查；不得用新增装饰、更多禁项或后续资产掩盖 Core 问题。

- 第一眼有角色吸引力、定位和服务对象；
- 具有至少一个清晰的视觉母题或专属记忆点；
- 品牌 IP / 吉祥物的主轮廓、主记忆点与个性一眼可读，未被无关细节、层叠服装或装饰稀释；
- 品牌 IP / 吉祥物至少达到品牌关联 Level 1 或 Level 2：移除外加制服、道具、Logo、文字与背景后，主体、主轮廓、材质、结构或行为机制仍可关联品牌产品、服务、体验或价值主张；仅依赖 Level 3 外挂提示即判定不通过；
- 游戏、漫剧、真人影视等叙事角色在移除 Logo、文字、无关背景与临时宣传道具后，仍可通过脸、体态、服装结构、职业装备、阵营符号、能力表现或行为方式识别所属世界与叙事身份；服装、武器、职业装备、发型和演员外貌等已确认设定不得被错误视为可移除的品牌外挂；
- 缩小后轮廓仍可识别；
- Core 以正面或 3/4 角度从头顶到脚底完整呈现，双脚/鞋完整可见，无半身、胸像、特写、下半身裁切或遮挡肢体；
- 主体、主轮廓和附加结构符合用户需求/参考图及不冲突的自主判断，未被默认头身化或拟人身体改写；
- 主体/物种、主轮廓、主色、核心道具、服装与材质均可追溯到用户要求、品牌资产、产品/服务机制、参考图、世界观或明确的自主设计判断；不得仅因行业、品牌品类、受众或场景套用高频默认形象、颜色或符号；
- 身体/毛发、服装/外壳、道具和背景可分辨，未融为单一色块；相邻部件须有足够的色相、明度或材质区分，无法清楚辨认颜色职责或层次即判定不通过；
- 当前应展示脸部时，已设计五官在正常观看尺寸下清晰可辨；口罩、面罩、头盔、刘海遮挡、无五官、背面、远景或侧后镜头按实际可见结构验收；
- 真人身份保真启用时，全身 Core 的脸必须仍为 `identity_source_image` 中的原参考人物；脸型、骨相、五官比例、眼距、鼻唇、下颌和可见辨识特征任一漂移即不通过，不得提取 Anchor 或进入衍生；
- 头身、躯干、肩胯、四肢、手脚和关节的相对比例明确，且适合三视图、表情、姿态、周边和应用延展；除透视/姿态视觉变化或明确跨年龄阶段外，不发生比例漂移。未明确跨年龄时，真人只生成妆容、服饰造型、动作等同龄版本；明确跨年龄时，仅按用户明确的本次变化内容调整获准的比例与年龄状态，同时保持同一面部身份；
- 配色可追溯到用户需求、参考图、角色身份或合理颜色来源；主辅点色职责与面积关系明确，主体、服装/外壳、道具与背景各自的具体颜色和材质层次可明确记录，无未要求的无来源高饱和主体色、大面积互补对冲、无意撞色或随机加色；
- 二维/三维媒介、画风与材质可追溯到用户需求、参考图或完整自主判断，未因行业名称被默认套用；
- 背景为与角色主色有足够明度对比的浅色纯净背景，无环境、建筑、道具、纹样、氛围特效或叙事元素；无设定页排版、文字、色卡、局部放大框、多格缩略图、Logo 或水印。

全部通过后，先输出“Core 放行”执行摘要，才可填写正式 Anchor；Anchor 必须记录已核查通过的核心设计来源、颜色来源、配色结论和材质分层。

## 3. Anchor 与资产衍生引擎

> 本节只决定生成什么、什么保持不变、什么可以变化以及如何路由；完整 Prompt 见第 4 节。

### 3.1 Core 锚点提取

模型完整全身 Core 通过 2.5 核查后，或用户提供视觉 Core 通过可见身份核对后，立即以实际画面为准校准正式 Anchor：保留真实出现且适合长期继承的特征，删除没有生成出的细节；用户明确设定或已确认的补全设计须与 Core 实际画面一致后才可写入。用户提供视觉 Core 的 Anchor 只覆盖其实际可见或用户明确的特征，不补写未见身体、服装、道具或结构。单体 Anchor 应覆盖可确认的主体/物种、主轮廓、主色、核心道具、服装与材质各自的核心设计来源；以及已可确认的比例、脸型与五官、颜色来源与配色结论、具体颜色与材质分层、附加结构和轮廓分离方式。核心设计来源、颜色来源与配色结论一经对应核对确认，即为该角色长期继承依据。真人身份保真启用时，正式 `character_anchor` 仍完整记录 Core 中已确认的面部与全身视觉锚点；`identity_source_image` 与 `face_identity_lock` 只在内部强化这份 Anchor 的真人面部身份，不形成第二份对外 Anchor。跨年龄的阶段状态属于本次变化内容，不建立独立阶段 Anchor。品牌 IP / 吉祥物还须记录已通过核查的品牌本体关联及 Level；叙事角色还须记录所属世界、人物身份及可长期继承的阵营/职业/能力/关键设定锚点。

食品角色的单体 Anchor 还须记录：食材本体轮廓、可食表层与结构质感、五官与简化短肢体比例、主体低至中饱和色域，以及经确认的小面积品牌识别点；不得将厚重服装或高饱和配饰记录为主体身份来源，除非用户、品牌资产或参考图明确要求。

家族 Anchor 分两层：

- 家族统一 Anchor：共同画风、五官语言与身体比例基线（眼型/眼距、眉口简化、五官尺度与面部留白；头身、躯干/四肢、手脚/关节的相对关系）、色彩逻辑（整体色温、明度区间、点色使用边界）、材质域/共性材质语法、世界观或品牌语法；不得规定或覆盖成员的具体颜色来源、个人主色或具体表皮纹理。
- 单体 Anchor：每位成员的脸、轮廓、比例、颜色来源与配色结论、服装、道具、专属结构和具体本体材质；具体材质按主体记录表皮/毛发/外壳、纹理、切面、夹层、粗糙度、透明度、油润感等长期可见特征。

### 3.2 表演状态类

适用：表情页、表情包、姿态页、动作延展、单独动作图、表演定妆图。

先锁定正式 Anchor，再为每项资产建立**表演/互动 Brief**：动作目的、具体表情、互动对象、场景任务与镜头关系缺一不可。表情页只改变表情与轻微手势，不改变身份；姿态页每个动作必须符合角色性格和使用场景；定妆图通常是独立单张，可按用户需要附带一张设定卡。

输出形式：用户说“几个表情”“几个姿势”“一组”时优先合页；说“分别”“每个单独出”“定妆照/表演照”时优先独立图。影视、游戏、漫剧角色默认更偏独立单张，品牌 IP 和吉祥物默认更偏合页展示。

表情页中各表情只改眼、眉、嘴、脸部张力和必要手势，不能顺带改变脸型、眼睛结构、服装和道具；已设计且应可见的表情结构须清楚可读。三视图背面及明确遮挡设计按实际可见结构展示，不补全不可见五官。姿态页的动作应覆盖角色最常用或最能说明身份的行为，不为了数量生成无意义跳跃、挥手或站立。动作、道具和镜头均应说明角色职责，例如导览员指向路线、学习伙伴递出绘本、运动角色完成对应姿势。除非用户明确要求复用，衍生表演应尽量不同于 Core 的中性姿态/表情，并尽量不与同批其他资产重复；若结果仍近似，判定该资产不通过，重写 Brief 后重生。

### 3.3 设定与规范类

适用：角色设定卡、档案页、品牌手册页、制作参考页、三视图/转身图、服装/主题版本、配色表、道具/材质/机械结构拆解。

#### 角色设定卡 / 档案页

设定卡是角色设计说明与作品集开篇资产，不是 Core，也不是纯制作图。画面必须以一名完整全身角色为主体，头部、躯干、四肢与脚部完整可见，不得以半身肖像、局部特写、遮挡姿势或细节拼贴替代主角色；局部放大仅作辅助模块。设定信息按以下优先级组织：用户明确指定必须出现的角色名、身份、功能、口号、性格、世界观、故事、配色和细节；用户提供的其他补充设定；Skill 自主补充字段；装饰元素。固定文本如角色名、指定口号、标题和标签原样保留；未要求完整保留时，其他用户信息可压缩为不改含义的短句或标签，不为凑齐栏目虚构用户未提供的身份、能力、故事或世界观。角色默认占画面高度约 45%–70%，信息围绕角色轮廓外的安全区组织；空间不足时依次减少自主补充字段、细节框、装饰和背景符号，不裁切角色或压缩固定文本。

用户明确说“信息完整”“全部保留”“不要删减”“完整放入设定页”等时，进入完整信息模式：用户输入的信息不得删除、缩写、改写或以自主补充内容替代，且仍须满足完整全身角色、文字可读、信息不遮挡和版式层级。若单页无法同时满足这些条件，先询问用户采用连续设定页还是高密度单页；未确认前不擅自拆页、强行塞入或删减。

根据目标选择一种版式：主体展示型、信息分栏型、网格规范型、叙事氛围型或应用展示型。标题、标签、色块、边框和图标要继承角色画风，采用专业 IP 设计说明页的干净栅格、克制装饰、稳定留白和清楚分栏；不做通用 PPT 信息页，也不做赛博面板堆叠或元素平均铺满。

仅叙事角色设定页启用轻量氛围 Brief：从已确认的世界观中选定 **1 个环境色调、1 种光线/天气倾向、1–2 个低对比母题或材质纹理**。背景最多使用 1 个轻环境层，例如轻微渐变、模糊环境轮廓、纸张/金属/科技界面弱纹理或极少量有依据的阵营图形；标题、标签与边框可轻度呼应其语气。环境层、纹理、光线与母题必须位于角色和文字之后，低对比、低密度且不遮挡信息；不得补入剧情事件、复杂建筑、前景堆叠、粒子特效或无依据符号。无明确世界观资料时，保持干净设定页，只继承角色已有配色与材质；品牌 IP 设定页仍按提案式清晰分栏规则执行，不默认加入叙事氛围。

| 版式结构 | 适用情况 | 组织方式 |
|---|---|---|
| 主体展示型 | 单一 IP、吉祥物、主形象设定 | 角色占最大面积，信息环绕识别点 |
| 信息分栏型 | 品牌手册、提案汇报、角色介绍 | 一侧完整角色，另一侧放身份、性格、色彩与细节 |
| 网格规范型 | 制作参考、细节拆解、色彩/三视图辅助 | 统一网格，角色、局部、色卡和标签分区对齐 |
| 叙事氛围型 | 影视、游戏、国潮、文旅世界观角色 | 角色与背景符号、标题和世界观元素形成动线 |
| 应用展示型 | 商业 IP、包装、周边、App、展会 | 角色与载体共同展示，强调真实使用关系 |

#### 三视图与拆解

三视图需要正面、侧面、背面是同一角色的不同角度，角度标签清楚，比例、五官、服装、道具和结构锚点一致。背景仅使用干净简洁的纯色、低饱和渐变或极轻微品牌色，配合统一地面线和柔和投影；不加入场景、建筑、道具堆叠、氛围光效、复杂纹样或叙事背景，角色结构、比例、服装和道具是唯一阅读重点。拆解资产用于服装纹样、道具、尾巴、机械件、材质或局部结构；每个重点有名称和一句短说明。服装或主题版本只能改变被批准的版本层，保留角色身份与核心结构。

### 3.4 传播与应用类

适用：角色海报、概念海报、场景瞬间、社媒配图、IP 与 Logo 组合、包装、杯套、盒子、袋子、周边、App、官网、PPT、展会与应用展示合页。

#### 传播主视觉

每张海报和场景资产先建立**场景/互动 Brief**：场景依据、具体地点、时间、事件、角色任务、动作目的、站位、互动对象与镜头关系缺一不可；场景依据优先级为用户需求 → 角色设定/职责/世界观 → 当前主题与事件 → 自由选择的匹配环境元素。不得用抽象纹理、纯色背景或随机装饰替代场景，也不得只因风格标签自动套用高频环境符号。传统建筑、屋顶、屋檐、宫墙等仅为可选元素；没有用户要求或角色/剧情依据时，不让角色自动站在屋顶、屋檐等不合理位置。**除非用户明确要求复用 Core 姿态，或角色功能确实不需要动作变化，角色动作默认不同于 Core 主形象的站姿或手势，并服务当前场景任务**。主视觉应有标题、角色主体、具体场景、主题氛围、前中后景、品牌/世界观符号和清晰文字安全区。视线应从标题进入角色脸部、核心道具或行动线。角色不能只是居中站立，背景必须衬出角色轮廓；Brief 或实际画面不成立时，判定该资产不通过，改写 Brief 后重生。

#### 品牌应用展示

用户点名具体应用场景时，各场景独立生成；用户说“一套应用/周边/应用展示”时，生成应用展示合页并按行业选择 3–6 个载体。线上载体可纯色平铺展示；线下载体必须有真实环境、前后层次、空间关系和景深，像真实产品摄影。载体尺寸、方向与使用方式必须可信，角色、载体与品牌信息形成清晰主次关系，不做杂乱素材拼贴。

### 3.4.1 资产目标与交付补全

`asset_goal` 是本 Skill 唯一的交付组合决策源：先忠实记录用户原始诉求、Core 状态与明确排除条件，再按下表计算最终交付。不可因行业建议无边界扩张资产。

| Core 状态 / 用户诉求 | 最终 `asset_goal` |
|---|---|
| 已有稳定完整全身 Core + 单项衍生 | 仅目标资产 |
| 清晰局部参考图 + 任意诉求 | 完整全身 Core + 按下列规则计算的指定或默认资产 |
| 用户明确“只要 Core / 只出定妆图 / 不要设定页” | 仅指定资产 |
| 从零创建或 Core 重建 + 未明确资产 | Core 主形象 + 角色设定卡 |
| 从零创建或 Core 重建 + 点名资产 | Core/主形象/定妆图 + 角色设定卡 + 全部点名资产 |
| 用户明确完整/系统化/一套/规划资产 | Core 主形象 + 角色设定卡 + 三视图 + 表情图 + 姿态图 + 1–2 张行业相关扩展资产 |
| IP 家族 | 各单体角色 Core + 家族 Core + 家族设定图/lineup；按需求补表情/姿态/周边/应用 |

- “先看/先确定 Core”不自动移除设定卡；只有“只要 Core”“只出定妆图”“不要设定页”等明确排除语句才移除。
- 清晰局部参考图不是已有稳定 Core；必须先补齐并交付完整全身 Core，再计算后续资产。
- 已有稳定完整全身 Core 的完整/系统化任务不重复交付 Core，但补角色设定卡、三视图、表情图、姿态图与必要的行业扩展资产。
- 从零创建、Core 重建或清晰局部参考图补齐时，定妆图默认附角色设定卡；已有稳定完整全身 Core 的单项定妆图仅交付定妆图，除非用户另要设定卡。
- 仅在完整/系统化任务或用户明确允许行业补全时，才选择 1–2 张行业相关扩展资产；普通创建任务不因行业自动扩张。
- 家族默认不附重点角色设定卡；各单体角色 Core、家族 Core 与家族设定图/lineup 即为基础交付。

以下映射只将用户表述转换为目标资产名称，最终组合仍以上表为准：

| 用户需求信号 | 最终资产 |
|---|---|
| 三视图、转身图、正侧背 | 三视图 |
| 表情包、不同情绪 | 表情图 |
| 动作、姿势、常用动作 | 姿态图 |
| 人设、角色介绍、设定卡 | 角色设定卡 |
| 服装细节、道具、机械结构 | 服装/道具拆解 |
| 节日版、活动版、换装、主题参考图版本 | 主题/服装版本 |
| 配色表、标准色、颜色规范 | 独立配色表 |
| 包装、杯子、盒子、袋子 | 包装应用图 |
| 周边、贴纸、徽章、公仔、盲盒 | 周边 Mockup |
| App、UI、线上产品 | Online 应用图 |
| 展会、活动、大会视觉 | Offline 应用图 |
| Logo 结合、品牌组合 | IP 与 Logo 组合 |
| 场景图、放到某环境 | 场景图 |

每项已进入 `asset_goal` 的资产，再判断输出形式：

| 输出形式 | 适用资产与用户信号 |
|---|---|
| 合页设定页 | 表情页、姿态页、三视图、设定卡、应用展示、周边展示、主题/服装版本；“几个表情”“几个姿势”“几个应用”“一组”“一套应用”“放在一张图里” |
| 独立单张 | 定妆照、海报、独立展示图、明确点名的单个应用场景；“几张”“N 张”“分别”“每个单独出”“各出一张” |

- 单体角色 Core 与家族 Core 未指定数量时各默认只生成 1 张确定主形象，不生成多个候选 Core；
- “几个表情/姿势/动作/应用”默认输出 1 张合页，含对应数量的项目；
- 用户明确“几张/N 张/分别/每个单独出”时，按数量输出独立图；
- 明确多个具体应用场景时，每个场景各出 1 张独立应用图；泛泛说“一套应用/周边/品牌应用展示”时，输出 1 张应用展示合页；
- 三视图只输出 1 张独立三视图合页；每个主题/服装版本默认各输出 1 张独立合页，不与三视图、其他主题版本或拆解页混合。用户明确要求独立定妆图时，该主题版本才改为单张；
- 用户未明确时，品牌 IP/吉祥物偏合页设定页，影视/游戏/漫剧角色偏独立定妆图；
- 家族中的各单体 Core 是各角色的确定交付，不是同一角色的候选方向；家族 Core 默认 1 张。

#### 资产清单关卡

在生成前，必须根据 `asset_goal` 建立内部资产清单：逐项记录资产名称、数量、合页或独立单张形式、对应 Prompt 模板与完成状态。主题/服装版本还须记录其主题参考图、变化清单和被锁定内容；三视图不得与主题参考图或主题变化清单关联。家族任务还必须附家族成员注册表，记录成员名称、单体 Core/拼版来源、输入分组和总人数。资产生成前，先输出“衍生/家族前”执行摘要；摘要中的 `asset_goal`、实际输入、Core/Anchor 状态与资产清单必须逐项一致。每生成一项立即核对其数量、形式和关键用途；家族 Core 与 lineup 还须逐一核对成员注册表。最终交付前逐项对照清单与 `asset_goal`，点名资产、默认应交付资产和指定数量均不可遗漏，也不得自行新增未进入 `asset_goal` 的资产。

#### 资产包系统与独立子系列

- 同轮交付两类及以上资产时，先建立 `asset_system_rule`，使设定页、三视图、表情页、姿态页、海报或应用图成为同一套角色资产包；它们共享视觉系统，但不强行使用同一种版式。
- 某一**同类资产**明确要求分别输出 2 张及以上时，再建立该类专属 **`series_rule`**。它固定画幅比例、角色占比、标题/品牌区、视觉母题、色彩与光线基调；每张必须改变动作、镜头、场景、载体或功能主题，不能只替换背景。
- 合页不启用 `series_rule`，只继承 `asset_system_rule` 与本类合页模板；多类资产也不因共享 `asset_system_rule` 被错误合成为一张合页。
- 用户明确要求不同风格或不同方向探索时，不建立 `series_rule`；这不构成生成多个候选 Core 的理由。

### 3.5 图生图与局部编辑

所有衍生先明确：保持内容、允许变化内容、输出形式和必要文字，并以用户提供视觉 Core 或通过 2.5 核查的模型完整全身 Core 作为图生图母版。用户视觉 Core 的衍生不得超出原图可确认范围；完整全身、三视图或其他需展示未见区域的资产必须改用通过 2.5 的模型完整全身 Core。已有目标图类且只改方案时，优先轻度图生图或局部编辑；由草图/CAD/旧图等转成目标资产时，先建立完整全身 Core，再继承可识别骨架重绘。任何图生图不得破坏正式 Anchor、角色比例、核心道具或未指定区域。

## 4. 提示词结构与资产模板

> 先由第 3 节完成资产路由、`asset_goal`、资产清单、`asset_system_rule` 与必要的 `series_rule`，并输出“衍生/家族前”执行摘要，再调用本节模板；无用户图可见身份核对或 2.5 Core 核查放行、正式 Anchor 已锁定、对应执行摘要通过，不得调用任何衍生模板。所有衍生的 `base_image` 均为执行摘要中列明的用户提供视觉 Core，或已通过核查的模型完整全身 Core；前者不得用于超出原图可确认范围的资产。模板不得自行增加或移除 Core、设定卡或其他资产；只有 `asset_goal` 包含对应资产时才调用。以下模板中的正式 Anchor 必须逐字复用当前项目对应角色已确认的 `character_anchor`；不得在 Prompt 内重新编写角色身份。家族任务同时引用 `family_anchor` 与各成员对应的 `character_anchor`。

### 4.0 最终 Prompt 自然拼装

`asset_system_rule`、`series_rule`、图片输入、局部编辑范围、`identity_source_image`、`face_identity_lock` 与跨年龄校验均为内部执行信息，不得原样写入最终 Prompt。最终 Prompt 只写已经确定的可见画面，并按以下内在顺序自然组织为一段或数段描述，不显示编号、字段名、章节标题、冒号式模板或流程说明：

```text
[成品类型、画幅、媒介、镜头或构图]
+ [逐字复用一次的正式 character_anchor]
+ [仅真人：保留参考人物原有的面部身份与五官关系]
+ [本次变化的年龄/身份状态、服装、发型、妆容、姿态、表情与道具]
+ [主体尺度、位置、背景、场景、材质与光线]
+ [当前画面必要的少量限制]
```

正式 `character_anchor` 必须逐字复用一次，不做筛选、删减、改写或拆散；不得再以“保持正式角色 Anchor 不变”等前缀介绍。真人只追加一次简短面部身份强调，不重复 Anchor 中已有的脸型、眉眼、鼻唇等描述。跨年龄的阶段状态属于本次变化内容，不创建或输出独立阶段 Anchor，也不输出逐项禁令。

资产包与独立子系列只将画幅、角色尺度、构图、背景、色彩、材质和光线等可见共性融入对应画面；不写系列名称、序号、“继承系列规则”或“不得与其他图重复”。最终 Prompt 不写配色来源、颜色职责、可读性判断、内部输入来源或例外规则；只保留当前任务真正需要的 2–5 项限制。

### 4.1 Core 主形象 Prompt

## 5. 验收清单

### 5.1 Core 与 Anchor

- Core 有吸引力、定位、记忆点和可辨轮廓；
- 用户提供/已确认的清晰图可作为视觉 Core，经可见身份核对后进入不超出原图可确认范围的衍生；模型创建、补齐或重建的 Core 必须为已通过 2.5 核查的完整全身角色图。草图、低清图和无法稳定识别身份的图不得直接作为 Core；
- 主辅点色、材质、头身/躯干/四肢/手脚关节比例、五官、服装和道具适合后续复用；
- 主体/物种、主轮廓、主色、核心道具、服装与材质均可追溯到用户要求、品牌资产、产品/服务机制、参考图、世界观或明确的自主设计判断；不得仅凭行业、品牌品类、受众或场景使用固定物种、颜色、服装、道具或符号模板；
- 未指定数量时仅有 1 张确定 Core，不出现多张候选图；
- 皮肤/毛发、服装/外壳、下装、核心道具与背景未融为单一色块，且有明确色相、明度或材质分层；相邻部件的颜色职责与边界在正常观看尺寸下可清楚辨认，否则 Core 不得放行；
- 配色可追溯到用户需求、参考图、角色身份或合理颜色来源；正式 Anchor 已记录颜色来源、主辅点色的具体结论、面积关系与主体/服装/道具/背景边界。每种颜色有明确职责，无未要求的无来源高饱和主体色、大面积互补对冲、无意撞色或随机加色；
- 当前应展示脸部时，已设计五官在正常观看尺寸下清晰可辨，未被同色主体、高光、阴影或反射吞没；遮挡设定、无五官角色、背面、远景和侧后镜头按实际可见结构验收；
- 真人身份保真启用时，`identity_source_image` 已保留为面部身份依据；正式 `character_anchor` 完整继承 Core 中确认的面部与全身视觉锚点，全身 Core 的脸与原参考人物一致，未以相似人物替代；跨年龄变化只来自用户明确的本次变化内容，未改写角色身份；
- 模型完整全身 Core 从头顶到脚底完整呈现，双脚/鞋未裁切或遮挡，仅为正面或 3/4 角度；背景为与角色主色有明度对比的浅色纯净背景，无任何环境、建筑、道具、纹样、氛围特效或叙事元素；无排版、文字与应用信息。用户提供视觉 Core 按其实际可见范围验收，不得虚构未见区域；
- 品牌 IP / 吉祥物在移除外加制服、道具、Logo、文字与背景后，主体、主轮廓、材质、结构或行为机制仍达到品牌关联 Level 1 或 Level 2；
- 品牌关联由用户/品牌资产、产品或服务本体及机制、主轮廓/结构/材质或行为建立；未获明确支持的服装、潮流配件、墨镜、运动装备和行业符号不得抢占主体识别、主体面积或主色；
- 食品角色去除服装、道具、Logo 与辅助符号后，仍可通过完整食材本体、主轮廓与可食质感识别；采用可读五官与简化短肢体，不默认使用独立人形躯干、厚重服装或抢戏配饰；主体色来自食材、烘焙或可食表层，整体为低至中饱和色域，无未要求的荧光、大面积纯色服装、强互补撞色或多种高饱和配饰；
- 游戏、漫剧、真人影视等叙事角色在移除 Logo、文字、无关背景与临时宣传道具后，仍能从脸、体态、服装结构、职业装备、阵营符号、能力表现或行为方式识别所属世界与叙事身份；
- 正式 Anchor 以用户提供视觉 Core 的可见身份信息，或已通过核查的模型完整全身 Core 校准；前者不得补写未见区域，后者覆盖可长期识别的完整结构；只有对应身份核对通过后才可填写或更新 Anchor；
- 家族 Core 的视觉输入已覆盖成员注册表中每位成员的单体 Core；单次输入不超过 3 张，超过 3 位成员时已按均衡拼版分组。家族 Core 中成员数量严格等于注册表总数，每位恰好出现一次；出现缺失、文字补生成、新增、重复或融合角色即不通过，定向重生家族 Core；
- 家族共享视觉系统，同时成员不模板化同质；家族统一 Anchor 已记录共同五官语言与身体比例基线，家族 Core 与 lineup 中成员的眼型/眼距、眉口简化、五官尺度与面部留白，以及头身、躯干/四肢、手脚/关节的相对关系须保持相对统一；任一成员脱离该体系而成为另一套脸型、五官或身体比例即不通过。食品家族额外核对完整食材本体、简化短肢体、可食质感和低至中饱和色域是否共同成立，不得因家族统一性将食材改成通用人形吉祥物。家族 Anchor 的材质域/共性材质语法与成员 Anchor 的具体本体材质均已记录，且前者未覆盖后者。统一媒介、光线、真实度、表面细节密度和光泽控制下，每位成员仍保留符合自身物种、食材或角色本体的可辨材质；不得把成员统一为相同表皮、纹理或实体材质。食品家族示例：薯片保留薄脆、微孔与油炸金黄质感；甜甜圈保留烘焙面包体、糖霜与糖珠；坚果保留壳纹、切面与油润感；示例仅说明材质拆分方法，不强制套用具体食材。品牌家族至少半数成员达到 Level 1 或 Level 2，叙事家族在共享世界观下保持成员的阵营、职业、物种或角色职责差异。

### 5.2 一致性与结构

- 多图仍能认出同一角色；五官（如应可见）、头身、躯干、肩胯、四肢、手脚/关节、配色、材质和道具不漂移；透视或姿态造成的视觉变化不判为比例错误；
- 家族 Core、lineup 与后续单体衍生同时继承家族统一的五官语言、身体比例基线、材质域/共性材质语法和对应成员的具体本体材质；统一性不得造成成员材质同质化，单体材质也不得破坏同一视觉世界的渲染、光线和完成度；成员可保留身份所需的局部结构差异，但不得漂移为不同的脸型、五官体系或身体比例。
- lineup 必须基于已通过成员注册表核对的家族 Core；其成员数量严格等于注册表总数，每位成员可追溯到对应单体 Core 视觉输入。绵绵等已命名成员需逐位对照单体 Core 的专属轮廓、五官、比例、配色、服装和道具；绵绵额外核对云朵轮廓、绿圆眼镜、持书与身体比例。任一身份漂移、缺失或新增角色即不通过，返回家族 Core 定向重生。
- 真人身份保真启用时，每张衍生图的脸型、五官比例、眼距、鼻唇、下颌和可见辨识特征仍指向 `identity_source_image` 中的同一人；不通过即不交付，收紧 `face_identity_lock` 后以原始真人参考图定向重生。仅在整体身份未漂移且改动范围很小时，才可局部修脸后重新验收；
- 真人跨年龄图仅出现用户明确批准的比例、面部软组织、肤质、发色和造型变化；若出现换脸或重塑骨相，判定不通过；
- 同一资产包的设定页、三视图、表情页、姿态页、海报和应用图共享角色身份、已确认的颜色来源与配色结论、画风、标签/图标语言与信息层级；背景、氛围和信息色仅可适配，不得改写角色主辅点色，但各自版式服务本类用途；
- 后续衍生逐字继承当前角色已确认的品牌本体关联或世界观与叙事关联锚点；不得把品牌角色降级为仅靠外挂道具的通用角色，也不得把叙事角色错误改造成品牌产品拟物化角色；
- 后续衍生只继承正式 Anchor 中已确认的核心设计来源与结果；不得因行业、场景或传播主题重新套用默认物种、主色、服装、道具或符号模板；
- 三视图只核对同一 Core 的正面、侧面与背面结构，基础服装、表情基线、姿态基线、比例、材质、配色、道具与结构均不得因主题参考图改变；
- 主题/服装版本逐字复用同一正式 `character_anchor`，并仅执行变化清单中由主题参考图实际改变的服装、表情或姿态；若出现未授权换脸、比例/材质/配色漂移、主体或核心道具改写，或参考图未改变内容被替换，即不通过并按变化清单定向重生；
- 食品角色的主题/服装版本须保持食材本体、可食材质、低至中饱和主体色和短肢体比例，主题服装不得抢占食品主体识别；
- 同类独立子系列中的每张图可独立使用，具有统一视觉系统和阅读节奏，同时动作、镜头、场景、载体或功能主题不重复；
- 每项表演或场景资产均有成立的动作目的、表情、互动对象、场景任务与镜头关系；除用户明确要求外，不复用 Core 的中性姿态/表情，也不在同批资产中无意义重复；
- 主题变体不改变角色身份，且每个主题/服装版本为独立合页，不与三视图、其他主题版本或拆解页混合；
- 身体、服装、道具与背景分层清楚；
- 姿态类无多指、穿透、反关节、错误持物或重心问题；
- 局部编辑不误改 Mask 外区域。

### 5.3 三类资产

- 表演状态：每个表情/动作语义明确，符合性格和场景，并与动作目的、互动对象和镜头关系相符；
- 表情页及应展示脸部的定妆/近中景资产中，已设计的眼、眉、嘴等表情结构清楚可读；
- 设定与规范：设定卡的主角色必须完整全身可见，头部、躯干、四肢与脚部不被裁切或遮挡；用户明确指定的信息已保留，固定文本准确，未要求完整时的压缩不改变原意，自主补充内容与装饰不挤占用户信息；用户明确要求完整信息时，所有输入内容完整准确出现，若单页无法同时保证可读性与完整全身角色则先询问交付形式；标题、主体、信息模块和装饰层级清楚，色卡、细节、标签与版式适合说明/提案/制作，角色不压住关键信息；
- 叙事角色设定页：轻量氛围 Brief 可追溯到已确认世界观，且仅使用 1 个环境色调、1 种光线/天气倾向、1 个轻环境层与 1–2 个低对比母题或材质纹理；氛围内容位于角色与文字之后，低对比、低密度、不遮挡。若世界观资料不足则保持干净设定页；出现完整场景、剧情事件、复杂建筑、前景堆叠、粒子特效或无依据符号即不通过。品牌 IP 设定页不因本规则被附加叙事氛围；
- 三视图：只基于 Core 展示正面、侧面、背面；背景干净简洁，仅有纯色、低饱和渐变或极轻微品牌色、统一地面线和柔和投影；无主题服装、主题表情、主题姿态、建筑、场景、道具堆叠、复杂纹样或叙事元素，角色结构是唯一重点；
- 主题/服装版本：每个主题独立 1 张合页，主题参考图仅迁移变化清单中的服装、表情或姿态；默认不展示参考图，除非用户明确要求对照；
- 传播与应用：所有主题的海报/场景资产均有可追溯的场景依据、具体地点、时间、事件、角色任务、合理站位与环境/道具互动，以及动线、独立标题区和副标题/CTA 区；除用户明确要求外，动作不同于 Core 主姿态并匹配场景任务。传统建筑、屋顶、屋檐、宫墙等仅在用户或角色/剧情依据支持时使用，不因任何风格标签自动套用；应用图有可信载体、使用关系、品牌区与功能说明区，整体不拥挤。
- 输出形式：表情、姿态、三视图、设定卡、应用展示和每个主题/服装版本按合页规则交付；海报、定妆照和明确场景应用按独立单张交付；主题/服装版本仅在用户明确要求独立定妆图时改为单张；多张独立图必须有用户数量/“分别出”指令或多个明确应用场景依据。
- 多资产任务不因 `asset_system_rule` 被错误合成为一张合页；合页资产也不因 `series_rule` 被错误拆成多个独立图。

### 5.4 文字与交付

- 最终交付与 3.4.1 计算出的 `asset_goal` 及内部资产清单逐项一致；模板不额外补资产或漏掉点名资产、默认应交付资产或指定数量；
- 从零创建、Core 重建或清晰局部参考图补齐任务未被明确排除时包含角色设定卡；已有稳定完整全身 Core 的单项衍生不重复 Core 或设定卡；
- 完整/系统化任务包含角色设定卡、三视图、表情图、姿态图及 1–2 张合理行业扩展资产；
- 家族任务包含各单体角色 Core、家族 Core 与家族设定图/lineup，不默认附重点角色设定卡；
- 文字短、可读、无乱码、截断或遮挡；
- 标题、主体、信息模块、辅助装饰层级明确；
- 同级模块间距均匀，跨级留白明显，模块对齐、边距和标签基线统一；不平均散排、不依赖过小文字；
- 角色、背景、色卡、文字色块和应用载体共享一致色彩逻辑，同时保留足够的明度与材质差异；
- 海报、应用和场景资产仅调整背景、氛围或信息色，不改写角色主辅点色；角色脸部为阅读重点时不被文字、场景、反光或低对比吞没；
- 含文字资产满足 2K 与统一文字尾缀要求；
- 最终只交付用户需要的 Core、资产或 Prompt，以及一行“完成核对”：已交付资产与 `asset_goal` 是否一致、各项状态是否通过；不输出长篇内部检查过程。若不一致或存在未通过项，停止交付并补齐，不以文字解释替代。

### 5.5 真人身份保真测试

- 基于同一真人照片生成不同发型、妆容、职业服装和轻微姿态，验证仍为原参考人物；
- 用户只说“不同人生阶段”但未说明年龄跨度，验证只出现同龄造型差异，不主动老化；
- 明确生成少年、青年、成熟职业期与老年阶段，验证每阶段年龄表达清楚，同时保持同一骨相与五官关系；
- 生成大姿态、复杂场景海报和应用图，验证动作、镜头与场景不导致换脸；
- 仅修改发型或妆容，验证局部编辑未改动 Mask 外的脸部和其他区域；
- 各运行一项品牌 IP 与动漫角色衍生，确认未启用真人身份保真时仍沿用原有 Anchor 流程。
- 服装／身份版本最终 Prompt 中，正式 Anchor 逐字出现一次；真人脸部身份只强调一次；不出现 `Core`、`character_anchor`、`face_identity_lock`、`identity_source_image`、`series_rule` 等内部字段名、系列序号或流程话术。
- 跨年龄最终 Prompt 中，同一份正式 Anchor 保持不变；阶段状态只作为本次变化内容出现，不出现独立阶段 Anchor 或逐项禁令。

### 5.6 三视图与主题/服装版本测试

- 三视图仅验证同一 Core 的正面、侧面与背面，确认不混入主题服装、主题表情或主题姿态；
- 主题参考图只更换服装时，确认脸、比例、姿态、主体材质与核心道具不变；只改变表情或姿态时，确认服装、配色、主体结构与材质不变；
- 多个主题参考图分别生成独立主题/服装版本合页，确认不混合版本，且每页均逐字复用同一正式 `character_anchor`；
- 食品角色主题版本确认食材本体和可食质感仍为主体，主题服装未抢占识别。

### 5.7 执行摘要与门禁测试

- 从零创建任务：未输出含角色比例、主体与关联、配色与材质、Core 状态和 `asset_goal` 的生成前执行摘要时，不得生成 Core；
- 家族任务：摘要缺任一成员的单体 Core/拼版来源、总人数或分组时，不得生成家族 Core；
- 主题版本：摘要未列出主题参考图、变化清单与锁定项时，不得使用主题参考图；
- 衍生任务：Anchor 状态不是“已锁定”或 2.5 未通过时，不得生成三视图、主题版本或应用图；
- 最终交付：每项交付均可与执行摘要中的 `asset_goal`、实际输入和关卡状态逐项对应；无法对应即不交付。
- 用户上传清晰半身或全身角色图并要求主题服装、妆容、表情或姿态版本：直接作为视觉 Core 提取 Anchor 并图生图，不重复生成 Core；
- 用户上传清晰局部图并要求完整全身、三视图或其他需展示未见区域的资产：先补齐或重建模型完整全身 Core，再进入对应资产；

### 5.8 叙事角色设定页轻量氛围测试

- 奇幻、科幻、现代都市叙事角色各生成 1 张设定页：每页只使用可追溯的环境色调、光线/天气倾向和少量世界观母题，角色、核心道具、标题与信息模块仍一眼读清；
- 无明确世界观资料时：验证设定页只使用角色已有配色与材质，保持干净分栏，不擅自补环境、事件或符号；
- 与概念海报对比：验证设定页不承担剧情场景和强事件表达，仅保留轻微世界观气质。

## 最终执行红线

1. 用户提供/已确认的清晰图可直接作为视觉 Core 复用；草图、低清图和无法稳定识别身份的图须重建。仅当任务需展示原图未见区域、完整全身或三视图时，才补齐或重建模型完整全身 Core。
2. 正式 Anchor 从用户提供视觉 Core 的可见身份信息，或从已通过核查的模型完整全身 Core 提取，是所有角色衍生的唯一视觉身份标准；用户视觉 Core 不得补写未见区域，补齐设计必须与模型完整全身 Core 实际画面一致。真人身份保真启用时，`identity_source_image + face_identity_lock` 只在内部强化正式 Anchor 中的面部身份，不另建第二份对外 Anchor。
3. Core 后的资产全部走强一致性图生图：主题服装、妆容、表情和姿态版本可直接以清晰视觉 Core 为母版，且不得超出原图可确认范围；完整全身、三视图及未见区域资产统一以通过 2.5 核查的模型完整全身 Core 为母版；真人身份保真资产同时传入原始真人参考图与当前 Core；局部改图只改指定区。
4. 设定卡是基于 Core 的角色设计说明页，不是 Core 本身。
5. 三类资产只改变其允许变化层；任何资产不得为了排版、文字、场景或载体牺牲角色身份。
6. 最终 `asset_goal` 仅按 3.4.1 计算；“先看/先确定 Core”不移除设定卡，只有明确排除语句才可移除；模板不得自行增删资产，生成前后均须以资产清单逐项核对。
7. Core 默认 1 张确定主形象；衍生资产按合页 vs 独立单张规则输出，不继承通用生图的多候选默认。
8. 多类资产共享 `asset_system_rule` 但各按本类模板排版；只有同类且明确分别输出多张时才建立 `series_rule`。
9. Core、每项衍生资产与最终交付均须通过对应核查关卡；任一项不通过，先定向修正或重生，不得进入下一阶段或交付。
