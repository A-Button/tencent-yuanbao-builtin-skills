1. 完整流程

## 1. 完整流程

```text
理解目标
→ 补齐最低输入
→ 判断目标是否现实、安全
→ 核算时间与任务容量
→ 查证会改变计划的外部事实
→ 识别关键差距并排序
→ 设计阶段和通过标准
→ 拆成可执行任务
→ 加入缓冲、降级和调整规则
→ 生成聊天计划卡及必要文件
→ 仅在有明确增量价值时推荐0—3个定时节点
```

计划的增值不只是“把目标分成几步”，而是完成三项判断：

1. **目标判断**：目标是否清楚、现实和安全。
2. **路径判断**：哪些差距最关键，应该采用什么顺序和方法。
3. **执行判断**：可用时间能承载多少任务，什么情况需要降级或重排。

## 2. 输入与澄清

### 2.1 计划所需信息

| 字段 | 需要了解什么 | 处理原则 |
|---|---|---|
| 主目标 | 最终希望达到什么状态 | 无法识别一个主目标时必须追问 |
| 完成标准 | 什么结果算本轮计划完成 | 用户未定义但可合理建议时，先提出建议标准并标明 |
| 期限 | 截止日期或计划周期 | 缺失且会改变负荷或颗粒度时追问 |
| 当前状态 | 已完成内容、基础和主要差距 | 可以来自用户自述、附件，也可以在计划首阶段安排诊断 |
| 可投入时间 | 每天/每周时长和固定不可用时间 | 缺失且会改变任务量时追问；初稿不免此项 |
| 硬约束 | 健康、家庭、预算、规则和设备等 | 只补会改变路径、安全或可执行性的约束 |

不是每个缺失字段都值得打断用户。调用 `ask_user_question` 前先判断：

1. 缺失信息是否会使主目标或领域无法确定；
2. 是否会显著改变计划负荷、优先级或方法；
3. 是否涉及安全或不可逆风险；
4. 是否能从已有对话、附件、记忆或可靠公开信息取得；
5. 是否能用清楚、保守且不危险的假设继续。

只有前3项之一成立，且无法由第4项取得、也不适合第5项假设时，才追问。

### 2.2 追问优先级

一次最多提出四问，按下列顺序选择：

1. 缺失后无法确定本次规划什么：主目标、必要的完成标准。
2. 缺失后可能造成不安全或明显错误：健康限制、关键日期、不可接受项。
3. 缺失后会显著改变负荷和优先级：期限、当前基础、可投入时间。
4. 缺失后只影响体验：偏好、文件格式、排版样式；通常直接采用默认值。

不要询问可以从附件、上下文、记忆或官方信息中直接得到的内容。

默认把关键缺口合并到 1 次结构化追问中。只有用户第一次回答后，仍缺少会显著改变计划目标、负荷、方法或安全边界的关键信息，并且不能用清楚、保守且不危险的假设继续时，才进行第 2 次；第 2 次只问剩余关键缺口。补齐最小信息合计最多追问 2 次。

### 2.3 多目标处理

- 有多个目标时，追问这段时间优先保证哪一件；也允许用户选择几件都要、优先级相当。
- 主目标由用户确定。其他目标写进同一份计划，按剩余时间和精力安排，不另做一份完整计划。
- 用户选择优先级相当时，并列安排，不硬拆成一主多次。

## 3. 目标合理性判断

### 3.1 时间容量

按周计算：

```text
参考容量 = 用户每周可投入时间 × 约80%
```

约 20% 的余量用于临时事务、状态波动、补欠和休息。这是用户没有另行要求时的默认估算，不是机械上限：

- 用户给出的已经是保守的净可用时间，可以提高使用比例；
- 用户明确希望采用更高强度时，先说明代价和失败风险，在安全范围内尊重其选择；
- 评判重点是任务量能否落在真实容量内，并保留必要缓冲，而不是是否精确等于80%。

### 3.2 必需投入

估算完成目标需要的任务量，并标注依据：

- 有官方范围、题量、训练周数或面试日期时，按已知范围估算。
- 只有粗略目标时，给区间而不是伪精确单点。
- 任务耗时优先使用用户历史表现；没有历史数据时使用保守估计并标为假设。

若“必需投入 > 参考容量”，不要直接排满日历。依次给出：

1. 缩小范围：保住最高价值内容。
2. 调低完成标准：从“全面掌握”改为“达到通过线”等。
3. 延长期限：给出最早可行日期。
4. 增加资源：提高可用时间、获得辅导、器械或材料。

### 3.3 激进目标与用户选择

- **激进或期限内难以完整实现、但仍安全**：先说明问题和可选调整，由用户选择。写计划时只写用户选定的那一套阶段和任务。
- **用户坚持原目标**：按原目标写；问题与建议只出现在计划判断中，不另写一套执行任务。
- **不安全或明显有害**：危险部分不写入执行任务，即使用户坚持也不执行；在计划判断中注明不能做的部分，并给出更安全替代或建议专业评估。

目标合理性判断的价值是帮助用户做清楚的取舍，不是用固定阈值替用户做决定。

### 3.4 风险与依赖

检查：

- 目标是否依赖尚未报名、未确认的日期或资格。
- 是否存在用户无法控制的结果，如“保证拿到Offer”。
- 是否存在健康、法律或其他高影响风险。
- 是否存在前置任务，例如先完成简历再开始定向投递。

将不可控结果改写成可控过程指标。例如把“一个月拿到Offer”改为“完成岗位定位、材料准备、有效投递和面试准备”。

## 4. 信息查证与方法选择

联网的目的不是给计划堆引用，而是减少四类错误：依据过期、方法不当、资源不可用、风险被忽略。只有搜索结果可能改变计划的范围、顺序、负荷、资源或安全边界时才联网。

### 4.1 什么时候必须查证

出现以下任一情况时，使用 `web_search` 或 `web_fetch`：

1. **存在时效事实**：日期、报名、资格、规则、版本、岗位、渠道、价格或可用性可能变化。
2. **存在外部标准**：完成目标需要依据官方范围、评分标准、岗位要求、专业指南或行业规范。
3. **需要选择方法或资源**：不同课程、题库、训练方式、求职渠道或工具会显著改变计划效率。
4. **材料不足或冲突**：附件与公开信息不一致，或用户只有二手说法，无法据此确定计划。
5. **目标具有风险**：健身、健康、劳动权益等内容需要权威边界和停止条件。

以下情况不联网：

- 需要的信息只有用户本人知道，如自己的考试日、面试日、真实可用时间、伤病史、个人经历和偏好；
- 用户提供的最新官方材料已经足够；
- 稳定的通用规划原则可以直接应用；
- 搜索结果不会改变任何计划决定，只会增加装饰性引用。

### 4.2 查什么

将研究任务拆成四类，分别检索：

| 研究对象 | 要回答的问题 | 对计划的影响 |
|---|---|---|
| 硬事实与限制 | 什么时候、要满足什么条件、范围有多大、哪些不能做 | 确定期限、前置任务、范围和安全边界 |
| 可靠方法 | 有哪些被官方指南、研究或成熟实践支持的方法 | 决定阶段顺序、训练方式和任务配比 |
| 可用资源 | 哪些官方材料、课程、题库、渠道、工具或公开数据可实际使用 | 把抽象任务落实到具体对象 |
| 风险与验收标准 | 常见失败原因、停止条件、评分或通过标准是什么 | 设计检查点、降级方案和完成定义 |

不要把四类问题合并成一句“如何完成某目标”的宽泛搜索。先查限制，再查方法，最后选资源。

### 4.3 来源选择

按以下顺序选择：

1. **官方或原始来源**：考试主办方、政府、学校、公司官网、招聘页、专业指南原文。
2. **专业机构或研究**：学术论文、行业协会、医疗和运动专业机构。
3. **可信行业资料**：有作者、日期、方法和适用范围的成熟实践。
4. **社区经验**：论坛、面经和个人经验，只用于发现问题、资源和可能的做法。

选择来源时检查：发布日期、适用地区/人群、是否直接支持当前判断、是否与其他可信来源一致。社区经验不得作为资格规则、必考题、健康结论或公司事实的唯一依据。

### 4.4 如何进入计划

每条有实质影响的查证结果都应转化为一项计划决定：

```text
查证事实/方法：
来源与日期：
对计划的影响：增加、删除、提前、延后或调整哪项任务
仍不确定的部分：
```

若多个可靠来源结论不一致，展示分歧并采用更保守的方案，不伪造确定答案。

### 4.5 领域示例

| 场景 | 优先查证 | 首选来源 |
|---|---|---|
| 学习备考 | 日期、报名、考纲、科目、评分规则、官方资料 | 考试主办方、学校或主管部门 |
| 求职冲刺 | 岗位要求、招聘批次、城市和渠道 | 公司招聘官网、官方招聘账号 |
| 面试备战 | 公司业务、岗位职责、近期公开动态 | 公司官网、公告、官方招聘页 |
| 健身减脂 | 运动建议、禁忌、负荷和停止条件 | WHO、政府卫生机构及专业指南 |
| 其他个人目标 | 时效限制、权威方法、可用资源、验收标准 | 对应领域的官方或专业来源 |

## 5. 进度和任务生成

### 5.1 颗粒度

| 计划周期 | 规划方式 |
|---|---|
| 1—7天 | 拆解全部日期；每日至少有一个核心任务 |
| 8—30天 | 给完整阶段路线，详细拆解首周，后续按周 |
| 30天以上 | 给阶段和周节奏，详细拆解前两周 |

上表是执行约束，不是参考建议。超出表中拆解范围的时间段按周给节奏，不逐日铺满——数周以上的计划逐日铺满会制造虚假精度，也会让日期、周次和里程碑互相冲突。用户明确要求逐日时优先满足，但仍只对确实能安排到日的时间段给到日，其余说明按周执行。

起始日按下面规则确定，再推算星期和周次，不要逐行手写再对日历；用户指定的具体日期原样保留。发现周数对不齐时只改起始日或周数，不重排任务。

| 用户给了什么 | 起始日怎么定 |
|---|---|
| 明确的开始日 | 用该日（即使用户给的开始日已经过去，也原样保留） |
| 只给了结束日，或只说「开学前」「考前」 | 从生成当天写到该日（开学日、考试日未给出时，写下假设并按「生成当天 → 假设结束日」排） |
| 只给了周期长度（如 40 天、13 周），没给起止 | 从生成当天起算这段长度 |
| 开始日是推断出来的，且会使大部分任务落在已经过去的日期 | 改从生成当天起算，按剩余天数或到截止日期重排周期；不要输出已过期的完整日历，再写「请按剩余天数自行缩放」 |

「按周」在执行表里的写法：超出上表「拆到日」范围的时间段，每周或每个周段一行，至少包含日期范围（起止日，不只写「第3周」）、本周重点、做多少、完成标准。做多少按领域写：学习写题量或产出，健身写组次或时长，求职写岗位数或投递量。不要把整周日程写成一段散文塞进一格，也不要按日占行再填同一句「按周节奏」。同一张执行表里前半逐日、后半按周时，按周那一段要另写一行表头，不要继续填进上面逐日那几列。

从起始日到结束日中间不能断档。拆到日的那几周，每天都要有行，休息日也写「休息」或缓冲，不能隔天跳过。按周的那一段，每一周或每个连续周段都要有行，不能第 2 周之后直接跳到第 7 周，也不能日更写到 9 月 4 日、下一行变成 9 月 15 日。两段衔接处的日期要接上：逐日最后一天的次日，就是按周第一行的起始日。

### 5.2 进度结构

所有计划必须有清楚的时间或进展顺序，但不要求机械拆成多个阶段：

- 状态、策略或验收标准会发生变化时，使用多阶段结构；
- 1—7天或简单目标可以直接按日期、任务或里程碑组织；
- 不为了“看起来完整”制造没有差异的阶段。阶段按策略转折切（主科切换、考试、报名、目标降级），不按自然月切；相邻阶段目标和方法相同就合并。
- 面向用户的文字少用代号、多用白话，短但普通人能看懂。写「第1周」「适应期」「必保」，不要单独用 `W1`、`P0`、`A/B/C`。内部思考可以用代号，写入聊天和文件时换成白话。
- 阶段切分只做一次，写进执行主产物后，其他文件和聊天只引用，不重切。

采用阶段结构时，每个阶段应包含：

| 字段 | 定义 |
|---|---|
| 时间范围 | 明确开始和结束日期 |
| 阶段目标 | 该阶段结束时达到什么状态 |
| 核心策略 | 为什么此阶段先做这些事 |
| 关键任务 | 主要行动及优先级 |
| 通过标准 | 用什么证据判断可以进入下一阶段 |

### 5.3 任务结构

每项任务必须具备下面这些语义（做什么、对谁做、做多少、耗时、怎样算完）。写进执行表时列头按领域，不要全国一张「动作」「数量或输出」。

| 语义 | 含义 | 示例 |
|---|---|---|
| 做什么 | 完成、练习、比较、整理、模拟 | 完成并订正；精读后做题 |
| 对象 | 某章节、某训练动作、某类岗位、某组问题 | 阅读理解定位；存货章节 |
| 做多少 | 可数的题量、组次、岗位数或一页产出 | 20题、3组、5个岗位、一页对照表 |
| 预计耗时 | 这项大概要多久 | 45分钟 |
| 完成标准 | 怎样算做完 | 正确率达到70%，或能不看资料讲清三点 |
| 优先级 | 必做 / 应做 / 可选；简单计划允许核心任务均为必做 | 必做 |
| 依赖 | 仅在确有前置条件时填写 | 先完成第2章 |

| 领域 | 做什么的列头 | 做多少的列头 |
|---|---|---|
| 学习备考 | 学习内容，或科目/模块 | 题量或产出 |
| 健身减脂 | 动作，或训练内容 | 组次，或时长 |
| 求职面试 | 任务，或投递动作 | 数量或产出 |

不合格：

> 复习英语；坚持锻炼；准备面试。

合格：

> 用45分钟完成20道阅读题并订正，给每道错题标注“词汇、定位、推理”中的一个错因；正确率达到70%或能解释全部错题后完成。

不要只写原则或每日共用规则、没有按日或按周的任务行。

优先级用于帮助用户在时间不足时先保住最重要的动作。存在真实取舍时，应说明排序依据；任务都能完成且价值接近时，不强行拉开优先级。

### 5.4 缓冲、降级和校准

每份计划必须回答四个执行问题，呈现形式可以合并：

1. **缓冲在哪里**：哪些时段或任务量没有被排满；
2. **时间不足怎么办**：必须保留什么、可以舍弃什么；
3. **状态不佳怎么办**：最低可执行动作是什么；
4. **何时调整或重做**：看什么信号、何时检查、采取什么调整动作。

输出时至少明确：

- 执行缓冲；
- 时间不足或状态不佳时的最小可执行方案；
- 一个或多个可观察信号、检查时点和对应调整动作；
- 需要重新制定计划的触发条件。

## 6. 标准计划数据

所有领域先想清楚同一份计划（下面这些字段），再直接写成聊天或文件：

| 模块 | 必要字段 |
|---|---|
| 目标契约 | 主目标、完成标准、期限、约束、假设 |
| 计划判断 | 可行性、主要差距、优先级、查证事实和来源 |
| 进度结构 | 阶段/日期/周次/里程碑、重点和通过标准；按任务复杂度选择 |
| 执行任务 | 日期/周次、做什么、做多少、耗时、完成标准、优先级、依赖。列头按领域：学习用学习内容 / 题量或产出，健身用动作 / 组次，求职用任务或投递动作 |
| 缓冲与最小方案 | 执行缓冲、时间或状态不足时保留与舍弃的内容 |
| 执行校准 | 可观察信号、检查时点、调整动作和重新制定条件 |
| 快速启动 | 下一个可用时段能开始的低门槛、相关且具体的第一步；只渲染到聊天计划卡，不写入文件 |
| 推送建议 | 默认无；适合时给0—3个高价值节点、类型及待确认信息 |

## 7. 计划质量判据

- **完整性**：目标、期限、现状、资源、约束齐全或已列假设。
- **合理性**：计划任务量符合真实容量；激进目标已说明取舍，不安全目标已被阻止。
- **证据性**：优先级有成绩、考纲、岗位要求、身体基础或可信指南支撑。
- **可执行性**：每项任务都有做什么、做多少、耗时和完成标准。
- **可理解性**：面向用户的文字少用代号、多用白话，短但能看懂。
- **可检查性**：进度结构和任务有明确通过标准。
- **弹性**：存在缓冲、最小方案、检查信号和调整动作。
- **即时性**：包含下一个可用时段即可开始的低门槛第一步。
- **边界**：未承诺自动跟踪、文件管理或跨会话更新。
