# 报告的分析依据

只在 `hypotheses_required` 时读取。使用返回的 `chart_system`、`primary_topics`、`analysis_chart` 和用户原问题。此阶段整理有盘面依据、值得展开的判断，不预先设计文章章节，也不先写一份长报告。

```json
{
  "schema_version": "3.0.0",
  "chart_system": "bazi",
  "primary_topics": ["career"],
  "candidates": [
    {
      "id": "h1",
      "topic": "career",
      "claim": "结合当前盘面关系，对用户事业问题作出的判断与关键条件。",
      "signal_paths": ["chart.details.day_master.stem"]
    }
  ],
  "selected_ids": ["h1"]
}
```

示例只展示格式，不是专业分析样本。`claim` 写具体判断，`signal_paths` 使用当前盘面真实、具体的路径；路径存在不等于解释已获证实。需要时可增加 `manifestation` 或 `cost_or_contrast`，不强制把每个判断拆成表现与代价。

候选与入选数量按问题需要决定，不凑候选池、不设性格配额。入选判断覆盖所有用户关注主题即可；`personality` 可用于整体结构或性格，但不是必选。可直接只提交要使用的判断，不写评分、竞争过程或选择说明。明确的问题优先于主题分类，不强制缩成日常习惯。八字候选应是能由月令、日主与相关十神共同支持的结构性判断，说明它如何回答用户的实际问题；不要把同一条“应多自省、先做小事”拆成数条近义候选。

## 事实范围

- 原局候选不引用 `chart.details.luck_cycle_focus`；当前大运由第二阶段按 `timing_contract` 结合原局分析。
- 日期级只使用 `chart.stable.*`。范围盘若提供完整且稳定的四柱，可用相应 `pillars/details`，否则也只用稳定字段。跨界候选不选一个“更像”的，不补造缺失字段或分钟精度。
- 西占深报保持太阳、上升、月亮、金星、水星的已确定星座范围。未知项不补齐，范围内稳定上升照常使用。
- 西占候选优先写与用户原问法相关的配置关系：能组成判断时在同一条 `signal_paths` 引用至少两项已确定星座，并在 `claim` 中说明各自功能如何共同作用；只有一项可用或问题确实只涉及一项时才写单项判断。路径是可核验事实，配置间的心理关系仍是象征解释；不要把星座间的差异写成脚本未计算的相位。
- 不从人物身份、履历或已知事件倒推判断；表达与边界沿用已加载的 [safety.md](safety.md) 和对应体系的方法。

写入 `next_input` 后执行返回的 `next_command`。通过后再读正文契约，不提前加载后续文件。结构、主题和路径错误修正对应字段；warning 不触发额外生成。旧版 2.0 输入仍可用于在途报告，新生成使用 3.0。
