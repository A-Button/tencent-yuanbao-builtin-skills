# 需求萌发模板

用户尚未确定品类时使用。目标是收敛方向，不是销售具体型号。

## 先给方向

开头用一句“对号入座”式结论，明确用户更该看哪 1–2 个品类方向。例如：

- 想省时间、降低操作门槛 → 优先看 {品类 A}
- 更在意可玩性、可控性或长期扩展 → 优先看 {品类 B}

不要先解释品类历史、参数或品牌，也不要给型号、价格和商品链接。

## 按诉求收敛

每个方向用 2–3 条说明：

- **适合什么情况**：贴合用户场景/人群/预算。
- **为什么适合**：用用户能感知的体验或取舍解释，不堆参数。
- **不适合什么情况**：避免用户误选。

两类需求能够兼顾时，补一条可执行的“兼顾方案”，而不是强迫二选一。

## 下一步

结尾只问一个最能缩小范围的问题，例如预算、使用频率、空间、肤质或是否有特定功能刚需；说明补充后可以进一步收敛到具体类型。没有明确购买意愿时，不给商品链接。
