# 塔罗 HTML 当前实现策略

保存日期：2026-09-26。本文件描述 9 月 26 日合并测试候选；旧版和两个来源工作副本保留，尚待现网验收。

- 主交付：assets/tarot-draw-shell.html；源代码：assets/tarot-studio-source；构建包：assets/tarot-studio-bundle。修改源代码后重新构建，再运行 scripts/package_tarot_studio_shell.py，禁止只修改生成 HTML。
- 构建后体积与 SHA-256 记录在候选目录外层的文件清单中。
- 暗色固定三张牌、首次洗牌、逐牌正逆位文案、独立背景动画，保留已完成的移动端布局。手机三牌横排，解读纵向阅读。
- 分享：share-poster.js 加载三张内嵌原始 WebP，等待全部加载与解码成功，直接在 Canvas 绘制牌面、逆位旋转和文字，导出 PNG。逻辑宽度 720px、倍率 1.5，高度随最长文案延展。任一图片失败则整次导出失败，不缓存缺图海报。
- 结果图片：点击「分享结果图片」后打开适配可视区域的弹窗，图像独立滚动；手机底部提示长按保存或分享，PC 底部提供下载。关闭后恢复页面位置。规则见 image-save-share.md；复制结果及手动复制弹窗继续保留，海报由原生 Canvas 绘制。
- 高清素材：78 张原始 WebP、背景和牌背完整内嵌；保留宋体 400／500，600 字重不内嵌。总 HTML 上限为十进制 9,500,000 字节；模板预留 2,048 字节配置空间。打包、问题页生成和交付专项校验执行体积检查。
- 合入新的一屏方案：独立 viewport-probe 读取渲染区尺寸，统一预算牌位与牌弧；动画期间延后尺寸变化，手机结果保留纵向滚动，极小窗口允许内容增高。重抽时整体淡出，新牌从收拢状态洗牌；不恢复已撤回的 screen-fit 反复测量方案。
- 同一产物恢复牌局与结果；随机 artifactId 随生成文件固定，分享快照与本地状态分离。细节见 tarot-state-share.md。
- 检查：test_tarot_share_poster.mjs、test_tarot_standalone.js、verify_tarot_draw_html.py。现有检查覆盖导出调用、三图、逆位、失败阻断、文案换行、原始资源、字体和体积；没有完成真实浏览器像素检查，不得将单元检查写成手机／PC 实测通过。
