# 看房单

看房单属于当前 OAuth 用户，不属于某次对话或某个找房条件。工具从已验证的 Access Token 获取用户身份；不要询问、展示、猜测或提交 `user_id`。

## 查看

用户说“我的看房单”“看看收藏的房子”时，调用 `list_viewing_list`。直接使用返回的数量和房源快照；快照是加入时的数据，不代表价格和可租状态仍然不变。当前没有独立详情刷新接口，需要实时核对时应重新搜索，不能根据旧快照直接说仍可租或已经下架。

## 加入

用户说“收藏第二套”“把这套加入看房单”时：

1. 从本轮真实搜索结果里找到用户所指房源。
2. 使用该房源的 `listing_ref` 调用 `add_to_viewing_list`。
3. 只有工具返回 `saved=true` 才说明已经加入；同时可以告知最新数量。

不要传 `inv_no`、卡片 `id`、`house_id` 或自己拼装引用。没有可对应的 `listing_ref` 时，先重新搜索或请用户指出具体房源。

## 移出一套

用户明确说“把第二套移出去”“取消收藏这套”时，使用已展示结果或 `list_viewing_list` 返回的对应 `listing_ref` 调用 `remove_from_viewing_list`。只有 `removed=true` 才说明移除成功；`removed=false` 表示这套原本不在当前用户的看房单里。

当前不提供清空整张看房单的工具。用户要求“全部清空”时说明只能逐套确认移除，不要循环批量调用来模拟清空。

## 安全边界

- 看房单操作不修改城市、预算、租住方式、居室或当前搜索分页。
- 不把一个用户的引用或结果用于另一个用户；服务端最终按当前 OAuth 身份隔离数据。
- 加入和移出是写操作。用户只是比较、询问或打开详情时，不自动收藏或取消收藏。
- “预约看房”“约周末带看”不是看房单操作；当前 MCP 不提供预约能力。
