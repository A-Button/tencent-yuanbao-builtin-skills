# 报告正文

只在 `content_required` 时读取。使用 `validated_hypotheses` 与聊天中用户的实际问题，在 `next_input` 写入正文。不回读出生资料或搜索人物履历；需要阶段分析时读取 `timing_contract.analysis_chart`。

## 输入

```json
{
  "title": "能力如何转成事业与收入",
  "sections": [
    {
      "title": "命局中的生扶与输出",
      "hypothesis_ids": ["h1", "h2"],
      "paragraphs": [
        {"text": "结合已验证判断解释整体结构，再回答它对用户问题意味着什么。"}
      ]
    }
  ]
}
```

这是数据格式示例，不是文章模板。脚本注入体系、主题、版本等字段。`title` 与各节标题均可省略；`sections` 按你组织的文章顺序渲染，每节有非空 `paragraphs`，段落只需 `text`。需要强调时可选填 `highlights` 数组，其中短语须在原段恰好出现一次且互不重叠。用户可见字段用纯文本，脚本负责排版与转义。

## 组织内容

围绕用户原问题写一篇完整、可独立阅读的报告。主题 ID 只是后台覆盖索引，不是章节名称；保留用户具体问法，不把“创业还是留在现岗位”等问题降成泛泛的事业介绍。

按解释关系组织文章：命局格局、十神作用、旺衰与取用可以在同一段分析中贯通；事业与收入、关系与家庭也可以合并。标题、顺序、篇幅与段落数量由实际问题和资料决定，不固定“总论—性格—主题—建议”，不强制单列性格、术语解释、观察点或行动清单。专业判断要说清盘面关系、现实含义和关键条件，不必把所有内容改写成细小的行为偏好。八字报告先把原局中的主要生扶与耗泄关系说透，再推进到主题及阶段；后续段落增加新的证据、关系或适用条件，不换词重复一条建议。

各节 `hypothesis_ids` 可引用多个入选判断，同一判断可跨节使用；不必按候选顺序写，也不必逐条扩写全部入选项。全文应覆盖用户关注的主题，依据不足时明确说明该处的限制。引用路径可核验存在，但不能证明解释本身成立，仍需模型结合分析方法判断。

西占正文把入选判断放回用户的具体问题中：说明相关天体分别代表什么、已确定星座如何表达、组合后在什么情境下可能相互支持或拉扯，以及结论成立所依赖的条件。用户问两种选择时逐一比较，不改写成泛泛的性格介绍；用户问某段时间的结果，而输入只有本命配置时，回答可讨论的本命倾向并说明没有行运依据。章节按问题展开，不按太阳、上升、月亮、金星、水星固定排列；不要把 HTML 的单项位置标签当成组合论证，也不要从星座位置推断未提供的相位、宫位或未知上升。

## 阶段分析

`timing_contract.required=true` 时，在相关章节增加 `signal_paths`，使用脚本给定的当前大运与原局事实。可以放入事业等主题章节，或单独成节，不固定位置。该节可以同时引用原局 `hypothesis_ids`；纯阶段章节允许该数组为空。

- `available`：路径同时包含当前大运派生事实与原局事实，解释两者怎样互动，不凭年份补造流年或事件。
- `conditional`：每个涉及阶段的章节均引用两条匿名分支与原局事实，明确区分两种条件的影响，不替用户选边，不把条件结论写成已确定的命局特征。无需等字数，不显示内部分支 ID、性别或顺逆标签。
- 其他状态：不写 `signal_paths`，不补算大运；必要的不可用说明由脚本附在文末，不生成空章节。

八字阶段路径须指向派生事实，例如 `cycle.stem.ten_god`、`position_band` 或 `cycle.relations_to_natal` 下的具体关系；仅引用该步的 `gan_zhi` 名称不足以支持互动分析。

后台路径不出现在正文；阶段参考日由脚本显示一次。默认不展开流年。

## 生成与交付

写完直接执行返回的 `next_command`（`report_pipeline.py finalize`）。一次完成校验、Markdown 装配与 HTML 渲染，不增加模型润色或评分回合。

结构错误、未入选引用、遗漏主题、无效盘面路径、身份字段泄露和大运条件错误会阻止发布；不按字数、段数、章节顺序或重点比例要求返工。词法提示只是 warning，不自动追加生成；语义边界沿用已加载的 [safety.md](safety.md)。旧版 4.0 正文仍可完成续接，新生成使用本文的自由章节格式。

完成后按原交付协议核验并附上 HTML；聊天直接概括与用户问题最相关的结论，不重复全文。普通排盘则仍是命局概要／简要分析与盘面 HTML 在同一条回复出现，不因深报而增加首轮等待。
