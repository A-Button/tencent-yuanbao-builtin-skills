# WeStock

执行短路径：**确认必要项 → 最小查询 → 核验口径 → 回答或交付**。直接使用环境已有的 `westock`，不安装、不修改 CLI。只解决当前问题，不把简单比较升级为全面研究。

## 1. 先决定目标和交付形式

- 在内部列出必要项：标的/资产类型、市场、目标日期或区间、指标与条件、覆盖范围、输出形式。已明确的信息不重复询问；只在歧义会实质改变结果时澄清。
- **默认文本**：查数、解释、筛选名单、比较结论直接用文字或 Markdown 表格回答；不自动加载文件技能，不为短回答生成附件。
- **明确要文件**：仅当用户要求 Excel、Word、PPT、下载或可编辑附件时，按对应文件技能交付；Westock 只负责必要数据、计算口径和来源。不把文件生成设成所有任务前置条件。
- 附件或本轮已有结果已满足要求时直接使用，注明来源；不为“再确认一次”重复检索。用户要求更新或现有数据缺失时再调用。
- 必要项完成或已明确无法核验就进入回答；可选背景、更多年份、更多指标不阻塞交付。

## 2. 按意图选入口，只读需要的资料

**以下示例足够覆盖常见任务，匹配时直接执行，不先读参考文档或逐级查帮助。只执行需要的行，不把表格当成必跑清单。** 示例日期、代码、阈值均需替换为当前用户要求或已确认的值，不照抄样例日期，也不默认改成今天。

### 2.1 执行前最重要的四件事

- **多代码用逗号，作为一个参数**：`westock quote hk01810,hk00700,hk03690 --raw`。不能写成空格分隔的多个代码，否则可能只返回第一个。财报、支持批量的K线同理；搜索、minute及期货/外汇K线不能套用批量。
- **历史任务必须带历史参数**：指定日行情用`--date`，历史区间K线用`--start`和`--end`。不带日期的quote、仅带limit的K线通常查询最新数据，不能回答历史任务。
- **财报只取必要表**：利润/ROE用`--type income`，资产负债用`--type balance`，现金流用`--type cashflow`。最新N期用`--limit`；历史区间用`--start/--end`，两组互斥。财报批量按市场分组。
- **程序处理时一次保存完整JSON**：在所选命令上加`--raw > result.json 2> result.err`，随后复用本地文件。不要`2>&1`混入JSON、不要`head`截断JSON；纯文字查数直接读返回表即可。

### 2.2 名称与数据查询：完整命令速查

| 用户需要 | 完整示例 | 当场核对，不扩展查询 |
|---|---|---|
| 股票名称转代码 | `westock search 招商银行` | 默认只搜股票；代码已知则跳过，同名按市场消歧 |
| ETF/REIT名称转代码 | `westock search 张江 --type etf` | 不用股票默认搜索反复试基金名；看返回的etfDetail覆盖 |
| 找指数代码 | `westock search 沪深300 --type index` | 指数不是同名ETF |
| 找板块代码 | `westock search 半导体 --type sector` | 使用返回的真实板块代码，不猜pt编号 |
| 最新行情、多股比较 | `westock quote hk01810,hk00700,hk03690` | 仅适合最新时点需求 |
| 指定日行情、PE/PB/股息率 | `westock quote hk01810,hk00700,hk03690 --date 2026-03-31` | 返回代码与日期必须对齐请求，不能用最新值替代 |
| 最近60条日线 | `westock kline sh600036 --period day --limit 60` | 这是最新序列，不是任意历史区间 |
| 指定历史区间日线 | `westock kline hk01810,hk01024 --period day --start 2026-01-01 --end 2026-03-31` | 检查实际起止日、节点数、复权和截断 |
| 最新4期净利润/ROE | `westock finance sh600036,sh601398 --type income --limit 4 --fields core` | 不默认拉三大表；按EndDate识别每期 |
| 指定报告期区间财务 | `westock finance sh600036,sh601398 --type income --start 2025-01-01 --end 2026-03-31 --fields core` | 不同时传limit；区分报告期和披露日 |
| 必要资产/负债指标 | `westock finance sh600036,sh601398 --type balance --limit 4 --fields core` | 只有用户需要这些指标时才查 |
| 必要现金流指标 | `westock finance sh600036 --type cashflow --limit 4 --fields core` | 不为普通估值比较额外补完整现金流 |
| 股票分红历史 | `westock dividend sh600036 --years 3` | 按实际实施日统计；不直接套给基金/REIT |
| 公告列表 | `westock notice list sh508000 --limit 30 --offset 0` | 按日期、标题选必要ID，缓存列表 |
| 公告下一批 | `westock notice list sh508000 --limit 30 --offset 30` | 只有首批未覆盖目标窗口且有新增记录时继续；不用page |
| 公告全文 | `westock notice detail "$NOTICE_ID"` | NOTICE_ID必须来自刚才列表并已赋值；不猜ID，不重复读取同一全文 |
| 研报列表 | `westock report list sh600036 --limit 5` | 仅用户需要研报/具体冲突需核实时调用，不默认附加 |
| 个股历史资金流向 | `westock fund flow sh688981 --start 2026-02-21 --end 2026-02-27` | 区间按单代码查询；主力/超大单不是北向资金 |
| 核验交易日 | `westock trade-calendar --start 2026-02-21 --end 2026-02-27` | 仅需要解释休市或对齐窗口时调用一次 |
| ETF费率/档案 | `westock etf profile sh510300` | 返回仅行情覆盖时，不反复试未知基金命令 |
| ETF收益/回撤等概览 | `westock etf overview sh510300` | 未确认支持历史快照时，不拿当前值回答历史问题 |
| ETF净值序列 | `westock etf nav sh510300 --start 2025-01-24 --end 2026-01-23` | 净值不是场内价格，区间覆盖需核对 |
| 板块成份 | `westock sector constituent pt01801080` | 代码必须已确认；成份列表不是条件选股 |
| 指数成份 | `westock index constituent sh000300` | 当前成份不自动等于历史成份 |
| 行业经营数据 | `westock sector oper 煤炭` | 用行业名称/合法标识，不用板块代码 |
| 已知宏观短名 | `westock macro indicator us_inflation --date 2026-07-03` | 不确定短名/模式时才执行`westock macro list --region us` |

小型比较优先使用已有字段：quote中的`price`、`pe_ratio`、`pb_ratio`、`dividend_ratio_ttm`；income中的`NPParentCompanyOwners`、`ROEWeighted`/`ROE`/`ROETTM`、`EndDate`、`InfoPublDate`。以实际返回字段为准，累计/单季/TTM分别解释；必要字段缺失时才补一次`--fields all`，不要为寻找更多解释变量扩成全字段研究。

### 2.3 筛选与排行：直接使用已知合法入口

| 明确需求 | 完整示例 | 不要误用 |
|---|---|---|
| 历史时点沪深股息率>5% | `westock screen condition --market hs --expression 'DividendRatioTTM > 5' --date 2026-07-31 --limit 30 --orderby DividendRatioTTM --desc` | 不擅加PE等门槛；条件选股没有offset |
| 沪深0<PE<20且ROE>15 | `westock screen condition --market hs --expression 'intersect([PE_TTM > 0, PE_TTM < 20, ROETTM > 15])' --date 2026-07-31 --limit 20` | AND用intersect；只按用户明确条件组合 |
| 高ROE或高股息 | `westock screen condition --market hs --expression 'union([ROETTM > 15, DividendRatioTTM > 5])' --date 2026-07-31 --limit 20` | OR用union，不改成AND |
| 港股0<PE<15 | `westock screen condition --market hk --expression 'intersect([PeTTM > 0, PeTTM < 15])' --date 2026-07-31 --limit 20` | 港股PeTTM与沪深PE_TTM大小写不同；美股按支持字段用market us |
| MACD金叉信号 | `westock screen strategy --type macd_golden --date 2026-07-31 --limit 20` | 不以DIF>DEA的状态代替当日发生交叉 |
| ST标签股票池 | `westock screen label --type risk_st --date 2026-07-31 --limit 20` | 并查多个标签不自动代表交集 |
| 未来90天解禁事件池 | `westock screen event --type shareunlock_next_90 --limit 20` | 窗口已在类型中，不加date/start/end，不当历史事件全集 |
| 金叉池内估值排行 | `westock screen ranking --type fin_valuation --within-strategy macd_golden --limit 10` | 范围标识不能与universe混用；未指定日期不承诺历史结果 |
| 北向活跃固定榜单 | `westock screen ranking --type north_active_d` | 固定Top20，不是北向逐日净流入，不套普通分页/排序参数 |
| ETF高股息主题池 | `westock screen label --type high_dividend --asset etf --limit 20` | ETF主题与股票高股息条件不等价 |
| ETF规模排行 | `westock screen ranking --type size --asset etf --limit 20` | 单一维度不启动多池交集 |

已知字段/类型直接执行；只有名称或支持范围未知时才查对应清单：`westock screen condition --list-presets`、`westock screen strategy --list`、`westock screen label --list --asset etf`、`westock screen ranking --list --asset etf`。不要全部跑一遍。缺回撤字段、北向日频流量或全量分页能力时，说明边界，不枚举猜字段、不用相近指标替代。

### 2.4 两个短任务：取完必要数据就回答

**两家银行截至2026Q1的利润/ROE与2026-03-31估值比较**。假设市场与代码已确认，且需要在本地计算；两条独立请求可同轮发出：

```bash
westock quote sh600036,sh601398 --date 2026-03-31 --raw > bank_quote.json 2> bank_quote.err
westock finance sh600036,sh601398 --type income --start 2025-01-01 --end 2026-03-31 --fields core --raw > bank_income.json 2> bank_income.err
```

本地按EndDate取所需报告期及同比基期，核对代码归属；若是“当时已知”任务还筛InfoPublDate。用已核验数值算同比/差值后直接回复比较表；只有用户要求Excel才建文件。不默认增加balance、预测、研报和多页公告。响应缺少必要记录时按第5节处理，不宣称两条命令必然完整。

**两只REIT的指定日价格、市值、成交额及分派比较**。假设代码已经通过基金搜索确认：

```bash
westock quote sz180101,sh508000 --date 2026-07-31 --raw > reit_quote.json 2> reit_quote.err
westock notice list sz180101,sh508000 --limit 30
```

只找目标窗口实际实施分派的公告ID，按需读取详情；每份分派合计÷目标日价格即可得到计算分派率，不额外翻审计报告寻找相同答案。不自动查出租率、租期或管理人背景；列表未覆盖窗口才按支持的offset继续，无法确认完整性就说明缺口。默认文字/表格回答，不把创建文件作为必经步骤。

只有以上示例未覆盖的具体参数、字段或返回结构才读对应短文；仍不明确时查**目标命令**帮助一次。不以“再读一份指南”为完成简单任务的前置要求。

## 3. 控制查询与探索

1. **首选匹配的 Westock 能力**：结构化数据先用正确命令；已明确不支持的资产/字段/历史模式不必故意发失败请求。新闻直接走 `web_search`。缺口处理见第5节。
2. **按依赖批量**：先解析未知代码，再查询；无依赖请求同轮执行，支持多代码时用批量。同一市场分组财报；不同命令不共享日期、分页或条数参数。限频时降低并发，不增加分片洪泛。
3. **一次取数，复用结果**：后续要计算、生成文件或做集合操作时，第一次就用 `--raw` 保存完整 stdout，stderr单独保存；复用本地结果，不先读展示表再为解析重复请求。只读展示即可回答时，无需 JSON 或脚本。
4. **按请求键去重**：本轮记录命令、代码、字段、日期和覆盖；仅有新增必要项、数据变化或明确故障恢复依据时重查。不要重新获取相同公告或同一期财报。
5. **有界纠错**：同一参数/解析问题最多一次有依据的修正；暂时性服务故障最多一次有依据的重试。未知字段不换多个拼写盲试；批量缺标的先核对请求与返回，再至多一次小批诊断，不连改多个批量大小或退回全市场逐只循环。
6. **预算用于收尾**：小型单标的/双标的信息任务，首轮必要查询后至多一轮补缺；仍缺数据就解释边界。复杂全量任务先评估覆盖与工作量，不硬套小样本。环境提示进入收尾或仅剩约20%预算时停止非必要探索；没有显式预算也按阶段推进，不等待提醒。
7. **剩余预算不足**：文本任务立即组织答案；文件任务优先保存和必要校验，不再增加装饰、预览或清理。文件未完成必须明确说明，并给出已经核验的数据，不把错误文件称为完整交付。

## 4. 金融口径与数据处理速查（直接使用，不必先读参考）

**先区分金融定义、CLI能力和实现错误。** 会计算某个指标，不代表CLI直接提供该字段或对应历史数据；`#VALUE!`、`#NAME?`不等于金融公式本身错误。本节只选与用户问题有关的行，不逐条追加查询。已有字段释义已前置；下述本地计算公式是显式定义的分析约定，不是新增CLI接口或未执行查询的结果。

### 4.1 先锁定六个维度：对象、时间、频率、口径、币种、单位

| 检查项 | 正确做法 | 常见错误与停止条件 |
|---|---|---|
| 对象 | 确认证券代码、市场和资产类型；同一公司A/H/ADR不同，ETF/REIT不等于管理公司股票 | 不按返回列表顺序给多股记录补代码；无法确认归属则不混算 |
| 行情时点 | 同一指定交易日、时区和价格类型；休市时明确前一交易日或用户指定规则 | 不带日期查到今天的数据，不可包装为历史日期；盘中价/结算价/收盘价分开 |
| 财报所属期 | 用`EndDate`核对报告期，按需要取最近四期或基期，缺期如实列出 | `--limit 4`是最新四期，不保证截至历史日期的四期 |
| 可知信息时点 | 用户要求“截至当时已公开”时，再核对`InfoPublDate`等披露日≤截止时刻 | 目标季度结束不代表季报已经披露；只有报告期、没有披露日时标未确认 |
| 数据频率 | 日/周/月/季/年、累计/单期/滚动窗口一致 | 季度持仓不能分摊为每日资金；20个交易日不自动等于一个自然月 |
| 币种与数量级 | 读取当前端点的`CurrencyType`、`CurrencyUnit`、表头或可靠字段说明，保留原值再换算 | 港股财报不必以港元计价；quote、市值筛选、财报的同名字段不保证同单位 |

支持`--date`或历史区间不保证所有字段都具备历史截面/point-in-time能力；当前成份、最新概览、之后修订的财报不能默认为当时可见值。跨端点时先检查各自实际日期，不能仅按请求日期贴标签。缺失原因可能是未披露、正常无记录、覆盖不足或接口失败，四者不能合并成0。

### 4.2 财报字段、累计、单季度与TTM

| 问题 | 优先字段/来源 | 解释 |
|---|---|---|
| 归母净利润 | income：`NPParentCompanyOwners`；单季常见`NPParentCompanyOwners_Q` | 不等于营业利润、扣非利润、含少数股东损益的总净利润 |
| 营业收入 | income：`OperatingRevenue`、`TotalOperatingRevenue` | 与`OperatingProfit`营业利润区分；金融公司收入构成按报表解释 |
| ROE | income：`ROEWeighted`、`ROE`、`ROETTM`、`ROE_Q` | 加权、期末、单季、TTM定义不同，比较时固定同一字段与期间 |
| 总资产/负债/权益 | balance：`TotalAssets`、`TotalLiability`、`TotalShareholderEquity` | 期末存量，不能把四个季度期末资产相加当年资产 |
| 资产负债率 | balance或筛选已披露`DebtAssetsRatio` | 若披露值可用直接读取；自行负债/资产计算须另标计算值且说明口径 |
| 现金流 | cashflow：`NetOperateCashFlow`等 | 经营、投资、筹资及自由现金流不混用，不用净利润当现金流 |

- **累计值**：同一财年年初至本期的流量。Q1单季＝Q1累计；Q2单季＝半年累计−Q1累计；Q3单季＝前三季累计−半年累计；Q4单季＝全年累计−前三季累计。相减要求主体、币种、会计口径、修订版本一致。
- **TTM流量**：最近四个完整单季之和；若原始是同口径累计值，可用“上财年全年＋本年累计−上年同期累计”。不得把四条累计值直接相加。TTM净利润可重建，但TTM ROE、EPS、毛利率等比率/每股指标不能照此简单加减，应优先取披露字段。
- **同比**：同口径本期A对上年同期B；B>0时增长率为`(A−B)/B`。B=0时无通常百分比同比；B<0或由亏转盈时优先报告绝对变化及扭亏/减亏，不擅自改用绝对值分母称“标准同比”。用户明确给算法时遵循并标注。
- **环比**：本期对上一可比期；单季对上一单季，不能Q3累计对半年累计当经营环比。
- **比率**：ROE/ROA/毛利率等优先用披露值；若题目明确要求重算，则给出分子分母与计算结果，并与披露值分栏，不能冒充原始披露。
- 仅需净利润、ROE和行情估值的银行比较，不应因为PB有差异就自动增加整套资产负债、资本充足率、预测与研报。

算术自检（虚构输入）：Q1累计100、半年累计230，则Q2单季130；上年全年400、本年Q1累计120、上年Q1累计100，则TTM为420；本期120、同期100，则同比20%。

### 4.3 百分比、基点、金额与股数

| 场景 | 正确换算 | 容易犯的错误 |
|---|---|---|
| 字段5表示5% | 计算用0.05；Excel数值0.05设百分比显示得到5% | 数值5直接设百分比显示会变500%；不得再次乘100 |
| 15%升到18% | 增加3个百分点＝300bp；相对增长20% | 把“增长3%”同时用于绝对百分点与相对变化 |
| 利率/收益率基点 | 小数利率差×10000；百分点数值差×100 | 4.0%→4.1%是10bp，不是0.1bp或100bp |
| 元/港元/美元→相应币种亿元 | 已确认原值以单币种单位计时÷100000000 | 不能因为字段名market_cap就认定所有端点都以元计 |
| 万元→亿元；百万元→亿元 | 分别÷10000、÷100 | 已经是亿元的值再除1e8；把“百万元”自动解读成人民币 |
| 股→百万股；每10股→每股 | 分别÷1000000、÷10 | 把每10份派息直接除以每份价格，导致收益率扩大10倍 |
| 手、股、份、张 | 按实际合约/交易所单位转换；没有手数乘数就保留原单位 | 不把所有市场一手都设100股；期权张数不等于正股股数 |

缺值标记`null`、空字符串、`--`、非有限数不能变0。带`%`、千分位和单位的文本先按该字段契约解释，不通过“一律删除非数字字符”解析；负号、括号负数、币种、百分比会因此丢失。同一列保留一个单位，不把元、万元混放后直接排序。

### 4.4 价格收益、复权、交易日与区间贡献

- 价格收益率明确为`R=P1/P0−1`，P0必须大于0，P0/P1须同证券、同币种、同价格类型、同复权基准。标明“起始收盘到结束收盘”还是“起始日前一收盘到结束收盘”；用户指定窗口优先。
- **不要直接相加区间涨跌幅**：连续两个区间整体收益为`(1+R1)*(1+R2)−1`。+10%后−10%是−1%，不是0%。区间边界应接续且不漏/重算交易日；基准日含义写明。
- **K线复权**：股票模式文档有qfq/hfq/bfq；具体市场是否有效按命令限制。期货/外汇不使用股票复权，部分指数、板块、港美等通道也不能假设支持复权。不要把前复权quote与不复权K线混算；记录实取模式。
- 既有手册将部分历史quote描述为前复权；这不是全市场所有字段的统一保证。分派率、基差、真实交易价格要求对应口径时，核对是否实际原始收盘价；不能把复权价当可执行报价。
- 现金分红、拆并股、换月会影响序列。未复权价格变动不自动等于含分红总回报；复权序列也需确认调整方式。期货主连跨换月不等于持有同一合约收益。
- 交易日由目标市场日历和返回日期核对，不按自然日或周一至周五直接推算。无记录日可能休市也可能缺失，不能统称休市；成交量字段缺失不能按0计。
- 涨跌幅、区间振幅、距最高点回撤分别不同。找最大成交日同时报告日期和价格表现，只能提供转折线索，不能凭同时发生就断言消息或资金导致涨跌。

### 4.5 最大回撤与风险指标

序列应为按时间升序、正值、同口径价格/净值；先核验目标窗口覆盖。令`peak_t=max(P_0,...,P_t)`，损失幅度约定`dd_t=1−P_t/peak_t`，则`MDD=max(dd_t)`，结果非负。“最大回撤不超过20%”按`MDD<=0.20`判断。

- 若来源返回有符号回撤（例如−18%），先确认定义，再换成18%的损失幅度比较；不能直接用`−25%<=20%`把超限样本判通过。
- 虚构序列100→120→90→110，最大回撤为25%，不是末期收益10%，也不是最高/最低价差除最低价。
- 最大回撤不是波动率、近一年跌幅或52周高低点比。概览字段有`maxDrawdown1Y`不代表条件选股支持同名表达式，也不保证历史日期可查。
- 有限已知池可在完整日线/净值上本地计算。用户要求全市场时，还必须证明前置候选池完整；Top N行情上算回撤不能冒充全量筛选。
- 缺少核心序列、窗口不完整、候选不全时标未验证；禁止造`MaxDD1Y`等多个字段拼写连续试探。未明确支持时，一次确认能力后执行缺口分支。

### 4.6 估值、同比比较与因果结论

- PE比较固定TTM、上一财年或预测口径；PB通常依赖对应净资产时点，不能与任意季度资产混用。quote的`pe_ratio`/`pb_ratio`不是筛选表达式字段；筛选沪深常见`PE_TTM`，港美常见`PeTTM`。
- 低PE、低PB、高股息不等于低风险；亏损、周期高点、一次性损益、净资产质量都可能影响解释。仅在用户要求解释或已出现具体冲突时补证，不将这些因素全部变成必查清单。
- 用户明确“PE<10”时不静默加“PE>0”；若负PE会影响意图，明确处理假设。必要项缺失时，按用户要求剔除或标记，不补0后误选。
- ROE高且PB高可以作为估值与盈利能力相符的证据，但不能从两家公司一次截面推出“ROE完全解释PB溢价”。本地重算的PE/PB只作解释，不覆盖原始端点值。
- 比较先统一日期、报告期、币种和指标定义，再排序。差异＝A−B、比值＝A/B、相对溢价＝A/B−1，分母和方向写清；B≤0时通常不能按正值比率解释“溢价”。

### 4.7 分红、REIT分派、回购与持股

- 自然年“已实施分红”按实际实施/支付日期纳入，不能按报告所属年或公告发布日分组；方案、董事会提议、已宣告但未实施与已支付分开。中期与年度不是同一长度期间，需注明可比性。
- 每10股/每10份金额先除10；拆并股及份额变化时，历史每份金额也要转换到可比份额基础。用户要现金总额时不能只给每份值，反之亦然。
- 历史现金分派率约定`窗口内每份实际现金分派合计/目标日每份原始价格`；不是总回报，不保证未来分派。与服务端股息率TTM有口径差异时并列解释，不强行调到相等。
- 虚构样例：两笔每10份派0.6和0.4，合计每份0.10；价格2.00，对应分派率5%。同一份原始数据足够计算就不反复查审计报告寻找一致百分比。
- 总市值、流通市值、基金资产净值、基金份额、成交额是不同概念。分派总金额÷市值只在分子覆盖的份额与分母份额完全匹配时才可与每份法对应，不能混用总份额/流通份额。
- 回购的“本次金额”与“本轮累计金额”不同；不能把每天公布的累计数再相加。回购股数、金额、均价、实施日与披露日分别保存。没有回购记录的日期不自动等于接口出错。
- 持仓权重、机构持有比例、股东数量、持股数量与金额分开；多时点权重不能直接相加。持股市值变化含价格因素，不等于现金净买入。

### 4.8 资金流、市场广度与筛选范围

| 要回答的问题 | 正确指标/操作 | 不能替代 |
|---|---|---|
| 主力净流入是否持续 | 目标日逐日`MainNetFlow`等明确净额字段，缺日单列；按同口径核对超大单与大单关系 | 成交额大、委比高、单日上涨都不是持续净流入 |
| 主力与订单分类 | 来源定义主力=超大单+大单时再做加总；元→亿元后比较方向 | 不同来源的大单分类阈值不保证一致；中小单不称北向资金 |
| 北向连续5日流入 | 可逐日验证的北向净流量，每日>0并且5个目标交易日完整 | `MainNetFlow5D>0`、活跃成交榜、上榜次数、季度持仓均不等价 |
| 流入占流通市值 | 同币种净流入金额/对应日流通市值，写明单日或累计窗口 | 用总市值替流通市值，或把百分数字段再次除以金额 |
| 板块上涨广度 | 指定日完整或明确样本的成份，统计上涨/下跌/平盘及有效样本分母 | Top5领涨股不能证明板块普涨；当前成份不当历史成份 |
| 多标签/多条件 | 数值AND用intersect、OR用union；多标签并查须自己明确求交和截断范围 | 分别返回两个池不代表服务端已交集 |
| 排名和阈值 | 排序字段、方向、门槛、样本范围分别确定；并列按用户指定规则 | `--limit 10`不是阈值10，也不代表全量 |

**常用参数边界直接记住**：condition没有`--offset`；notice列表是offset而非page；event窗口在类型中，不套date/start/end；固定北向活跃Top20不套limit/offset/排序/范围参数；within-label/strategy/event互斥且不同于universe。逐日数据不可得时，直接说明该必要条件不能验证，不用相近资金指标绕过。

排行类型与门槛字段也不同：`CompScore`对应`--min-CompScore`；`cap_main_net`对应`--min-MainNetIn`；`cap_main_5d`对应`--min-MainSum5d`；`margin_chg_d`对应`--min-MChgD`。不用命令类型名字机械拼参数；未在本节覆盖的映射可直接打开第7节所列排行字段表。

### 4.9 ETF比较：费率、净值、持仓、跟踪与流动性

- `profile`重点是费率/档案/经理；`overview`可能含`maxDrawdown1Y`、`chgPctYtd`、规模及溢折率；`holdings`可能是申赎清单或重仓变化；`nav`为净值序列。每条字段先确认含义，不把“持仓”默认成某季完整资产配置。
- 文档描述`nav`缺`EtfNav`时可能回退`ClosePrice`；因此不能只凭字段名nav认定是正式净值。缺少原始净值证据则保留疑问，不用价格替代算基金净值回报或回撤。
- 管理费、托管费、服务费先统一为年费率。0.15%+0.05%=0.20%/年，不包括佣金、冲击、价差和申赎成本；净值收益通常已扣基金层面费用，不再重复扣一遍。费用生效日也要匹配历史任务。
- 溢折率本地约定`场内价格/同日每份净值−1`；正为溢价。盘中价格与前一日净值不同步时降低结论置信度；不能将持仓PE高低称为场内溢价。
- 净值区间收益、累计净值收益和分红再投资总回报不同，比较多只基金必须统一算法、起止日与分红处理。份额×单位净值与资产净值作核对时，注意份额时点、量纲和披露口径。
- **跟踪差异**：在同一窗口、同类回报序列上定义基金累计回报减基准累计回报。**跟踪误差**：常用同频主动收益`e_t=r_f,t−r_b,t`的样本标准差乘`√N`年化，N为明确的一年同频观测数；不是跟踪差异绝对值，也不是基金自身波动率。样本不足、缺基准或时间不齐则不能重算。
- 买卖价差、成交额、深度、份额和跟踪误差可能互相矛盾，按维度给出主选/备选理由；综合打分只有用户需要时才做，说明权重、方向和归一化，缺指标不能假设最优。

### 4.10 期货基差、到期与年化（本地计算，不代表CLI新增能力）

首先确认**实际合约**与标的、交易所、合约月份、到期/最后交易日、币种、报价单位和乘数；主连/主力不等于某月可交割合约。当月合约在目标日已到期时，说明事实并按用户约定选择，不能静默换成下一月。

| 指标 | 明确约定后再算 | 条件与限制 |
|---|---|---|
| 基差B | 用户未给符号约定时先声明`B=F−S`，F为期货、S为现货 | 该约定下正为期货升水；若题目定义S−F，全部方向跟随题目 |
| 基差率b | `b=(F−S)/S` | S>0、同一时点与报价单位；不能换成F作分母而不说明 |
| 到期天数d | 目标日期至确认到期日的自然日差或用户指定计息日法 | d≤0不能做剩余期限年化；不以工作日代自然日 |
| 简单年化 | `b*D/d`，D为显式约定365或360 | 是剩余基差的机械外推，不是未来收益预测；临近到期放大误差 |
| 复合年化 | 仅在用户需要且`1+b>0`时用`(1+b)^(D/d)−1` | 与简单年化分开报告，不暗中替换 |
| 每手金额差 | 在点位报价且乘数有效时`B*合约乘数` | 不是保证金收益率或已实现盈亏 |

虚构样例：F=4020、S=4000、d=30、D=365，B=20点、b=0.5%、简单年化≈6.0833%。资金成本、分红、融券、手续费、滑点、保证金和交易时点都会影响可执行性，不能把升贴水直接称为无风险套利。

现有文档主要列外盘与港股股指期货，不能据此保证某个境内股指或历史合约已覆盖。资料查询可使用已识别合约的`westock futures detail fuGC`一类入口；示例合约不是用户合约。`fu*`/`r_hd*`、`hf_*`通道能力有差别，部分hf仅行情、不提供K线；缺历史价格或真实到期日时明确不能完成对应计算，不猜日期/合约。

### 4.11 期权比较：先确认链能力，再比较同一组报价

**覆盖证据**：v6评估所用CLI曾对`westock option --help`和`westock options --help`返回unknown command，这只能说明当次环境没有这两个入口，不能推断所有版本永远不支持期权。当前帮助有明确入口再使用；没有期权链/历史能力证据时，不枚举近似命令名、不把正股行情当期权价格，定向公开补缺后仍缺即说明无法验证。

- 平值选择在同一标的、到期日、乘数及调整类型下最小化`abs(K−S)`，K为行权价、S为同期正股价格。等距并列给出两档或明确规则；Call和Put比较用同一K与到期日。
- 虚构例：S=308.632时，307.5距现价1.132，310距现价1.368；单按最近行权价应选307.5，不能因整数习惯选310。若市场采用其他平值定义需明确。
- 买价Bid、卖价Ask、最新成交Last分别标注；Last可能陈旧，不能代替可交易价差。有效报价需`Ask>=Bid>=0`且Ask>0，否则标异常/不可比。
- 绝对价差=`Ask−Bid`；若用户未规定价差率分母，明确采用中间价`mid=(Ask+Bid)/2`，相对价差=`(Ask−Bid)/mid`，mid>0。若题目指定Last或Ask作分母按其要求，不能混口径。
- 虚构例Bid=2.0、Ask=2.2，价差0.2、mid=2.1、mid口径价差率≈9.5238%。成交量是窗口流量，未平仓量是存量；价差小、成交多、OI大分别说明，不单凭一项决定“更易成交”。
- IV是按某模型从报价反解的隐含波动率，缺期权链、标的价、到期时间及模型输入就不能自行“补算一个IV”。不同报价时点、币种或合约调整不可混合比较。

### 4.12 外汇交叉汇率、债券与事件窗口

- 报价`A/B`先写清“1单位A兑换多少B”；例如EUR/USD与USD/CNY相乘得到EUR/CNY。相反方向需要取倒数，Bid/Ask也需交换：倒数Bid=1/原Ask、倒数Ask=1/原Bid，不能只倒数一个中间价声称可套利。
- 比较直接与交叉报价，先定义偏差方向；若要求“交叉−直接”，就是`cross−direct`，相对偏差通常依题目指定分母计算，带符号值和绝对偏差分别列出。不能一处用直接价、一处用交叉价作分母。
- 同步日期/时区、在岸CNY/离岸CNH、即期/远期、Bid/Ask/Mid与手续费都需一致；不一致时仅作有边界的比较，不输出无风险套利结论。
- 债券净价与全价区分：同一单位下全价=净价+应计利息；每百元面值报价不等于每张现金金额。票息、到期收益率、当期收益率不同；赎回/回售/转换条款优先核对真实合约和日期。
- 可转债转股溢价、纯债溢价、回售触发条件不是普通股票PE；文档中的`bond_*`是特定资产字段，普通股票缺字段不补0。
- 事件分析区分披露日、实施日、交易日。若研究公告反应，盘后披露通常下一交易日才可交易；收益基准和窗口由用户或明确约定决定，不把“下一个交易日涨跌幅”自动当整个事件收益。
- 宏观指标所属期、公布日、实际值/前值/预测值分开；修订后的前值不一定是当时值。指数点位、扩散指数和百分比不是同一种度量。只用当前任务需要的指标，不默认做宏观全景扩查。

### 4.13 JSON解析与把金融公式写入Excel

`--raw`随命令、批量和模式改变；先确认顶层类型和少量键名，**不根据上一次返回猜这一次结构**。

| 实际形状 | 处理方法 |
|---|---|
| `[{字段:值}, ...]` | 直接记录列表；单代码可按请求绑定，多标的缺代码不得按顺序补代码 |
| `{data:[{data:{code:0,data:{证券代码:[记录]}}}], ...}` | 检查每层业务状态；按代码映射展开并保留代码，不按外层data长度算证券数 |
| `{Data:[{Symbol:代码,Data:{nodes:[记录]}}], ...}` | 按Symbol展开K线；保留每条日期及原字段，验证代码与区间覆盖 |
| 错误对象、空集合、未知结构 | 分别处理失败、待解释的空结果、结构未知，不都变成成功空列表 |

完整可复用解析代码在[parsing.md](references/parsing.md)，直接读此文件即可，不需先读索引。解析失败检查已保存的stdout，不重取数据；数值型代码、多证券缺归属、冲突代码应拒绝猜测。CLI退出0可能业务失败，成功请求数1可能只代表一次API调用；批量请求60只实际只回1只，仍缺59只。

| 错误/需求 | 先查实现问题 | 不要误修 |
|---|---|---|
| 数字参与计算变`#VALUE!` | 输入是否是“10亿元”“5%”文本；引用是否偏到表头；日期是否是真实日期值 | 不通过换金融分母、补0消掉错误 |
| `#NAME?` | 函数名、未定义名称、中文/特殊字符表名引用；跨表使用`='输入数据'!B2`这样的合法引用 | `'输入数据'!B2`没有开头等号时只是文本，不是公式 |
| `#REF!` | 被删除行/列/工作表、移动后引用失效 | 不重复查询Westock来修文件地址 |
| `#DIV/0!` | 分母为0、缺失、错误类型或日期差d=0 | 不用`IFERROR(...,0)`把未知分母变成有效零收益 |
| 百分比放大100倍 | 数值5需转0.05再用百分比显示；已是0.05就不再除100 | 金融值与显示格式分开，显示正确不保证值正确 |
| 日期差/年化 | 起止日期是日期类型；明确日计数和D；到期<=估值日停止计算 | 文本日期相减、用字符串日期长度或整数年月日相减 |
| 重算后仍旧缓存 | 检查实际生成文件、工作表、关键公式与重算引擎支持；`openpyxl`写公式不负责计算 | 不将`data_only=True`读到的旧缓存/None当新计算结果 |

先用同一组输入作一条本地算术自检，再映射到单元格；它是检查，不替代用户要求的可编辑公式。分别定位金融定义、输入值、公式字符串、引用地址、数值格式和缓存。只修核心错误，不能为了“零报错”删除必要公式、伪造缓存或把所有结果硬编码成正确样例。

### 4.14 六类任务的最小金融核验

| 任务 | 足够回答前必须核对 | 不应再扩展的内容 |
|---|---|---|
| 银行利润/估值比较 | 指定行情日、四个报告期与同比基期、同一ROE字段、币种和市值单位；公式输入是数字 | 不默认补所有年份balance和资本分析；已有记录只复用 |
| 苹果等期权比较 | 正确标的、同日链、真实到期日、最近行权价、有效Bid/Ask、价差率分母 | CLI无入口就停止猜名；不能用其他到期链或当日最新数据填历史缺口 |
| 股指期货基差 | 真实月份合约与到期、F/S同期价格、符号与分母、d>0、乘数 | 主力合约不能自动代当月；缺输入不能假造年化 |
| 高股息＋回撤筛选 | 股息率与负债率单位、历史窗口完整、回撤正负约定、前置池是否全量 | 不用一年跌幅代MDD，不无限扩大候选池 |
| 港股筛选 | PeTTM/股息率/市值字段、币种倍率、准确不等式、排序和缺失剔除 | 不盲目对全部候选拉三表，不以最新值替历史截面 |
| ETF工具比较 | 同期费率、规模、成交/价差、真实净值、基准/跟踪口径、缺失与权重 | 不把净值回报再扣一次年费，不为可选外观拖延交付 |

本节足够解决常见定义和口径选择；字段缺失、数据错误或文件引擎不支持时，仍应明确边界。更多知识不等于要求更多调用，原先的停止规则继续有效。

## 5. 缺口处理：停止该分支，不无限换源

| 情况 | 动作 |
|---|---|
| 参数错误或解析错误 | 依据目标帮助/已保存JSON修正一次；仍失败，标记失败原因 |
| 接口错误、限频、权限或覆盖不足 | 保留成功部分；可恢复故障有限重试，否则仅用 `web_search` 补必要公开信息 |
| 字段/日期/资产能力明确不支持 | 不继续猜命令；说明缺口，必要时一次定向公开来源检索 |
| 正常无匹配、尚未披露或明确无记录 | 如实回答；不放宽条件、不换市场凑结果，不将其当成接口故障 |
| 空值含义不明、批量缺标的或名单截断 | 最多一次覆盖核查；仍未知则保留未知，不声称完整或零值 |
| 全市场筛选缺核心能力 | 说明无法确认完整名单；最多核验已有候选，不爬取全市场重建筛选器 |

公开补检只取可靠原文，核对日期与单位；检索摘要只作线索。仍不可核验就结束该缺口分支。新闻不可用也不回退CLI新闻。不得绕过登录/付费/权限、不直连私有接口、不从训练记忆补数。补充项标记实际来源，不冒充Westock。

## 6. 回答与交付

- **文本**：先回答问题，再给必要数值/候选表、日期、单位、来源和限制。无需固定长报告；来源放在相应事实附近。正常空结果也是完整答复。
- **文件**：采用简单且满足要求的结构，尽早写入已获取数据；只做可打开性、关键数据与公式检查。必要校验通过后立即交付，不为美化/清理耗尽预算；按运行环境的附件机制确认导出。仅在沙盒保存路径不等于用户收到文件。
- **部分完成**：分别说明已完成、缺失原因和对结论的影响；未经验证的公式或损坏文件不可作为正确成果。用户明确要文件而未完成时，文本说明只是降级，不宣称完成原文件要求。
- 区分原始数据、计算值、分析判断；相关性不写成已证实因果。来源注明腾讯自选股与实际原始来源，网页数据标实际发布方、日期和链接。
