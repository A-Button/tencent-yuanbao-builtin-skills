# 训练 SOP：计划、完成、调整、要领与身体记录

调用方式和统一成功条件见 SKILL.md。本篇只规定训练与身体记录的判断、单次调用和主对话卡行为。

## 1. 固定判断规则

`workout_readiness` 记录当天疲劳（1–5）和酸痛，并按固定规则返回建议：

- 疲劳 >= 4 → `rest`（今日休息）
- 疲劳 == 3，或有中度及以上酸痛 → `reduced`（减量训练）
- 其余 → `normal`（正常训练）

轻微酸痛只记录，不降档。`normal` / `reduced` / `rest` 只能照抄工具回执，不自行判断或作为参数传入。同一天重复记录会覆盖。

统一成功判断：命令退出状态为 0 且业务 JSON 为 `"ok": true`。失败按「真实原因 + 下一步」回复；成功写操作通常 1 句，查询 1–3 句。问训练时不要出饮食卡：禁止调用 `diet_record`、`diet_estimate`、`diet_day`。这三个工具一调就会出饮食卡。训练只用本篇的 `workout_*` 和身体记录工具。

## 2. 可直接执行的 SOP

### SOP A：查看今日训练

1. **触发**：「今天练什么」「练到哪了」「完整训练清单」。
2. **必要判断**：确定查询日期；不根据旧卡猜状态。
3. **单次调用**：`workout_today`。
4. **成功判断**：统一条件；`today.session` 为 `null` 是成功的无训练状态。
5. **回复**：正文 1–3 句。用户要求完整清单时，以回执 `today.session.exercises` 为准完整列出。不出饮食卡，不要再调 `diet_day`。

### SOP B：疲劳评估

1. **触发**：用户描述当天疲劳或酸痛并要训练建议。
2. **必要判断**：疲劳必须明确为 1–5；酸痛有部位时可带程度，不给程度按轻微。
3. **单次调用**：`workout_readiness`。
4. **成功判断**：统一条件并读取回执 `advice`。
5. **回复**：用 1 句照抄建议，不自行升降档，不出卡。

### SOP C：新建训练 / 加练

1. **触发**：「今天排一场」「再加一个动作」「晚点加练」。
2. **必要判断**：动作必须来自资料库。当天无训练时给 `plan_name`、`cycle_index`、`cycle_size`；已有训练时只追加动作。组数、次数、负重未给则用资料默认值。
3. **单次调用**：`workout_plan`。
4. **成功判断**：统一条件。加练接在末尾，不改既有动作或计划名；已结束的训练加练后会重新打开。一场最多 20 个动作。
5. **回复**：通常 1 句确认，不出卡。

### SOP D：完成整场

1. **触发**：用户说 `今天的训练全部完成了，帮我记上`，或明确说今天整场和全部动作都完成。
2. **必要判断**：这句话已经是整场完成，不追问具体动作。
3. **单次调用**：`workout_finish`。
4. **成功判断**：统一条件，并确认 `session_done=true`、`done_count=total_count`；工具会把该场所有动作 `done` 置为 1，并把 session.status 置为 `done`，重复调用幂等。
5. **回复**：1 句确认，不出卡。当天无训练时按工具失败如实说明并提示先排训练，不得假装完成。

### SOP E：完成指定动作

1. **触发**：用户自然语言点名一个或多个动作，如「练完了臀桥、硬拉」或「第 1、3 个做完了」。
2. **必要判断**：提取 `names` 或 `positions`；名字或序号不清时先问，不猜。只有笼统说「练完了」、又不是「今天的训练全部完成了，帮我记上」时，询问是整场还是哪些动作。`positions` 从 1 数，按当天排期顺序。
3. **单次调用**：`workout_done`。
4. **成功判断**：统一条件；只标记点名动作，全部完成时工具自动收场，重复标记安全。
5. **回复**：只记点名的动作，成功后只回 1 句，不出卡。`今天的训练全部完成了，帮我记上` 不走这里，走 SOP D。

### SOP F：调整动作

1. **触发**：修改某动作组数、次数或负重。Now「改计划」上屏的是「我想调整今天的训练计划」，这句话还没说改哪一项，先问清楚再调用，不要当成练完。
2. **必要判断**：按动作名或第几个定位；至少明确一个修改字段。`load_text` 为空字符串表示徒手。
3. **单次调用**：`workout_adjust`。
4. **成功判断**：统一条件，只改传入字段。
5. **回复**：通常 1 句确认改动，不出卡。

加动作不属于调整字段，按 SOP C 调 `workout_plan`。

### SOP G：查看动作要领

1. **触发**：用户直接用自然语言点名动作或序号询问要领；卡片不再提供依赖选中状态的「查要领」按钮。
2. **必要判断**：优先使用今天清单中的 `position` / `name`，也可直接使用资料库 `exercise_key`。找不到或有歧义时询问，不拿相近动作替代。
3. **单次调用**：`workout_detail`。
4. **成功判断**：统一条件。
5. **回复**：查询 1–3 句，保留必要动作安全提醒，不出卡。

### SOP H：身体记录

1. **触发**：记录体重、腰围、臀围或大腿围，或查询趋势/档案。
2. **必要判断**：写记录至少有一项数值；档案只含性别、身高、年龄和活动量，体重必须走每日记录。
3. **单次调用**：写入用 `body_log`；趋势用 `body_trend`；查看/设置档案用 `body_profile` / `body_profile_set`；消耗用 `body_expenditure`。
4. **成功判断**：统一条件。缺档案或体重时基础代谢为 `null`，不以 0 或估值代替；无训练时训练消耗为 0。
5. **回复**：写操作通常 1 句，查询 1–3 句，并保留数据缺失说明。不出卡。

## 3. 动作定位

动作相关工具按动作名或第几个定位，不用先查 id：

- `workout_done {"names":["臀桥","硬拉"]}` 或 `{"positions":[1,3]}`
- `workout_adjust {"position":2,"sets":4}`
- `workout_detail {"position":1}`，也可给 `name` 或 `exercise_key`

`position` 从 1 数，按当天完整排期顺序。找不到名字、序号越界或名称有歧义时，工具会附当天清单；照回执修正一次，不做部分写入。

## 4. 主对话不再出训练卡

训练的增删改查都只在正文里说明。用户说「今天的训练全部完成了，帮我记上」时直接 `workout_finish`，不追问具体动作。Now 里的训练提醒仍按 reminders.md 发，那不是这张对话卡。
