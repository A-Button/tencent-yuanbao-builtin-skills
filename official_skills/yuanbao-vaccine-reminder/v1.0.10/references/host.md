# 疫苗字段映射

在进入具体孩子的个性化规划、查找已有档案，或用户授权保存、提醒、发布卡片时读取；查找不构成写入授权。

## 责任边界

- 先加载宿主 `make-things` Skill。Thing、Todo、Trigger 和 Now 的工具选择、实际 Schema、创建顺序、读回、重试、幂等与生命周期均由它负责。
- 本 Skill 只提供疫苗领域的字段含义、日期来源、授权范围和对象间的一致性要求；不要复制 `make-things` 的通用流程，也不要把下文的逻辑名称直接当作工具参数。
- 始终以当次加载的 `make-things` 指令、Schema 和真实回包为准，不依赖历史版本或本地快照。
- 无法加载 `make-things` 或缺少所需能力时，如实报告未创建；不得改用本地文件、临时脚本、无日期 Todo 或虚构数据库。

## 业务对象

| 对象 | 疫苗业务应提供 | 不应写入 |
|---|---|---|
| Thing | 孩子姓名或用户选定的稳定称呼、精简接种台账、来源／核对状态、最近有效安排、提醒偏好、关键待核对项 | 原图、证件号、完整住址／电话、批号汇总、工具日志 |
| Todo | 同次就诊的疫苗、行动日期／时段、日期来源、预约状态、必要准备 | 历史接种记录、无日期的档案索引 |
| Trigger | 提醒目的、用户选择的时间或节奏、时区、日期来源、最新事项关联 | 完整病史、把参考日写成预约成功 |
| Now | 一个孩子、一次就诊；称呼／阶段、接种日期、机构、疫苗及剂次（卡面不含时段），默认无按钮 | 未授权健康详情、示例 ID、虚假的预约或送达状态 |

## 写入门槛

- 提到孩子或上传材料不等于同意保存；“记下来”才保存，“提醒我”才创建通知。
- “帮这个孩子长期维护／做一份持续更新的规划”等明确持续管理请求，可视为创建或更新该孩子疫苗 Thing 的授权；普通咨询、“看看下一针”或单纯上传仍不是写入授权。
- 创建 Todo 或 Trigger 前必须明确：哪个孩子、同次就诊包含哪些疫苗、行动日期／时间、日期来源、预约状态和提醒节奏。
- 程序年龄窗、通知单参考日或模型推算不是个人预约。没有具体日期时可把“待安排”保存到 Thing，但不创建带日期的 Todo 或 Trigger。
- 一次指令只修改用户明确要求的对象，不自动增加其他疫苗、日期、随访或提醒。

## 查找或新建 Thing

- 一个孩子跨多次对话、材料整理和接种规划共用一个疫苗 Thing，不按疫苗、计划或会话另建 Thing。
- 保存或长期维护前必须有孩子姓名或用户选定的稳定称呼。优先使用用户明确提供的称呼；若只在疫苗本上识别到，写入前回显一次；缺失或模糊时只追问“这位孩子怎么称呼？”。
- Thing 标题应包含姓名／称呼，例如“小院儿的疫苗规划”；可读内容首部同样明确“孩子：小院儿”。实际字段仍以当次 `make-things` Schema 为准，不自造参数。
- 进入具体孩子的个性化规划或准备写入前，先让 `make-things` 按“孩子姓名／称呼＋疫苗主题”查找候选，再读取唯一候选的最新内容；不要只凭本轮会话假设不存在。
- 唯一命中时，在该 Thing 上去重、追加或修正；确认无匹配且已经获得保存或长期维护授权时，才创建新的疫苗 Thing。
- 查询失败、结果未知或出现多个可能属于同一孩子的候选时，不以“可能没有”为由新建。先按 `make-things` 能提供的信息消歧；仍不能唯一确认时，只向用户询问一个必要的区分信息。
- 不能只凭相同小名合并两个孩子，也不能因为昵称变化就直接新建。只使用当前会话中用户已提供、且对区分孩子确有必要的信息；不索取证件号等敏感标识。

## 疫苗业务一致性

- 写入最新台账时去重、追加或修正，不用本轮局部结果覆盖其他已确认记录。
- 同次就诊的多个疫苗合并为一个 Todo，预约提醒和当天提醒也按该次就诊合并。
- 默认可建议 D-7 预约和当天接种两次提醒；用户指定的节奏优先。已预约时跳过预约提醒，D-7 已过期时不创建过去规则。
- 改期、暂停、恢复、取消或完成时操作已有对象；通用生命周期由 `make-things` 处理。没有新日期时旧日期不再作为有效计划。
- Thing 容量不足时，明确说明哪些已保存、哪些仅在当前会话，并把未保存明细交还用户留存。

## 提醒计算与回调

确认日期和授权后，用固定脚本计算；不通读源码或临时重写日期逻辑：

```bash
python3 /data/skills/yuanbao-vaccine-reminder/scripts/plan_vaccine_reminders.py --input /data/workspace/VACCINE-REMINDERS.json
```

输入为 `{"authorized":true,"timezone":"Asia/Shanghai","visits":[{"visit_id":"稳定就诊键","date":"YYYY-MM-DD","date_confirmed":true,"date_source":"user_selected","appointment_status":"unknown"}]}`。
`date_source` 仅接受 `user_selected / doctor_arrangement / confirmed_booking`；确认来源必须真实，不能把用户跳过或参考日期填成确认。`appointment_status` 为 `booked / not_booked / unknown`。
默认 D-7 与 D0 的 08:00 要在设置时回显；用户指定时间／节奏时，在该 visit 内传 `reminders:[{"purpose":"vaccination","days_before":1,"time":"09:00"}]`，整个列表覆盖默认，不再暗加提醒。`purpose` 为 `booking / vaccination`，提前天数为非负整数。

输出只是一份本地计算结果，不是已保存或已启用。将有效 `reminders` 和固定 `callback` 语义交给 make-things，并以真实 Thing/Todo 关联适配宿主参数；不把 `visit_id` 冒充服务器已创建的对象。`skipped` 中的已预约或过期原因必须在结果中简短说明。当前时刻已过 D-7 的具体时间就跳过，不擅自改为同日稍后。

回调先加载本 Skill 主文件及本字段映射，再加载 make-things，重读最新事项、核对日期和有效绑定、检查事件去重，然后才决定调用 show_widget；出卡时按下方“提醒卡内容”重组最新信息，不照抄旧标题或旧会话长文案。定时回调发布成功只收口本次一次性提醒（用户提前预览不收口原提醒），不能把接种 Todo 标为 DONE；实际接种需另有事实确认。回调和卡片不能凭旧会话恢复已取消或已改期的安排。

## show_widget 时机

1. **首次设置结果**：授权范围内 Todo 已写入、提醒启用或停用结果已确认后，仅在当前会话用文字说明实际安排、后续提醒和跳过原因，不调用 show_widget；部分成功如实说明，未知先按宿主核对。
2. **提醒到点**：按上述回调检查后，D-7 尚需预约、D0 尚需接种时发布对应卡。同一就诊不同提醒时点是不同事件；同一事件重试去重。用户自定义节奏同样处理。
3. **提前预览**：用户明确要求现在发一张验证时，允许早于原触发时间发布，按主文件固定无图摘要卡模板展示真实接种日期。只检查安排仍有效，不要求原触发时点已到；不修改／停用／收口原 Trigger，不完成 Todo，也不以预览记录抑制后续定时事件。
4. **不发卡**：普通问答、图片刷新、重复读取、已经失效的旧提醒。后续改期只更新已有安排并在会话确认，不重新发一张“首次设置”卡；明确要求通知时再按宿主处理。

卡型、参数、事件标识及成功回执均以当次 make-things Schema 为准，不自造 wait 类型，不复制其他版本的 recommendation.id 或 now_id 字段。提醒卡简短、默认无按钮；工具缺失时说明未发布，不能把文本回复冒充 Now。

## 提醒卡内容

预览与到点共用[主文件的固定出卡格式](../SKILL.md#固定出卡格式预览与到点共用)：image_text、data={}；title 按称呼、绝对日期、完整疫苗剂次紧凑排列，summary 仅承载机构及必要院区，不附街道门牌。单疫苗标题目标28字符、摘要目标20字符，均为软预算，多疫苗优先列全且允许超过28字，按主文件手机文案预算计数和压缩；不是客户端精确字数上限。本场景无图、无底部按钮，省略 actions；不使用 todo_remind 或 recommend_list。

只读最新有效安排，不照抄旧 Todo 长标题；日期粒度和来源真实，预约提醒明确“预约”。正文不重复 source；源标签仍按宿主要求保留真实关联。卡面日期只写月日，同年省年份、跨年带年份；title 和 summary 均不写星期、上午／下午或具体时段。已确认接种时段保留在会话详情及原安排中，不修改 Todo／Trigger 时间；机构简称须已确认且无歧义，不能丢掉必要院区。多疫苗完整列出，长内容仍可能超出客户端两行标题／一行摘要的限制，不能靠字数估算声称展示已通过。

实际 show_widget 参数按主文件检查；事项归属失败不绕过。手机截图才用于验证可见换行／截断，工具成功只证明发布。

## 结果披露

- 分别报告档案保存、Todo 更新、Trigger 启用、Now 发布、卡片可见和通知送达，不把其中一个结果概括为全部成功。
- 只有当次 `make-things` 的真实回包或读回证据才能支持“已保存、已启用、已发布”。
- 结果未知时按 `make-things` 的查询与重试规则核对；仍无法确认就报告未知，不盲目重复创建。
- 对照计算结果核对每次就诊的有效提醒、跳过原因及实际写入／启用回包；全部有效提醒启用才称本次提醒设置完成。另行披露 Now 发布结果；不要宣称尚未到点的提醒已经送达。
