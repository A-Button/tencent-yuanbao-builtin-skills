# 交通查询与卡片展示

本 Skill 负责把交通查询结果交付给用户。产品航班和国内火车票来自 `tongcheng-travel-search`；航班运行动态来自网页检索到的飞常准页面；卡片由已发布的 `make-things v1.2` 的 `show_widget` 发布。三者用途不同，不能用同程的航班产品搜索结果证明延误、取消、登机口或实际起降。

## 查询

1. 分清用户要查的是航班／火车票产品，还是某个航班的运行动态。两种都要时分别取数，并标明各字段的来源。日期使用航班或车次的**当地服务日期**；“今天”“明天”按出发地当地时区解析，不把跨午夜延误改成另一天的航班。
2. 查航班、国内火车票时，加载实际发布的 `tongcheng-travel-search`，按它的 `SKILL.md` 和对应的 `references/flight-search.md` 或 `references/train-search.md` 选择工具与入参。标准航班列表用 `tongcheng-travel-search/flight_search`；标准国内铁路列表用 `tongcheng-travel-search/train_search`。往返分去程、返程查询。用户选定航班后，详情和国际航班验价遵循同程 Skill 的顺序与真实产品标识；火车票没有详情或验价能力。长尾、主观筛选仅在同程 Skill 规定的适用场景使用 `tongcheng-travel-search/ai_search`。工具名或 Schema 与已发布包不符时停止该查询，不猜名称或字段。
3. 查航班动态时，确认航班号、服务日期、出发和到达机场；共享航班还要核对实际执飞航段。使用运行时可用的 `web_search`（或等效网页搜索工具）检索 `飞常准 航班号 日期 出发机场 到达机场 航班动态 site:variflight.com`，参数按实际工具 Schema 传递。核对结果的真实主机、日期、机场和航段；需要时打开本次结果链接核实原页面。不猜详情 URL，不绕过登录或验证码。只把已核实的飞常准自有页面当作动态证据，不采用新闻、历史准点率、固定时刻表、下载引导页或其他网站的摘要冒充本次状态。
4. 航班动态区分计划、预计、实际时刻和航站楼／登机口；字段缺失就标为未知。记录页面实际给出的更新时间、查询时间和原页面链接；查询时间不能冒充源更新时间。页面过期、互相矛盾或身份不清时说明无法核实，不推断航班正常、延误或取消。公开航班动态不等于用户已购票订单状态。

同程结果只展示真实返回的班次、时间、机场／车站、票价、余票等字段；搜索价不承诺最终可售，空结果不表示现实中没有班次。缺少必要且无法从上下文确定的航线、日期或航班身份时先补齐信息；铁路未指定日期时遵守同程 Skill 的未指定日期规则。

## 展示

取得可用且可归属本次查询的结果后，加载**实际发布的 `make-things v1.2`**，读取其 `references/show-widget.md`，按运行时 `show_widget` Schema 组织一张卡并调用一次。3–5 个真实候选可用 `recommend_list` 展示；候选少于 3 个或仅有一条航班动态时，用无图 `image_text` 摘要卡，`data={}`，详情放在会话中。标题和摘要让用户不点开也看得懂；同程数据标“同程旅行”，网页动态标“飞常准（网页检索）”，不同来源的字段不能混写成同一个来源。飞常准的实际页面链接、检索时间和更完整的字段放在会话详情中。

无图摘要卡设置 `source.label`、整卡 `tap={"type":1,"agent_chat":{}}`，并设置一个「看详情」按钮回到本会话。不要为了发卡搜图；卡片发布到 Now／「此刻」不等于系统 Push 送达。

卡片类型、`data`、点击目标和图片要求以 `make-things v1.2` 的发布协议为准；不要凭记忆套用其他版本的 `show_widget` 字段，也不为满足卡型编造图片、链接或班次。一次性查询只需展示卡片，不自动创建 Thing、Todo、Trigger 或监测规则。只有已存在且核对归属的真实事项才能填写 `thingId`／`todoId`。

仅在 `show_widget` 返回真实发布 ID 后说明卡片已展示。该调用不保证幂等；超时、回包缺失或结果未知时不自动重发，说明发布结果未确认。没有可信结果或当前环境缺少所需工具时，如实在会话说明已查到的事实与缺口，不发布伪结果卡，也不声称卡片已显示。
