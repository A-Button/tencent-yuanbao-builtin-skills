# 短工作流：必要数据到结果

仅复杂任务按需使用一条工作流；不是每次都必读。所有流程默认可直接文字/Markdown回答，**仅用户明确要求文件才增加文件创建与验证**。示例步骤不是必须达到的调用数，也不得省略用户真实需求。

## A. 两家公司财务与估值比较

1. 记录代码、报告期、同比基期、目标行情日和必要指标。不扩展为三大报表全面研究。
2. 代码未知才按目标市场解析一次；行情和所需报表无依赖可同轮查询。
3. 历史财报按合理区间取必要的income，核对EndDate；补同比基期在同一区间或同轮请求，不按多个年份/报表交替补查。确需资产指标才取balance。
4. 一次完成JSON结构识别、代码归属和单位/日期核对。累计/单季/TTM分开；披露ROE不自行拼算。
5. 计算指定同比、差值、排序；只核对会影响结论的冲突。不得为解释PB再启动完整杜邦分解、预测、研报及公告遍历。
6. 文本：比较表＋判断及依据＋缺口即结束。文件：用同一份数据生成最小比较模型，关键公式验证后导出；不重新请求已缓存数据。

完成标准：每个要求的指标有数据与口径，或明确列为无法核验；并给出用户要求的比较结论。未经支持不能声称缺口已经补齐。

## B. 基金/REIT收益与交易特征

1. 基金名按正确类型搜索，保留真实代码；不以管理人股票代替，不猜REIT专用子命令。
2. 目标日行情取得价格、市值、成交额；公告只找指定窗口实际分派所需的ID。必要ID保存一次，分页有新增ID且仍需覆盖时才继续。
3. 根据支付日期统计现金分派，统一每份单位，按用户定义公式计算。已能自行算分派率，不为找一个相同披露值反复翻审计报告。
4. 分别比较分派、规模、流动性；不默认补出租率、租期、估值预测或管理人历史。不将历史分派作未来保证。
5. 文本直接给表和结论；明确要文件再创建。缺分派记录或历史价格，保留缺口和影响，不静默用最新值。

## C. 全市场多条件筛选

1. 先查当前支持字段/市场/历史模式，确认所有必要条件可实现。合法条件一次组合，不能靠猜字段名试出能力。
2. 服务端已经返回条件值，优先直接使用；必要时一次核对日期和字段单位。支持的分页只用于用户要求的完整结果。
3. 需要本地回撤等计算时：只有前置池完整、历史序列覆盖和执行规模均可核验才继续；否则交付明确标注的有限样本或能力缺口，不冒充全量。
4. 行业分布、阈值敏感性只使用必要字段；行业未知可以归为未分类，不能因此为每只候选做全面研究。
5. 原始条件、样本范围、满足与未验证情况写入最终结果。没有匹配也直接回答，不通过更换市场或放宽门槛凑名单。

## D. 缺乏关键能力时

以“需要逐日核验的北向资金”为例：已有帮助/返回只有季度持仓、活跃交易额，且没有目标日频净流量，登记核心字段不可得。不要再用主力资金、5日总净额、上榜次数替换概念。用户已经允许“无法取得则说明”时，立即输出该说明及已有可核验部分。

公开补检只补必要原文信息，不试图通过搜索和全市场抓取重建同等覆盖。无法核验就停止。文本可说明局限；用户要求文件时可交付包含已核验数据和缺口说明的文件，但明确它未满足原完整名单要求。

## E. 事件后收益与多年财务验证

- 事件分析：已有股票池则不重新筛选；事件池的窗口必须匹配用户目标。按实际披露日、交易日历和用户要求的收益窗口计算。若用户未定义事件前后基准，明确采用的基准与理由，不固定套某个模板窗口。
- 多年ROE：不要用当前ROETTM先筛后宣称覆盖全市场连续多年达标。有限已知池可一次取足够财报，按财年、披露日和报表字段验证；缺少年度即未验证。
- 一次取回的日历、行情、公告、财报均复用；并行降低等待，不等于可无限扩大候选数或日期组数。

## F. 期货基差与期权流动性比较

1. 先确认输入存在：实际合约/到期日、同日标的与合约价格、乘数、报价单位及时间。入口不支持对应历史链时不猜命令；公开补缺仍不足则明确不能计算。
2. 基差先写符号F−S或用户定义；年化先确认日期差d>0和365/360日基准。期权则先固定到期日、K、标的S、Bid/Ask及mid分母，不把不同到期的Call和Put比较。
3. 用[入口金融口径](../SKILL.md#4-金融口径与数据处理速查直接使用不必先读参考)中的数值样例作公式级自检，再应用真实输入；样例不是市场数据，不写进用户结果当事实。
4. 解释收益/风险时标明理论比较，不把数据不同步或机械年化当无风险套利。只有用户需要文件才进入下一节，文字任务可到此直接答复。

## G. 金融公式映射到Excel后的错误定位

- 分清定义错误（方向、分母、单季/累计）、数据错误（日期、单位、缺失）和实现错误（文本数字、单元格引用、函数、缓存）。不要出现`#VALUE!`就重新查询全部Westock数据。
- 输入先数值化并保留原始单位；关键列固定字段→单元格映射。跨表公式写入字符串必须含等号，表名有空格/符号时正确引用；不能将单元格地址文字当输入值。
- 只拿一条已确认输入验证关键公式，全部通过后批量填充。出错时比较公式与实际引用单元格值，不盲目全局替换多个字符串使问题扩散。
- `openpyxl`不执行公式；确认实际输出文件经可用引擎重算，不能读取旧缓存假称新结果。引擎缺能力时报告限制，不伪造缓存，不用IFERROR补0掩盖必要指标未知。
- 剩余预算只做必要校验与导出，失败明确部分完成；不以数值正确的手写文本替代用户要求的可编辑公式，却声称任务全部完成。

## 收尾检查（两种交付形式共用）

- 是否回答了用户真正的问题，而不只是“已经收集数据”？
- 来源、日期、单位、原值/计算值和样本边界是否明确？
- 是否还有足够证据会改变核心结论的冲突？没有就不继续查。
- 文本任务：直接最终答复，不创建附件流程。
- 文件任务：必要检查后立即按环境附件机制交付；沙盒中有文件但未导出不能算已交付。不在预算末尾做可选美化、反复预览或清理。
