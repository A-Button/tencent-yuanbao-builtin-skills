# Word 文档插图与配图规范

> 思路对齐 PDF skill 的「可信度 vs 美观度」取图策略，适配 docx 的 `ImageRun`（新建）与 OOXML `w:drawing`（编辑）。

## 何时需要配图

| 场景 | 是否配图 | 说明 |
| --- | --- | --- |
| 报告 / 研报封面 | 建议 | 封面图或品牌区；正文图表另计 |
| 营销文案、产品宣传 | 建议 | 产品图、场景图增强转化 |
| 论文 / 实验报告 | 按需 | 实验装置、结果曲线；须图题编号 |
| 行业研报 | 建议 | 产业链示意图、数据图表 |
| 公文 / 请示 / 批复 | **原则上少图** | 除非用户附件含必须引用的图 |
| 简历 | 通常无图 | 除非用户明确要求头像 |
| 邮件 / 通知 | 通常无图 | 保持简洁 |

## 图片来源优先级

1. **用户附件中的图片**（最高优先级）：产品图、截图、logo——直接插入，不替换为「相似图」。
2. **用户明确提供的 URL / 路径**：下载或复制后插入，保留可追溯来源。
3. **可生成 / 可绘制时**：装饰性、示意图、信息图——文生图或简单图表；风格与文档一致。
4. **禁止**：凭空插入不可验证的「真实照片」（人物、产品、现场）冒充实拍；找不到可靠素材时**留白或用文字说明**，并在回复中告知用户。

与 PDF skill 对齐的取向：

| 取向 | 适用 | 策略 |
| --- | --- | --- |
| 可信度优先 | 工作报告、行业研究、财务分析、新闻科普、真实产品页 | 优先用户附件与可检索真实图；找不到则留白或克制图标 |
| 美观度优先 | 营销宣传、创意海报、画册型文档 | 可生成贴合版面的装饰图，但仍不得伪造具体真实产品/人物 |

## 插图落位

| 位置 | 用途 |
| --- | --- |
| 封面 / 扉页 | 主视觉、品牌、报告标题区 |
| 章节开头 | 可选章节导引图（不宜过大） |
| 表格 / 数据段落后 | 解释性配图、补充说明 |
| 正文居中 | 标准插图位，上下各留一空行 |
| 附录 | 大图、细节图、原始截图 |

同一插图**不要**在正文与附录重复插入（除非用户要求）。

## 版式硬规则

1. **居中**：插图段落 `jc center`（docx-js：`AlignmentType.CENTER`）。
2. **宽度不越界**：图片宽度 ≤ 正文区宽度（A4 默认内容区约 9026 DXA；留边距后常用 6000–8500 DXA）。
3. **图题编号**：正式报告使用「图1」「图2」… + 图题文字；论文体例可用「图 1-1」。
4. **图题字体**：与正文同族，可略小一号；图题在图下方居中。
5. **上下留白**：图前、图后各至少一段空行或等效段间距。
6. **不与正文重叠**：禁止浮动层压字；Word 内用 inline drawing，不用绝对定位叠在段落上。
7. **防分页切断**：长图尽量独占一段；必要时前插分页符。

## 实现路径

### 新建文档（docx-js）

```javascript
new Paragraph({
  alignment: AlignmentType.CENTER,
  children: [new ImageRun({
    type: "png",
    data: fs.readFileSync("product.png"),
    transformation: { width: 400, height: 300 },
    altText: { title: "产品图", description: "星野手冲套装", name: "fig1" }
  })]
}),
new Paragraph({
  alignment: AlignmentType.CENTER,
  children: [new TextRun({ text: "图1  星野手冲咖啡套装", size: 20 })]
})
```

### 编辑现有文档（OOXML）

1. 图片放入 `word/media/`；
2. 在 `word/_rels/document.xml.rels` 添加 image relationship；
3. 在 `[Content_Types].xml` 注册 MIME；
4. 在 `document.xml` 对应段落插入 `w:drawing`（见 SKILL.md「图片」一节）。

## 交付前检查

- 文档内至少 1 个 `word/media/*` 或 `w:drawing`（若任务要求配图）；
- 图题编号与正文引用一致（正文出现「如图1所示」则须有图1）；
- 用户附件中的图片未被 silently 丢弃或替换。
