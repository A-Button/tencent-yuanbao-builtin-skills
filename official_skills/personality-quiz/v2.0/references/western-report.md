# 西洋星盘分析

使用已核对的去身份化盘面。普通排盘先给简要结论再附盘面，明确只要盘面时不解释；只给太阳／月亮等标签的轻聊使用 [zodiac-personality.md](zodiac-personality.md)，不重排。

## 可用事实

新盘读取返回的 `analysis_charts.western`；报告使用流水线返回的去身份化数据。日期级只用 `chart.stable.planet_signs`；范围盘只用稳定行星与实际存在的 `chart.stable.ascendant.sign`。不挑候选、不推未知上升、度数或宫位。

深报只使用已确定的太阳、上升、月亮、水星和金星星座，信号路径为 `chart.planets.sun|moon|mercury|venus.sign` 各自展开后的真实路径、`chart.ascendant.sign`，或日期／范围盘的对应稳定路径。候选值、度数、相位、其他天体与宫位不进入现有深报 Schema。五项是可用范围，不是五个必写章节。

普通技术分析可使用完整分析盘中真实存在的 `chart.planets`、`chart.aspects`、`chart.houses`、`chart.ascendant`、`chart.zodiac` 与 `chart.coverage`。非空上升是可用事实；状态字段、页面太阳简述和四项短标签不是配置关系的证据。HTML 展示五项位置和轻量说明，不能代替模型的分析。

## 分析提纲

先用用户原话确定要回答的判断或取舍，再选择能支持该问题的配置。太阳可讨论表达与认同，月亮可讨论反应与照顾需要，水星可讨论思考沟通，金星可讨论偏好与关系表达；已计算的上升可补充初见与进入环境的方式。它们是文化象征主题，不是已验证人格因果。

解释链应是“已确定的配置 → 各自涉及的主题 → 放在一起时可能出现的配合或拉扯 → 用户所问情境中的可观察表现和条件”。例如关系问题可同时看月亮的照顾需要与金星的表达偏好，再看水星如何沟通；事业问题可把太阳的投入方式与水星的思路、已确定的上升对新环境的进入方式联系起来。例子只是选材方式，不能预设任何人的星座或结论。即使配置同向，也要说明它们在不同功能上的分工，不把它们等同；配置看似不同时，只称象征主题的张力，不伪称已计算相位。

普通排盘的聊天正文先给一条有依据的概括判断，再用相关配置之间的关系给出简要分析；这是默认解读。用户已有具体问题，就先直接回答其分歧、条件或范围，再给证据链，不转成泛泛人格简介；没有具体问题，则选最能说明整体特点的已确定配置，不逐项念标签。有两项相关稳定配置时，至少讲清一条关系，指出各自功能以及配合或张力；证据仅够一项时只解释一项，并说清组合判断所缺信息。模型正文与事实 HTML 在同一回复交付，不在附件之后再启动第二次解读。用户问“现在／何时”时，说明本命盘没有行运或阶段数据，仍可回答本命配置涉及的偏好与取舍。深报在多个主题间组织连续论证，不按五个天体分章，也不把主题 ID 当章节。

技术分析中的火星、相位等，只有确实相关且数据存在时才加入；同星座不等于合相，星座相对也不等于已计算的对冲。不要只从太阳写完整人格，也不要逐个天体背诵形容词。

有阶段／行运数据才能讲动态，当前本命盘没有该数据就不生成近期事件或日期。用户反馈调整解释，不回填盘面；信号缺失就缩小范围。普通概要不规定句数，专业词在有帮助时解释即可；共同表达和边界复用 [safety.md](safety.md)。精确出处按需查 [source-registry.md](source-registry.md)。
