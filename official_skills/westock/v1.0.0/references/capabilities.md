# 能力、时间和覆盖边界

本页区分已知能力、限制与需要核验的部分；不承诺CLI已修复。以实际帮助及响应判断当前版本，未知项一次核对后保留未知，不进行多轮猜测。

## 时间契约

| 数据 | 选择方式 | 必须检查 | 不能推断 |
|---|---|---|---|
| 指定日行情 | `westock quote`的date | 实际返回日、价格口径、复权、是否休市回退 | 所有附带字段都一定是当日历史快照 |
| 历史K线 | start/end、period | 最早/最晚日期、节点数、截断、缺失交易日、复权 | 成功状态意味着区间完整 |
| 财报最新N期 | `westock finance`的limit | 每条EndDate、InfoPublDate、报表类型 | “最新4期”就是用户历史截止日的4期 |
| 财报日期区间 | start/end，与limit互斥 | 区间实际筛选含义、EndDate、披露日 | 自动满足“截至当时已知”、无后续修订 |
| 公告/分派 | 公告时间、原文实施日 | 发布、登记、除权、实际支付日分别核对 | 报告期或公告日等于分红实施日 |
| 筛选/排行 | 该入口支持的date/窗口 | 当前字段是否历史快照、候选范围与截断 | 带date就支持所有字段历史回溯 |
| 事件池 | 类型内嵌窗口 | 对应时间区间 | 近期池是全年完整事件集合 |
| 宏观/行业数据 | 对应短名的date/year等 | 所属期、实际发布日期、修订情况 | 查询历史日期一定返回当时可见版本 |
| 成份/持仓/档案 | 对应命令实际支持方式 | 数据截至日、频率、历史覆盖 | 当前名单是历史名单；季度值是日频值 |

不要把“数据所属期已结束”和“当时已经披露”混为一谈。用户只规定财报期而非当时已知信息时，也应注明实际披露时点，避免自行把任务扩展为历史事件研究。历史能力不能确认时不凭相似最新值补齐。

## 资产与批量例外

- 搜索默认股票；ETF/LOF/REIT先按基金类型搜索。`etfDetail=仅行情`仅支持该覆盖下的行情，不保证ETF档案/持仓；REIT不是其管理公司股票。
- `westock search`和`westock minute`不支持多代码；不要统一向所有命令塞逗号代码。
- `westock kline`期货/外汇通道仅单代码，部分日期区间能力与股票不同，核对真实返回；不能静默用最新N条替代历史区间。
- 财报按市场分组，避免跨市场字段与币种混用；只查必要`--type`。即使响应显示success，也逐个检查请求代码与实际返回代码。
- `westock fund flow`须按市场及模式核对；沪深历史区间的单代码限制不能被最新快照批量能力覆盖。
- 北交所行情覆盖不意味着条件选股支持北交所；港美条件字段大小写不同。股票策略/标签/事件/排行与ETF模式不能互换。
- 宏观多短名以空格分隔，只合并相同日期模式；地区参数属于清单命令，不随意加到指标查询。

## 期货、期权与计算能力不要混为一谈

- 现有期货手册主要说明外盘及港股股指的搜索、合约资料和行情，不能推定任意境内月份合约或历史链已覆盖。主连不是固定月份；真实到期日必须有合约证据，不猜“每月某日”。
- v6评估已观察到CLI对`option`和`options`帮助请求均返回unknown command；这只是当次环境证据，不是所有版本永远无期权能力。当前入口未确认时，停止枚举近似命令名；有明确能力再用，没有则定向公开补缺并注明历史覆盖。
- 期权平值、价差率或期货基差可在输入齐备时本地计算；会公式不代表已经取得价格、到期日、波动率或权利金。公式不是新的服务端字段，不能据此声称查询完成。
- `overview`里出现最大回撤，不代表`screen condition`支持同名筛选表达式；字段查询能力、筛选能力、历史能力分别核对。
- 具体基差/年化、期权价差/平值、MDD和单位自检直接见[入口金融口径](../SKILL.md#4-金融口径与数据处理速查直接使用不必先读参考)。报价时点不齐、S≤0、d≤0、价差交叉或关键字段缺失，必须阻断相关计算，不能输出“可套利”。

## 已知易错的“不等价”

| 用户要求 | 不能替代为 | 正确处理 |
|---|---|---|
| 北向连续5日净流入 | 主力资金、活跃榜成交额、上榜次数、季度持仓 | 缺日频证据即说明无法确认，不重建替代池 |
| 连续多年ROE达标 | 当前ROETTM或最新报告ROE | 有限候选逐年验证；全市场历史筛选能力不明则说明 |
| 近一年最大回撤门槛 | 一年涨跌幅、波动率、52周高低点比 | 必要历史序列完整才能计算，并验证候选覆盖 |
| ETF现金分派或净值指标 | 股票分红入口、场内价格 | 使用支持该基金的公告/净值来源，缺失则保留缺口 |
| 板块历史普涨 | 当日Top5上涨样本 | 需要全体可核验成份的广度；否则只能说领涨/证据不足 |
| 指数完整成份 | 另一指数成份或ETF持仓 | 只可作为明确标注的替代样本，不补成目标完整名单 |
| 成交量与价格同时变化 | 确定因果 | 仅说明线索和限制，不直接下因果结论 |

## 返回完整性与错误

一次业务请求成功数不等于证券数量。JSON的`data`、`Data`、`nodes`、Symbol代码位置可能不同，按[解析分支](parsing.md)识别；不要递归寻找任意同名键。

- 核对requested与returned代码集合；缺标的标记partial，不按返回顺序补代码。
- 同时保留报错记录和成功记录；错误或空值不得补0。
- limit命中时怀疑截断；没有分页能力不发明offset。总数、覆盖或历史字段无法验证时不声称全量。
- 退出码0仍可能出现`service error`；退出码非0也可能留有可读的部分数据。不得因shell管道最后一个命令成功而判查询成功。
- 错误类别分别处理：参数/未知命令、解析结构、限频/服务故障、权限、明确无匹配、覆盖未知。不确定的空集合不是已证实的“全市场没有”。

## 预算与优先级

先回答必要项，再考虑增强项。即使查询成功，新增查询也需要一个尚未解决的必要问题。限制作用于每个缺口和整个任务，不能通过不断切换端点重置重试次数。

文字回答不需要安装解析环境、生成文件或加载文件技能；文件输出则必须为保存、核心验证和最终导出留出时间。具体收敛与降级遵循[入口规则](../SKILL.md)，低频示例不能覆盖这些规则。
