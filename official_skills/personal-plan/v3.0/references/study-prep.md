## 1. 场景和输入

适用于考试、证书、语言、课程和技能学习计划。用户只要求解一道题、解释知识或生成一次材料时，不使用本规则。

### 1.1 最小输入

| 字段 | 需要了解什么 | 可接受证据 |
|---|---|---|
| 目标 | 考试/学习对象及通过标准 | 分数、等级、证书、可完成任务、作品或实际能力 |
| 日期 | 考试日期或计划周期 | 官方日期、用户给定周期 |
| 当前基础 | 已学内容、最近表现、知识空白 | 成绩、测评、错题、用户自评 |
| 内容范围 | 要学哪些科目、模块或能力 | 官方考纲、课程目录、教材、项目要求 |
| 时间 | 工作日/周末可用时长和固定课程 | 用户日程 |
| 材料 | 已有教材、课程、题库和笔记 | 用户上传材料 |

信息不足时，优先选择以下四问：

1. 最终目标和通过标准是什么？
2. 截止日期是哪天？
3. 当前做到什么程度，或最明显的困难是什么？
4. 工作日和周末分别能投入多少时间？

不要假设系统拥有历史学习档案。只有用户提供成绩、错题或学习记录时，才依据这些数据诊断。

## 2. 学习诊断

先输出简短诊断，再排计划。

### 2.1 区分感受与证据

| 信息 | 处理方式 |
|---|---|
| “感觉数学很差” | 记为用户感受，不能直接决定全部时间 |
| 模拟卷代数正确率40% | 记为可量化弱项 |
| 从未学完某章节 | 记为范围缺口 |
| 做题慢但正确率高 | 记为速度问题，不等同知识缺口 |
| 错题重复出现 | 记为掌握不稳定，需要间隔重做 |

若用户感受和数据不一致，明确写出差异。例如：

> 用户认为词汇最弱；最近两套题显示主要失分来自长难句定位。计划先保留词汇复习，同时提高阅读定位训练优先级。

### 2.2 诊断维度

- **范围差距**：哪些内容尚未覆盖。
- **掌握差距**：哪些知识学过但不会应用。
- **速度差距**：是否能在考试时间内完成。
- **输出差距**：是否能写、讲、做或迁移，而不只是看懂。
- **稳定性差距**：是否会重复犯同类错误。

### 2.3 计划边界确认

学习计划在生成前要确认三个边界：

1. 用户真正要解决的是通过考试、提高分数、补单一弱项，还是完成一个可验证的学习成果；
2. 工作日、周末和固定课程分别占用多少时间；
3. 用户提供的成绩、错题和自评中，哪些是事实，哪些只是感受。

首版计划生成后，在当前会话内允许用户指出最难执行的部分。按原因调整：

| 原因 | 调整方式 |
|---|---|
| 时间太紧 | 缩减任务量，保留测试和纠错 |
| 任务太大 | 拆成更小的学习与输出任务 |
| 难度过高 | 增加前置知识或示例练习 |
| 时段不合适 | 与低认知负荷任务互换 |
| 资料太多 | 只保留一套主资料和一套验证资料 |

这是当前会话内的计划校准，不代表系统会长期记录执行情况或自动修改计划。

## 3. 目标与时间校验

1. 考试类目标核对考试日期、报名、考纲、科目和评分规则；优先官方来源。非考试型学习不机械套用这些字段。
2. 计算剩余天数、可用周数和总学习容量。
3. 默认按约80%的可用时间估算任务，保留缓冲；用户明确选择更高强度时，说明代价后在安全、可执行范围内调整。
4. 估算完成范围和必要练习所需时间，写清估算依据。
5. 若容量不足，优先给出：
   - 保住高分值和高提分空间内容；
   - 缩小资料和课程范围；
   - 降低目标分数或改为先通过；
   - 延长周期或增加有效投入。

以下情况必须预警：

- 用户计划时间显著超过其现实日程；
- 临近考试仍要求完整学习全部新内容；
- 只安排看课看书，没有练习和检测；
- 连续安排高负荷、没有睡眠和缓冲。

## 4. 内容优先级

对科目、模块或能力分别判断四项：

| 维度 | 评分含义 |
|---|---|
| 目标重要度 | 分值、必考程度或对最终目标/可观察能力的贡献 |
| 当前差距 | 当前表现距离完成标准有多远 |
| 提升空间 | 在剩余时间内能否明显改善 |
| 前置关系 | 是否是其他内容的基础 |

优先级原则：

1. 高重要度、高差距、可提升的内容优先。
2. 前置知识早于依赖它的综合任务。
3. 低分值且短期难以提升的内容可降级。
4. 不把时间平均分给所有科目。
5. 每周保留已掌握内容的少量维护，避免只补弱项导致优势退化。

## 5. 阶段模式

根据剩余时间选择模式，不机械套用固定30天：

| 距离考试 | 主要模式 | 内容比例与原则 |
|---|---|---|
| 15天以上 | 系统补齐 | 建立范围地图，补关键基础，开始专项练习 |
| 8—14天 | 强化整合 | 综合练习与弱项强化并行，减少低价值新内容 |
| 4—7天 | 冲刺提炼 | 核心考点、错题和计时训练为主，不大规模开新模块 |
| 1—3天 | 状态保持 | 熟悉题型、易错点和考试准备，减少高风险突击 |

非考试型学习可采用：

1. 基础建模：建立知识框架并完成最小输入。
2. 专项练习：围绕薄弱点进行输出。
3. 综合应用：完成项目、模拟任务或完整测试。
4. 验收巩固：用可观察结果验证目标。

常见计划类型：

| 类型 | 重点 |
|---|---|
| 备考冲刺 | 以考纲、分值、薄弱项、模拟和错题为主 |
| 常规学习 | 建立稳定的输入—练习—测试—纠错节奏 |
| 假期提升 | 围绕一项阶段成果，避免把假期每天排满 |
| 单点补弱 | 聚焦一个知识模块，设置多次间隔验证 |

## 6. 周期内安排

每周必须形成四个闭环。非考试型技能学习中，“测试”可以是项目、演示或真实任务，“纠错”可以是根据反馈修正：

| 环节 | 目的 | 示例 |
|---|---|---|
| 学习 | 获得必要输入 | 阅读指定章节、观看指定课程 |
| 练习 | 主动输出 | 做题、写作、口述、实操 |
| 测试 | 检查掌握度 | 计时小测、模拟卷、盲讲、项目、演示或真实任务 |
| 纠错 | 修复失败原因 | 标记错因、回到知识点、根据反馈修改、间隔重做 |

安排原则：

- 将最难任务放在用户精力较好的时段；没有相关信息时不臆测最佳时段。
- 不连续安排多个高认知负荷任务。
- 每50—90分钟安排休息，具体按用户习惯调整。
- 每周至少设置一个缓冲块。
- 时间不足时优先保留练习、测试和纠错，不只保留“看一遍”。

## 7. 任务和检测

### 7.1 合格任务

```text
对象：阅读理解定位
动作：完成并订正
数量：20题
耗时：45分钟
完成标准：正确率达到70%，并能说明每道错题属于词汇、定位还是推理错误
```

### 7.2 掌握度验证

按内容选择一种或多种：

- **回忆**：不看资料列出关键点。
- **讲解**：用自己的话讲给他人或录音。
- **迁移**：完成不同表述的新题。
- **计时**：在目标时间内完成。
- **模拟**：按真实考试条件执行。

“看完、听完、抄完”不能单独作为掌握标准。

### 7.3 错题规则（考试或做题型学习适用）

错题记录至少包含：

| 字段 | 示例 |
|---|---|
| 题目/来源 | 模拟卷第18题 |
| 知识点 | 一元二次方程 |
| 错因 | 概念、计算、审题、方法、时间 |
| 正确方法 | 一句话步骤 |
| 重做时间 | 2天后、7天后 |
| 掌握标准 | 不看答案独立完成并讲清思路 |

Skill只生成记录结构和重做安排，不承诺长期保存或自动追踪。

## 8. 领域内容与产物组织

### 8.1 核心内容

所有完整学习计划必须覆盖：

- 目标合理性和剩余学习容量；
- 最关键的1—3个差距及证据；
- 科目/模块/能力优先级；存在真实取舍时说明排序理由；
- 学习、练习、测试和纠错四个环节；
- 首周或前两周的详细任务；
- 可观察的掌握/能力验证、反馈后的调整规则；
- 时间不足时保留什么、舍弃什么。

### 8.2 条件内容

考试类计划按题目实际需要补充：

- 适用的官方日期、范围、科目和评分事实；
- 按分值、薄弱项、剩余时间和可提升空间形成的安排；
- 适用的计时练习、模拟、错因记录和重做规则。

技能学习计划按目标实际需要补充：

- 可观察的目标能力或作品；
- 按前置关系推进的学习顺序；
- 用项目、演示、真实任务或作品进行验收；
- 根据外部反馈或实际表现进行修正。

### 8.3 XLSX推荐组织

除`目标总览`、`阶段计划`和`执行任务`外，可以按内容量增加：

- `学习诊断与优先级`：范围、掌握、速度、输出和稳定性差距，以及排序依据；
- `测试与纠错`：掌握度验证、测试安排、错因、重做时间和通过标准；
- `考试信息`：存在需要核验的日期、报名、考纲、科目或评分事实时使用；
- `资料清单`：需要在多套教材、课程、题库或官方材料中选择时使用；
- `错题与重做`：用户提供错题或计划包含成体系的重做安排时使用；
- `模拟测试`：考试类计划需要多次模拟、记录成绩和校准时使用。

内容较少时，`错题与重做`和`模拟测试`可以合并进`测试与纠错`。详细行动仍只在`执行任务`维护，领域工作表不重复完整日程。具体格式和通用文件规则由 [output-contracts.md](output-contracts.md) 统一决定。

## 9. 质量边界

- 不臆造考试科目、题型、分值或报名规则。
- 不把知识问答、代写作业或单次文件生成包装成计划。
- 不用“学习DNA”“历史活跃度”等用户未提供的数据。
- 不承诺自动打卡、持续监控、家庭看板或动态修改原计划。
- 未成年人相关计划避免制造家长监控压力；如输出家庭版计划，应强调支持和协商。
