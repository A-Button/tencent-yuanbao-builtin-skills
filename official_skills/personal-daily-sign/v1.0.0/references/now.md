# 此刻卡片

日签在原会话交付完整图片与签文后，使用已加载 `make-things` 的 `show_widget` 发布一张 `image_text` 卡片。默认复用同一张为 340×140 展示窗口设计的横版图；仅当用户明确要其他比例的主图时，另做同主题横版封面供此刻使用。卡片标题用当张签名，摘要写与签文同源的一句预览，让用户知道点开会读到什么。

## 发布请求

按实际 `show_widget` Schema 填写；当前工具封装的关键结构如下，示例地址与 ID 必须换成真实回执：

```json
{
  "card_type": "image_text",
  "title": "<当张签名>",
  "summary": "<当张签文的可读预览>",
  "source": {"label": "我的日签"},
  "data": {"cover": {"url": "https://example.com/actual-generated-image.png"}},
  "tap": {"type": 1, "agent_chat": {}},
  "actions": [
    {"action_id": "a7f2", "label": "查看完整签文", "tap": {"type": 1, "agent_chat": {}}}
  ]
}
```

若日签属于持续服务，在顶层附上当前原会话绑定的真实 `thingId` 和 `todoId`；单张日签无需为出卡新建 Thing。封面使用图片工具或平台实际给出的可访问 HTTPS 地址。仅有会话可展示的短链而没有符合 `show_widget` 要求的地址时，先保留待发布状态，继续交付原会话中的完整日签。

## 查看完整签文

整卡与按钮都静默打开生成这张签的原会话，`agent_chat` 传空对象，不发送“查看今日日签”等 prompt。原会话的这条回答必须直接放有完成图和完整签文，卡片标题与签名保持一致，便于用户回去识别。当前 tap 只支持打开会话，尚不能定位到某条具体回答；不能把按钮改成发 prompt 来重新生成或复述签文。

`actions` 是顶层按钮数组，不能放进 `data`。发布后核对请求是否包含“查看完整签文”、`show_widget` 是否返回真实 `now_id`，再在此刻端上验收按钮是否实际出现、点击是否仅导航。工具成功回执只能确认卡片创建，不能替代端上验收；若请求已带 `actions` 而端上没有按钮，记录为卡片渲染待查。

## 当日状态与修订

每日常规一张，重复回调复用已交付图和真实发布回执。发布请求结果未知时先核对，避免重复建卡。用户修订今日签时在原会话交付新图和文字；若实际卡片接口支持更新，再同步原卡。没有更新能力时保留旧卡与新签的不同修订状态，不宣称旧卡已替换。发布成功不代表设备推送或用户已读。

日签在此刻作为已表达兴趣用户的轻陪伴内容出现；明确待办和临近时限优先。当前 `show_widget` 没有排序字段，排序目标由产品层验收。
