## 1. 阶段路由

先判断用户当前最需要推进的主阶段：

| 当前状态 | 主阶段 |
|---|---|
| 不清楚职业方向或在多个方向间犹豫 | 职业定位 |
| 方向已定，但简历、作品集或经历证据不足 | 材料准备 |
| 材料基本可用，需要寻找岗位和安排投递 | 岗位搜索与投递 |
| 已有目标公司、JD或面试日期 | 面试备战 |
| 已有一个或多个Offer，需要比较或谈判 | Offer决策与谈判 |
| 已接受Offer，需要离职、交接或入职准备 | 过渡与入职 |

一次只为当前主阶段制定详细计划。其他阶段作为后续里程碑，不同时展开成多份完整计划。

仅要求改写简历、进行模拟面试、判断劳动合同或代写谈判话术时，使用相应专项能力；个人计划可以安排这些动作和规定产物，但不把所有专项工作强行塞入本次计划。

## 2. 输入、材料与真实性

### 2.1 最小输入

| 阶段 | 必要信息 |
|---|---|
| 职业定位 | 当前经历与教育、可证明优势、偏好/排斥、城市与现实限制、希望开始行动的期限 |
| 材料准备 | 目标岗位或代表JD、现有简历/项目材料、主要缺口、交付期限 |
| 搜索与投递 | 目标岗位、行业与城市、经验/薪资等底线、现有材料、周期和可投入时间 |
| 面试备战 | 公司、JD、日期与轮次、简历/真实经历、担心的问题、可准备时间 |
| Offer决策 | 各Offer书面条件、个人优先级、答复期限、不可接受条件 |
| 谈判与入职 | 已确认条件、目标与底线、时间节点、交接/入职要求和地区 |

### 2.2 材料处理

- 使用现有文件与图片理解能力读取简历、JD、Offer、职位页面和用户记录。
- 先提取事实，再做判断；无法读取时请用户粘贴关键文本。
- 联系方式、身份证明、薪资证明和前雇主机密只保留完成计划所需的最小信息。
- 需要最新岗位、公司、薪酬或劳动规则时，查证当前官方或可信来源，并记录日期。

### 2.3 真实性

- 能力、项目、指标和结果必须来自用户真实经历。
- 没有数字时追问范围、规模、效率或影响，不补造百分比。
- 没有相关经历时标为缺口，设计学习、作品、相邻证据或诚实说明。
- 不编造公司业务、岗位状态、薪资、面试题或录用概率。
- 不用无依据的“匹配度83%”；改用覆盖项数量和证据状态。

## 3. 职业定位

### 3.1 三圈定位

最多形成两个主方向，依据三项交集：

1. **能证明的能力**：已有项目、技能和结果；
2. **愿意持续投入的内容**：偏好、动机和不可接受项；
3. **市场真实需求**：近期代表岗位的共同要求。

每个方向输出：

| 字段 | 内容 |
|---|---|
| 目标岗位与相邻岗位 | 主方向和可接受的相邻选择 |
| 用户证据 | 能直接支持该方向的经历 |
| 市场要求 | 3—5个代表JD的共同要求 |
| 关键缺口 | 硬限制、弱证据和需补能力 |
| 验证动作 | 信息访谈、岗位抽样、作品或短期实践 |
| 选择标准 | 何时继续、调整或停止该方向 |

方向不清时先设计低成本验证任务，不直接要求用户重写整套简历。

### 3.2 跨行业迁移

寻找与目标岗位在方法、规模或责任上相似的“桥梁经历”：

1. 找到最接近目标工作逻辑的真实项目；
2. 区分可迁移方法和行业专属经验；
3. 使用目标岗位能理解的术语表达，但不改变事实；
4. 对无法迁移的硬缺口设计补齐或诚实说明。

## 4. 简历与证明材料准备

本阶段交付的是“材料准备计划”，不是默认代写完整简历。

### 4.1 JD—经历证据矩阵

| 证据状态 | 判断 | 计划动作 |
|---|---|---|
| 直接证明 | 有同类任务、个人行动和真实结果 | 在材料和面试中突出 |
| 可迁移 | 方法或责任相似，但行业/场景不同 | 补充迁移逻辑和差异 |
| 弱证据 | 提到但缺行动、数字或复盘 | 追问事实并重构表达 |
| 无证据 | 确实没有相关经历 | 做作品/学习、降低目标或诚实说明 |

按优先级处理：

- **P0**：必需能力中的弱证据或无证据；
- **P1**：核心职责对应的强证据和关键项目；
- **P2**：加分项、格式和表达润色。

### 4.2 材料任务

计划可包含：

- 目标简历：围绕一个主岗位版本整理；
- 项目证据卡：背景、个人职责、行动、结果、数字来源和复盘；
- 作品集/案例：只选择能证明P0/P1能力的内容；
- 自我评价：能力标签、1—2项证明和岗位连接；
- 求职信或补充说明：仅在目标渠道确有需要时安排。

量化必须来自真实事实。用户明确要求执行改写时，可调用写作或文档能力另行完成，并保留改动说明。

## 5. 岗位搜索与投递

### 5.1 代表JD抽样

搜索3—5个近期有效、来自官方或可信渠道的代表JD：

1. 提取重复职责、必需条件和加分项；
2. 标记城市、经验、学历、语言等硬限制；
3. 形成岗位筛选标准；
4. 避免被单一JD带偏。

### 5.2 渠道选择

根据行业、职级和地区选择2—4个主渠道：

- 公司招聘官网或官方招聘账号；
- 内推或可信职业网络；
- 适合当前行业和职级的招聘平台；
- 校招、行业协会、猎头或专业社区等专项渠道。

渠道优先级必须结合当前事实，不照搬固定平台排名。

### 5.3 有效投递

每项任务写清数量和质量标准，例如：

> 从两家目标公司的官方招聘页筛选5个满足城市、经验和职责底线的岗位；记录3项共同要求，排除不满足硬条件的岗位；预计60分钟。

计划应覆盖：

- 岗位筛选；
- 必要的材料定制；
- 投递数量和完成标准；
- 合理跟进节点；
- 用户自行填写的状态记录。

不以无差别海投替代定位，不承诺系统自动维护投递状态。

## 6. 面试备战

### 6.1 备战主流程

1. 查证公司业务、岗位事实和面试轮次；
2. 建立JD—经历证据矩阵；
3. 找出P0/P1准备重点；
4. 按剩余时间安排公司研究、证据补齐、题目准备、模拟和检查；
5. 准备60秒自我介绍、必要时的3分钟版本和三个反问；
6. 真实面试后预留一次复盘任务：有效表达、卡点、面试官关注点和新获得信息。

### 6.2 轮次重点

| 轮次 | 重点 |
|---|---|
| 初筛/电话面 | 基本匹配、动机、稳定性和60秒介绍 |
| 业务一面 | 专业基础、执行细节和项目真实性 |
| 主管/二面 | 系统思考、复杂问题、决策与复盘 |
| 交叉/高阶面 | 协作、影响力、冲突和业务视角 |
| HR面 | 动机、职业规划、薪资、到岗和稳定性 |

### 6.3 题包

需要针对性题包时，读取 [interview-question-design.md](interview-question-design.md)。本文件只规定：

- 题目必须来自JD、用户真实经历或证据缺口；
- 题量服从剩余时间；
- 不把社区面经写成“必考”；
- 不用题库替代准备计划。

## 7. Offer、谈判与入职准备

### 7.1 Offer信息核对

先整理书面条件和待确认项：

| 维度 | 核对内容 |
|---|---|
| 固定与浮动收入 | 月薪、月数、奖金条件和发放方式 |
| 长期激励 | 股权/期权数量、价格、归属和离职处理 |
| 福利与成本 | 社保公积金、假期、补贴、通勤和城市成本 |
| 工作内容 | 职责、汇报线、团队、地点、出差和工作强度 |
| 成长与风险 | 业务阶段、直属经理、试用期、稳定性和机会成本 |
| 时间节点 | 答复期限、入职日期和待完成流程 |

不根据口头承诺填入确定条件；缺失项形成向招聘方确认的问题。

### 7.2 Offer比较

先让用户给每个维度设权重，再比较：

- 总体报酬；
- 工作内容与成长；
- 直属经理与团队；
- 业务与稳定性；
- 城市、通勤和生活影响；
- 工作强度；
- 个人长期方向。

评分只用于帮助梳理偏好，不替用户做最终决定。对不可逆或高影响选择同时列出最坏情况和退出成本。

### 7.3 谈判计划

谈判计划至少包含：

1. 期望、可接受范围和不可接受条件；
2. 可用于支撑诉求的真实经验、稀缺能力和当前市场数据；
3. 优先谈的1—2项，不同时争取所有条件；
4. 开场、依据、请求、停顿和确认的对话结构；
5. 对方拒绝、部分接受或要求立即决定时的备选动作；
6. 任何调整最终以书面Offer为准。

薪酬范围、市场水平和劳动规则可能变化，必须按地区、岗位和日期查证，不使用固定涨幅承诺。

### 7.4 离职、交接与入职

按用户地区和实际要求核对：

- 书面通知和时间节点；
- 工作、资料、权限和关系交接；
- 背调联系人和真实材料；
- 入职文件、体检或设备要求；
- 首周业务、人员、流程和成功标准的了解计划。

劳动权益、竞业、赔偿和合同条款只做信息整理并引用当前官方规则；需要判断时建议咨询专业人士。

## 8. 计划阶段与任务

所有职业计划共同要求：

- 识别用户当前阶段、目标和现实限制；
- 使用真实经历、附件和可信市场事实形成差距判断；
- 把当前阶段的行动写成可量化任务；
- 给出检查信号和下一步调整方式。

职业目标可以按需组合以下阶段，但详细拆解仅围绕当前主阶段：

1. 定位与验证；
2. 证据和材料准备；
3. 岗位搜索；
4. 有效投递；
5. 面试备战与复盘；
6. Offer决策与谈判；
7. 过渡与入职。

不要求每个计划覆盖全部阶段，也不因未展开与当前目标无关的后续阶段而视为不完整。每项核心任务包含动作、对象、数量/输出、耗时和完成标准；只有存在前置关系时填写依赖。不可控的“拿到Offer”只能作为期望结果，可控任务才进入计划。

## 9. 领域内容与产物组织

### 9.1 核心与条件内容

职业计划只展开当前主阶段。先覆盖该阶段的核心内容，再根据用户目标、输入材料和计划范围选择扩展内容：

| 主阶段 | 核心内容 | 按需扩展 |
|---|---|---|
| 职业定位 | 两个以内方向、用户证据、关键缺口、验证动作和选择标准 | 需要判断市场需求时，增加代表岗位和市场要求 |
| 材料准备 | 目标材料、现有证据、优先任务和验收标准 | 有具体JD时增加JD—证据矩阵和P0/P1/P2任务 |
| 搜索与投递 | 目标边界、渠道、岗位筛选和可量化的投递动作 | 需要市场校准时增加代表JD共同要求；需要用户自行跟踪时增加记录模板 |
| 面试备战 | 岗位重点、准备优先级、日程、核心问题和可用真实素材 | 有公司/JD/简历时增加事实与证据矩阵；根据需求增加自我介绍、反问、题包、STAR素材或模拟评分 |
| Offer与谈判 | 书面条件、答复期限、用户权重和待确认信息 | 多Offer时增加比较；用户希望谈判时增加目标/底线、依据、步骤和书面确认节点 |
| 过渡与入职 | 时间节点、交接、材料和首周准备 | 涉及背调、劳动规则或特殊入职要求时增加相应核验与待确认事项 |

不因未展开与当前目标无关的扩展模块而判定计划不完整。

### 9.2 XLSX推荐组织

除`目标总览`、`阶段计划`和`执行任务`外，可以按当前主阶段和内容量增加：

- `岗位与能力差距`：职业定位、材料准备或求职冲刺需要比较方向、岗位要求和用户证据时使用；
- `JD分析`：存在具体JD或需要汇总代理岗位要求时使用；
- `材料清单`：需要准备简历、作品集、证明材料或入职文件时使用；
- `投递记录`：用户希望自行记录公司、岗位、日期、状态和下一步时使用；
- `Offer比较`：比较两个及以上Offer时使用；
- `谈判与入职准备`：目标、底线、谈判步骤、交接或入职事项较多时使用；
- `JD匹配`：面试备战需要呈现JD—简历证据矩阵时使用；
- `问题清单`：需要准备成体系的问题时使用；
- `STAR素材`：用户有多段真实经历需要映射和复用时使用；
- `公司研究`、`模拟评分`、`自我介绍与反问`、`面试前检查`：相应内容足以独立使用时增加。

具体行动和日期只在`执行任务`完整维护；领域工作表保存证据、题目、素材、比较或记录结构，不重复整份排期。内容较少时允许合并到最相关的工作表。具体格式和通用文件规则由 [output-contracts.md](output-contracts.md) 统一决定。

## 10. 质量边界

- 不保证Offer、面试通过率、薪资结果或入职体验。
- 不把多个职业阶段同时展开成巨型计划。
- 不编造经历、岗位、公司、薪资或书面条件。
- 不把简历改写、完整模拟面试、劳动合同判断或长期求职看板当作本Skill自动完成的能力。
- 不使用未经批准的外部OCR或大模型API处理用户材料。
- 不承诺自动维护投递、面试、Offer或入职状态。
