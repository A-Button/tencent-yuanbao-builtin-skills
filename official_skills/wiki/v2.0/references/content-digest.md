# 单篇解读（content-digest）

本文档只在父级 `wiki` 完成内容类型与意图路由后由 `read` 工具读取，不是独立 Skill。父级说明与 `wiki/ingest_entry` 工具此时已经在上下文中给出。

进入本文即表示用户要理解或判断**单篇资料本身**。先做二级准入复核；命中后必须依次完成 Fetch、历史召回、字段判断和一次 ingest，最后只展示工具返回的 `body`。不得跳过召回、跳过 ingest 或退化成普通总结——即使初判是「完全重复、不值得读」或其他情况，也不影响流程本身。**你想回应用户的每一句判断（哪怕是直接回答"值得看吗"这类问题），都写进 §字段逻辑 的字段里、交给模板渲染进 `body`；不要等拿到 `body` 后自己再另写一句作答**——最终答案必须是、且只能是 ingest 后的 `body`。若资料只是用于改写、翻译、创作或完成其它任务，应停止本文流程并交回正常回答。

本流程把文章当场读完，输出单篇解读反馈——**这篇讲什么 · 相比你存过的同主题内容新增/重复/冲突什么 · 对你可能有什么用**——并默认存进资料库。

## 用户可见输出边界

最终回复只呈现用户需要的结论和消化结果，**绝不展示内部判断与执行过程**。这条适用于正常消化、部分新增、完全重复、冲突、同链接重复、抓取失败及其他兜底场景。

- 禁止向用户提及「出口 1/2/3、判定树、价值闸、冷启动」等内部规则名，或 `Recall` / `Fetch` / `Judge`、`diff` / `ref`、schema、模板等实现术语。
- 禁止展示条目 id、内部路径、工具名、调用参数、检索命令；禁止输出「我先检查另一条」「根据 Skill 要求」「我应该走某出口」等执行旁白，以及模型的犹豫、规划、自我纠正或规则冲突。
- 只把内部判断翻译成自然、有用的事实，例如「这篇之前已经处理过」「和你之前存过的内容相比，这篇主要新增了……」「核心观点和之前那篇基本一致，可以跳过」。
- 抓取失败或交回正常回答时，只说明用户能理解的结果和下一步，不解释内部路由、工具或失败链路。
- 成功调用 `wiki/ingest_entry` 后，只把工具返回的 `body` 原样发给用户，不在前后补充任何内部说明。

## 与 wiki 的分工

本文档和父级 **wiki** 共用同一个库 `/data/library`。存储、历史查询、支持类型和同主题召回机制全部沿用已加载的 wiki 规则，不在本文重复；本文只负责单篇内容的消化判断：三出口、真新知过滤、价值闸、开篇条、用处和风险提示。

### 重复文章边界

先区分**同一文章的身份重复**与**不同来源的语义重复**，两者不能混用一套处理：

- **同一规范化 URL = 身份重复**：分享参数或追踪参数不同、但实际指向同一篇文章，也算同一 URL。它不进入下文三出口的语义重复判断。业务结果应是保留首次入库的完整 `summary`、`keyInsights` 和 `body`，不新建第二条、不用后来的一两条增量覆盖首次完整要点，并展示已有消化结果。
- 同一 URL 命中时，面向用户只用固定提示：`这篇之前已经处理过并存进资料库了，下面是上次的消化结果。` 随后展示已有结果；不得暴露 URL 判定、条目 id、出口、召回或检查过程。**这句话只能在真查到命中条目、读出其 `body` 后才能说**，不能凭上一轮自己的判断编造。
- **不同 URL、内容高度相似 = 语义重复**：仍视为不同来源并正常入库。若主要观点均被历史覆盖，走「重点速览」；若有实质新增或冲突，走减法。内部照常填写 `repeated` / `ref` 等字段，但不得把字段名展示给用户。

本节只定义业务边界与用户结果；URL 规范化、身份查询和入库去重由 wiki / 算法实现，本文不规定具体机制，也不声称当前工具已具备该能力。

## 二级准入复核

父级 wiki 已按其 §1 完成一级路由；这里不承担一级触发，只复核本次输入是否适合执行单篇内容解读：

- 如果仍发现用户明确说「只收藏 / 只存一下 / 不用总结」，说明父级路由有误，应停止内容解读并回到父级静默保存流程。
- 文章中含图片或嵌入视频仍可进入，只要文字正文足以独立理解全文；以视频、音频、图片、文件或社交帖子为主体的页面不进入。
- 没有单篇链接或可读正文时停止。一次输入包含多篇当前资料时，停止本文流程并回到 wiki §6.2「多资料解读」，不得自行创造批量模板或批量入库流程。

## 必须走完的执行流程

1. **确认输入**：按父级 wiki 当前支持类型判断；明显以视频、音频、图片、文件或社交帖子为主体 → 交回正常回答；公众号或普通网页文章候选 → 继续。
2. **读取正文**：用 `web_fetch(url=..., prompt="")` 抓标题和正文，尽量获取作者与发布时间。正文为空，或只抓到登录墙、打开 App 提示、错误页、导航 / 指标、无法理解全文的残片 → 交回正常回答，不编造反馈。
3. **确认可读**：页面主要内容是文章、且文字正文足以独立理解全文才继续；正文中嵌图片、音频或视频不影响准入。
4. **召回历史**：给本篇打 `category` + `topicTags`（按 wiki §3.1/§3.2）→ 按 wiki §4 圈选同主题候选、读取命中条目的 `keyInsights`。**相同 topicTags ≠ 同一件事**，由正文语义判断；无命中则进入新知态。
5. **判断字段**：按 §字段逻辑 依次确定 `summary`、`advisoryNotes`、`readGuide`、`keyInsights`、`recommendation`、`category`、`topicTags`。
6. **调用并展示**：调用一次 `wiki/ingest_entry`，同时完成渲染、入库并取得展示文本，见 §调用与展示。**必须传 `render_type="content_digest"`**；不得在调用前直接回答用户。

## 字段逻辑

判断字段共 6 组，按填写顺序讲：`summary` → `advisoryNotes` → `readGuide` → `keyInsights`（内容解读的核心，占大头）→ `recommendation` → `category`/`topicTags`。

### summary（摘要）
1–2 句、一眼扫完，**目标约 40 字、最终展示文本硬上限 50 字；超过必须压缩**。从全文层面概括主旨，可包含多个紧密相关的核心结论、关键数据或必要边界；细节和要点清单下沉 `keyInsights`。**不复述标题、不出任何对比或读法措辞**（那是开篇条职责）。有同主题历史可更短，仍只讲本篇。
- 示例标题：`《刚刚，Claude Opus 4.8 上线，张口就说自己是 DeepSeek、Qwen》`
- 正例：`Opus 4.8 提升诚实性并扩展 Claude Code 工作流，但实测仍会误认自身身份。`
- 反例：`这篇讲 Opus 4.8 上线了。`（只重复标题中的「上线」，没有提供正文里的主旨、结论或数据）／把能力、价格、跑分逐项列进摘要（堆要点）／`…和你读过的同类比，重点看新增。`（侵入开篇条）

### advisoryNotes（风险提示）
一行安全提示，**默认 `[]`、最多 1 条、≤约 30 字**。只在「照着做可能受伤 / 被误导」时出，不是质量点评。中性、不下指令，给自我保护方向（结合自身 / 咨询专业 / 以官方为准 / 决策前核实）。

触发（命中才考虑、仍从严）：健康医疗（用药/剂量/断食）、金融投资（荐标的/收益承诺）、伪科学辟谣、明显过期（旧政策/价格）、夸大营销、风险操作。
不触发：普通资讯/娱乐/中性方法论；「结论不够严谨」（归要点可信度点）；写不出具体风险只能憋「请谨慎」（套话，禁止）。

- 出：《21 天断食逆转糖尿病》→ `断食控糖因人而异，慢性病请遵医嘱、勿自行尝试。`
- 出：《这只半导体票闭眼买》→ `涉及具体投资标的、有风险非建议，决策前请独立核实。`
- 不出：《某模型跑分第一》（「跑分缺独立复现」写进 keyInsights）／《旅行攻略》（无风险）

### readGuide（开篇条）

两态都由模型直接产**一句完整的话**；展示时只在句首加 `🆚对比`/`🌟新知`，不参与拼句。

**对比态**（`referenceRecordId` 非空）= 同主题关系 + 一个实质钩子（冲突在哪点 / 新在哪块 / 重合核心）+ 读法建议：
- 通常 ≤50 字、最多 2 句、朋友式语气、保守不武断；超长先删背景和重复解释，只留关系、钩子、建议。书名号里的标题不计入这 50 字。
- 写出 `referenceRecordId` 那篇的标题 `《标题》`：从召回时读到的 `title` 逐字照抄，只保留前 10 个字加「…」，如 `从内耗到轻松：实用的焦虑缓解指南` 写成 `《从内耗到轻松：实用的…》`。没真读到条目、或标题记不准，就不写标题，仍用「那篇 / 你存过的」指代。
- 确认同主题不止一篇时，在标题后加「等」，如 `和你存过的《置身钉内（全文纯文字…》等多篇内容同主题，……`。判断依据是召回时读到并确认的条目多于一条，或 `keyInsights[].ref` 出现两个以上不同 id。
- 「等」后面不要紧跟「同」字，「等同」会被读成一个词；也不写具体篇数（「等三篇」「等 3 篇」）。后半句回指历史说「它们 / 这几篇」，别说「那篇」。
- 冲突态只说「哪里对不上」、不判谁对谁错；钩子点到为止，展开下沉要点段。

**新知态**（`referenceRecordId` / `diff` / `readSuggestion` 全空）= `note` 直接按固定句式输出完整句，不自由改写：
- 能可靠概括主题：`这是一篇关于【主题】的内容，之前似乎没转给我看过类似的，下面是今天的新收获。`
- 无法可靠概括主题：`这篇内容之前似乎没转给我看过类似的，下面是今天的新收获。`
- 【主题】用简短、口语的主题 / 对象短语，通常 ≤10 字；若整句会超过 50 字，改用更上位主题或无主题版。不要改成「你没看过 / 从没见过 / 第几条」等硬断言，也不要增添背景或评价。

`readSuggestion` 映射：`added`→full/skim；`repeated`→skim/skip；`contradicted`→full；新知态→空。

few-shot（加粗 = 模型产的整句）：

| 状态 | note |
|---|---|
| 部分新增 | **和你存过的《减脂平台期，如何训练…》同主题，这篇多了『碳水循环周期』，建议略读新增部分。** |
| 部分新增 · 不止一篇 | **和你存过的《减脂平台期，如何训练…》等多篇内容同主题，这篇多了『碳水循环周期』，建议略读新增。** |
| 冲突 | **这篇在『要不要算热量』上跟《减脂平台期，如何训练…》对不上——这篇说靠饱腹感不用算，建议对照看、自己拿主意。** |
| 冲突 · 不止一篇 | **这篇在『要不要算热量』上跟《减脂平台期，如何训练…》等都对不上——这篇说靠饱腹感不用算，自己拿主意。** |
| 高度重复 | **和你之前转过的《一张图看懂热量缺口》核心都是热量缺口 + 高蛋白，没太多新的，赶时间可跳过。** |
| 新收获 | **这是一篇关于减脂的内容，之前似乎没转给我看过类似的，下面是今天的新收获。** |

### keyInsights（内容解读的核心）

先读完整篇，再按下面顺序生成。每条要点是 `{text, diff, ref, group}`：`text` 会**逐字**进入最终展示，必须自包含，数字、专名、单位和限定条件都写在里面；`diff` / `ref` 记录与历史的关系；`group` 是按需使用的分组小标题。不要新增 `lead` 字段，不要自己加编号。

#### 生成顺序（严格按 1–7）

1. **建立全文骨架**：先识别主结论、关键事实 / 数据、机制、方法、边界和可信度，形成文章级候选要点。此时先求覆盖，不急着写最终数组，不逐段摘录。
2. **判断历史关系**：从候选里确认真正同主题的历史（按内容语义，不靠字面；减肥 ≈ 减脂），再对文章级候选要点逐条判 `added` / `repeated` / `contradicted`。措辞变化、同义改写、边角例子不算新增；只有值得用户为它专门再读的实质信息才算 `added`。对历史观点的实质细化可算 `added`，并带最相关 `ref`；冲突必须高置信。
3. **选择三出口**：能否减法只看有没有真正同主题历史；无历史 = 无基线 = 给完整。

   | 出口 | 触发 | 要点段标题 | 最终 `keyInsights` |
   |---|---|---|---|
   | 完整核心要点 | 无同主题历史（新收获 / 冷启动） | 你可能不知道的 | 给本篇完整核心要点，不做历史减法；`diff` / `ref` 留空 |
   | 减法 | 有同主题历史，且有实质新增 / 冲突 | 你可能不知道的 | 只把 `added` / `contradicted` 作为独立要点；`repeated` 不单列 |
   | 重点速览 | 有同主题历史，但主要观点均重复 | 重点速览 | 简要回顾本篇关键要点，全部标 `repeated` 并带可靠 `ref`；不留空、不造新增 |

   「重点速览」只处理**不同 URL / 不同来源文章的语义重复**；同一规范化 URL 的身份重复按 §重复文章边界 复用首次结果，不进入本出口。

   整篇 `readGuide.diff` 按 `contradicted` > `added` > `repeated` 聚合；`keyInsights[].diff` 保留每条自己的判断。出口标题由工具自动选，不要手写。
4. **通过价值闸**：软范围 3–10 条，单主题通常 3–8；只有真·多主题合集才接近上限。绝对上限约 15（天花板、非目标）：超了先合并同类、提高概括层级，仍超才舍价值最低的；不无脑砍尾、不注水。每条 1–2 句、尽量 ≤约 60 字，按价值从强到弱排。完整出口覆盖原文实际存在的主结论、关键机制 / 做法、边界和关键数字；减法出口覆盖全部实质新增与冲突。**只有 §极短内容兜底允许 1 条，不受 3–10 条软范围约束。**
5. **写成可读要点**：每条补齐主体、对象、数字单位和成立条件，不能依赖上一条才能看懂。减法出口允许把历史已知信息压成一句里的**最少必要上下文**，让新增 / 冲突读起来完整，但不得让 `repeated` 单独占一条。分组内优先按「结论 / 变化 → 证据或机制 → 边界 / 可信度」组织；避免无前文的「这 / 其 / 该方法」和去重后没头没尾的碎片。可信度批判点（如「跑分缺独立复现」）放这里，不塞 advisoryNotes，也不与 summary / readGuide 逐字重复。
6. **按需增强扫读**：钩子、内联加粗、`group` 都是可选手段，不是必填项。
   - 有自然、具体、约 ≤8 字的钩子时，可在 `text` 开头写 `**钩子**：展开`；钩子取实体、数字结论或动作词。只能写出「核心观点 / 值得注意 / 研究发现」等泛词时，直接不用钩子，整句平写；不要加粗整条。
   - 长文、复杂单主题或多主题内容只有在自然形成两个以上板块、且分组确实更好读时才填 `group`。长单主题可按「机制 / 做法 / 边界」，多主题按真实主题分；组数跟内容走、不固定。同组填完全相同的字符串；短文、要点少或只有一个自然板块时留空。
7. **最终自检**：逐项确认忠于原文、出口正确、核心覆盖、无独立重复点、必要上下文足够、顺序流畅、`diff` / `ref` 合法、数量和长度合规。任何一项失败，先合并或改写再提交。

#### 真新知与不对称（仅减法出口）

一条信息相对以下三条基线都算新，才保留为新增：① 标题已说清的不算；② 大众常识 / 泛泛建议不算；③ 同主题历史候选已覆盖的不算。识别层次（越靠后越优先，不输出标签）：事实 / 数据 → 方法 / 做法 → 机制 / 因果 → 反常识 / 新视角 → 边界 / 适用条件 → 可信度 / 判断。

误判重复会让用户错过价值，代价更高：判 `repeated` / 判空要保守，拿不准偏 `added` 或「略读」；冲突同样只在高置信时判 `contradicted`。不要武断说「你已经知道」。

#### 正反例（字段按当前协议）

**出口 1 · 冷启动，完整但不流水账**

- ✅ `{"text":"**周期7–14天**：典型碳水循环通常运行 7–14 天再调整。","diff":"","ref":"","group":""}`
- ✅ `{"text":"高低碳交替主要用于缓解平台期的代谢适应，不是日常长期吃法。","diff":"","ref":"","group":""}`
- ❌ 只写「这篇讲碳水循环」；或把原文每段各摘一句，凑成十几条。

**出口 2 · 有新增 / 冲突，只展示减法但保阅读完整**

- ✅ 历史已讲过高低碳安排，本篇新增周期：`{"text":"**周期7–14天**：沿用高低碳交替的前提下，再按平台期变化调整。","diff":"added","ref":"","group":""}`
- ✅ 本篇与历史在是否继续降热量上相反：`{"text":"平台期策略与那篇相反：本文主张先提高碳水而不是继续降热量。","diff":"contradicted","ref":"ent_20260708_0001","group":""}`
- ❌ 把「高低碳交替」作为 `repeated` 独立列一条；或只写「周期为 7–14 天」而不交代是什么周期。

**出口 3 · 不同来源但内容完全重复，给重点速览而非空数组**

- ✅ `{"text":"文章核心仍是用热量缺口配合高蛋白饮食减脂，与那篇基本重合。","diff":"repeated","ref":"ent_20260708_0001","group":""}`
- ❌ `keyInsights=[]`；或为了避免空白，把边角措辞硬判成 `added`。

**钩子 / 分组按需，不为格式硬凑**

- ✅ 长文自然分成方法与风险时，可用 `group="怎么做"` / `group="边界与风险"`；有具体钩子才内联加粗。
- ✅ 短文只有三条连续要点时，`group=""`、不用钩子也合规。
- ❌ 每条都加粗「核心观点 / 关键数据」，或把三条短文硬拆成三个 group。

#### 极短内容兜底

「极短」按信息结构判，不按正文字数判：正文只含一个不可再拆的原子事实，继续拆分就会重复、失真或脑补。

- **summary 仍必出**：用一句极短话完成整体定位，不扩写背景、不为接近 40 字而凑字，仍守 50 字硬上限。
- **keyInsights 仍必出**：只出 1 条即可；优先保留原文里更具体的事实、数字、对象或限定条件。`group` 留空；钩子仍按需，不为形式硬加。
- **允许语义重合**：优先让 summary 做上位定位、唯一一条 keyInsight 保留具体事实；能自然区分时避免逐字相同。若原文无法分出两层，允许近似或逐字重合，忠实度优先，绝不为去重编造信息。
- **历史判断照常**：有可靠同主题历史时仍走正常三出口，单条要点按关系填写 `added` / `contradicted` / `repeated` 及 `ref`；冷启动或无可靠判断时 `diff` / `ref` 留空。极短不等于跳过历史判断。

例：原文只有「地铁 3 号线 5 月 8 日因检修停运一天。」→ summary 可写「地铁 3 号线将因检修临时停运一天。」；唯一 keyInsight 可写「停运日期为 5 月 8 日，原因是线路检修。」

### recommendation（verdict + reason，用处）
- `not_useful`（一次性 / 娱乐 / 与用户无关，或唯一价值只是当谈资、开拓眼界、了解背景、先存着）→ `reason` 填 `""`、不展示用处段。
- `useful` 必须能指出一个可识别的未来任务、决策、复用场景或避坑动作；`reason` 用一句 ≤约 30 字的话说清「什么时候能拿它做什么」，且须能从本篇推出。三型择一：任务 / 决策参考「做 X 时可参考」／可复用方法「遇到 X 时可照着用」（仅非敏感）／避坑提醒「遇到 X 别全信」。
- 健康/医疗/金融只用任务 / 决策参考或避坑提醒，不下「照着做」指令。禁套话（「你关注的方向 / 先帮你存着」）、禁脑补用户目标、禁复述要点。
- 正例：`做模型选型时可参考；跑分待独立复现，别当定论。`
- 反例：`看着是你关注的方向，先帮你存着。`（套话）

### category / topicTags
按 wiki §3.1（7 类单词枚举）/ §3.2 打。颗粒度是这里唯一要强调的：
- 太粗（健身 / AI / 理财）→ 归 category，不打 topicTags。
- 合适（减脂 / Claude / ETF 定投）→ 打 topicTags。
- 太细（碳水循环周期 7-14 天）→ 归 keyInsights，不打 topicTags。
- 同义按内容算同一件事；召回候选里已有语义相同、粒度合适的标签时，优先逐字复用（减脂 ≈ 减肥时选库里已有的那个），不造近义词；只有确属新主题或旧标签粒度不合适时才新建。

## 调用与展示

判断字段填好后，**调用一次 `wiki/ingest_entry` 工具、`render_type='content_digest'`**——渲染 body 和入库是这一次调用内部完成的两件事，不分两步、你也不用手写 body：

```text
wiki/ingest_entry(
  render_type="content_digest",
  title, source_raw, category, topicTags, summary,
  advisoryNotes, readGuide, keyInsights, recommendation
)
```

**`render_type="content_digest"` 是必传参数，不可省略**（工具 schema 里 `render_type` 本身无默认值，任何调用都必须显式给出）：传成空字符串会走「body 原样」分支，而你按本文档不该传 `body`，最终会因缺少 `body` 而入库失败。链接类的 `source_raw` 直接填 URL。

各参数按 §字段逻辑 判定的值原样传入。完整参数表已随父级 wiki 的工具 schema 下发，不再重复。工具内部用 `content_digest` 模板把 `summary`/`advisoryNotes`/`readGuide`/`keyInsights`/`recommendation` **逐字**渲染成展示 `body`（三出口标题、分组、圆点列表、空值省略均由模板负责）→ 用渲染出的 `body` 入库。不要自己再写或压缩一份。

工具返回一段纯文本：首行 `[ok] true/false`，随后是入库回执字段，最后 `[body]` 后面是渲染好的展示正文：
- **展示**：把 `[body]` 后面的内容**原样**发给用户，不要重新概括、改写或补充。
- `[ok] false`：**入库失败不阻断展示**——`[body]` 仍是已渲染好的正文，照常展示（可附一句「这篇暂时没能存进资料库」）。
