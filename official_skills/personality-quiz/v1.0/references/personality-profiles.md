# 人格类型场景档案

本参考只在修改、审查或诊断人格结果页的类型场景正文与代表人物时读取。它是结果页的静态解释层，不参与计分，也不把常见倾向写成对个人经历的事实判断。

## 内容

权威内容表位于 `scripts/mbti_type_profiles.json`，必须完整包含 16 个四字母类型。每型固定提供：

- `career`：事业发展；
- `emotion`：情感婚恋；
- `study`：学业考试；
- `talent`：天赋挖掘；
- `representatives`：恰好 3 位类型参考人物及简短身份。

四个主题正文使用直接面向被测者的第二人称：每段都以“你”或“你的”开头，后续同主语分句可以自然省略。不得用“用户、被测者、受测者、命主、本人、该类型的人”代指被测者，也不得使用第一人称“我”。“他人、别人、对方、伴侣”等确实指向其他人的词可以保留。

正文使用“更可能、偏好、容易、需要”等倾向语言，不把常见特征写成对个人经历的事实判断。研究来源只保留在内部来源台账中，不写入运行时数据，不在结果页展示来源说明或外链。

代表人物只显示姓名和简短身份，并使用小卡片呈现。人物姓名、职业与类型归类不进入复制交接数据。

## 结果选择与呈现

类型档案跟随 `personality-scoring-core.js` 已确定的元宝类型选择，不再实现第二套类型判断：

1. 四轴都确定时显示该类型的一份档案；中文人格名称仍只出现在元宝下方，不在档案模块重复。
2. 含一个或多个 `X` 时显示与元宝相同的最多两个等权分支，只使用类型码区分；不得显示“参考方向”字样，不得合成虚构的边界类型，也不要求用户二选一。X 的统一提示文案为“X表示你同时具有两种倾向”。
3. 直线作答、质量不通过或类型选择为空时隐藏整个档案模块。

模块放在“简要分析”之后、“继续聊聊”之前。不要显示“典型表现”大标题、可见副标题或方法说明；为读屏保留一个非可见语义标题即可。四个正文标题依次为“事业发展、情感婚恋、学业考试、天赋挖掘”，呈现为连续报告式段落与轻分隔线，不做四张互相竞争的仪表盘卡片。人物区改用三张紧凑小卡片；桌面可并列，窄屏和移动端回到单列，不加载人物图片。

## 构建边界

构建器必须验证 16 型、四项第二人称正文和每型 3 位人物后，把内容表直接写入自包含 HTML。运行时不得请求网络、调用模型、写持久化存储或包含类型资料外链。校验器必须拒绝缺型、缺主题、非第二人称正文或人物数量错误的生成物。
