# 产物渲染规则

本文件只决定“用什么形式呈现”。计划的通用语义字段以 [planning-core.md](planning-core.md) 第6节为唯一来源；领域核心内容和本题适用的条件内容以命中的领域文件为准。

## 1. 选择顺序

1. 用户明确指定HTML、PPTX、XLSX、DOCX或纯聊天时，在当前能力支持范围内优先满足。
2. 用户没有指定时，先判断是完整计划还是轻量安排：
   - **完整计划**：目标需要跨多个时间点执行，存在先后顺序、任务量、完成标准或后续检查，默认生成聊天计划卡和XLSX；
   - **轻量安排**：只解决当前或一次性的小安排，不需要后续跟踪，默认只生成聊天计划卡。
3. 不因格式变化删除计划的必要内容。
4. 用户只指定一种格式时，该格式替代默认XLSX；用户明确需要执行和阅读/汇报等多个用途时，可以生成多个文件。
5. 用户表达了打印、分享、汇报、演示或网页浏览等明确消费需求但未指定格式时，选择合适的DOCX、PPTX或HTML；只是判断“可能有帮助”时不自动增加文件，只在Answer中提供弱入口。

用户指定的格式明显不适合时，仍优先满足，并调整排版。例如用PPTX呈现长计划时，将完整任务放在附录页，不删除任务字段。

多个文件可以包含重叠信息，但必须来自同一份标准计划数据，并针对执行、阅读或展示重新组织。XLSX承担执行和自行记录；DOCX、PPTX或HTML承担阅读、打印、分享或汇报，不分别生成互相矛盾的计划。

## 2. 主产物必须保留的内容

完整计划以一个执行主产物为准：没有文件时主产物是聊天Answer；生成文件时通常以XLSX或用户指定的文件为主，聊天只提供计划卡和使用入口。存在补充阅读/展示文件时，所有文件从同一份标准计划数据渲染。执行主产物至少覆盖：

- 目标、期限、完成标准、约束和假设；
- 可行性判断、关键差距和优先级；
- 适合任务复杂度的时间/进展结构、重点和通过标准；
- 可执行任务的动作、数量或输出、耗时和完成标准；
- 执行缓冲、时间或状态不足时的最小方案；
- 可观察信号、检查时点、调整动作和重新制定条件；
- 命中领域文件规定的核心内容，以及本题触发的条件内容。

“快速启动”只在聊天Answer中呈现，作为帮助用户低门槛开始行动的入口，不写入文件，也不创建“快速启动”工作表。

领域规则与本文件冲突时：

- **内容是否必须出现**：以领域规则为准；
- **内容如何排版和使用哪种文件**：以本文件和用户要求为准。

## 3. 聊天计划卡

### 3.1 固定内容

聊天 Answer 始终让用户快速知道五件事：

1. 目标、期限和最重要的约束；
2. 目标是否可行，以及最关键的取舍；
3. 计划的时间/进展主线；
4. 下一个可用时段可以开始的第一步；
5. 有文件时，文件是什么以及如何使用。

### 3.2 条件内容

出现对应情况时再补充：

- 使用了未确认信息：列出关键假设；
- 任务容易被现实波动打断：说明缓冲和最小方案；
- 依赖实时事实或外部标准：给出关键来源和日期；
- 定时任务有明确增量价值：提供弱入口或待确认清单。

没有文件时，聊天计划卡同时承载完整计划；可使用以下结构：

```markdown
## 计划判断
- 目标与期限：
- 可行性：
- 关键差距：
- 关键约束/假设：

## 计划路线
| 日期/阶段 | 重点 | 通过标准 |

## 先执行这些
| 日期/周次 | 优先级 | 任务 | 数量或输出 | 耗时 | 完成标准 |

## 现实变化时
- 缓冲：
- 最小方案：

## 检查与调整
- 在【时间】检查【信号】；若【条件】，则【调整动作】：

## 现在怎么开始
- 下一个可用时段先做：
```

有主文件时，聊天只展示计划判断、路线总览、快速启动和文件说明，不重复粘贴全部任务。标题和措辞可以根据场景调整；评判重点是信息是否存在且清楚，不要求机械套用模板。

## 4. 文件渲染

### 4.1 XLSX

XLSX是完整计划在用户未指定格式时的默认执行载体。固定包含三张核心工作表：

| 工作表 | 唯一职责 | 不应重复的内容 |
|---|---|---|
| `目标总览` | 目标、期限、完成标准、现状、约束、假设、合理性判断、关键差距、优先级和事实来源 | 完整日程和逐项执行任务 |
| `阶段计划` | 阶段时间、阶段目标、重点、里程碑和通过标准 | 每天的详细动作和执行记录 |
| `执行任务` | 日期/周次、优先级、动作、对象、数量或输出、耗时、完成标准、适用的依赖和最小方案 | 大段目标分析和领域方法说明 |

`执行任务`固定增加三个由用户自行填写的空白列：`状态`、`实际结果`、`反馈/问题`。不得替用户预填状态，也不得暗示系统会自动读取、同步或更新这些记录。

领域文件规定必须覆盖的专业内容，可以根据内容量和可读性合并进核心工作表，也可以拆成领域工作表。领域文件提供推荐工作表菜单，但不机械生成空表。

所有工作表遵循：

- 每张表只有一个主要职责；
- 同一详细信息只在一个位置维护，其他工作表只做摘要或引用；
- 行动排期只在`执行任务`完整维护，领域工作表只放诊断、动作处方、题目、证据矩阵等支撑信息；
- 冻结表头，设置合理列宽和日期格式；
- 生成后检查字段、引用关系和跨表数据是否一致。

### 4.2 DOCX

适合连续阅读、打印和手册。用户指定DOCX，或明确需要XLSX之外的阅读版本时，推荐顺序：

1. 结论与目标；
2. 现状、证据和关键差距；
3. 时间/进展路线；
4. 执行安排；
5. 适用的领域模块；
6. 缓冲、最小方案、执行校准和风险边界；
7. 来源、假设及待确认信息。

标题层级清楚；长表格必要时横向排版，不用大段重复聊天内容。

### 4.3 PPTX

适合汇报和讲解，不是默认执行载体。用户明确需要展示版本时，推荐结构：

1. 目标与判断；
2. 现状和差距；
3. 进展路线；
4. 近期行动；
5. 关键领域模块；
6. 风险、缓冲、最小方案和下一步；
7. 详细任务附录。

一页只表达一个主要结论。完整任务字段放在附录表格中，避免为了视觉简洁丢失执行信息。

### 4.4 HTML

适合网页阅读、打印或用户明确要求的轻交互展示。至少包含：

- 页面摘要和目标状态；
- 时间或进展结构；
- 可筛读的任务表；
- 适用的领域模块；
- 缓冲、最小方案、执行校准和风险提示；
- 打印友好样式。

HTML必须自包含；除非用户明确要求，不依赖外部服务器、登录态或长期存储。

## 5. 文件质量

- 文件名、标题、计划日期和版本清楚。
- 重要内容不能只依赖颜色、批注或动画表达。
- 生成后检查结构、字段、分页/工作表、链接和可读性。
- 不写“系统后续自动更新”“已同步到文件库”等当前不存在的能力。
- 用户明确要求其他支持格式时，沿用同一计划数据、领域核心内容和本题适用的条件内容进行渲染。
- 同时生成多个文件时，目标、日期、阶段、任务量、优先级、合理性判断和安全边界不得冲突；信息可以因消费方式不同而详略不同。
