# 人格结果页元宝规则

本参考只在修改、审查或诊断人格结果页的元宝角色时读取。元宝是结果的视觉解释层，不参与题目计分，也不把四字母近似包装成正式 MBTI 诊断。

## 角色资产与映射

16 个无性别元宝保持统一的绿色本体、白色脸窗、黑色简眼和漂浮手脚；类型差异只由姿态、眼神、一个主道具与少量符号表达。权威资源位于 `assets/yuanbao-personalities/`，`manifest.json` 固定文件、替代文本、尺寸、SHA-256 与 `visual_offset_y`。构建器必须校验清单与图片后，把 16 张 WebP 内联进最终 HTML；不得从网络加载、写入持久化存储或在运行时重新生成角色。

## 结果选择规则

角色选择必须由 `personality-scoring-core.js` 的确定性函数完成，页面不得复制另一套判断：

1. `quality` 不是 `pass`、类型为空、类型格式非法或直线作答：显示 0 个元宝。
2. 四个轴都确定：显示该完整类型的 1 个元宝。
3. 只有一个 `X`：显示把该轴分别补成两端后的 2 个相邻类型，且两者视觉权重相同。例如 `INTX` 显示 `INTJ` 与 `INTP`。
4. 有两个或更多 `X`：仍然只显示 2 个等权的边界代表，不展开全部组合。第一个把所有 `X` 按轴的高端补成 `E / N / F / J`，第二个按低端补成 `I / S / T / P`；已经确定的字母保持不变。例如 `XNXJ` 显示 `ENFJ` 与 `INTJ`，`XXXX` 显示 `ENFJ` 与 `ISTP`。

任何路径都不得显示超过 2 个元宝。多个 `X` 时的两个角色只是帮助理解模糊边界的代表方向，不是穷举，也不能描述成用户同时拥有两个确定类型。

## 呈现与交接边界

- 结果首屏使用一个简洁的身份表头：左侧显示“你的人格”和结果类型码，右侧显示一个或两个元宝；含 `X` 时，小号解释文字必须紧接在类型码下方，不单独占据横跨表头的一行。
- 元宝图片不使用卡片描边、外框或额外身份标签。中文人格名称只在对应元宝下方出现一次，页面其他位置不重复；双角色尺寸和层级必须相等，也不得用“主类型 / 次类型”排序。
- 角色图使用固定正方形可视槽，按清单中的 `visual_offset_y` 在槽内移动源画布，使不同导出组的主体底部落在同一视觉基线；不得通过改变某一角色的显示宽度来伪装对齐。
- 元宝图与相邻图注表达同一身份时，图片使用空替代文本，由图注承担读屏名称，避免重复播报。
- 含一个或多个 `X` 时统一说明为“X表示你同时具有两种倾向”；候选角色仍按上方确定性规则选择，正文不再维护另一套单 X / 多 X 提示文案。
- 直线作答继续只给重测提示，不展示角色、类型称呼或人格洞察。
- 元宝图片、称呼、资源哈希与选择结果都不得写入 `PERSONALITY_RESULT_V1`；复制交接仍然只包含四轴连续值与大五原始均值。
- 更换任一角色图时，必须重新导出 320×320 WebP、更新清单哈希和视觉偏移，并通过资源完整性、归一化基线、X 分支上限、离线构建和交付校验测试。
