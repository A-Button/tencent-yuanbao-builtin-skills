# AGENTS.md 生成指南

## 概述

本文档详细描述如何基于代码分析结果生成 AGENTS.md 文档。

## **CRITICAL** 输出规范

- **文件命名**: 文件名 `AGENTS.md`，存放于目标目录根目录
- **长度控制**: 文档总长度控制在 500 行以内，模块概述 100 字以内，单个功能描述 50 字以内
- **语言规范**: 使用中文（zh-CN），专有名词首次出现提供中英对照，代码块中保持原始英文名称
- **内容聚焦**: 仅输出与代码逻辑、业务功能直接相关的内容，**禁止**输出以下无关内容：
  - 构建配置（webpack、vite、rollup、esbuild 等）
  - 打包脚本和构建流程
  - CI/CD 配置
  - 代码格式化/Lint 配置（eslint、prettier、biome 等）
  - 测试配置文件（jest.config、vitest.config 等）
  - 环境变量配置文件说明
  - Docker/容器化配置
  - 部署脚本和发布流程

## 生成流程

### 0. 读取分析结果

从 `.analysis-temp.md` 临时记录文件中读取所有代码分析结果。

### 1. 内容整合

#### 1.1 提取核心信息

从分析记录中提取以下关键信息：

- **模块职责**: 识别模块的主要用途和核心价值
- **功能列表**: 汇总所有主要功能点
- **架构特点**: 识别使用的设计模式和架构风格
- **依赖关系**: 整理内部和外部依赖

#### 1.2 功能分组

将相关功能按照以下维度进行分组：

1. **按业务领域**: 如用户管理、消息处理、数据存储等
2. **按技术层次**: 如 UI 组件、业务逻辑、数据层等
3. **按使用场景**: 如初始化、运行时、清理等

### 2. 生成文档

按照文档模板格式生成各章节内容，按照**文档生成规范**生成 `AGENTS.md` 文档。

### 3. 文档质量检查

将生成的 `AGENTS.md` 文档和 `.analysis-temp.md` 一起进行质量检查，确保文档内容完整、准确、易读。

### 4. 删除临时文件

删除 `.analysis-temp.md` 临时文件。

### 章节编写指南

#### 使用场景（**CRITICAL**）

**重要性**: 文档中最重要的章节，必须优先编写。

**要求**:
- 列出所有主要调用位置（通过 `search_content` 验证）
- 说明触发时机（点击、Hover、页面加载等）
- 说明传递的参数

**示例（UI 组件）**:
```markdown
## 使用场景

### 触发入口
1. **消息右键菜单**（`conversation/components/context-menu/`）
   - 触发时机: 右键消息 → 选择"转发"
   - 传递数据: 消息内容、消息 ID

2. **多选浮动栏**（`conversation/components/multi-select-floating-bar/`）
   - 触发时机: 选中多条消息 → 点击"转发"
   - 传递数据: 消息 ID 列表
```

**示例（Hooks 模块）**:
```markdown
## 使用场景

**useShareToWechat**（微信分享）
- 调用位置:
  1. `shared/invite-dialog/` - 邀请卡片的"微信邀请"按钮
  2. `conversation/components/multi-select-floating-bar/` - 多选消息后分享
- 触发时机: 点击"微信邀请"或"分享到微信"按钮
- 传递数据: 分享标题、描述、缩略图 URL
```

#### 模块概述

**要求**:

- 1-2 段文字，控制在 100 字以内
- 说明模块解决什么问题
- 突出核心价值和主要特点

**示例**:

```markdown
## 模块概述

聊天输入模块负责处理用户消息的输入、编辑和发送。支持文本输入、文件上传、表情选择等功能，并集成了输入状态管理和消息发送队列。
```

#### 目录结构

**要求**:

- 只展示关键目录和文件
- hooks 文件每个都需要展示
- 使用树形结构展示
- 为重要文件添加简短注释

**示例**:

```
ChatInput/
├── index.tsx # 主组件入口
├── ChatInput.tsx # 输入框组件
├── hooks/
│ ├── useInput.ts # 输入状态管理
│ └── useSend.ts # 消息发送逻辑
└── components/
  ├── Toolbar/ # 工具栏组件
  └── EmojiPicker/ # 表情选择器
```

#### 核心功能

**要求**:

- 使用详细格式描述所有功能
- 每个功能包含用途、实现、特点三个维度
- 避免过于细节的描述

**格式模板**:

每个功能包含用途、实现、特点三个维度：

```markdown
### 消息发送

- **用途**: 处理用户消息的发送流程
- **实现**: `useSend.ts` 中的 `sendMessage` 函数
- **特点**: 支持重试机制和发送队列

### 输入状态管理

- **用途**: 管理输入框的状态和文本编辑
- **实现**: `useInput.ts` 中的 `useInputState` Hook
- **特点**: 支持撤销/重做、草稿保存
```

#### 使用场景

**要求**:

- **必须包含**: 所有模块文档都必须有此章节
- **章节位置**: 紧跟在"模块概述"之后
- 列出所有主要调用位置和触发时机

#### 可选章节

以下章节根据模块复杂度选择性添加：

| 章节     | 添加条件                               | 优先级 |
| -------- | -------------------------------------- | ------ |
| API 参考 | 模块有明确的对外 API 或者组件的 Props | 中     |
| 技术架构 | 架构复杂或使用特殊设计模式             | 低     |
| 最佳实践 | 有重要的使用建议                       | 低     |
| 注意事项 | 有重要的限制或约束                     | 中     |
| 依赖关系 | 依赖关系复杂或有重要的外部依赖         | 低     |

**禁止添加的章节**:
- ❌ "性能优化" - 这是通用开发知识，不属于业务文档
- ❌ "最佳实践" - 除非是业务特定的实践，否则不要添加
- ❌ "开发指南" - 通用开发技巧不要写入

## 内容质量检查

### 使用场景检查（**CRITICAL**）
- [ ] 是否包含"使用场景"章节
- [ ] 是否列出所有主要调用位置
- [ ] 是否说明触发时机和传递参数

### 简洁性检查
- [ ] 是否删除了通用性能优化、最佳实践等通用知识
- [ ] 是否删除了构建配置、测试配置等无关内容
- [ ] 是否避免了冗余描述

### 准确性检查
- [ ] 功能描述是否与代码实现一致
- [ ] 文件路径、触发时机是否正确

### 交叉验证

生成文档后，需要进行以下验证：

1. **功能覆盖**: 检查分析记录中的所有主要功能是否都已包含
2. **路径验证**: 确认文档中引用的文件路径都存在
3. **术语一致**: 检查专有名词使用是否符合规范
4. **格式规范**: 确认 Markdown 格式正确
