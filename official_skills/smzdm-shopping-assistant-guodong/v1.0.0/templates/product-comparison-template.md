# 商品对比模板

用于两个及以上明确候选。先做出选择，再用少量关键差异解释，不写“都不错，看需求”。

## 开场方向（内部骨架）

不要原样输出本标题。开头用一两句提示最关键的差异与选择方向：例如“更在意 {需求 A} 时，{型号 A} 更合适；{需求 B} 是优先级时，{型号 B} 更有优势”。只有用户约束清晰、差异明确且证据充分时才直接点名首选。首次出现的每个型号，如果已确认详情页 URL，使用 Markdown 文本超链接。

## 关键差异

| 对比项 | {型号 1} | {型号 2} | 影响 |
|---|---|---|---|
| {会改变选择的维度} |  |  |  |

只放 3–5 项；维度应直接对应用户场景，例如清洁、续航、舒适度、性能或售后。不要重复参数表与功能表。

## 各自适配与代价

每个型号用一小段说明：

- **更适合谁**：与用户的具体诉求绑定。
- **明显优点**：最多 3 条。
- **需要接受的代价**：最多 2 条。

## 最终建议（按需）

- {用户画像/关键诉求} → {更适合的型号}，因为……
- {用户画像/关键诉求} → {更适合的型号}，因为……

不要原样输出本标题。仅在前文仍需结合用户约束收敛时保留；有明确首选时，用一句话说明首选与备选。不要写奖杯、星级或空泛的“按需选择”。

## 风险提醒（按需）

仅在存在未被“代价”覆盖的独立风险时保留；不要求固定数量。优先 1–2 条与当前候选直接相关、可据此行动的提醒，不加入无依据的渠道或价格内容。
