# 用户确认后的题库发布

只在用户明确确认指定样本版本准入时使用。不能由“生成好了”“自审通过”“看起来不错”推断准入授权，也不因历史上其他样本获批而自动收入本次样本。

1. 确认来源目录、专题ID、版本和目标题库。优先使用用户指定路径；本机已配置路径见local-eval-bank.json。路径不存在/在另一台机器无法识别时先确认，不凭文件名把用户整个目录移动过去。
2. 重验实际源文件及Hash、历史/问题隔离、任务映射、逐字证据和最终复审报告。若确认后内容改变或发现阻断，先解释并取得该修订版本的批准。
3. 在题库`topics/<topic-id>/<version>/source/`保存源包的原样副本。通过暂存与校验后发布，不覆盖同名版本。相同版本/Hash重复请求应只核验已有条目；不同Hash同名版本必须拒绝覆盖。
4. 版本目录保存`entry.json`（相对文件入口、精确Hash、schema/评分协议、题目与允许历史）、`admission.json`（批准文本/时间、批准的版本与源Hash、检查结果及已知局限）、专题说明。`catalog.json`登记精确topic/version/entry Hash，历史目录修订保留；运行不解析隐式latest。
5. 准入状态记录在新admission外层，不为把pending改成admitted而修改原source/manifest，破坏既有Hash。解释原manifest记录的是当时交付状态。
6. 默认保留原目录，验证副本和目录登记后报告正式入口。删除、移动清理或修改旧位置链接需要另外明确授权。整个工作区、凭证、无关附件和实验输出不得混进题库。

题库只持有源历史、留出问题、Rubrics、接入与审阅材料；第三方生成的Event/MU/EU、答案和跑分保留在独立实验目录，按topic/version/Hash引用题库。收录不等于已实测有效，也不强制把不同专题的评分口径统一成同一套阈值。

如果环境无文件权限，交付准入方案/待执行清单，不声称已发布。修改目录索引时核对并发变化，避免覆盖他人的新增条目。
