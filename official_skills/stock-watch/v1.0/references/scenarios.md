# 四个场景的完整步骤

咨询建议 / 异动监控 / 到价提醒 / 资讯查询，逐场景的取数、回答、出卡、发动态。

## 场景一：咨询建议 & 询问是否创建盯盘

用户带着持仓/自选来问「怎么操作」。只读咨询，不启用任何规则。

发不发 Now 动态看这一轮用户**提没提盯盘**，不看当下有没有 Thing：

- **只问怎么操作、没提盯盘** —— 只出主对话 A2UI，不发动态。
- **已经在盯盘里，问股票或盘面** —— 发 **1 张** `stock`，不追发全清单总结。
- **这一轮提出要盯**（「帮我盯一下 Meta」「加入盯盘」，包括答完第 5 步他说好）——
  走「创建」，**必发那张 `stock` 盘面卡**。Thing 是这一轮现建的，不构成不发的理由。

0. **要判断开没开盘、或要在回答里说「现在几点」，先 `TZ='CST-8' date '+%Y-%m-%d %H:%M %A'`。**
   会话历史里的时间戳是上一轮的，照着推会把盘中说成休市（见 SKILL.md 那条）。
1. 缺代码先 `westock search`。一次并行取数（批量）：`quote` + `technical` + `fund flow` + `news list` + `report list` + `events`（配方见 data-recipes.md 场景一），需要更深再补 finance / consensus / rating / chip。
2. **K 线只取数、不出图**：`westock kline` / `technical` 照常拉，写进下一步的分析和 `show_advice`。不要 `load_app(stock-kline)`，不要跑 `emit_kline.py`。取数这一步本身不发动态，发不发看第 4 步。
3. 回答**结论先行** ：一句总判断 + 逐个股票的分析（技术面+资金面+消息面综合）+ `现价/涨跌幅`（沪深京港涨红跌绿，美股绿涨红跌），注明数据时刻与币种；休市只报最近交易时刻。数据取不到如实说，不编造点位。
   同一轮用 `show_advice` 把这些结论落成一张卡，每只票一行「名称 代码 · 建议标签」+ 现价涨跌 + 一行理由：

   ```bash
   python3 /data/skills/stock-watch/scripts/_run.py show_advice '{"basis":"基于实时行情 + 基本面","footer":"想看更细的资金流向、估值或历史走势，随时继续问我。","items":[{"code":"sz300750","name":"宁德时代","price":9.12,"change":0.52,"change_pct":6.05,"as_of":"09/21 15:00","as_of_kind":"close","advice":"持有","reason":"放量突破前高，储能订单催化；短线涨幅偏大，回落到 8.6 附近再加。"}]}'
   ```

   `advice` 与 `reason` 必须来自第 1 步取到的数据，**这张卡只要文字不要数据，最容易被拿来编**。
   `reason` 必须在 30 个字符以内，只写一句最关键的依据；完整技术面 / 资金面 / 消息面
   放在对话正文，不要把整段分析塞进卡里。
   `basis` 据实写：没查基本面就不要写「基于实时行情 + 基本面」。
4. **已有盯盘 Thing、问的是股票或盘面**，**或者这一轮用户提出要盯**：同一轮按「Now 动态发什么卡」发 **1 张** `stock`（`items` 放今天要盯的，最多 3 只），**就这一张，不要再追一张全清单 `recommend_list`**——那张是 20:00 收盘日结专用。只有「纯问怎么操作、全程没提盯盘」才跳过这一步——**别拿「刚建的 Thing 不算已有」当借口跳过**。
5. 答完主动询问：「要不要把这几只加入长期盯盘」。用户同意 → 走「创建」，把标的、持仓/自选属性沉淀为 Thing/Todo，并把本轮 `stock-watch` 的稳定 App ID 合并进新建 Thing 的 `mcp_app_ids`（不要绑 `stock-kline`）。**建盯盘任务默认开启异动监控 + 每晚 20:00 资讯汇总**（见「创建」），到价/止损提醒按用户明确要求再加。用户只要行情、明确不通知 → 到此结束，不启用规则。已在盯盘里则无需再问一遍。
6. 客观陈述数据，**一定**要附风险声明，不构成投资建议。

## 场景二：异动监控（在已有盯盘 Thing 下）

用户要监控异动时：标的已在盯盘 Thing 下（通常由场景一沉淀）就在该 Thing 下确认/补建异动 Trigger；**尚未盯盘则先按「创建」新建盯盘 Thing（默认即含异动监控）**。Judge 只用原生 `stock_market_data`。

**默认异动规则**：`量比（volumeRatio） ≥ 2` **且** `涨跌幅绝对值 ≥ 5%`（涨、跌都算异动），两条同时满足才命中。用户可按标的覆盖阈值。condition 明确比较最新返回值与阈值；空数据、缺日期、错误或含义不清不算命中，也不凭推测启用。

⚠️ 建规则前先用 `stock_market_data` 实测该标的返回里**是否含量比字段**：若原生工具不返回量比，则该规则降级为仅 `涨跌幅绝对值 ≥ 5%`，如实告知用户「量比暂不可判、仅按涨跌幅触发」，不臆造量比值。

命中后走「回调与动态」发一条 Now 动态：先用 westock `news list` + `events` + `fund flow` 做**异动归因**（一句异动原因，取不到就写「暂无明确消息面」，不编造），再用 `show_anomaly` 出盯盘卡（标的 + 现价涨跌 + 量比 + 归因）。**不要再调 `emit_kline.py`。** `grade` 如实写：扶摇未接入前只能是 `inferred` 或 `unknown`；量比取不到就整个字段省略，不要填 0 冒充。

## 场景三：到价提醒

用户提到「监控某价位/跌到 X 提醒我/涨到 Y 提醒」时，在该股票的盯盘 Thing 下按「创建」建到价 Trigger；**尚未盯盘则先新建盯盘 Thing 再加到价规则**。到价提醒不随建盯盘默认开启，只按用户明确的价位要求建。

规则按实际结果启用（或明确保持停用）之后，用 `show_alert_set` 出一张「已为 X 设置 Y 提醒」的盯盘卡。
**卡上只陈述条件本身**：规则仍停用、授权未完成或启用失败时，正文写「已记下观察，规则尚未运行」，不能写「已开启」。

到价单独建一条规则，不跟异动合并，写法见 [triggers.md](./triggers.md)「两类规则」：Judge 调 `check_anomaly`，传 `mode: alert` 和 `alert_price` / `alert_direction`，condition 只读 `triggered`；单独挂一个到价 Todo。命中后走「回调与动态」发一条到价动态，用 `show_alert_hit` 出盯盘卡（标的 + 现价涨跌 + 触发条件）。**不要再调 `emit_kline.py`。**

## 场景四：资讯 / 公告 / 研报查询

用户问某股的资讯、公告、研报时，**westock news 为主 + web_search 兜底**，整理成 **item 卡片**回答。问的是某一条/某只的细节，回答走主对话 `show_news`，不发动态。**问资讯总结 / 今日资讯 / 我盯的票有什么新闻**，且已有盯盘 Thing，按「Now 动态发什么卡」发一张 `recommend_list`，不要再附股票卡。

1. 取数：`westock notice list --type` + `news list` + `report list` + `events`（配方见 data-recipes.md 场景四）——近期、结构化、权威，优先。
2. **web_search 兜底**：westock news 只覆盖**近期**且范围有限；当用户**指定较早时间段/历史公告**，或 westock 返回为空/不足时，用 web_search 按用户指定时间补搜公告与资讯。整合两源、按标的与时间去重、标明来源（区分 westock / web）。
3. 加工：**按重要度排序**（重大公告 / 评级或目标价变动 / 关键事件 > 一般新闻），每条标 `利好/利空/中性`（利好红、利空绿）+ **一句话解读**（对股价潜在影响）+ 来源 + 时间；判断依据来自内容本身，拿不准标「中性/待观察」，不臆断。
4. **展示成 item 卡片**：用 `show_news` 出资讯卡，每条一行（标题 / 彩色标签 / 「时间 · 来源 · 一句话解读」）：

   ```bash
   python3 /data/skills/stock-watch/scripts/_run.py show_news '{"source_line":"来自「资讯监控」· 盯盘 2 只 · 每晚 20:00 汇总推送","summary":"已按重要度排序，盘中重大消息此前已即时推送。","items":[{"kind":"notice","code":"sz300750","name":"宁德时代","title":"签订海外储能大单","stance":"利好","published_at":"2 小时前","origin":"巨潮资讯","takeaway":"订单超预期，短期偏利好"},{"kind":"report","code":"sh600519","name":"贵州茅台","title":"中信证券「买入」","published_at":"今早","takeaway":"目标价上调至 1900"},{"kind":"news","title":"财经新闻 · 锂价止跌反弹","published_at":"昨晚","origin":"财联社","takeaway":"成本端边际改善"}]}'
   ```

   **盯了几只票就把它们的资讯合成一张卡**，归属标的逐条给（`code` + `name`），没有归属的行业新闻省略这两个字段。
   标签规则：给了 `利好` / `利空` 就标方向，否则退回标类型（公告 / 研报 / 事件 / 新闻）。
   **拿不准就别给 `stance`**——标类型是陈述事实，标方向是下判断。资讯类不挂 stock-kline K 线。
5. **问资讯总结且已有盯盘 Thing**：同一轮再按「Now 动态发什么卡」发 1 张资讯 `recommend_list`，覆盖关注标的今日资讯，不要附 `stock` 卡。问的只是某一条公告细节则跳过。
6. **回流闭环**：若该标的尚未盯盘，答完可顺势提议「加入盯盘后每晚自动汇总资讯」，同意即走「创建」。已盯盘则无需重复提议。

主动推送（走「回调与动态」的 `show_widget`，前提是该标的已在盯盘 Thing 下并开启了资讯监控）：

- **每晚 20:00 收盘日结** —— 每日固定时间的原生 Trigger，收盘后一次推**两张**（版式见「Now 动态发什么卡」）：先一张盘面总结 `recommend_list`（覆盖清单全部标的的收盘行情，清单非空就发），再一张资讯 `recommend_list`（聚合当日新资讯，当日无新资讯就只发前一张，不打扰）。禁止 create_timer。
- **盘中重大即时** —— 命中重大公告/评级剧变时即时推送到 Now，同样用资讯 `recommend_list`，不要改发 `stock` 卡。
