# 小程序入口

目标：先确认入口符合用户当前需求，再交付一张小程序卡。用户要入口时，加载本技能后先查询，不凭记忆直接回答“去微信搜索”。

## 查找并选择

1. 从本轮和上文提取小程序名，或事项、办理地、机构／院区。已有信息直接沿用；只有缺失信息会改变入口时才问一个必要问题。定位不等于办理地。不要为了查全国性平台追问城市。
2. 按宿主提供的 schema 调用 `wxa_recall`；若为延迟工具，用宿主 `DeferExecuteTool` 调用它。`query` 只含小程序名或办理事项；需要地区时用已知办理地限定。只传实际需要、schema 支持的字段，不传个人原始材料。工具不可用时走下文降级，不猜接口。
3. 在 `app_list` 中核对名称、服务、地区、机构与用户预期。指定“京通”就找京通，不换成名称相近的其他平台；“办进京证”等事项不能仅按关键词把同名商业代办推荐为官方入口。简介和功能词是筛选线索，不是官方身份或业务覆盖证明。身份／适用范围不清时，用官方机构网页核对；仍有歧义就追问或降级。最多一次针对性细化检索，不循环泛搜。
4. 确认匹配后只选一个。可复用本会话已核对且事项、地区、机构均未变化的结果；用户改了目标，重新核对。只有候选列表、尚未核对，不能视为已经匹配。不要把多个候选都做成卡让用户替你筛选。

## 单独交付入口

从选中的真实候选里原样提取 `basic_info.username`、`basic_info.nickname`，以及存在时的 `basic_info.head_img_url`，组成仅含 `basic_info` 的 JSON；不增加任何其他字段。用宿主 `write` 保存到本轮唯一的 `/data/workspace/` JSON 文件，再调用：

```text
python3 /data/skills/service-entry-finder/scripts/_run.py build_card --input /data/workspace/本轮入口.json
```

文件名由本轮自行确定，不覆盖其他任务的文件。输入文件只是工具参数，不是交付物，不调用 `present_files`。同一结果只调用一次构卡入口；不要直接运行 `build_card.py`。被其他 Skill 使用时，由当前 Agent 执行以上流程，调用方不再重复发卡。

卡片由包内固定模板与结构化事件交付客户端，默认打开小程序首页。脚本负责参数校验和映射，模型不设计卡片协议、不猜页面路径、不拼 URL Scheme。**禁止在正文补写任何入口卡 `<media_info>`、卡片 JSON、`wxapp_card`、`miniprogram_card` 或 `button`；也不调用 `show_widget` 或创建 Thing／Todo／Trigger。** 不根据脚本返回再构造第二份卡片。

正常完成后至多一句“京通入口。”这类简短说明；卡片已表达名称时不重复说明。不罗列功能、跨平台入口、办理步骤、政策、免责声明或“如果点不开”兜底。入口任务完成即收尾，不主动追问下一项业务；若宿主更高优先级规则强制要求追问表单，仅遵守其合法格式，不将入口跳转参数塞进表单。

## 失败与边界

- 无匹配或身份未确认：说清尚未找到可靠入口，必要时只问办理地或机构；不把未确认候选出卡。
- 检索／构卡不可用：一句说明，附已核实的官方网页，或“可在微信搜索「已确认名称」”。没有确认名称就不编造。不要以正文卡片标签“补救”。
- 脚本 `card_emitted` 仅表示已生成并发出结构化事件，不证明客户端可见或微信已打开。结果未知时不盲目重复构卡，不声称“卡片已经显示／肯定能打开”。客户端明确反馈无法打开时再给文字替代。
- 入口不表示有号、符合资格或办理成功。不登录、填报、预约、支付或提交申请，不改变其他业务的记录与提醒。
