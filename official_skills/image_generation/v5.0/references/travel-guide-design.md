# 旅行攻略长图

## 一、目标

读取一段用户提供的纯文本旅行描述（行程、路线、想去的地点、目的地或玩法），提取其中的行程要点，研究目的地视觉特色，并直接调用生图模型生成一张完整的竖向旅行攻略图。

- 适合约 390px 宽的手机浏览与社交分享。
- 忠实使用用户纯文本里已写明的行程，**不重新规划、不擅自增删地点、不改变顺序**。
- 只输出一张完整图片，不生成组图、分页、网页、文档或排版代码。
- 参考图只用于学习视觉语法，不照搬其信息量、文案、签名短句、装饰符号和固定构图；成图必须具有可识别的原创变化。

## 二、工作流（主控流程）

```text
1. 读取用户的纯文本旅行描述，判断其确为旅行相关内容；否则停止并说明。
2. 提取用户偏好、核心目的地、天数/日期、核心地点、推荐路线与交通衔接（用户写到什么程度就用什么程度，不硬造）。
3. 建立信息清单：保留全部行程信息，剔除非行程元数据（见"信息准入"）。
4. 搜索核心目的地的人文、景观、美食特色，生成 destination_visual_profile。
5. 用户未指定风格时执行"风格路由"，仅按目的地主导特色选出大风格（人文城市→手帐 / 风景环境→海报 / 美食亲子→卡通；不看信息密度）。
6. 在大风格内选子风格：手帐风按天数（1 天→H3，2 天及以上→H2）；
   实景感海报风按天数（单日→P1 电影感沉浸封面 / 多日→P3 杂志收藏式）；
   卡通拼贴风按主题（景点打卡→C2 青春照片拼贴 / 美食攻略→C3 美食福利地图）。
7. 按天数、路线结构、信息量选择"信息版式"，并设计字体层级。
8. 组织一条完整生图指令（含文字白名单、文字禁用项、锁定比例与 2K 尺寸），调用生图模型生成整图。
9. 直接展示最终成图；除非用户询问，不输出内部评分、风格编号、搜索过程或提示词。
```

## 三、全局锁定项（唯一权威，优先级最高）

以下为不可协商的硬标准，适用于所有大风格、子风格与版式；其他章节如与本节冲突，以本节为准。文中其他位置一律引用"见全局锁定项"，不重复展开。

### 3.1 画幅与分辨率

- 所有成图固定 `2:3` 竖版，**任何风格、信息密度或参考图都不改变此比例**。
- 交付为原生高清 2K，目标约 `1707×2560px`；模型仅支持离散尺寸时选最接近的 `2:3` 原生尺寸，长边不低于 2560px。
- 不接受 `3:4`、`3:5`、`9:16`、`1:2`、异常长图或低分辨率交付，也不得靠裁切/拉伸/补边伪装成 2K。
- 生图指令必须明确写入"2K、高分辨率、文字边缘清楚、细线完整"。

### 3.2 文字保真（第一风险，优先级高于信息密度）

- 成图只能出现"文字白名单"中的文案；标题、日期、DAY、时间、地名、交通、说明都必须逐字可辨。
- 禁止乱码、伪字、错别字、缺字、粘连、断笔、重复字符、异常标点、无意义文字，以及脏话、辱骂、歧视或其他不当文本。
- 关键文字放在纯净、低复杂度背景上；不用过小字号、过度变形字体、重纹理、强倾斜或低对比描边牺牲识别性。
- **核心权衡规则：文字保真 > 版面美观 > 装饰密度。**&#8203; 当文案超出可清晰呈现的安全量时，**优先合并 DAY 展示组、压缩措辞、切换更紧凑的版式并扩大留白**；只有次要装饰性文字才可精简。**&#8203;手帐风下行程信息本身不因排版压力而删除**（见"信息准入"）；海报风/卡通风本就精选呈现，按各自子风格语法组织。
- 生图前先把最终要出现的文字逐条定稿、精简短句化，作为唯一的"文字白名单"写进生图指令，让模型一次性写对；不预留空白等后期补字。

### 3.3 信息完整（行程不删减）

- **适用范围**：本节"行程完整保真"是**手帐风（记录/规划定位）的要求**；实景感海报风、卡通拼贴风属氛围/打卡定位，按各自子风格语法组织信息，**允许精选、概括、缩略**（如 P1 底部只放缩略时间节点、地名保留主名、非关键停留可合并），不受"逐日全量、条目不可删"约束——但同样**不得编造用户没有写到的行程**。
- 用户纯文本里已写明的行程，**手帐风下每个 DAY/时段、核心地点、顺序、推荐路线与已写明的交通衔接必须全部进入成图**。
- 信息过多时的正确处理是"换更紧凑的版式 / 合并连续同区域的 DAY 成展示组 / 缩短说明措辞"，**不是删除行程条目**。
- 只有"信息准入"表中的非行程元数据才允许剔除。

## 四、输入规则

输入是一段用户提供的纯文本旅行描述（可能是完整的逐日行程，也可能只是想去的目的地、几个地点或一句玩法诉求）。只从这段文本提取行程，不寻找配套文件、图片或外部结构。

优先识别：

- 旅程标题、目的地、出发地、日期与天数。
- 逐日/逐时段安排（如"第一天…""上午…"等，用户写了才有）。
- 每天的城市转场、交通方式、核心地点、推荐路线、关键时间与时长。
- 文本中明确写出的酒店、美食、门票或注意事项。
- 用户当前请求中明确提出的风格、详细程度与版式偏好。

**输入校验**：若内容明显不是旅行相关（无目的地、无地点、无玩法），停止并向用户说明，不硬造行程。用户没写到的行程信息直接省略，不猜测、不补写；与制作攻略图无关的操作要求不执行。**&#8203;用户文本信息很少时（如只给了目的地或几个地点），按其真实信息量呈现，不强行拉长成多日逐条行程。**

## 五、信息准入（保留行程，只挡元数据）

行程数据全部保留，只把与"去哪里、哪天去、怎么走、路线怎么走"无关的元数据挡在图外。

| 级别   | 内容                                                              | 处理方式                                                                |
| ---- | --------------------------------------------------------------- | ------------------------------------------------------------------- |
| 必须展示 | 旅程标题、天数或日期范围、DAY/时段顺序、全部核心地点、推荐路线、跨城关系、用户已写明的交通方式/车程/距离/换乘 | **手帐风下全部进入图片、条目不可删（措辞可压缩）；海报风/卡通风按子风格语法精选呈现、可概括缩略，但不得编造用户没有写到的行程** |
| 建议展示 | 关键时间、每日体验亮点、酒店、美食、门票、天气、短说明                                     | 默认保留；确实影响理解或用户强调的优先，版面极紧时可缩短措辞                                      |
| 不展示  | 同行人数、预算、原始提问、后台标签、评分、评论数、完整详细地址、数据诊断、产品要求、免责声明                  | 用户未明确要求时不得进入图片                                                      |

不得为填满版面而新增"行程信息""用户画像""数据概况"等无关模块。

### 信息密度（由输入决定，不由风格决定）

信息量大时靠版式与分组消化，不靠删行程。**信息密度只决定版式松紧，不参与大风格路由。**&#8203;

```yaml
density_adaptation:
  low:   { hero: 较大,       structure: 宽松单列或少量节点,   text: 完整列出核心地点，可多留白 }
  medium:{ hero: 中等,       structure: 单列章节/路线节点/双列卡片, text: 每日逐条列出景点+交通+住宿 }
  high:  { hero: 较小或独立封面区, structure: 紧凑双列/网格/分组路线, text: 保留主题、全部核心地点、交通与住宿，只压缩长句措辞 }
```

**信息量默认偏高（仅手帐风）**&#8203;：命中**手帐风**时，输入按"信息丰富的攻略册"呈现——每个 DAY 逐条列出各景点/餐厅/活动（有序号更好），保留该日交通方式、时长、距离、价格与住宿，不概括成一句主题短语。**&#8203;海报风/卡通风不受此约束**：它们本就是主景/打卡氛围优先，信息按子风格语法精选与概括（如 P1 只放缩略时间节点）。

- 信息少：增加留白与主视觉占比，不硬凑文案。
- 信息多：压缩说明措辞、合并连续同区域 DAY 为展示组、减少装饰图或切换紧凑结构；**核心地点与推荐路线始终保留**。
- 同一段文本切换大风格时，旅程概览、每日骨架、核心地点、推荐路线与关键交通保持一致，风格只改变表达方式与素材权重。

## 六、目的地特色研究

解析用户文本后、选择风格前，用可用搜索能力研究**实际停留游玩的核心目的地**（不研究所有途经城市）。搜索只增强画面地域识别度，**不修改用户行程**。

| 类别 | 搜索内容                    | 画面用途              |
| -- | ----------------------- | ----------------- |
| 人文 | 标志建筑、历史文化、传统工艺、节庆、城市生活  | 建筑轮廓、纹样、人物活动、装饰细节 |
| 景观 | 地貌、植被、水系、季节、气候、天际线、典型色彩 | 主视觉、背景、配色、环境氛围    |
| 美食 | 代表菜品、小吃、食材、餐具、市场与街巷饮食   | 局部场景、拼贴素材、装饰元素    |

优先使用权威旅游、文化遗产、地方机构与多源一致的信息；无法确认的元素不使用。搜索不可用时，只用用户文本已有信息与可明确判断的通用视觉元素。

搜索后在内部生成：

```yaml
destination_visual_profile:
  primary_destinations: 1至3个核心目的地
  user_focus: 自然 | 人文 | 美食 | 亲子 | 摄影 | 综合
  landscape: 1至2个高辨识度景观元素
  culture: 1至2个高辨识度人文元素
  food: 0至2个与用户需求相关的美食元素
  palette: 3个主色和1个强调色
  hero_candidate: 一个最适合主视觉的场景
  hero_visual_strength: 强 | 中 | 弱   # 目的地是否有风光大片/强地标属性，供风格路由用
  trip_vibe: 规划编排 | 风光氛围 | 轻松打卡   # 旅程主导气质，供风格路由用
  title_font_mood: 与目的地气质匹配的标题字体调性（如 荒野草原自驾→毛笔书法/苍劲手写；欧洲古城浪漫→精致衬线/轻手写；都市摩登→高级现代无衬线；冰雪极地→清冷细劲字形；水乡古镇→秀雅宋楷）
  supporting_motifs: 2至4个辅助元素
  avoid: 容易误导或与目的地无关的元素
```

每张图最终只使用 3–5 种目的地元素。搜索到的新景点/美食**只能作为不带行程含义的视觉素材**，不得写进 DAY 行程或说成用户已安排的餐厅。

| ------- | --: | --: | ----: |
| 自然观光、自驾 | 60% | 25% |   15% |

## 七、风格路由

**路由只看目的地主导特色这一个维度**：这趟旅程去的核心目的地、玩的主导气质是"人文城市 / 自然风景 / 美食亲子"中的哪一类，就走对应大风格。**&#8203;用户需求（明确指定的风格）优先级最高；信息密度、天数、信息多少一律不参与判定**（它们只在选定风格后决定子风格与版式松紧）。

三类大风格与三类目的地特色一一对应，目标是让三者命中比例大致均衡（各约三分之一）：

- **人文 / 城市 / 古城历史** → **手帐风**（记录与规划定位：讲清逐日怎么走、走哪几站、怎么衔接，路线地图＋逐日信息）。
- **风景 / 自然环境 / 山海湖泊旷野** → **实景感海报风**（氛围与大片定位：一幅写实主景传达目的地情绪与美感）。
- **美食 / 亲子 / 主题乐园** → **卡通拼贴风**（轻松与打卡定位：活泼年轻有趣味，强调打卡感与美食诱惑）。

### 路由判定步骤（按序执行，命中即定）

```text
1. 用户显式指定风格 → 直接服从，跳过后续。

2. 判断目的地的【主导特色】是三类中的哪一类，据此路由：
   - 主导为【人文历史 / 城市街区 / 古城古镇 / 建筑文化】 → 手帐风
   - 主导为【自然风景 / 山海湖泊 / 峡湾雪山 / 草原旷野 / 度假环境】 → 实景感海报风
   - 主导为【美食探店 / 亲子玩乐 / 主题乐园 / 萌宠市集】 → 卡通拼贴风

3. 复合特色（目的地同时具备两三类特色，如京都=人文+美食、三亚=风景+亲子）：
   看【用户这趟主要为什么去、旅程的主导玩法是什么】来定其中一类为主导——
   为吃/带娃玩为主 → 卡通；为看风光/度假为主 → 海报；为逛人文古城/深度游为主 → 手帐。
   不设固定优先级、不让任何一类默认兜底，按行程实际气质取真正占主导的那一类。
```

**均衡原则（唯一自查）**&#8203;：判完回看一句——三类目的地特色本身在真实旅程里就大致三分天下（人文城市游、风光度假游、美食亲子游各占一大类），**不要因为习惯或信息量把行程都往某一类塞**。若发现连续多次都命中同一风格，检查是不是把复合目的地的"主导特色"判偏了，回到第 3 步重判。

实景感海报风指生图模型生成的写实旅行视觉，**不冒充用户实拍照片，也不标注"实拍"**&#8203;。

## 八、三类风格及子风格

每个子风格是可复用的视觉语法，不是固定模板；实际内容量按信息密度重新排版。

### A. 手帐风

| 子风格          | 适用                         | 版式与图像                                                                                                                                                                                                                                     | 配色与质感                                                                                                                             | 密度兼容                                                                                            |
| ------------ | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `H2 多日路线旅行册` | 2 天及以上，需同时理解逐日安排、交通衔接与区域移动 | **标题居左上、地图占更大空间、共用同一张纸底、无分区框**：左侧竖列 2–6 张宽度舒展、统一淡底、弱边框的多行 DAY 卡（Day标签+路线标题+交通行+逐条编号景点+住宿行+一张真实照片拍立得，各卡题材各异），右侧是精致手绘水彩地图（无框无面板，柔和手绘海岸线+陆海分明不平涂+节点真实相对位置+融入不圈出的小插画+氛围插画+景点名+与卡片一致的Day标签+带小交通图标与耗时的纤细手绘虚线）；底部两层信息带承接交通方式&注意事项与通栏行程总览轴（不做成方框） | 近白冷底（约 #FCFCFA，不黄不灰）；精致、雅致的手绘水彩手帐风，柔和淡雅、低到中饱和、通透干净；全图统一手写体、同级同字号；DAY 用柔和低饱和识别色（雾蓝/鼠尾草绿/淡珊瑚/淡杏）；禁止发黄做旧、重彩、灰调、鲜艳卡通塑料感、逐卡不同底色、任何区块边框 | 2–3 天逐日展示；4 天以上把连续同区域日期合并为 4–6 个展示组，每组仍逐条列全成员日的景点、交通与住宿并配 1 张照片；卡片、地图节点、底部节点使用同一套展示组、Day 标签逐字一致 |
| `H3 单日插画游线`  | 1 天行程；步行/骑行/自驾/公交/景区串联     | 一条连续阅读游线贯穿画面，场景插画沿路线交错，补充时间、距离、总时长；**底部保留两个信息模块：「行程总览」编号轴 + 「漫游小贴士/注意事项」**                                                                                                                                                                | 精致手绘水彩、近白冷底、手写体，与 H2 同调；钢笔线稿＋淡彩                                                                                                   | 按地点数调整节点大小，保留全部核心地点与连接信息；地点少时增加留白与主场景，不虚构                                                       |

**手帐风子风格选择：`1 天 → H3；2 天及以上 → H2`。**&#8203; 天数是第一判断条件，从行程的天数或明确日期推断；仅用户明确指定时才覆盖。同一子风格可改变构图细节、配色、装饰与标题设计以避免雷同。

手帐风禁止：全页小号手写字、路线穿过文字、同图混用多种插画语言、为热闹堆叠无关贴纸。

#### H2 视觉语法

H2 = "左上角克制标题 ＋ 左侧宽度舒展、统一淡底的多日信息卡 ＋ 右侧大幅无框精致手绘水彩地图（柔和轮廓+陆海分明+相对位置+融入式小插画+氛围插画+简化导览线）＋ 底部两层信息带"。整体是**精致、雅致的手绘水彩手帐风**，全图统一**手写体**中文，配色柔和淡雅（不发黄不发灰、也不鲜艳卡通）。生图提示词开头必须先写以下四条硬要求，再写风格与内容，不用"可以、尽量、建议"等弱措辞：


- **下层一整条"行程总览"横轴**：贴着底边，从 Day1 到 DayN 用小图标/小圆点顺序串联，每个节点下写"Day N + 该日主题"，节点之间用小箭头，段间可标主要交通。此横轴独占底部最下一行、通栏排布。
  各组只用小标题（如"交通方式 & 时间参考""注意事项""行程总览"）、细线、小图标和留白区分层次；文字小而清楚、对齐整齐。输入没有的组直接省略。图标不可靠时改纯文字。禁止：底部出现独立方框/面板/色块盒子、大而空的卡片、厚阴影、虚构交通、"路线示意/以实际交通为准"等免责说明。

**底部两模块（H2、H3 等所有手帐风子风格通用，只增底部、不改上方布局）**&#8203;：无论几日行程，画面底部都在原有版式基础上保留两个信息模块——**「行程总览」**（用 ①→②→③… 编号小轴按顺序串起当日/全程节点，下方一句总结如"全程约 8km，步行为主，建议预留 8–10 小时"）与**「漫游小贴士 / 注意事项」**（3–4 条带小图标的实用要点，如舒适步行鞋、带水防晒、某处建议日落前到达等）。两块横向并排、只用小标题+图标+留白区分，不做成方框盒子。

**H2 提示词顺序**：`四条硬要求（近白冷底不黄不灰/精致手绘水彩手帐风柔和淡雅不卡通/地图无框与整页同底/地图柔和手绘海岸线+陆海分明不平涂+相对位置+融入不圈出的小插画+氛围插画+带交通图标耗时的纤细手绘虚线）→ 全图统一手写体、同级同字号 → 2:3 与"标题居左上、地图占大空间"布局 → 左上角克制手写标题+提示条+签名 → h2_groups 逐组展开（Day标签+路线标题/交通行/编号景点/住宿行/真实照片拍立得白框各卡题材各异；卡片宽度舒展、统一淡底不逐卡换色）→ 地图（柔和手绘海岸线+陆海分明+节点相对方位+融入不圈出的手绘水彩小插画+氛围插画填空+Day标签与卡片一致+带交通图标耗时的纤细手绘虚线）→ 地标插画去重且小而精不圈出 → 左卡 visual_mode(默认photo、真实照片非渲染、拍立得白框胶带、题材各异不克隆、少人) → 底部两层信息带 → 字体层级 → 文字白名单 → 禁止项`。

### B. 实景感海报风

| 子风格          | 适用                                  | 版式与图像                                                                                        | 密度兼容                                                         |
| ------------ | ----------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `P1 电影感沉浸封面` | **单日行程**；情绪旅行、旷野、公路、峡湾、摄影感，分享吸引力优先  | 一幅完整写实场景全幅铺底作绝对主体（约占 **72%–80% 高度**）、主标题/地名叠在上方主景区；底部一条**矮而透、横向排布**的信息条承载时间节点与两个小板块；不拼图、不画地图 | 底部信息条**合计不超过整图 28% 高**、**时间节点横向流式排布不竖排、默认不逐节点配图**；主体永远是那张大照片 |
| `P3 杂志手账明信片` | **多日行程**；海岛、湖泊、古镇、度假、蜜月等有强摄影主景的多日旅程 | 干净刊头＋一幅完整写实主景构成上半部；中下部 1 张撕边亮点卡、3–5 张同尺寸纵向拍立得、2–3 个纸片信息块                                     | 低：主景大＋3 张照片；中：4 张＋亮点清单；高：合并相邻 DAY 为最多 5 个照片组，压缩说明，不增加照片墙或缩字  |

**实景感海报子风格选择（按天数路由）**&#8203;：**单日行程 → P1；多日行程 → P3**。P1 靠一幅全幅主景＋底部紧凑信息承载单日；P3 靠主景＋同格式照片组＋纸张信息块承载多日，默认不画地图路线。

海报风禁止：地图与风景拼成半幅主视觉、复杂照片上堆小字、多个互相抢夺的主景、声称画面为真实拍摄。

#### P1 电影感沉浸封面固定语法（单日，直接写进生图指令）

P1 = "一幅全幅电影感写实主景（绝对主体）＋ 底部一条紧凑、横向排布、精致克制的信息条"。**核心：底部要矮、要横向、要缩略，绝不侵占主景氛围**。

- **主体与占比（主景优先）**&#8203;：那张完整写实场景照片是绝对主角，约占整图 **72%–80% 高度**；**底部信息区合计不超过整图 28% 高度**（比之前更矮）。信息区叠在照片下方渐隐的暗色/柔色带上，保证文字清晰，但**尽量矮、尽量透，不压住主景的天空/山体等氛围区**。
- **底部信息必须横向紧凑排布（关键）**&#8203;：**不要把 6 个时间节点竖排成 6 整行**——那样太高太挤。改为**横向流式排布**：时间节点按顺序**横向铺开、折成 2–3 行**（如一行放 2–3 个"时间+地名"），节点之间用小圆点/短箭头/竖细线分隔；**信息可缩略**——地名只保留主名（可省略冗长外文全称），非关键停留可合并，让整块更短。
- **节点小照片改为克制**：**默认不再逐节点各配一张照片**（那是导致底部过高的主因）。只在信息条最上沿放**一横排 3–5 张极小的缩略拍立得**（现实主义摄影、真实相机质感、非绘制），统一小尺寸、横向一排、绝不竖排堆叠；
- **字体（随目的地气质自适应、与画面融合，绝不生硬）**&#8203;：**标题字体不是固定一种，而要按目的地气质自适应选择**（参照 `destination_visual_profile.title_font_mood`）——荒野/草原/山地/自驾/公路用**苍劲有力的毛笔书法或粗犷手写笔触**；欧洲古城/浪漫海岛/蜜月用**精致衬线或优雅轻手写**；都市摩登/夜景用**高级现代无衬线**；冰雪/极地/峡湾用**清冷细劲的字形**；水乡古镇/东方人文用**秀雅宋楷或毛笔**。**&#8203;标题要与画面融为一体，不是一块生硬贴上去的白色描边大字**：字体的笔触、颜色、质感从主景中提取（如雪山/极地取冷白青灰、落日/草原取暖金、森林取墨绿），标题轻叠在主景低复杂度区域（天空/水面/雾气/草坡），用轻微投影、色调呼应或半透明与场景自然过渡；描边要极细或不描边，避免突兀的粗白描边和硬色块。字号克制偏小、留足呼吸，不撑满画面。
- **底部两个信息板块（横向并排、缩略）**&#8203;：底部再加 **「注意事项」** 与 **「推荐交通」** 两个小板块，**左右横向并排**、各 1–2 行短句、字号小；信息缩略到关键要点即可，不写成长段落。
- **主标题位置**：主景标题/地名仍放在**上方主景区**（叠在照片上、靠上或居中偏上），不要挪到底部信息条里；底部信息条只承载时间节点＋两个小板块。
- **禁止**：底部信息区超过整图 28% 高度、时间节点竖排成多整行、**标题用与目的地气质无关的千篇一律字体、生硬的粗白描边大字、与画面割裂的硬贴文字**、照片竖排堆叠或放大、在主景氛围区（天空/山体）上压密集小字、把主标题挪到底部。

**P1 提示词顺序**：`一幅全幅电影感写实主景占72%–80%高度、主景上方叠主标题/地名 → 标题字体按目的地气质自适应(见 title_font_mood)、笔触与配色从主景提取、与画面融合不生硬 → 底部一条矮而透的暗色/柔色信息条（≤28%高） → 时间节点横向流式排布折成2–3行(时间+缩略地名、小分隔符)、不竖排 → 横排3–5张极小缩略拍立得(现实主义、非绘制) → 底部「注意事项」+「推荐交通」两小板块横向并排、缩略短句 → 文字白名单 → 禁止项`。

#### P3 纯文本固定语法（不依赖任何参考图，直接写进生图指令）

```yaml
p3_editorial_plan:
  original_caption: 与本次旅程相关的原创短题记，可省略
  hero_scene: 一幅目的地写实主景（对应 hero_candidate）
  highlight_card: 3至5条短亮点
  day_photo_groups: 3至5个 DAY 或连续 DAY 展示组及对应写实场景
  polaroid_tilt_sequence: 左倾与右倾交替，奇数时中间一张可端正
  bottom_modules: 2至3个清单/引语/风物静物/吊牌
  destination_only_decor: 最多2种与目的地相关的小装饰
  forbidden_template_motifs: 与本目的地无关的固定海岛/花卉/贝壳/邮戳元素
```

- **顶部减法**：顶部约 15%–20% 是与整页连续的干净暖象牙白刊头，仅放主标题、小副标题、细分隔线、可选原创短题记与一个小型目的地邮戳；不出现撕裂横边、胶带、折角、浮起阴影、多层纸片或大面积做旧。
- **单一主景**：上半部约一半用一幅连贯电影感写实旅行场景作唯一视觉中心，不拼成半景半表格、不加第二主景。
- **亮点纸卡**：主景一侧覆盖 1 张窄幅暖白撕边纸卡，半透明胶带固定，内放 3–5 条短亮点、统一线稿图标与细分隔线，宽度不超过主景约三分之一。
- **DAY 照片组**：中下部横向放 3–5 张同尺寸、同纵向比例、同白边的写实拍立得，拍立得下方白边上补充浪漫文艺的小字描绘文案，按 DAY 或连续 DAY 一一对应，轻微交叠，旋转约 1°–2° 左右交替；禁止横向长图、大小混杂、全部同向或水彩/卡通照片。
- **底部收藏区**：2–3 个协调模块（行动清单/短引语/风物静物/牛皮纸吊牌），仅 1–2 片小胶带与最多 2 种轻装饰；禁止与目的地无关的花朵、贝壳、热带符号。
- **材质与配色**：干净暖象牙白背景，纸纤维近看可见；撕边、胶带、阴影只集中在亮点卡、拍立得与底部收藏区；禁止脏黄纸、重颗粒、大片污渍、焦边、全页叠纸。配色从主景提取，整体低至中饱和。
- **内容对应**：主景、每张 DAY 照片与风物静物分别对应用户文本的目的地或 DAY 主题；搜索不可用时按文字生成可信近似，不声称真实照片，不把研究到的新地点写进行程。

## 九、字体设计层

字体是画面风格的一部分。先定标题字的视觉概念，再设计 DAY、地点、时间、说明的可读层级。手帐风命中 H2/H3 时优先遵循其子风格语法。

| 层级       | 设计要求                                                   |
| -------- | ------------------------------------------------------ |
| 主标题      | 有明确风格与材质感（书写笔触、厚涂、纸片拼字、描边、压印等），与目的地及大风格一致，避免无设计感的默认粗黑体 |
| DAY／章节标题 | 中度风格化，与主标题同源但更克制，用字号/字重/色块/标签形成稳定系列                    |
| 时间、地点、交通 | 清晰规整中文字体，固定列宽与基线，不用难辨艺术字                               |
| 体验说明与贴士  | 最克制，短句、稳定行距、高对比，优先保证手机阅读                               |

- 手帐风标题可用毛笔/钢笔/旧刊/印章/压印质感，正文用易读手写体。
- 海报风标题可用刷笔/海报字/描边/轻浮雕，正文用高对比现代字体。
- 卡通风标题可用胖体/剪纸字/彩色描边/泡泡字，正文用统一圆体。
- 只让主标题和少量章节标题承担强风格；时间、地点、长说明不全部艺术化。风格化不得破坏中文准确性。

**H2 手帐风字体专项（必须遵循）**&#8203;：H2 全图统一采用**手写体/手账体**中文字体（清秀、工整、易读的手写风，而非印刷黑体/宋体），营造手帐的亲笔书写感——主标题用更有笔触的手写大字，DAY 标签、路线标题、景点、交通、说明依次减小但**都保持手写体**。**&#8203;同一层级的所有文字字号必须严格一致**：所有 DAY 卡的路线标题同字号、所有编号景点同字号、所有交通行同字号、所有 Day 标签同字号；不得某张卡字大某张卡字小。手写体须保证每个字清晰可辨，不潦草、不连笔到难认。

**P1 海报字体专项（随目的地自适应、与画面融合）**&#8203;：P1 主标题**不套固定字体**，按 `destination_visual_profile.title_font_mood` 随目的地气质自适应（毛笔书法/精致衬线/现代无衬线/清冷细劲/秀雅宋楷等），并从主景提取笔触、颜色与质感，让标题像画面的一部分自然融入；副标题、时间、说明用与之协调的克制字体。禁止不分目的地一律用生硬的粗白描边大字。

## 十、信息版式

风格决定气质，版式决定信息组织，二者分别选择后组合。

| 版式    | 适用                    | 画面结构                 |
| ----- | --------------------- | -------------------- |
| 路线海报  | 自驾、环线、线性跨城，路线比逐日细节更重要 | 标题＋一张主路线图/游线＋2–5 条摘要 |
| 分日章节  | 2–6 天，每天多个游玩地点        | 顶部概览＋纵向 DAY 章节，图文分区  |
| 交通时间轴 | 航班、高铁、换乘或硬时间很多        | 单列时间轴，时间/动作/地点顺序清楚   |
| 单日漫游  | 单日 CITY WALK 或局部集中游览  | 大标题＋连续游线＋沿途场景＋少量贴士   |
| 紧凑行程册 | 5 天以上或信息较密            | 顶部概览＋双列或紧凑网格 DAY 卡   |

7 天以上优先紧凑行程册；每天保留核心信息与推荐路线，靠紧凑网格容纳，不生成超长单列长卷。

## 十一、顶部视觉与地图规则

**顶部**只能选一种主视觉：完整氛围封面 / 完整路线地图 / 标题设计。禁止半边风景＋半边地图或表格；地图、封面、DAY 信息必须清楚分区。

**地图/路线（生图模型无精确坐标能力，只做"可信关系"）**&#8203;：

- 全图最多一张地图。线性行程用一条主路线；放射型行程可在同一张地图用统一的分日支线系统。
- 地图只放城市、住宿基地或少量关键节点，不塞入所有市内景点；依用户文本的地点顺序与已有地理信息表达路线，不改顺序。
- 地图用于攻略理解、不作精确导航；除非用户要求，不加"路线示意/以实际交通为准"等免责声明。
- 除 H2 外的子风格遇地点过多、尺度混杂、标签易重叠或缺可靠地理关系时，可取消地图，改用 DAY 卡、时间轴或阅读顺序线。

## 十三、手机排版要点

- 全图固定 `2:3` 竖版，约 `1707×2560px`（见全局锁定项）。
- 字号层级：主标题最大 → DAY/每日主题 → 地点 → 时间与说明。
- 主标题、副标题、说明用统一基线；日期放固定位置。
- 同级 DAY 模块保持相同宽度、内边距、标题高度与行距；时间/地点/时长形成稳定列关系。
- 正文短句化：每个景点/交通/住宿用一行短句表达，逐条排列即可；避免密集小字与孤字换行，单条尽量不超过两行，但**不得为缩短而把多个景点合并成一句**。
- 地图、插画、照片场景、卡片与文字之间保留足够留白，不互相遮挡；整体至少保留约 20%–25% 有效留白。
