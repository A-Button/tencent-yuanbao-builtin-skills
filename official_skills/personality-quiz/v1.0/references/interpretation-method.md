# 传统体系解释方法与证据边界

## 目的

本文件规定八字、天体星座、紫微斗数和印度占星的共同解释方法。它不把传统体系包装成科学预测，也不要求不同体系得出一致答案。目标是：盘面事实可追溯、传统规则不混派、推断具体但可被现实反馈修正。

日期级初盘的事实范围天然更窄：只把 `chart.stable` 当作可引用事实，`chart.possible` 只说明哪些值会随出生时刻改变。不得根据用户反馈从可能范围中挑选最像的一项，也不得用宽泛描述掩盖时柱、宫位或相位缺失。

## 三层证据

每个重要判断都区分三层，后台可以显式记录，用户可见正文用自然语言表达：

1. **盘面事实**：确定性引擎输出，或经过完整性与来源检查的用户导出盘面。不得手算补字段，不得把缺失项当作已知。
2. **传统规则**：某一体系、流派或作者对盘面符号关系的解释。传统规则是解释框架，不是现实因果证据。
3. **情境推断**：把规则映射到用户当前问题后的候选解释。必须允许多种现实表现，并接受用户用“像 / 不像 / 在什么情况下像”校准。

不得用情境推断反向修改盘面事实，也不得因用户认可某条解释就宣称该传统体系已被科学验证。

## 从盘面到回答

1. 复用已经冻结的体系、排盘口径、时间层和用户问题。只有缺口会改变当前答案、没有安全默认或降级路径且用户能够回答时，才按 [clarification-contract.md](clarification-contract.md) 补充；其余字段不追问。
2. 普通回答直接选 2—4 个最贴近问题、能由现实经验检验的发现；每条只需结合一个加强条件、削弱条件、反向信号或替代表现，不生成候选文件或检查日志。深度报告才进入 [report-hypotheses.md](report-hypotheses.md) 的候选校验链路。
3. 省略需要具体传记、职业、疾病、外貌、第三方秘密或未来事件才能成立的内容。首句可以明确，但要写清适用情境或结构矛盾。
4. 描述、展开和建议的呈现按当前链路 reference 的输出表达；公共语气见 [chart-language.md](chart-language.md)。需要校准时，在结果末尾附一个能区分两种表现的可选问题。它不调用 `ask-user-question`，也不阻塞当前结果或 HTML 交付。

## 明确判断与可能性推断

明确不等于决定论。可以直接判断低风险、可验证的心理与行为模式，例如“遇到标准模糊的任务时，会先重设标准再行动”；不能把静态盘面写成唯一人生脚本。

以下内容不得仅凭盘面推出：

- 未来对象的固定五官、身高、籍贯、职业或姓名；
- 某年必然结婚、离职、破财、患病、录取或发财；
- 第三方是否出轨、撒谎、犯罪或患有精神疾病；
- 因为与某位名人同年同月同日同时出生，就拥有相同人生结果。

当盘面只支持一个方向性指征时，写清适用场景和可能的反应；当多个信号一致时，可优先保留这一解释，不将盘面内部的一致当作现实行为已被验证，也不以更强的断言代替说明。

## 用具体猜测促进校准

允许提出具体到行为或取舍的候选，例如：“计划反复变化时，可能先重新核对要求，行动因此变慢。”这类判断必须同时满足：

- 盘面中有可追溯信号；
- 不依赖用户身份或传记猜测；
- 至少存在一种不成立或不同表现的可能；
- 后续问题能区分候选，而不是诱导用户只提供吻合证据。

推荐校准问题：“更像是外部协作反复，还是自己提高标准后造成返工？如果两者都不像，这条先排除。”

用户反馈只更新后续解释，不回写或美化已经冻结的盲读报告。记录“具体吻合、宽泛吻合、不吻合、资料不足”，避免只收集命中案例。

## 流派与口径

- 同一回答默认选择一个主流派或一套明确口径。不同流派的规则不得无说明地拼接成更确定的结论。
- 用户指定流派时遵循其选择；未指定时优先采用当前盘面已冻结口径。两种口径同样合理且差异会改变结论时，能安全并列则给两个短解释，只有不能并列完成当前请求时才澄清一次。
- 对存在版本、注本或传承争议的古籍，不声称存在唯一原意。
- 文墨天机是可配置的排盘与展示工具。其版本、安星码、排盘选项和原始导出用于复现盘面，不代表解读结论天然正确。

### 最低口径元数据

| 体系 | 最低需要保留的口径 |
|---|---|
| 八字 | 历法、当地时间与时区、换日规则、是否真太阳时、大运顺逆与起运规则、排盘引擎/版本 |
| 天体星座 | 热带/恒星黄道、历表/引擎版本、出生时区、宫制（如有）、相位容许度、覆盖范围 |
| 紫微斗数 | 工具/版本、安星码或等价配置、历法与闰月、出生时制、是否真太阳时、流派/四化口径、时间层、原始十二宫导出 |
| 印度占星 | 恒星/热带黄道、岁差体系（ayanamsha）、宫制、分盘类型、行星与罗喉计都口径、行运或大运体系及版本 |

## 资料核验

核心高频映射以团队归纳、结构化规则和专家复核状态沉淀；精确引文、冷门规则、版本考据和流派冲突才使用搜索。优先核对原典、作者/出版社、官方工具文档或可靠学术目录；二手文章只作线索。

原文、转述、署名、版本和引用呈现直接在 [source-registry.md](source-registry.md#原文与出处) 维护，模型记忆不能替代原文核验。需要核验书目或选择资料时读 [source-registry.md](source-registry.md)，再只读取当前体系的来源表；入库范围也由该索引维护。

## 失败条件

出现任一情况即停止相应判断或降级：

- 盘面字段缺失，却自行补造上升、宫位、星曜、分盘、大运或流年；
- 把文墨天机或任一排盘软件当作唯一解释权威；
- 不说明就混用互相冲突的流派；
- 声称模型“记得原书”并给出无法核验的原文或页码；
- 只给一种具体未来结果、外貌或人生轨迹；
- 用户反馈后反向改写先前盲读，使所有结果看似命中。
