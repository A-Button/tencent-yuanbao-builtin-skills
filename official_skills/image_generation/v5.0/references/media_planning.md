# 社媒图文策划与编排

## 1. 职责与路由

把用户输入编译成适合社媒传播的单图或系列视觉。依次通过四道门槛：`Research Gate → Editorial Gate → Art Direction Gate → Quality Gate`，中间完成视觉制作与排字。

触发场景：小红书封面与轮播、公众号头图与内页、B站/抖音/快手封面、朋友圈配图、图文卡片、攻略、穿搭图鉴、九宫格、Banner、H5 视觉稿，以及已有系列的续作、补齐和跨平台适配。

路由边界：

- 数据、流程、关系图解为核心 → `infographic_design`。
- 连续剧情和跨格分镜为核心 → `storyboarding`。
- 电商主图、详情页、独立品牌 KV，或明显是商业视觉宣传/广告海报（品牌宣传海报、产品广告、活动主视觉、促销/招生/开业/发布会等宣传海报、单张宣传 KV）为核心 → `commercial_design`。此类以单张视觉冲击、品牌调性和卖点主张为主，**即使发布在社媒也直接路由出去，不走本技能**；prompt 明显指向商业宣传海报时，此判断先于其他路由。
- 与社媒传播无关的普通单图 → 基础生图能力。

路由自检：本技能只处理以**内容编排**为核心的社媒图文（封面、图文卡片、攻略、种草、穿搭、多页系列内页等，重在跨页信息分配与图文密度）；一旦识别为上述商业宣传海报/广告 KV，立即路由到 `commercial_design`，不得因其"要发小红书/朋友圈"而误留在本技能。

## 2. 决策优先级

`用户明确要求 > 品牌与核心资产 > 事实与合规 > 传播目标与受众 > 内容关系 > 参考图有效规律 > 平台阅读环境 > 装饰偏好`

平台只决定画幅、浏览方式、安全区和阅读节奏，不直接决定配色、字体、审美或信息密度。同一系列的不变量与受控变化规则见 §3.11；核心要求是系列保持主体身份与风格一致，但每页主视觉必须在景别、姿态、机位或构图上产生可见差异，禁止多页重复几乎相同的站姿和取景。

**先按任务语义定义成品（硬规则）：** 不得只因数量大于 1 就自动判定套图；先识别用户说的是系列内页、轮播、九宫格、同主题组图，还是若干独立备选；此判断对文生图和图生图同样先行，无法从需求与上下文确定时按澄清规则集中问一次。判为系列（`series_mode: true`）必须建立并满足系列感（见 §3.11）；判为独立备选（`series_mode: false`）则各图允许不同风格调性，不套系列一致性约束。用户明确要求“6 张小红书穿搭分享内页”时，`小红书穿搭分享内页` 定义成品类型，`6 张` 定义系列页数，因此最小交付单位是“完成图文编排的一页”，不是一张裸人物摄影。此时 6 张风格相近的人像照不等于 6 页穿搭内页；每页都必须包含主题化版式、穿搭信息、图文注释和系列锚点。若用户要求的是 6 张独立人物写真或 6 个备选方案，则不得擅自套用连续内页规则。

**成品类型默认判定（硬规则）：** LOOK、穿搭、攻略、种草、测评、图鉴、清单等社媒图文类请求，无论文生图还是图生图，默认成品 = 图文成品页；仅当用户明确表示“只要人物写真 / 只要素材图 / 不要文字”时，才允许交付纯图或纯素材。成品类型存疑时一律按图文成品页处理，不得赌向裸图。

**图文成品页最低门槛（硬规则，缺一即不合格，后文统称“最低图文门槛”）：**

- 每页有明确的页面或 LOOK 主题标题；
- 每页 ≥3 个具体观点或搭配点文字（非口号、非同义改写、非无答案提问）；
- 每页至少 1 组“实物名称 + 对应实物视觉”的图文配对（单品、产品、食材、工具、地点、人物等）；穿搭等多实物可拆解页，“对应实物视觉”须为独立单品视觉（抠图缩略或特写），仅在主图拉引线标注不算；
- 每页有页码或系列锚点。

达不到最低图文门槛的产物只是**素材**，不是**成品页**；除非用户明确只要写真/素材，否则不得作为最终交付。

## 3. 主流程

### Gate 1：Research——先保证内容充分、准确、有依据

#### 3.1 重建任务

读取当前指令、历史上下文、参考图、品牌资产和已有结果，输出：

```yaml
task_brief:
  task_mode: new | revise | continue | adapt
  communication_goal:
  expected_user_action:
  target_audience:
  platform_and_placement:
  format_and_count:
  series_mode: true | false
  ratio:
  content_source:
  required_copy:
  core_subject:
  reference_and_brand_assets:
  reference_asset_roles:
    - asset_id:
      explicit_role_from_prompt:
      inferred_roles: [identity_reference, edit_base, content_source, style_reference, layout_reference, pose_reference, color_reference, brand_asset]
      must_preserve:
      may_change:
      forbidden_transfer:
  reference_transfer_map:
    - target_aspect: identity | clothing | pose | composition | layout | hierarchy | color | tone | style | texture | background
      source_asset_id:
      source: explicit | inferred
      transfer_strength: strict | close | inspired
      evidence:
  continuity_requirements:
  finished_page_definition:
  hierarchy_requirement: "5 layers by default, never fewer than 4"
  hard_constraints:
```

比例不得缺失；用户未指定时按发布位置选择。只在缺失项会显著改变任务且无法从上下文或工具获得时集中澄清一次。

先区分“参考图提供什么”与“最终要做什么”。对每张参考图建立 `reference_transfer_map`，明确哪些视觉属性从哪张图迁移到成品。执行顺序为：`用户显式映射 > 上下文中已经确认的映射 > 基于任务与画面的合理推断`。

- `identity_reference` 只提供人物身份、面貌和用户明确要求保留的体貌特征；不自动提供服装、背景、姿势、构图、版式或视觉风格。
- `edit_base` 才表示在原画面上直接修改，并按指令决定哪些像素结构要保留。
- 用户显式指定参考关系时必须严格执行。例如“参考图一的人物、参考图二的风格”表示身份、面貌与人物特征只取图一，画面语言只取图二；不得交换来源、平均混合两个人物、把图一的服装或背景误当成必保留项，也不得用图二的人物身份污染图一的人物。又如“参考竞品爆款、做同调性但不同选题”：用户只说“同调性”、未点名具体元素时，视为对该图的高保真整体迁移（≥80%），逐项覆盖①排版、②字体设计、③人物风格、④视觉层级、⑤色调、⑥画面质感六个维度，按 `strict`/`close` 强度迁移；仅选题、文案与具体内容重新生成、列为 `forbidden_transfer`。“同调性/同风格”是明确的高保真要求，不得降级为泛泛的“参考了”，“不同选题”只换内容、不构成降低调性保真度的理由。
- 用户没有说明每张图参考什么时，允许结合最终任务、画面中最显著的可迁移特征和多图之间的互补关系自行推断。可推断维度至少包括：①颜色与色调；②排版、构图与视觉层级；③人物姿势、动作与机位；④插画、摄影、材质、光影等画面风格；也可按任务需要推断服装、背景、纹理或局部元素。不得默认整张图的所有属性都要复制。
- 推断时优先选择与成品类型有用且不冲突的属性：人物形象照通常可提供身份或姿势，成熟设计稿通常可提供排版、层级、配色和风格。若同一张图承担多个角色，逐项记录；若多张图对同一属性冲突，优先使用用户指定，其次选择最符合传播目标的来源，并在计划中写明假设。
- 沿用 §2 的“穿搭内页”例：仅给出人物形象照时标记为 `identity_reference`，跨页锁定相貌与身份，服装、场景、姿态、景别、页面构图均可重设，成品仍由“穿搭内页”定义。

#### 3.2 判断是否研究

出现以下任一情况时，必须先调用搜索、网页读取或资料工具：

- 用户提供公众号、网页、论文、报告或文档链接。
- 主题陌生、专业、事实不足或需要具体案例、数据、步骤和判断标准。
- 涉及新闻、人物、价格、门票、开放时间、法规、医疗、金融等时效或高风险信息。

用户 Prompt 很短、只给主题或分到每页的信息很少，不自动等于必须联网，也不得直接进入生图。先在 Editorial Gate 做逐页内容缺口分析，再按缺口选择补全方式：

- `web_fetch`：读取用户给出的网页、公众号、报告、文档或已经找到的目标页面，提取原始事实、结构和可视化信息。
- `web_search`：补充具体事实、数据、案例、步骤、判断标准、地点、产品、趋势或专业背景；优先官方、原始和权威来源。
- `picture_search`：研究与主题相关的实物、场景、姿势、造型、版式和视觉表达，帮助确定视觉支持内容；搜索图片只作研究和信息线索，未经授权不得直接进入成品。
- `self_generalize`：对创意性、常识性、非时效、非高风险内容进行专业泛化，例如为穿搭页补充搭配逻辑、适用场景、单品拆解和行动 TIP。不得用泛化编造具体数据、价格、功效、出处或可核验事实。

可混合使用以上路径。用户 Prompt 简短但任务语义已经完整时，AI 应主动补全，不因用户未写满每页文案而追问；只有缺失信息会显著改变核心成品、且无法通过上下文、参考素材、研究或合理泛化解决时，才集中澄清一次。

#### 3.3 建立来源内容地图

禁止“先高度摘要、再把摘要分页”。先把来源拆成独立信息单元：结论、事实、数字、原因、步骤、对比、案例、引用、注意事项和行动建议。

```yaml
source_content_map:
  - {id, type, content, priority: A|B|C, evidence_or_source, visualizable_as, certainty}
```

不得为了增加信息量编造内容。无法核实的信息标记不确定并避免作为核心结论。

**通过条件：** 已有事实和来源被正确提取；重要事实有依据；不确定项已处理；信息不足的位置已标记为待补全。创意性或常识性内容尚未展开时可以进入 Editorial Gate 继续泛化，不能因为 Prompt 简短就卡住；涉及外部事实但仍缺依据时不得进入最终编排。

### Gate 2：Editorial——决定每页说什么以及信息密度

技能存在的意义是产出比基模直接出图更充分的内容。出图前必须在本阶段把每页信息量编排足：规划够填满五类文字角色和图文配对的实质内容，宁可信息偏满也不能让画面空洞、缺内容。内容不足时执行逐页补全：需要外部事实时回 Research 调用工具，需要创意性或常识性扩充时在 Editorial 中自行泛化；不得靠加大留白、堆装饰或放空来充数。

#### 3.4 逐页补全并选择传播密度

内容策划阶段必须决定每一页具体有哪些内容。将用户输入分配到页面后，逐页检查现有信息是否足以支撑页面主题、五类文字角色、最低图文门槛和目标密度；不足时不得把同一句话拆开改写、用空洞问题、装饰或大留白凑页。

```yaml
page_content_enrichment:
  - page_id:
    page_goal:
    missing_content_types:
    enrichment_route: self_generalize | web_search | web_fetch | picture_search | mixed
    added_units: [{content, function, source_or_basis, certainty, visualizable_as}]
    enrichment_status: pass | fail
```

逐页优先检查是否还需要扩充：①一句明确结论；②原因或搭配逻辑；③步骤、部件、单品或细节；④例子、比较或使用场景；⑤适用条件、限制或注意事项；⑥可执行 TIP；⑦与这些信息一一对应的图片、特写、图标或标注。按页面职责选择需要的类型，不机械要求每页全部相同，但每页至少形成一个完整的“结论＋解释/证据＋具体行动或细节”信息闭环。

工具获取的事实写回 `source_content_map` 并保留来源；AI 自行泛化的内容标记为 `editorial_inference`，只能作为创意策划、常识性建议或表达扩充，不能伪装成外部事实。补全后重新计算每页有效语义单元，未达到目标密度则继续补料，达到后才能编写最终 Page Document。

先根据传播目标和预期行为选择密度，再逐页调整：

| 密度 | 典型目标 | 有效语义单元 | 常见模块 |
| --- | --- | ---: | ---: |
| 低 | 视觉主导页（封面、氛围、单人物/单品展示） | 3–6 | 1–3 |
| 中 | 种草、解释、轻量比较 | 6–10 | 3–5 |
| 高 | 攻略、教程、测评、决策支持 | 10–18 | 4–7 |

一个独立结论、数字、原因、步骤、比较项、判断标准或行动建议计 1 个有效语义单元；重复标题、装饰口号、没有答案的问题和同义改写计 0 个。密度过高和密度不足都属于错误。

密度越高，越要每页给出一句可提炼的小结论并置于显著位置（页面标题或首行），让读者不处理全部细节也能拿到要点；中高密度页缺少小结论视为不合格。

即便是低密度（视觉主导）页面，也必须满足**最低图文门槛**与五类文字角色；“低”只减少有效语义单元和模块的数量，不降低结构完整度，不得据此掉回“人物照＋一句标题”的裸图。真正的纯写真、纯素材需求已在路由与成品类型判定阶段排除，进入本技能的任务默认都需图文编排。

#### 3.5 选择内容关系与版式原型

版式不得只由“好看”或通用模板决定，必须同时由 `内容关系 × 主题语义 × 阅读动作` 推导。先提取主题中可转译为空间结构的对象、动作、顺序、关系、材质或文化符号，再决定网格、主图裁切、文字区位置、阅读路径和注释方式：

```yaml
theme_layout_grammar:
  topic_nouns:
  topic_actions:
  native_structure: layer | route | sequence | comparison | catalog | anatomy | scene
  reading_action:
  layout_translation:
    grid_logic:
    image_text_relation:
    annotation_logic:
    recurring_theme_device:
  rationale:
```

主题关联必须进入页面骨架，而不只是换颜色、贴图标或加背景纹样。例如：穿搭把“全身造型＋单品层叠＋搭配理由”转译为人物主图、纵向注释栏、编号搭配点和底部 TIP；旅行把“地点＋移动”转译为路线、节点和行程节奏；教程把“先后动作”转译为步骤轨道和阶段结果；书籍把“阅读与批注”转译为纸页、书签、边注和摘录区。仅添加几个主题符号，但仍使用与内容无关的通用卡片网格，视为未建立主题版式。

| 内容关系 | 原型 |
| --- | --- |
| 地点与移动 | `MAP_FLOW` |
| 时间与步骤 | `TIMELINE` |
| 方案与差异 | `COMPARISON_GRID` |
| 独立知识块 | `CARD_DASHBOARD` |
| 单一人物或产品 | `HERO_DETAIL` |
| 主体加多部件/条目拆解（含穿搭多单品 LOOK） | `SHOWCASE_BREAKDOWN` |
| 变化与效果 | `BEFORE_AFTER` |
| 有序推荐 | `RANKING_LIST` |
| 总结与互动 | `CTA_QUIZ` |

每页选择一个主原型，必要时只叠加一个辅助原型。

原型只提供信息骨架，不能直接充当最终版式。每页必须在 `page_bible` 中写明该原型如何被当页主题语义改造；无法说明“为什么这一页的主题适合这样排”时，回到本节重做。系列内页共享色彩、字体、图像语言、注释语法和系列锚点，但网格、主图位置和模块结构可以按当页主题受控变化；禁止无理由地一页杂志、一页海报、一页通用 PPT 卡片随机拼接。

#### 3.6 分配系列内容

按需使用 `cover / overview / detail / comparison / summary / cta` 页面职责。每页只表达一个核心结论，但可以使用多个支撑模块；多页必须形成递进、对比、转折、汇总或行动关系。

先建立跨页覆盖矩阵，再写页面文案：

```yaml
coverage_matrix:
  - {source_unit_id, priority, page_id, module_title, presentation}
coverage_status: {priority_a: 100%, priority_a_b: ">=85%", repetition: "<=10%"}
```

用户指定页数时在可读范围内压缩与合并；无法容纳时说明限制并建议增加页数。用户未指定时使用完成目标所需的最小必要页数。

#### 3.7 编写逐页 Page Document

先写完所有可见文案，再进入视觉设计：

```yaml
page_document:
  page_id:
  page_role:
  page_thesis:
  visible_takeaway:
  density_profile:
  source_unit_ids:
  modules:
    - title:
      supporting_points:
      visual_support:
  page_relation:
  planned_visual_layers: [L1, L2, L3, L4, L5]
  theme_layout_link:
  payload_status: pass | fail
```

每页必须有明确标题和可见结论。模块标题尽量直接表达结论，不只写“背景、原因、数据”。中高密度页面默认使用 3–5 个有标题模块；弱信息页面可减少模块，但不能失去页面主题。列举具体实物的模块，`visual_support` 必须落到该实物本身的图像，不得留空或用无关装饰替代。

沿用 §2 的“穿搭内页”例：仅有人物 `identity_reference` 时不得等参考图给现成文案、也不得直接进入人物生图，先策划整套内容——确定系列总命题，每页分配不同的 LOOK 主题或场景、穿搭公式、3–5 个具体搭配点和 1 个可执行 TIP，六页之间避免只换衣服颜色或背景。每页搭配点须能在人物服装、单品特写或引线标注中被看见，不写与画面无关的泛泛建议。

**通过条件：** A 级单元全覆盖；每页密度符合目标；没有空转页和无答案的提问页；封面承诺将在正文兑现。未通过不得进入 Art Direction Gate。

### Gate 3：Art Direction——决定为什么这样设计

#### 3.8 从受众与内容推导视觉方向

```yaml
art_direction:
  audience_profile:
    life_stage:
    knowledge_level:
    aesthetic_preference:
    reading_context:
  content_character:
    topic:
    emotional_tone:
    cultural_context:
    material_associations:
  visual_strategy:
    carrier:
    style:
    palette_and_roles:
    typography:
    imagery:
    texture:
    rationale:
```

从受众、内容气质、传播目标和品牌资产推导视觉风格。介绍书籍时从书封、纸张、时代与文学气质取材；专业测评强调可信与清晰；人物穿搭强调编辑感、服装和姿态。不得使用“小红书=奶油色、公众号=商务风”等平台刻板模板。

主题若自带标志性视觉资产，必须优先提取其标志性色彩、符号与质感作为色彩和图像锚点：书籍取书封主色、纸张与年代气质，实体或概念主题取其代表造型、象征物与惯用色，品牌取标准色与视觉语言。有明确气质的主题不得套用无依据的通用模板（完整禁令见 §3.11）。

载体可选平面设计卡、插画编排、杂志图文、摄影主视觉＋设计系统或纯摄影；观点卡、攻略、清单默认不使用“整幅照片＋半透明文字条”。科技、数码、编程、机器人、AI 等题材定风格时，可参考「§6 附录」的科技类关键词选取或混合方向，但仍须由内容与受众推导（有主题依据才可用，见 §3.11）并遵守其中的渐变禁令。

#### 3.9 封面钩子与字体设计

封面是独立传播入口，只使用一个主钩子：问题、收益、结果、反差、身份或关键数字。让用户在约一秒内理解主题、适用对象和阅读收益。

- 使用一个最大主视觉、一个明确主标题和 2–4 个辅助信息模块；辅助模块（分类标签、角标、贴纸）用来丰富层次和设计感，但体量和对比都要弱于主标题，不与其争夺焦点。
- 封面文字（不含主视觉）必须规划五类角色，缺少任一类都不得交付：①主标题——经过设计且与主题紧密关联；②副标题——承接或补充主标题；③正文内容——给出关键观点、步骤、卖点或内容预告，不能只有口号；④说明性文字——解释适用人群、场景、条件、图注或阅读收益；⑤装饰性文字——标签、角标、系列锚点、页码或强调短句。五类文字的权重必须明显分级，正文和说明性文字也必须各司其职，不得合并成一行含糊小字，更不得只放孤立主标题或两级文字。
- 主视觉必须兑现标题的核心钩子和内容承诺，不只是标题点名的身份或领域：钩子指向解决问题、警示、教程、对比或结果时，要用问题、冲突、对比、警示、动作或结果把钩子演出来，画面情绪基调与钩子一致，不得用无关氛围感或纯环境展示顶替、也不得只与大领域泛泛相关；标题点名具体主体（某类人群、人物或产品）时，主视觉必须出现该主体本身，不得用抽象图标、符号或泛化场景替代。
- 主视觉要有视觉张力：用真实主体、主题标志性符号或强对比构图撑起画面焦点；禁止用纯色/深色背景加居中大字冒充封面（通用模板禁令见 §3.11）。
- 单独设计标题断行、强调词、字体性格、字重和色彩对比；设计感不得牺牲中文可读性。用于视频流与信息流封面（B站、抖音、快手）时，标题要用大字号、强字重、描边或多色强调做出冲击力，在缩略和快速滑动中一眼抓住；但冲击力只叠加在主标题上，不豁免本节五类文字与画面层级下限——这类封面同样要给出正文内容（具体看点或内容预告）和说明性文字，达到默认 5 层、硬下限 4 层，不得只剩大标题＋一句口号＋标签。
- 主标题必须与其背后区域拉开足够对比（明度差为主，辅以色相或饱和度），确保缩略态也能一眼读到；禁止标题与背景同色系造成淹没。背景本身对比不足时，用衬底色块、半透明蒙版、局部压暗/提亮、描边或投影把标题从背景中托出，但只作用于标题区域，不破坏整体画面。
- 封面视觉权重参考（先规划再出图，非死板面积）：主视觉约占一半、居绝对主导，主标题次之，副标题、正文、说明、装饰依次减弱；主视觉更大时其余等比缩放，但五类文字都要可见、可辨且不争抢主焦点，装饰只补充主题识别、不得形成第二视觉中心。

#### 3.10 子页编排与视觉语义

- 每一页（封面和子页都不例外）都要有一个明确的视觉主体物——像一幅画的主体，可具体可抽象，但要让人一眼 get 到这页在讲什么；其余文字和元素按主次围绕它展开，做到有重点、有详有略、有层级，反对平铺和平均分布。
- 层级指视觉层级，由面积、位置、对比、字号字重、色彩和繁简共同决定，面积只是其一：占地大的元素（如一张表格）不必然是视觉主体，视觉权重才决定主次。下文所有占比都是视觉权重参考，不是死板的面积指标。
- **每页默认建立 5 个可辨识的画面层级，硬下限为 4 个。** 层级必须同时包含图像、文字和空间关系，不得把“五类文字角色”误当成全部画面层级：
  1. `L1 主视觉焦点`：人物、产品、关键对象、核心对比或结果，第一眼被看到。
  2. `L2 核心结论`：主标题或本页一句话 takeaway，与 L1 形成直接语义关系。
  3. `L3 解释模块`：副标题、关键证据、分解图、步骤、单品或对比模块，用来解释 L1/L2。
  4. `L4 注释细节`：正文说明、编号、引线标注、参数、搭配理由、注意事项或图注，必须与具体视觉成对出现。
  5. `L5 系列与环境层`：页码、栏目标签、底部 TIP、系列锚点、主题纹理或低权重装饰，用来收束整套图。
- L1–L4 必须承载不同信息职能；L5 不得靠无意义贴纸凑数。只有用户明确要求极简氛围页且传播目标允许时，才能将 L4 与 L5 合并为 4 层，且仍须保留图、标题、解释信息和系列锚点。少于 4 层、只有人物＋背景、只有大图＋一句标题，均直接判定失败。
- **L1 必须是图像性的视觉主体物**（人物、产品、实物、场景、成果或核心对比）：任何文字——主标题、大数字、倒计时、口号、价格——无论字号多大、设计多炫，都只属于文字层（L2 及以下），不得充当 L1。主体信息薄的题材（促销、倒计时、纯数字、纯口号）必须主动补一个真实主体作 L1，让文字叠加其上或并置，而非让文字独占画面。
- 系列子页文字（不含图片）同样规划五类角色：①主标题；②副标题；③正文内容——承载与主题相关的具体观点、步骤、搭配理由或结论；④说明性文字——用图注、引线标注、条件、参数、来源或注意事项把图片和正文解释清楚；⑤装饰性文字——标签、角标、页码、系列锚点或低权重强调。即使配了图也不能用图替代文字角色；五类文字必须有明确权重和职能差异，禁止正文与说明混成一团，也禁止各级权重相近导致“平均、发平”。
- 重要信息层级（核心模块、关键观点、主要语义单元）必须一条信息配一张相关图（图标、插画、实拍或从主视觉裁切/延伸的画面），图文强相关、把层级拉开，次要说明可不配图；图像/图表须承担展示、解释、证明、对比或引导作用，弱信息展示页可用大图＋少量文字，但图上文字须落在对比足够区域或加衬底/蒙版，不与背景融为一体。
- 图文强关联：凡指向具体实物的文案（服饰单品、产品、食材、工具、地点、人物）必须配对应视觉（抠图缩略、实拍小图或写实图标）成对出现，禁止写成脱离画面的纯文字标签罗列，指向主图的引线标注只作补充、不能替代独立单品视觉；可拆解主体（多部件/条目/维度，穿搭多单品 LOOK 为典型）用「主图＋条目清单」视觉清单版式（每条＝缩略图＋名称/短说明的规整网格），是子页信息密度主要来源而非靠加大主图或文字，只在主图拉引线、无独立单品缩略图即视为视觉清单缺失。
- 子页视觉权重参考（非死板面积）：普通页文字信息略多于视觉、留白约一到二成；高密度页信息占主导、留白更少；采用视觉清单的拆解页视觉占比可升至约一半。
- 用接近性、相似性、共同区域和连续性组织模块，模块内紧凑、模块间清楚分区；禁止让每个短句独占超大卡片，禁止用大图标、空白或装饰伪造内容完整度。

母版必须让读者并排看到任意 2 页时，立即判断它们属于同一套；同时，每页的变化要服务于当页主题和内容职责。**尺寸与风格绝对统一**——比例、安全区、色彩、字体、图像语言、调性，以及背景基调、强调色、单品清单/卡片/注释样式和标题区位，都不得跨页改变；在此前提下允许排版方式的受控微调（模块位置、网格疏密、主视觉景别）丰富视觉，强调须复用同一锁定强调色与卡片样式，只调排版、不动风格调性。以穿搭套图为例：统一人物质感、字体、色彩、LOOK 标签、编号、页码和 TIP 区，而通勤页用纵向注释栏、叠穿页用主造型＋单品分解、约会页用柔和焦点图＋细节标注、周末页用松弛网格；各页骨架贴合当页主题，仍能被识别为同一系列。人物照本身不能替代这些完成页面所需的信息编排。

丰富画面按主次使用两类手段，都不得抢主视觉：①装饰性元素——与主题相关的符号、线条、贴纸等，体量小、对比弱，只做点缀；②背景设计——背景是最次要的一层，可在主视觉和内容都偏素时用主题相关的纹理、渐层或图案补充层次，但不得盖过主视觉与正文。背景只使用 3–5 个主题相关符号，以低对比、细线条或半透明形式放在边角和模块间隙，不压在正文后方。

“高级感”必须落实为：一个主视觉中心、一套一致语言、克制配色、精确层级与对齐、统一图片质感、主题化装饰和完整细节。避免通用 PPT 模板感、无主题依据的深色科技风、过度渐变、发光、玻璃、阴影、无意义 3D 和风格混用。色调必须服务主题气质，与主题无关的暗色堆叠是典型土味来源。

### Production：生成、编辑、排字与合成

#### 3.13 选择实现方式

按页组合使用：`用户素材 → 新生成素材 → 编辑已有素材 → SVG/图表 → 确定性排字 → 页面合成`。先生成角色、产品或主视觉锚点，再制作依赖页面。采用视觉清单的拆解页，需把每个单品/实物作为独立视觉素材生成或抠图，再与主图和文字合成对齐的图文条目，不得只在主图旁堆放文字标签。

当最终交付被识别为图文内页时，**无论文生图还是图生图，都必须分两阶段完成**：

- **图生图两阶段：** 第一阶段以 `identity_reference` 生成或编辑人物主视觉，并跨页保持相貌一致；第二阶段按各页主题把主视觉放入 `series_layout_blueprint` 的相应页面变体，加入穿搭标题、搭配说明、图文注释、页码和系列锚点。
- **文生图两阶段：** 第一阶段生成无字视觉底图（人物、产品或场景主视觉）；第二阶段确定性排字，加入主题标题、观点/搭配点文字、实物图文配对、页码和系列锚点，合成为满足**最低图文门槛**的页面。

两种路径都遵循同一条状态纪律：只完成主视觉、未完成排版合成的产物一律标记为 `asset_ready`；只有达到最低图文门槛且完成排版合成才可标记为 `page_done`。只有当最终任务本身就是纯人物写真或素材生成时，第一阶段结果才可以直接成为交付物。

页面超过约 60 个可见汉字，或包含数字、日期、价格、品牌名和多卡片正文时，默认生成无字视觉底图并确定性排字。为文字预留卡片、边栏、标题区或留白；禁止让生图模型自行改写 Copy Deck。

#### 3.14 编译生成指令

系列任务先写简洁的 `series_mother_prompt`，锁定比例、设计令牌、主题版式语法、系列母版、五层画面结构、页码、重复主体、整体节奏和全局禁忌；再为每页写独立 Prompt。`series_mother_prompt` 必须明确最终目标是排版后的完整页面，并区分 `visual_asset` 与 `finished_page`，不得只描述摄影场景：

1. 画面用途、比例、页面职责和密度。
2. 页面核心结论、精确可见文案或无字排版容器。
3. 主要区域比例和阅读顺序，不锁死微观坐标。
4. 必须出现的人物、场景、模块、图标、数据和视觉关系。
5. 主视觉与标题的关系、允许变化的动作与场景。
6. 设计令牌、系列锚点和本页负向约束。

比例必须同时写入 Prompt 并作为工具真实参数传入；同系列禁止使用 `auto` 或混用比例。

图生图时逐张写明编辑目标、保留项、删除/替换/新增动作、文字替换和最终比例，不使用“其他不变”“文字改一下”等模糊表达。

多参考图任务还必须把 `reference_transfer_map` 编译进生成或编辑指令：逐项写明“哪个属性取自哪张图、保留强度、哪些属性不得从该图迁移”。人物身份、姿势、风格、配色和版式不得用笼统的“参考所附图片”合并描述；显式指定为 `strict` 的属性必须优先锁定，推断为 `inspired` 的属性只迁移规律，不要求像素级复刻。

### Gate 4：Quality——只交付准确、清楚、统一的结果

**交付状态一票否决（最先检查）：** 凡被判定为图文成品页的任务，每页状态必须为 `page_done` 且满足**最低图文门槛**；任何一页仍为 `asset_ready`，或只交付裸人物/裸产品/裸场景素材图，整个任务直接判失败，不进入后续检查。仅当用户明确要求纯写真或纯素材时例外。

不论文生图还是图生图，先通过同一套 `universal_output_gate`。生成方式不能降低成品标准：

1. `image_text_integration`：是否真正图文结合；图片与文字是否互相解释、证明或补充，而不是恰好同时出现。
2. `hierarchy_and_text_roles`：画面是否至少有 4 个可辨识的视觉层级；主标题、副标题、正文内容、说明性文字、装饰性文字五类文字角色是否齐备、清楚且权重不同。
3. `information_richness`：信息是否足够支撑传播目标和页面数量；是否有具体观点、步骤、搭配点、证据、条件或行动建议，而非空洞口号和装饰充数。
4. `series_consistency`：套图的比例、安全区、字体角色、色彩、图像语言、注释方式、页码与调性是否统一；页面变化是否属于同一设计系统内的受控变化。
5. `visual_emphasis`：视觉层级是否有详有略、主次明确；能否先看到主视觉和核心结论，再依次读取解释、细节与装饰，而不是所有元素同权重平铺。
6. `communication_clarity`：目标受众能否在约一秒内判断每页“要干什么、讲什么问题、给我什么价值”；不能只识别人物或场景却不知道页面主题。
7. `cover_hook`：封面主视觉是否直接演出或证明标题承诺；两者是否强关联；主标题是否在缩略态具备足够字号、字重、对比、断行设计和视觉冲击力。

图生图在以上七项全部通过后，再通过 `reference_fidelity_gate`：

```yaml
reference_evidence:
  - {asset_id, requested_or_inferred_aspect, source: explicit|inferred, expected_transfer, visible_output_evidence, verdict: pass|fail}
```

- 用户明确说明参考图及参考属性时，逐项严格遵循，不得串图、错绑、漏掉或擅自改写。
- 用户未说明“参考什么”时，AI 必须先推断要参考的方向，再检查颜色与色调、排版与视觉层级、人物姿势、画面风格等被选属性是否在成品中产生可见影响。只在计划中写“参考了”，但无法指出成品证据，视为没有参考。
- 参考遵循不等于整图复制。只检查 `reference_transfer_map` 中明确选择的属性；未被选择且用户未要求锁定的属性允许变化。

随后逐页并整套执行详细检查。每项按对应节的完整规则逐页核验，此处只列对照节与判失败线，不重复规则原文：

| 检查项 | 对照 | 判失败线（未列即以对照节规则为准） |
| --- | --- | --- |
| `research_check` | §3.2–3.3 | 事实无依据、时效未核验或存在编造 |
| `coverage_check` | §3.6 | A 级未全覆盖、A+B <85%、重复 >10% |
| `content_enrichment_check` | §3.4 | 缺口页未补足；泛化未标 `editorial_inference` 或伪装成事实；同义改写凑数 |
| `payload_check` | §3.4、§3.7 | 密度不匹配、缺标题/可见结论；中高密度页小结论不醒目；靠留白/装饰充数 |
| `cover_check` | §3.9 | 未一秒识别、缩略不可读、图文不扣合、承诺未兑现、五类文字缺项或权重未拉开；视频流封面只剩大标题＋口号＋标签 |
| `art_direction_check` | §3.8 | 风格不源于受众/内容、未提取主题标志性资产、套无依据通用深色模板 |
| `layout_check` | §3.10 | 无明确主体物、层级未按视觉权重拉开、五类文字缺项、说明未与图成对、重要层级缺强相关图、平铺发平 |
| `hierarchy_check` | §3.10 | L1–L5 证据缺失、层级 <4、L1–L4 职能重复；裸人物照或大图＋一句标题 |
| `communication_check` | §3.4、§2 | 只能描述画面有什么，说不清"解决什么问题/核心结论/下一步" |
| `theme_layout_check` | §3.5 | 仅换主题色/贴图标/铺纹理/套通用卡片，主题未进入版式骨架 |
| `reference_role_check`（图生图） | §3.1、§3.14 | 显式来源串图/错绑/擅改；推断无依据或默认复制整图；"同调性/同风格"六维整体迁移 <80%；`identity_reference` 被降级为纯摄影或无依据锁死原服装背景姿势构图 |
| `binding_check` | §3.10 | 具体实物文案无对应视觉或未成对；可拆解集合未用视觉清单；多实物页仅引线标注、无独立单品视觉 |
| `series_check` | §3.11 | 未建 `series_layout_blueprint`；比例/安全区/字体/色彩/背景基调/强调色/图像语言/卡片注释样式跨页改变；页码缺失或不一；重复人物相貌不一或主视觉无差异；图文内页只交付同风格素材图 |
| `copy_check` | §3.13 | 乱码、错字、溢出、错误数字、不可读字号；标题/正文与背景同色系淹没、缩略不可读 |
| `platform_check` | §4 | 比例、安全区、浏览节奏或交付格式错误 |
| `rights_check` | §5 | 出现未授权品牌、IP、人物肖像、网络素材或违规引流 |

任何硬性检查失败都不得交付。按问题回退：事实与来源 → Research；内容分配与密度 → Editorial；风格与版式 → Art Direction；生成、文字和比例 → Production。

## 4. 平台速查

| 发布位置 | 常用比例 | 核心约束 |
| --- | --- | --- |
| 小红书封面与轮播 | 3:4 | 缩略态清楚，多页统一，首图建立阅读或收藏理由 |
| 抖音/快手竖屏 | 9:16 | 顶约 8%、右约 12%–15%、底约 20% 避让关键信息 |
| B站封面 | 16:9 | 右下约 5%–8% 避让，缩略态识别主题，标题在视频流中要有强冲击力 |
| 公众号头图 | 16:9 | 负责主题预告，不堆正文 |
| 公众号内页/长图 | 竖向长图 | 控制移动端字号、分段和连续阅读 |
| 朋友圈 | 1:1 或 3:4 | 同组只选一种；九宫格优先 1:1 |
| Banner/焦点图 | 按投放位 | 只保留一个主信息和必要行动入口 |
| H5 移动页 | 9:16 | 区分视觉稿、分页、长图与真实交互 |

## 5. 合规与交付

- 不生成虚假标题党、极限词、未经证实的功效、认证、价格或数据。
- 不伪造红包、播放条、点赞、系统通知等平台 UI，不擅自加入水印或站外引流。
- 不使用未授权品牌、IP、人物肖像和网络图片作为最终成品资产。
- 参考优秀作品时迁移结构规律和视觉语法，不复制具体画面。
- 交付前确认文件数量、顺序、命名、比例、格式、来源说明和后期排字情况。

## 6. 附录：视觉风格参考

风格库仅供 Gate 3（§3.8）在确定视觉方向时**取词、启发和混合**，不是可套用的模板；具体风格必须由内容气质与受众推导，且满足「有主题依据才可用」（§3.11）。同一系列只锁定一种主风格，必要时叠加一个辅助方向。

### 6.1 科技类（数码、编程、机器人、AI、工业等题材）

| 风格 | 关键词 |
| --- | --- |
| 暗黑未来科技风 | 黑色背景、冷色霓虹、机械元素、强对比 |
| 赛博编程风 | 代码字符、故障效果、扫描线、数字界面 |
| 未来实验室风 | 机器人、机械臂、数据面板、精密工业感 |
| 极简科技海报风 | 大数字、少量线框、清晰留白、信息层级强 |
| 游戏 UI 科技风 | 任务面板、倒计时、等级界面、发光按钮 |
| 科幻 HUD 界面风 | 参数框、坐标线、监测数据、透明信息面板 |
| 蓝黑工业机械风 | 金属机器人、冷蓝灯光、硬朗结构、低饱和背景 |
| 数字终端风 | 命令行、等宽字体、代码窗口、系统提示符 |

**科技类硬禁令：** 禁止蓝紫色渐变、发光渐层这类"AI 感"很重的廉价未来风——它是典型土味与塑料感来源。冷色霓虹以单色或双色强对比为主，避免大面积蓝紫渐变铺底；风格元素（代码、HUD、机械、终端等）须作为解释主题的实义视觉，不得沦为与内容无关的氛围装饰。

### 6.2 小红书常见赛道风格倾向

按赛道快速定位视觉方向，仅作起点参考；最终风格仍由具体主题、受众与内容气质推导，不得因赛道就套固定模板。

| 赛道 | 典型视觉风格 | 典型视觉元素 | 风格倾向 |
| --- | --- | --- | --- |
| 美妆个护 | 高级杂志感、韩系清透、实验室科技感 | 人脸特写、肤质对比、产品质地、镜面、水滴、成分符号 | 精致、干净、显贵；强调“效果可见” |
| 穿搭时尚 | 街拍感、Lookbook、复古杂志、极简高级 | 全身人物、服装轮廓、色卡、单品拆解、拼贴、胶片边框 | 强调人物气质与风格标签，画面比文字重要 |
| 美食饮品 | 高饱和食欲感、治愈生活感、日系餐桌感 | 食物近景、拉丝、蒸汽、酱汁、餐具、手部动作、价格标签 | 暖色、高质感、强调新鲜与真实体验 |
| 家居生活 | 奶油风、侘寂风、北欧极简、生活方式杂志 | 空间全景、局部细节、材质纹理、收纳前后对比、平面布局 | 整洁、舒适、有秩序；追求“理想生活感” |
| 母婴育儿 | 柔和治愈、绘本感、日系家庭纪实 | 宝宝、亲子互动、圆角卡片、手绘图标、柔软织物、成长记录 | 温暖、安全、可信；避免过度商业和攻击性 |
| 旅行户外 | 电影感、胶片感、自然纪实、户外机能风 | 大景别、人物背影、地图、路线、车票、天气、坐标、装备 | 强调氛围感和“我也想去”，同时兼顾攻略信息 |
| 健身健康 | 运动大片、清爽极简、数据科技感 | 身体线条、动作分解、对比图、热量、心率、进度条、健康图表 | 自律、力量、变化感；健康类则更克制可信 |
| 学习成长 | 手账感、校园感、知识卡片、清爽信息图 | 笔记、书本、荧光笔、便签、流程图、重点框、桌面场景 | 信息清晰、可保存、低干扰；强调“马上能学会” |
| 职场商业 | 商务极简、互联网产品感、财经资讯感 | 数据图表、电脑界面、人物半身、关键词、大数字、箭头关系 | 理性、高效、专业；标题冲击力强于装饰性 |
| 兴趣生活 | 风格最分散，常见可爱、潮流、极客、手作感 | 宠物、设备、作品过程、收藏陈列、角色 IP、工具材料 | 强调个性与圈层认同，视觉辨识度比普适审美更重要 |
