# 查询速查：先回答必要问题

本文只负责高频查询路径。命令参数细节从[数据命令索引](data/commands.md)定位单个分册；字段从[数据字段索引](data/ai_usage_guide.md)定位。不要为简单查数加载完整手册。

## 1. 名称、资产与代码

- 用户已给定有效代码：保留并直接查询。保留`sh/sz/bj/hk/us/t/ks/kq/pt`等返回前缀，不自行改成裸代码。
- 名称未知时先确定资产类型：普通股票默认搜索；ETF、LOF、REIT先使用基金搜索类型，指数、板块、债券、期货、外汇分别指定类型。
- 示例：`westock search 招商银行`；`westock search 张江 --type etf`；`westock search 半导体 --type sector`；`westock search 沪深300 --type index`。
- REIT的基金管理人、底层资产公司和基金代码不同，不用股票默认搜索反复变换名称。`--type etf`搜索覆盖部分REIT，不等于这些结果都支持`westock etf profile`；看`etfDetail`及实际返回。
- 一次正确类型搜索后，名称过长/别名不匹配时允许一次有依据的简称修正；仍无结果说明未识别，不遍历全部名称和类型。不臆造`westock reitsfund`等命令。
- 日韩股票按目标市场使用`westock search 丰田 --market jp`或`westock search 三星 --market kr`；搜索的市场参数不能套用到筛选，且与资产类型参数互斥。

## 2. 最小查询组合

示例代码/日期仅演示语法，不是任务默认值。仅执行必要行；需计算/文件时首次查询即加`--raw`保存，否则直接读展示表回答。

| 所需信息 | 完整示例 | 注意 |
|---|---|---|
| 最新或某日行情 | `westock quote sh600036,sh601398 --date 2026-03-31` | 查到PE/PB/股息率就不额外查全套财报解释每项变化 |
| 历史日线 | `westock kline sh600036 --period day --start 2026-01-01 --end 2026-03-31` | 检查实际起止日、复权和截断；区间模式的limit是返回上限，不是自动全量 |
| 最新几期利润/ROE | `westock finance sh600036,sh601398 --type income --limit 4 --fields core` | 只问利润/ROE用income，不默认三表 |
| 历史报告期利润 | `westock finance sh600036,sh601398 --type income --start 2025-01-01 --end 2026-03-31 --fields core` | 与limit互斥；按返回报告期/披露日筛选，不能假定区间自动完成时点约束 |
| 资产/负债 | `westock finance sh600036,sh601398 --type balance --limit 4 --fields core` | 只有必要指标在该表才增加请求 |
| 现金流 | `westock finance sh600036 --type cashflow --limit 4 --fields core` | 不用其他报表或自行拼算冒充披露字段 |
| 公司分红 | `westock dividend sh600036 --years 3` | 适用股票；REIT/基金分派覆盖需单独确认 |
| 公告列表 | `westock notice list sh600036 --limit 30` | 分页用已支持的offset，不猜page参数 |
| 个股资金 | `westock fund flow sh600036 --start 2026-03-01 --end 2026-03-31` | 核对日期/市场；区间通常单代码，按实际帮助确认 |
| ETF档案 | `westock etf profile sh510300` | 费用/类型/经理，不等于行情或历史风险指标 |
| ETF收益/回撤等 | `westock etf overview sh510300` | 只在需要对应指标时用；未确认历史覆盖时不当历史值 |
| ETF净值 | `westock etf nav sh510300 --start 2026-01-01 --end 2026-03-31` | 与场内价格K线分开 |
| 板块成份 | `westock sector constituent pt01801080` | 使用真实搜索返回的板块代码，记录完整性与数据日期 |
| 指数成份 | `westock index constituent sh000300` | 当前成份不自动代表历史成份 |
| 宏观指标 | `westock macro indicator us_inflation --date 2026-07-03` | 短名或日期模式未知才先查`westock macro list --region us` |
| 行业经营 | `westock sector oper 煤炭` | 必要时查`westock sector oper --list`，不使用板块代码 |

## 3. 财务字段与一次性解析

| 需求 | 表 | 常用返回字段 |
|---|---|---|
| 归母净利润 | income | `NPParentCompanyOwners`；单季通常为`NPParentCompanyOwners_Q` |
| 营收 | income | `OperatingRevenue`与`TotalOperatingRevenue`分清口径 |
| 披露ROE | income | `ROEWeighted`、`ROE`、`ROETTM`不可混作同一指标 |
| 资产负债率 | balance | `DebtAssetsRatio`；以该模式真实返回为准 |
| 报告期/披露日 | 对应报表 | `EndDate` / `InfoPublDate` |
| 历史PE/PB/股息率 | quote | 实际JSON可为`pe_ratio` / `pb_ratio` / `dividend_ratio_ttm` |

- 只问某指标时使用对应`--type`。仅用户明确要求三表或全面财务分析时省略`--type`。
- 无后缀财务值可能为年初至今累计；`_Q`是单季，`TTM`是滚动期。先确认再比较，不将累计增速当单季增速。
- 最新N期可能包含目标截止期之后的财报；优先按合理区间取一次，再在本地按报告期过滤。按“当时已知”分析还需筛披露日，缺披露日时标记不能确认。
- 窄表缺**必要**字段时允许一次`--fields all`；不能为了寻找更多可解释变量自动扩成100多列。
- 程序读取必须先按[解析分支](parsing.md)判断这份JSON形状。单代码、批量、日期模式可能不同。不要反复打印整份响应，不把业务请求成功数当成标的数量。
- 已完成代码归属、日期、单位和字段校验后复用结果；不额外检索研报、预测或历史年份来“证明数据没错”。只有具体冲突会改变核心结论才核查。

### 3.1 同期比较的计算前检查

- 年初累计流量取单季时按同财年相邻累计值相减；Q1不用再减上一年Q4。资产、负债、权益是存量，不能把期末数做同样相减来冒充披露余额。
- TTM流量可由最近四个独立季度求和，或上年全年＋本年累计−上年同期累计；比率、EPS、ROE不套流量求和。缺少基期就标无法完整计算，不能将已有三季补成四季。
- 同比要固定单季或累计口径；上年同期为0或负值时不能机械描述百分比增长，给出绝对变化和原因。若用户指定算法则明确按该算法。
- 返回的是报表发布日期还是预约披露日要区分；未来披露预约不是已发布财报，拿到最新值也不是历史时点值。
- 公式、算术自检与例外已集中在[入口财报口径](../SKILL.md#42-财报字段累计单季度与ttm)，无需再进入其他索引。完整字段清单直接读[data/ai_usage_guide-01.md](data/ai_usage_guide-01.md)。

## 4. 公告、分红和REIT：有范围地读原文

1. 先取目标标的、日期行情与公告列表。记录待找的是**已实施分派**、报告披露还是新闻，不混用。
2. 按公告类型/标题/日期筛选相关ID；只读必要ID的详情，同一ID本轮只获取一次，原文保存供本地检索。
3. 示例列表：`westock notice list sh508000 --limit 50 --offset 0`。`offset`是记录偏移，不是页号。仍需确认返回是否新增ID；页面显示“第1页”不单独证明offset失效。
4. 公告按时间顺序返回且已覆盖窗口下界时停止翻页。若顺序不明、重复页或无法确认完整性，记录不足；不反复试25/30/60/100等偏移值。
5. 分派按实际支付/实施日筛选，统一每份与每10份单位。用户要现金分派率时，用已核验分派合计和目标日价格计算，标记为计算值，不必再找审计报告中的近似分派率。
6. 只要价格、分派、规模、成交额已足够回答比较，就停止扩查；出租率、租期、经营现金流不是默认必查。
7. `etfDetail=仅行情`或profile空结果不应触发一串未知基金子命令。保留行情，必要分派从对应公告取得；覆盖仍不足就定向公开补缺或说明未知。

## 5. 新闻与公开补缺

- 新闻/开放报道直接`web_search`，不先查代码或CLI新闻；用于关键结论的报道读原文，核对发布时间、事件日期和发布方，原文不可读时注明未核验。
- 结构化数据仍先用匹配的Westock能力；已有证据确认不支持时直接登记缺口，不重复失败请求。仅补缺失必要项，不将整项换源，不爬全市场重建筛选器。
- 相同数值不同日期/复权/单位时先对齐；无法对齐不平均拼接。数据充分即回答，别以“还可以补一条新闻”延后结果。

## 6. 查询后如何结束

**文本任务**：返回数字或比较表、结论、实际时点与来源，附必要限制即可。默认不生成文件。

**文件任务**：把同一份已核验数据交给指定文件流程，不再重复查询。尽早写文件、完成必要验证后立即用环境附件机制交付，不把排版优化当作无限循环。
