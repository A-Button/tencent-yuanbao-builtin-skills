# Now 动态发什么卡

发到 Now 的五种卡：卡型怎么选、字数、配色、按钮、payload 骨架。跟主对话那三张 A2UI 卡是两套东西，改一边不等于另一边跟着变。

## Now 动态发什么卡

Now 走 make-things 的 `show_widget`，卡型是平台的**五选一**（`card_type` 传字符串）：
`image_text` / `recommend_list` / `todo_remind` / `todo_choice` / `stock`。
这跟主对话那三张 A2UI 卡是**两套东西**，改了一边不等于另一边跟着变。
**发到动态里不要再调 `stock-watch`**——A2UI 出不去。

### 当面问：按问题类型固定出卡

下面三类**必须发 Now 卡**，没有例外。没建 Thing 的纯咨询（只问行情、不提盯盘）仍只出主对话
A2UI，不发动态。

| 用户说什么 | 发几张 | 发什么 |
|---|---|---|
| **要盯某只 / 某组**（新建盯盘） | **1 张** | `stock`，`data.items` 放本次纳入盯盘的那几只。详见「创建」 |
| 股票 / 盘面（已在盯盘里） | **1 张** | `stock`，`data.items` 放今天要盯的那几只 |
| 资讯总结 | 1 张 | `recommend_list` 推荐列表卡，把关注标的的今日资讯汇成一张 |

**「帮我盯一下 Meta」这类话一出现，这张盘面 `stock` 卡就是默认动作**，不用等用户再问一句
「今天怎么样」。规则建没建成、授权过没过，都不改变发不发这张卡——见「创建」那节。

「股票 / 盘面」包括：今天怎样、我盯的票、盘面、自选行情。「资讯总结」包括：今日资讯、关注的股票有什么新闻、晚上汇总。问某一条公告细节仍走场景四的主对话 `show_news`，不要为一条新闻再刷一张动态。

**当面问一律只发一张，不许追发盘面总结。** 全清单的盘面总结 `recommend_list` 改成收盘后
定时推（见下一节），用户当面问的时候不要再补一张——问的是「今天怎么样」，答案在主对话正文
和那张股票卡里，再来一张覆盖全清单的总结只是重复。资讯总结那张也不要附 `stock` 卡，不挂 K 线。

### 主动推：事件一张 `stock`，每晚 20:00 两张总结

| 什么时候 | 发几张 | 发什么 |
|---|---|---|
| 到价命中 / 异动命中 | 1 张 | `stock`，`items` 只放命中的那一只 |
| 每晚 20:00（收盘后，每日定时） | 2 张 | ① 盘面总结 `recommend_list`，覆盖清单全部标的；② 资讯总结 `recommend_list`，覆盖当日新资讯 |

**盘面总结只有这一个出场时机。** 它是「今天这一天，你盯的这些票收成什么样」，是一份收盘后的
日结，不是随叫随到的查询结果。所以到价命中、异动命中、用户当面问盘面，都只发那一张 `stock`，
不要顺手带一张总结——事件推送要的是「这一只现在出事了」，多一张全清单反而把重点冲掉。

两张总结同在 20:00 推，顺序是**先盘面后资讯**。盘面那张只要清单非空就发，休市日和当天没成交的
标的照写最近一次收盘价，注明数据时刻；资讯那张当日无新资讯就不发，不用凑。清单为空（Thing 下
一只票都没有）两张都不发。

### ① 股票卡（`stock`）——一组子卡，无 K 线

make-things `show-widget.md` 已改版。**一个 Now 一张 `stock`，`data.items` 里一组子卡。**
不要再每只票发一张。点名了哪几只就放哪几只；问盘面没点名，放今天值得盯的（涨跌明显 / 贴关键位 / 有触媒），
**至少 1 只、最多 3 只**。清单其余的票写进后面那张 `recommend_list`。

`title` 写这次通知（最多两行）。**不要传 `data.hint`**：牛仔 NowCard proto 没有这个字段，传了就是 40001 `unknown field "hint"`（2026-09-21 腾讯那次）。提示写进 `title` 或放到后面总结卡的 `summary`。
要点必须来自本轮 `quote` / `technical` / `news`，不编触媒。休市只报最近交易时刻。

**`trend` 按实际涨跌填，不要为美股对调。** 平台股票卡固定：`2` 上涨红、`3` 下跌绿、`1` 平盘灰、`0` 未指定灰。
美股绿涨红跌只在后面的 `recommend_list` 用圆点表达，不要在这张卡上叠 emoji。

到价/异动：`items` **只放命中的那一只**，`title` 写事件句。

**股票卡配不了按钮。** make-things 的 `show-widget.md` 三处写死
「纯展示，无图表、无按钮，不配置 `actions`」，2026-09-22 那张盘面卡就是配了也没画出来。这张卡上能点的只有**整卡 `tap`**，
一张卡只有一个落地，按「查看详情」的语义指向自选股个股页：

```json
"tap": {"type": 2, "h5": {"url": "https://wzq.gtimg.com/mm/detail?market=2&type=2&scode=00700"}}
```

URL 跟主对话 A2UI 卡的「查看详情」同一条规则：**`market` 与 `type` 取同一个值、成对出现**，
`0` 深交所 / `1` 上交所 / `2` 港股 / `3` 美股 / `bj` 北交所，`scode` 是去掉市场前缀的裸代码。
北交所那一档是字面量 `bj`，不是数字。把 `type` 写死成 `0` 只有深市碰巧对，
港美股会打开另一只票，而且 URL 照样 200，不报错。

**判据是 `items` 里有几只，不是哪个场景**：只有一只就配整卡 `tap` 指向它——到价/异动天然
只有一只，盘面卡在用户只盯一只时也是一只，都要配上。放了两只以上就别配，整卡指向谁都不对。

所以**多标的的盘面卡是一张纯展示卡**：没有按钮（make-things 写死不支持），也没有整卡 `tap`
（指不准）。这是平台限制，不是漏配，别为了凑交互硬塞 `actions` 或随便挑一只当 `tap`。
「帮我分析」只活在每晚 20:00 那张盘面总结 `recommend_list` 的顶层 `actions` 里。

**逐只点进个股页，`stock` 卡做不到。** `StockItem` 只有七个字段——`time` / `name` /
`code` / `current_price` / `prev_close_price` / `change` / `trend`（见 make-things
`show-widget.md`），**没有 `tap`**；逐项 `tap` 是推荐项（`recommend_list`）独有的。
所以这张卡上能点的只有整卡那一下，放两只以上就连这一下也没有。

要「每只票都能点进自己的个股页」，只有一条路：用 `recommend_list`。20:00 那张盘面总结
就是这么做的——每行 `items[].tap` 各自指向自选股个股页。别为了加跳转把 `tap` 塞进
`StockItem`，下游不认这个字段，卡照发、点了没反应，跟 `openUrl` 一个坑。

**40001 `value must be 'image_text'` 不是要你改成图文卡。**
工具 schema 是 oneOf，`data` 对不上 `stock` 分支时会报第一支（image_text）校验失败。
根因几乎总是还在 `data` 根上塞旧字段 `code/name/price/change/rising/status`。
改成下面这份骨架，不要改 `card_type`。

### ② 推荐列表卡（`recommend_list`）——全清单总结

make-things `show-widget.md` 明确支持这张卡：`data.items` 每项 `item_id` / `title`，可选 `desc`。
`show_widget` 收下并回 `now_id` 只说明下游落库。2026-09-21 腾讯那次动态页显示「这张卡片暂无法显示，内容格式不受支持」，是**牛仔 Now 前端还没画 RecommendList**，不是协议写错、也不要改成 `image_text`。图文卡按 make-things 的 `show-widget.md` 必须有真实 `cover.url` 和整卡 `tap`，没图就发不了，不能拿空 `data: {}` 顶替总结。

**Now 列表卡的文本字段没有颜色属性**，涨跌/利好只能靠字符。用彩色圆点 + ▲▼：

| 市场 | 涨 / 利好 | 跌 / 利空 | 平 / 中性 |
|---|---|---|---|
| A 股 / 港股 | 🔴 ▲ | 🟢 ▼ | ⚪ |
| 美股 | 🟢 ▲ | 🔴 ▼ | ⚪ |

圆点按市场惯例翻转，箭头只表方向、两边一样。两只都在涨也会一红一绿——
**卡上第一句必须写清口径**，放进 `summary`。完整口径是「A股/港股 红涨绿跌，美股 绿涨红跌」，
但 `summary` 只显示一行，整句写进去会被截断，所以压成这句：

```text
A股港股红涨绿跌，美股相反
```

漏了这句就是纯误导。

### 按钮和逐只跳转都挂在这张卡上

`recommend_list` 是**唯一能配按钮的那张**：顶层 `actions` 给整卡的后续动作，
`data.items[].tap` 给每一行自己的落地。股票卡两样都没有，所以盘面那一组的交互全靠它。

| 这张卡 | 顶层 `actions` | 每项 `tap` |
|---|---|---|
| 盘面总结 | 「帮我分析」→ `type 1` 回会话，带 prompt | 该标的自选股个股页 → `type 2` h5 |
| 资讯总结 | 「聊聊对持仓的影响」→ `type 1` 回会话 | `type 2` h5，跳这条新闻的原文页 |

个股页 URL 与股票卡整卡 `tap`、主对话 A2UI 的「查看详情」同一条规则，不要另拼一套。
`action_id` 同卡唯一、不编码语义（`a_analyze` / `a_holdings` 就够），行为只由 `tap` 决定。
按钮最多两个，多了 H5 会挤。

**`send_prompt` 以按钮上那句话开头，后面必须接上具体标的。** 两个约束缺一不可：

- **开头照抄 `label`**，用户点「帮我分析」，主对话里那条消息就得以「帮我分析」起头；
  整句换成别的说法，他会以为自己点错了。
- **标的写进 prompt，不能指望上下文。** 光发一句「帮我分析」过去，主对话收到的就是
  这四个字——**它不带卡上下文，Agent 不知道你指的是哪几只票**。

```text
label: 帮我分析            → send_prompt: 帮我分析腾讯控股、阿里巴巴现在该怎么操作
label: 聊聊对持仓的影响     → send_prompt: 聊聊对持仓的影响：腾讯控股、阿里巴巴今天这些资讯
```

标的取这张卡 `data.items` 里的名称，**最多列 3 只**，超了写「等 N 只」（如
「帮我分析腾讯控股、阿里巴巴等 5 只现在该怎么操作」）。用名称不用代码——那条消息用户看得见。

口径跟主对话那张 A2UI 卡对齐：它的「帮我分析」拼的就是 `帮我分析{名称}现在该怎么操作`
（见 `scripts/_card.py`）。两个界面同一个按钮发出两种 prompt，是 bug 不是设计。

### 一行封顶：`summary` 和 `desc` 都会被截断

Now 列表卡的 `summary` 与每项 `desc` **各只画一行**，超出直接截断成「…」。
2026-09-22 那张卡上「A股盘中。主力净流入 5.48 亿，回购 11 亿 + 拟募…」就是这么断的。
`show_widget` 协议里没有行数或字号参数，H5 也不吃，只能在这边收字数：

| 字段 | 写多长 |
|---|---|
| `summary` | ≤ 18 字，只放颜色口径那一句 |
| `items[].title` | ≤ 20 字，够放「圆点 + 名称 + 现价 + 币种 + ▲▼ 涨跌幅」 |
| `items[].desc` | ≤ 20 字，一句话只说最关键那一条 |

**判断依据写进主对话正文，不要指望卡面能展开。** 均线、量比、资金、触媒挑一条最能解释
今天这根 K 的写上去，其余留给正文。

**盘面总结**一张，**只在每晚 20:00 的收盘日结里发**，当面问不发（见「主动推」）。
标题带数据时刻（来自行情，禁止墙上时钟）；日结场景这个时刻就是各自的收盘时刻：

```text
今日盯盘总结 · 09/21 收盘
A股港股红涨绿跌，美股相反
🟢 华钰矿业 21.21 CNY ▼1.07%
跌破 MA5，量比 0.82 缩量
🔴 腾讯控股 427.40 HKD ▲2.00%
脱离 52 周低点，MA20 仍压制
🟢 英伟达 222.27 USD ▲1.34%
多头排列，218.7 是强弱分界
🔴 特斯拉 364.27 USD ▼0.53%
机器人催化，359 支撑 375 压力
```

一只一行标题（圆点 + 名称 + 现价 + 币种 + ▲▼ 涨跌幅）+ 一行解读。清单有几只就写几只。
解读每行 ≤ 20 字，休市那几只把「收盘 / 休市」放进正文说，别占 `desc` 的位置。

### 两种 `recommend_list` 逐字段对照

它们卡型相同、字段结构相同，**内容配方完全不同**。别拿一张的配方去填另一张：

| 字段 | 盘面总结 | 资讯总结 |
|---|---|---|
| 什么时候发 | 20:00 日结第一张 | 20:00 日结第二张；盘中重大即时 |
| `source.label` | `智能盯盘` | `资讯监控` |
| `title` | `今日盯盘总结 · <数据时刻>` | `今日资讯总结 · <日期>` |
| `summary` | `A股港股红涨绿跌，美股相反` | `利好利空颜色同盘面口径` |
| `items[].title` | 圆点 + 名称 + 现价 + 币种 + ▲▼涨跌幅 | 圆点 + 名称 + ` · ` + 资讯标题 |
| `items[].desc` | 一行技术/资金解读 | 一句话解读 + ` · ` + 来源 |
| `items[].tap` | 该标的自选股个股页 | 这条新闻的原文页 |
| `actions` | 「帮我分析」+ 标的 | 「聊聊对持仓的影响」+ 标的 |

**2026-09-23 实际发错过一张**：资讯内容配了盘面那套署名和按钮（`智能盯盘` + 「帮我分析」），
`title` 自己编成「Meta 与特斯拉 资讯汇总」，`desc` 写成「利好 · 来源 · 时间」把解读挤没了。
卡照样发出去，没有任何报错——**这张表就是用来防这个的，发之前逐行对一遍**。

两处容易丢的：`title` 用固定前缀，不要按本次标的现编；`desc` 的价值全在那句**解读**，
「利好」已经由圆点表达过了，不要用它顶掉解读的位置。

**资讯总结**一张，不要股票卡：

```text
今日资讯总结 · 09/21
利好利空颜色同盘面口径
🔴 华钰矿业 · 镍价高位
镍价高位偏支撑 · 财联社
🔴 腾讯控股 · 暂无公司公告
反弹更像超跌修复 · westock
```

每条：圆点 + 名称 + 标题，下一行「一句话解读 · 来源」，同样 ≤ 20 字，时间挤不下就省掉。没有新资讯的标的写「今日暂无新公告/新闻」，不要省略成没盯。拿不准方向就用 ⚪，不要硬标利好利空。

价格、涨跌幅、币种、资讯标题一律照取数返回值写。

### 请求怎么写：跑脚本，不要手拼

**三种卡的入参一律由脚本生成，你只提供数据。** 署名、标题前缀、summary 口径、圆点配色、
字数截断、按钮 prompt、自选股链接全在代码里，你碰不到，所以每次长得都一样。

```bash
python3 /data/skills/stock-watch/scripts/now_board.py '<json>'   # 盘面总结（20:00 日结第一张）
python3 /data/skills/stock-watch/scripts/now_news.py  '<json>'   # 资讯总结（日结第二张 / 盘中重大）
python3 /data/skills/stock-watch/scripts/now_stock.py '<json>'   # 股票卡（到价 / 异动 / 盘面 / 新建盯盘）
```

**把它打印的那行 JSON 原样作为 `show_widget` 的入参**，一个字段都不要增删改写。
它们只打印文本、不出卡，所以**不走 `_run.py`**（那是主对话 A2UI 的通道，走错会当成出卡）。

| 脚本 | 必填 | 每条 `items[]` |
|---|---|---|
| `now_board.py` | `thing_id`、`as_of` | `code`、`name`、`price`、`change_pct`、`currency`，可选 `note`（那行解读） |
| `now_news.py` | `thing_id`、`date` | `title`（资讯标题）；可选 `code`/`name`（行业新闻可省）、`stance`（只认 `利好`/`利空`）、`takeaway`、`origin`、`url` |
| `now_stock.py` | `thing_id`、`title` | `code`、`name`、`time`、`price`，可选 `prev_close`、`change_pct`、`todo_id` |

脚本会**硬拦**几件事，报错就按提示补数据，不要绕过去自己拼 JSON：`thing_id` 缺失、
`as_of`/`date`/`title` 缺失（数据时刻不许用系统时间）、`stock` 卡放超过 3 只、
资讯条目缺 `title`。取不到 `url` 的那条自动不配 `tap`，拼不出链接的市场自动不配跳转。

下面两份骨架是**给人看的对照**，说明脚本会产出什么形状；**不要照着手写**。

### 骨架长什么样（对照用）

`recommend_list` 按 make-things `show-widget.md` 抄骨架，**只换股票正文**。
`stock` 同样以 `show-widget.md` 为准；样例和下游发卡里的 `hint` **不要抄**（proto 没有这个字段）。make-things **SKILL.md 表格仍写着旧的
`status/code/price/change/rising/chart`，那一行过时了，不要抄。**

顶层确定的约定：

- `card_type` 传**字符串** `stock`，**不要传数字 `5`**。IDL 枚举是 5，牛仔 `show_widget` 要字符串。
- 正文放顶层 **`data`**，**不要**再包一层 `"stock": { ... }`，也不要传 `conversation_id` /
  `thing_id` / `todo_id`（IDL 名）。关联事项用 camelCase `thingId` / `todoId`。
- 协议必填 `card_type` / `title` / `data`；`summary` / `actions` / `tap` 可选。
- **`source` 协议上可选，但我们每张卡都必须传。** 它画成卡片左上角那行蓝字，是用户在
  一屏动态里认出这卡谁发的唯一标记。漏了不报错、卡照出，只是顶上光秃秃一片，跟别的业务卡
  混在一起分不出来（2026-09-23 线上就是这样）。按子场景署名，**只有这两个值**：

  | 卡 | `source.label` |
  |---|---|
  | 盘面总结、股票卡（到价 / 异动 / 盘面） | `智能盯盘` |
  | 资讯总结（每晚日结、盘中重大） | `资讯监控` |

  别再编第三个名字，也别把资讯那张改署成「智能盯盘」——用户是按这行字区分「这是行情」
  还是「这是资讯」的。
- 嵌套枚举（`tap.type`、`trend`）传**数字**。
- **禁传** `kind`、`eventId`、`skill_name`、`uri`、`activity.*`、`push`、`triggerId`、
  `user_id`、`conversation_id`。这些是旧协议，现在传了会被拒。
- 按钮回会话：`{"action_id":"a_x","label":"…","tap":{"type":1,"agent_chat":{"send_prompt":"…"}}}`。
  `tap.type` 只有 1（回会话）和 2（开 H5）可用，3（小程序）牛仔宿主不支持。
- 图片只认**公网可达的 HTTPS 地址**，沙箱本地文件和内部短链都显示不出来。
- **发布成功的唯一凭据是回包里的 `now_id`。** 没有 `recommendation.id`，也没有去重——
  同参数再调一次就是**另发一张卡**。所以超时、40001 或回包缺失时**不要自动重试**，
  如实说「发布结果未确认」。

盘面总结（`recommend_list`）骨架，按钮和逐只跳转都在这儿：

```json
{
  "card_type": "recommend_list",
  "title": "今日盯盘总结 · 09/21 16:08",
  "summary": "A股港股红涨绿跌，美股相反",
  "source": {"label": "智能盯盘"},
  "thingId": "<真实 thing_id>",
  "actions": [
    {
      "action_id": "a_analyze",
      "label": "帮我分析",
      "tap": {"type": 1, "agent_chat": {"send_prompt": "帮我分析腾讯控股、阿里巴巴现在该怎么操作"}}
    }
  ],
  "data": {
    "items": [
      {
        "item_id": "hk00700",
        "title": "🔴 腾讯控股 430.00 HKD ▲2.63%",
        "desc": "主力净流入 13 亿，MA20 仍压制",
        "tap": {"type": 2, "h5": {"url": "https://wzq.gtimg.com/mm/detail?market=2&type=2&scode=00700"}}
      }
    ]
  }
}
```

`item_id` 用带市场前缀的代码，同卡唯一；`tap.h5.url` 里的 `scode` 是去掉前缀的裸代码。

资讯总结同一骨架，换 `title`/`desc`，按钮换成「聊聊对持仓的影响」：

```json
{
  "card_type": "recommend_list",
  "title": "今日资讯总结 · 09/21",
  "summary": "利好利空颜色同盘面口径",
  "source": {"label": "资讯监控"},
  "thingId": "<真实 thing_id>",
  "actions": [
    {
      "action_id": "a_holdings",
      "label": "聊聊对持仓的影响",
      "tap": {"type": 1, "agent_chat": {"send_prompt": "聊聊对持仓的影响：腾讯控股、阿里巴巴今天这些资讯"}}
    }
  ],
  "data": {
    "items": [
      {
        "item_id": "hk00700",
        "title": "🔴 腾讯控股 · 暂无公司公告",
        "desc": "反弹更像超跌修复 · westock",
        "tap": {"type": 2, "h5": {"url": "<westock 返回的那条新闻 URL>"}}
      }
    ]
  }
}
```

**每条资讯点进去是那条新闻的原文页，不是回主对话。** `tap` 一律 `type 2` + `h5.url`，
URL 用 westock 返回的那条新闻 h5 地址。

取 URL 的时候注意：`westock news article` 默认打出来的 markdown 表只有
`time / id / title / src / summary / typeStr` 这几列，**url 不在里面**。加 `--raw` 取 JSON
看全量字段，从那里拿链接。

**URL 只能用取数真返回的，不许拼、不许猜**——`id`（如 `SN2026…`）不是链接，别拿它去凑。
真有哪条取不到 URL，那一条就**不配 `tap`**（不可点）；退回主对话是错的，用户要的是原文。

到价/止损股票卡照这份抄，只换真实行情和 Thing ID（**已去掉会被拒的 `hint`
和画不出来的 `actions`**，整卡 `tap` 指向该标的自选股个股页）：

```json
{
  "card_type": "stock",
  "title": "已为宁德时代设置 8.00 止损提醒",
  "source": {"label": "智能盯盘"},
  "thingId": "<真实 thing_id>",
  "todoId": "<真实 todo_id>",
  "tap": {
    "type": 2,
    "h5": {"url": "https://wzq.gtimg.com/mm/detail?market=2&type=2&scode=03750"}
  },
  "data": {
    "items": [
      {
        "time": "09/18 16:07:58",
        "name": "宁德时代",
        "code": "03750·HK",
        "current_price": "9.006",
        "prev_close_price": "8.860",
        "change": "+0.14%",
        "trend": 2
      }
    ]
  }
}
```

盘面行情同一 `data.items` 结构，可放最多 3 只；**不配 `actions`**（协议禁止），
也不配 `tap`（多只票，整卡指向谁都不对）。
`time` 来自「数据时刻」梯子，禁止墙上时钟。`prev_close_price` 用 `westock quote` 的 `prevClose`。
价格和涨跌幅都是**已经格式化的字符串**。`trend`：`0` 未指定灰 / `1` 平盘灰 / `2` 上涨红 / `3` 下跌绿。

**这些写法都会 40001，禁止：**

- `data` 根上平铺 `code` / `name` / `price` / `change` / `rising` / `status`（腾讯那次就是这样被拒的）
- `chart` / `candles` / `x_labels`
- 顶层 `"stock": { "items": ... }` 而 `data` 里没有 `items`
- `"card_type": 5`
- `data.hint` / `tip`（proto 没有 hint，2026-09-21 传了就是 `unknown field "hint"`）
- 拿空 `data: {}` 的 `image_text` 顶替总结（图文卡必须有 `cover.url` + 整卡 `tap`）

**给 `stock` 卡配 `actions` 不报 40001，但更坏：**工具照样回 `now_id`，按钮直接不画，
看起来像发成功了。要按钮就用 `recommend_list`。

**禁止把 Show Widget Reference 里的示例原文发出去。** 文档里的「周末活动推荐 /
城市绿道散步 / 咖啡馆阅读」是协议样例，不是业务内容。盘面卡被拒时，不要用那份样例
「试通协议」——平台不去重，发出去就是用户动态里的一张真卡。被拒就停，报告 40001，
改股票正文再发，不许换题重试。

回调事件仍按事件发：到价/异动命中发该标的一张 `stock`；每晚资讯汇总发一张资讯 `recommend_list`。
不要拿盘面那套「股票卡 + 全清单」去套到价命中——那是**新建盯盘**才发的（见「创建」）。
