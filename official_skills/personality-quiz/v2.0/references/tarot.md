# 塔罗抽牌与解读

## 新牌局入口

先复用用户已经给出的具体问题。只有用户明确说“随便抽、自由抽、不带问题、你直接抽”或同义表达时，才以“此刻最需要留意什么？”作为中性问题直接进入牌桌；单说“帮我抽张塔罗”仍视为缺少问题。缺失时合并问一次：“选择事业、爱情、学业、财运方向，或写下此刻最想看清的问题。”快捷方向分别映射为“近期事业／感情／学业／财务上最需要看清什么？”。使用宿主真实 `ask-user-question`：标题引导填写问题，选项提供四个快捷方向和“不清楚 / 不想说”，输入栏接受自由文本；选择跳过时可用上述中性问题。工具不可用或确实不支持时才用普通消息。用户回答后立即进入牌桌，不复述、不确认、不追加领域、牌阵或语气问题。

当前牌桌采用 `tarot-studio` 暗色交互，固定抽取三张牌，不显示牌位含义。交付牌桌时，正文自然提示用户凭直觉选牌，并在完成后使用页面的「复制给元宝」返回会话继续解读。

获得问题后立即运行：

```bash
python3 scripts/artifact_pipeline.py tarot \
  --question "<用户选择或输入的原问题>"
```

流水线构建并校验牌桌，把页面写到宿主能收取的位置，并返回 `delivery` 与填好路径的 `media_info`。脚本失败或 `delivery.ok` 为 false 时不要改流水线、不要自己搬文件，也不要说牌桌已搭好。**`delivery.ok` 为 true 时必须交付**：把 `media_info` 贴进回复草稿，再运行返回的 `verify_command`，通过后把同一份草稿发出。

```
<media_info>[{"type": "file", "description": "塔罗牌桌，可直接洗牌抽牌", "path": "<output 绝对路径>"}]</media_info>
```

页面首次进入自动洗牌，本地完成抽牌、翻牌与静态牌义，抽完后在三张牌下分列对应的正逆位文案。「分享结果图片」生成含三张牌和文案的 PNG，在分享弹窗中展示，手机底部提示长按图片保存或分享，PC 底部提供下载图片。具体规则见 [image-save-share.md](image-save-share.md)。复制失败时进入手动复制弹窗，可全选完整结果。用户也可复制已揭示牌面回对话，不自动发消息。页面会在同一浏览器存储空间内恢复牌局；产品级 HTML 分享还需宿主按 [tarot-state-share.md](tarot-state-share.md) 接入结果快照。修改页面或诊断交付才读 [html-skill-architecture.md](html-skill-architecture.md)，正常构建不读实现规范。

不要讨论页面组件、接口、脚本抽牌、随机种子或技术回退。不要在对话里先替用户抽牌，也不要在页面交付前输出一版文字牌面。

## 收到牌面交接后

解读的输出表达直接维护在 [tarot-interpretation-method.md](tarot-interpretation-method.md#输出表达)；新牌局入口和静态牌桌展示不加载表达规范。

用户粘贴牌面信息即表示牌局已经完成。直接以其中的背景问题、牌名、朝向、位次、关键词和基础解释为事实层：

- 不重新抽牌，不要求补出生信息；
- 背景问题缺失时按通用牌义解读，不重新启动新牌局问答；
- 不把基础展示句原样扩写成结论；
- 不推断第三方秘密、忠诚、心理状态或未来行动；
- 不因用户不满意而不断重抽；“再抽一次”只由用户在页面主动触发。

完整读取 [tarot-interpretation-method.md](tarot-interpretation-method.md)，按核心母题、朝向机制、位次、用户问题、替代表现、校准问题与可逆行动完成解读。需要核对 78 张牌的内容覆盖、来源分层或流派边界时读取 [tarot-content-model.md](tarot-content-model.md) 与 [tarot-systems-and-corpus-design.md](tarot-systems-and-corpus-design.md)。

牌义足够时直接解释；需要情境参考时才按方法中的命令检索少量案例。案例不是古典原文或真实用户个案，不因排名靠前就作为事实。

牌面用于象征性自我观察，不作为未来事实或高影响决定依据。结尾保留传统文化与自我反思边界声明。
