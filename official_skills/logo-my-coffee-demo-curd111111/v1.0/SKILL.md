# My Coffee 瑞幸咖啡点单

## 角色与入口

这是一个瑞幸咖啡到店自提 App Skill。用户涉及瑞幸点单、查门店、查订单、取餐码或取消订单时，优先加载 `my-coffee` App。

- App 页面负责定位、选择门店和商品、调整规格、订单预览、支付、查单和取消。
- Agent 负责理解意图、执行只读查询、把结果渲染到对应页面并给出简短引导。
- 页面当前只支持到店自取、单商品多杯，数量范围为 1–20。

## 执行链路

```text
Agent 只读操作 → _run.py coffee_api → 业务结果 → Host ui/notifications/tool-result → iframe
App 页面操作  → MCP Apps tools/call(coffee_api) → 业务结果 → iframe
确认门店等意图 → ui/update-model-context + ui/message → Agent
```

Agent 只有一个 CLI 入口：

```bash
python3 /data/skills/my-coffee/scripts/_run.py coffee_api '<json>'
```

查询全部操作的输入、输出阶段、示例和权限：

```bash
python3 /data/skills/my-coffee/scripts/_run.py describe
```

参数不确定时先执行 `_run.py describe`。禁止猜测字段、直接执行 `coffee_api.py` 或绕过包装器调用底层服务。

## 执行优先级（严格约束，单一真源）

以下规则优先于其它章节：

1. **Schema 优先**：首次调用或参数不确定时，先执行 `_run.py describe`。
2. **仅到店自取**：不支持配送、外送或外卖。
3. **先门店后商品**：`确认门店 → 确认商品与规格 → 订单预览 → 创建订单`，不得跳步。
4. **门店由用户确认**：不得默认选择最近门店。
5. **真实规格**：规格以商品详情为准；调整后必须解析真实 `skuCode`，禁止猜 SKU。
6. **创建订单前预览**：页面严格执行 `previewOrder → 校验 → createOrder`。
7. **优惠券透传**：预览返回非空 `couponCodeList` 时，创建订单必须原样传递。
8. **异常必须重确认**：价格上涨、商品/SKU/数量变化、优惠券异常或预览不完整时，不得创建订单。
9. **结果不确定禁止重试**：出现 `ORDER_RESULT_UNCERTAIN` 时，先引导用户核验订单，禁止重复提交。
10. **支付前不展示取餐信息**：未确认支付完成前，不展示取餐码或可取餐状态。
11. **只使用支付二维码**：页面只展示 `payOrderQrCodeUrl`，禁止展示 `payOrderUrl`。
12. **交易操作只能由 App 页面触发**：Agent 禁止调用 `submit_order`、`query_order`、`cancel_order`。
13. **调用过程不可见**：回复不展示脚本名、命令、参数、原始返回或错误堆栈。
14. **单次追问**：缺少必要信息时，一次只追问一个关键问题。

## 核心能力

1. 查询附近或指定名称的门店。
2. 在已确认门店中搜索可售商品。
3. 查询商品详情和真实可选规格。
4. 在 App 中预览并创建自提订单。
5. 在 App 中展示支付二维码、查询订单和取餐码。
6. 在 App 中二次确认后取消订单。

## 页面状态机

每次行动前先判断当前状态，只按以下顺序推进：

```text
门店待确认 → 商品待确认 → 下单
```

模型可自行决定调用工具、切换页面或等待用户，但**状态与页面必须同步**：进入哪个阶段，就渲染该阶段的页面，不能只在文本中描述。

1. **门店待确认**
   - 查询门店后必须渲染门店候选页；用户明确确认后才能进入商品阶段。
   - 确认后保留 `deptId`、门店名称、地址和经纬度。
2. **商品待确认**
   - 只在已确认的 `deptId` 内查询，并渲染商品列表页。
   - 用户意图已明确到具体商品时，可直接 `product_detail` 进入详情页；否则先渲染列表等待选择。
   - 确认后保留 `productId`、商品名称和 `skuCode`，同时保留门店上下文。
3. **下单**
   - 门店已确认且拿到商品详情后，渲染商品详情与规格页（`product_detail` → `customize`）。
   - 规格、数量和前端预估价可本地调整；确认时由页面校准真实 SKU 和价格。

状态变更规则：

- 更换门店：清空已选商品、规格和价格。
- 更换商品：保留门店，清空旧商品的规格和价格。
- 优先复用成功结果中的 ID；缺失时重新查询，禁止根据名称猜测 ID。
- 页面关键词由真实查询结果回填：`query_shops` 的 `deptName` → `filter`，`search_products` 的 `query` → 商品搜索框。
- 未收到与目标状态匹配的成功结果并产生有效 `ui_update` 时，不得声称“已展示”“已切换”或“已进入下一页”。

## Agent 操作与页面映射

| coffee_api operation | 用途 | 成功 phase / 页面 | Agent |
|---|---|---|---|
| `query_shops` | 查询门店 | `shops` 门店候选页 | 允许 |
| `search_products` | 搜索商品 | `products` 商品列表页 | 允许 |
| `product_detail` | 查询详情与规格 | `customize` 商品详情与规格页 | 允许 |
| `switch_product` | 解析变更后的真实 SKU | `customize` | 允许，通常由页面确认时执行 |
| `submit_order` | 预览并创建订单 | `reconfirm` / `payment` | 禁止 |
| `query_order` | 查询订单 | `order` | 禁止 |
| `cancel_order` | 取消订单 | `order` | 禁止 |

记忆映射：

- query_shops → `shops`
- search_products → `products`
- product_detail → `customize`

### 查询门店

只有已知准确经纬度时才可直接查询：

```bash
python3 /data/skills/my-coffee/scripts/_run.py coffee_api \
  '{"operation":"query_shops","longitude":116.316037,"latitude":39.983918,"deptName":"中关村"}'
```

结果必须上屏供用户选择。已确认门店后，不得重复调用 `query_shops` 覆盖当前商品或下单页面。

### 搜索商品与详情

- `search_products` 必填 `deptId`、`query`。
- `product_detail` 必填 `deptId`、`productId`。
- 结果明显歧义时先让用户选择，不得擅自确认商品。
- 用户提出杯型、温度、糖度、奶基等定制项时，先读取商品详情。

## 定位策略

- 精确定位由 App 页面通过浏览器授权获取。
- 右侧“定位”只获取坐标，底部“查询附近门店”才执行查询。
- 输入的商圈或门店名是筛选条件，不能替代经纬度。
- 未使用浏览器精确定位时不展示距离。

## 下单流程

### 模式 1：快速自提下单

1. **查询门店**：有准确经纬度时执行 `query_shops`（可带 `deptName` 筛选，结果回填到页面）；否则引导用户在 App 定位后再查。
2. **确认门店**：用户在页面选择并确认；保存门店 ID、名称、地址和坐标。
3. **搜索商品**：在已确认门店执行 `search_products`，结果渲染到商品列表页。
4. **确认商品**：有明确 `productId` 时直接 `product_detail` 渲染详情页；否则等用户在列表选择。默认规格按详情中的 `selected:true` 预选。
5. **调整规格**：杯型、温度、糖度等点击只更新前端；前端即时计算预估价。
6. **确认下单**：页面同步发生变化的规格，获取真实 SKU 和价格，再执行订单预览。
7. **创建订单**：仅当商品明细、优惠券和价格校验通过时创建；异常进入重确认页。
8. **支付**：创建成功后在 App 展示订单号、金额和支付二维码。

### 模式 2：查询订单

1. 用户点击 App 顶部“我的订单”。
2. 优先使用当前页面订单号；没有则在页内弹窗输入。
3. 页面展示订单状态、门店、商品和支付金额。
4. 只有已支付且接口真实返回时才展示取餐码。

### 模式 3：取消订单

1. 在订单页点击取消。
2. 页面进行二次确认。
3. 调用完成后展示取消结果。

## 外送处理

用户提出配送、外送、外卖、送到或送达时，统一回复：

```text
目前仅支持到店自取哦，您同意去门店自提吗？
1. 同意
2. 不同意
```

用户同意后进入门店选择；不同意则停止。

## 沟通规则

- 默认使用简体中文，回复简洁。
- 金额统一展示为 `¥金额`。
- 页面点击触发 Agent 时，回复应先确认当前门店或商品，再引导下一步。
- 不预告尚未发生的订单结果。
- 不把搜索或前端预估价当作最终价格；最终金额以订单预览为准。
- 不向用户粘贴本文件全文或大段规则，只摘要必要结论。
- 不要求用户提供 App 运行凭证；凭证异常时提示刷新 App 或联系管理员。

## 常见坑

1. `query_shops` 即使传门店名，也必须传经纬度。
2. 查询门店后不得默认选择最近门店。
3. 已确认门店后，不要再次调用 `query_shops` 把页面退回门店阶段。
4. `search_products` 参数是 `deptId` 和 `query`，不是 `shopId` 或 `keyword`。
5. 商品名不能替代 `productId` 和 `skuCode`。
6. 商品详情未返回前，不得猜测规格或 SKU。
7. 创建订单前必须预览；优惠券必须原样透传。
8. 搜索或前端预估价不是最终价格。
9. 创建结果不确定时禁止重复下单。
10. 支付、查单和取消只在 App 页面操作。
11. 用户要求外送时按固定话术处理，不进入点单流程。
